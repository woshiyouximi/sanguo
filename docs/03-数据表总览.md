# 03 数据表总览：三国群英传2（1999，宇峻奥汀）的 10 个 INI

> 本文档由 `tools/gen_docs.py` 从 `extract/json/*.json` 生成，所有数字都是解析实测值。
> 解析器 `tools/parse_ini.py`（通用 INI→dict，自动编码探测）；各表导出脚本 `tools/export_*.py`。

## 0. 一句话结论

PAK 内 10 个 INI 共 **1,750,311 字节 / 90,694 行 / 3,848 段 / 86,820 个字段行**，
构成一套完整的"数据驱动"配置：技能表决定战斗、物件表决定一切图形与动作、
剧本表决定五个时代的武将与城池、物品表决定成长曲线、文本表决定全部对白。

## 1. 编码：实测不是 GBK，而是 Big5（cp950）

任务书假设"INI 都是 GBK(936)"，实测**全部失败**：

| 编码尝试 | 结果 | 证据 | 说明 |
|---|---|---|---|
| `utf-8-sig` | 失败 | 首个中文字节即报错 | 不是 UTF-8 |
| `gbk` (cp936) | **失败** | `UnicodeDecodeError: 'gbk' codec can't decode byte 0xa4 in position 106` | 任务书中的假设被实测推翻 |
| `cp950` (Big5 繁体) | **成功** | `A9 D2 C0 F8 B3 5C` → `黃巾賊` | **实际编码** |
| `big5` | 成功 | 与 cp950 结果一致 | 同义别名 |

- 受影响文件：MAGIC / MESSAGE / SANGO / THINGS / TIMES1-5。
- 例外：`COMBINE.INI` 是纯 ASCII（只有坐标与路径）。
- 判据不止"能解码"：cp950 解出的中文在游戏语境里全部成立
  （`黃巾賊`、`命療術`、`主將L1 (主體) - 劍`、`群雄割據`），gbk 解出的是乱码。
- **原始编码 cp950，需转简体**：本项目文档统一用繁体原文引用字段值，
  正文用简体叙述。若要把数据转简体，注意 `後/后`、`鍾/钟`、`臺/台` 一类一对多映射，
  建议 Big5→Unicode 后再走 opencc `t2s`，不要用 gb18030 往返（会丢字）。
- `tools/parse_ini.py` 因此按 `utf-8-sig → gbk → cp950 → big5 → latin-1` 顺序试解，
  并用"可疑字符惩罚"（西里尔/希腊/制表符/私用区得分高）挑最像中文的那次结果。

## 3. 表间引用关系

```
SANGO.INI [SYSTEM].Times01..05 ──> TIMES1..5.INI（五个剧本入口）
SANGO.INI [ITEM] ────────────────> TIMES.General.Weapon / Horse / Thing（按名字引用）
SANGO.INI [FONTS01..07] ─────────> SANGO.20 / SANGO.15 / SANGO.IDX / MINGASC.20 / OLDASC.15
SANGO.INI [TERRAIN] ─────────────> SHAPE\BG\*（图层）
TIMES.General.SKILL / WISESKILL ─> MAGIC.INI 的 [MAGIC]×110 / [WISE]×67（按顺序号）
TIMES.General.FACE ──────────────> SHAPE\FACE\FACE001..400.SHP（1:1 编号）
TIMES.General.Force ─────────────> THINGS 兵种（13 个，Sequence 100..112）
MAGIC.SCRIPT ────────────────────> SCRIPT\MAGIC.SO（501..610 共 110 个脚本入口）
THINGS 动画序列（图形名）────────> SHAPE\<Directory>\<图形名>.SHP（34220 处引用）
THINGS 动画里的 !nnnn ───────────> SCRIPT\MAGIC.SO 的脚本号（15 处）
COMBINE.INI [SHAPE] ─────────────> SHAPE\FACE\FACE001..004（拼一张 192×192 测试图）
```

这张图解释了"为什么字段含义可以确定"：几乎每个字段都能在另一张表里找到对应物。
本项目的字段结论优先采用"有对应物"的推定，其余明确标注**推测**。

## 4. 交叉验证汇总（7 项，另有结构常量见第 5 节）

| 检查项 | 方法 | 结果 | 结论 |
|---|---|---|---|
| THINGS 图形名 ↔ 磁盘文件 | 34220 处图形引用逐个核对文件是否存在 | 34195/34220（99.93%） | 真实物件 100% 命中；25 处缺失全在两段非运行数据上 |
| TIMES FACE ↔ SHAPE\FACE | 401 名武将的 FACE 字段逐个核对文件 | 401/401 = 100%（五份剧本同） | FACE001..400 共 400 个文件；模板段复用 FACE001 |
| MAGIC.SCRIPT ↔ MAGIC.SO | 脚本号范围 + 与武将 SKILL 编号空间互证 | 501..610 连续 110 个 | 261,008B / 110 ≈ 2373B 每脚本 |
| 书籍加智力 ↔ 修正版说明 | SANGO.INI [ITEM] 的 INT 与 Description 比对 | 7 / 10 / 13 / 17 / 20 全对 | 说明文档的 7-10-13-17-20 就是**数据表内**的设定值 |
| 兵符位掩码 ↔ THINGS 兵种 | 13 个兵符 Force 与 Sequence 100..112 对位 | 13/13 全对 | Force = 1<<k，顺序完全一致 |
| GENERAL.CITY ↔ POS 槽位 | CITY 与 POS 第 N 个空格槽比对（N=剧本号） | 1999/2001（T5 两例例外） | 司馬昭、司馬師 POS 第 5 槽=許昌 而 CITY=鄴 |
| 等级/体力上限 ↔ 说明文档 | 初始 BaseHP/BaseMP 与 99 / 32767 对照 | 初始值 ≤ 99，全表无 32767 | 32767 是运行时上限，表内只存初始值，二者不矛盾 |

## 5. 陷阱：四个 `Total*` 常量不是计数

| 常量 | 值 | 实际条目 | 判定 |
|---|---|---|---|
| `SANGO.INI [SYSTEM] TotalThings` | 99 | 77 | 物品数组容量 |
| `THINGS.INI [SYSTEM] TotalObjectDefine` | 300 | 621 | 物件定义容量（小于实际，更说明不是计数） |
| `TIMES*.INI TotalGeneral` | 512 | 401 | 武将数组容量 |
| `TIMES*.INI TotalCity` | 64 | 60 | 城池数组容量 |
| `TIMES*.INI TotalKing` | 15/19/9/9/6 | 15/19/9/9/6 | **真计数**，与实存君主段相等 |

读表时若拿 `TotalGeneral=512` 去遍历数组会越界；真正的条目数只能数段。

## 6. 七条关键结论

| # | 结论 |
|---|---|
| 1 | 10 个 INI 共 1750311 字节 / 90694 行 / 3848 段，全部为 Big5 繁体（COMBINE.INI 纯 ASCII）。 |
| 2 | 技能表 177 条 = 110 武将技 + 67 军师技；武将技脚本号 501..610 连续且唯一，平均每个脚本 2373 字节（MAGIC.SO 261008B）。 |
| 3 | THINGS 620 个正式物件 + 1 段测试物件 [OBJECT2] + 1 段中文骨架，图形引用 34220 次、真实物件 100% 命中磁盘文件。 |
| 4 | 兵种恰好 13 个，兵符 Force = 1<<k 位掩码，与 THINGS Sequence 100..112 顺序一致。 |
| 5 | 5 个剧本共用同一套 401 名武将，STR/INT/Loyal 五份完全相同（差异 0 条），剧本只切换 POS/CITY/Status。 |
| 6 | CITY 字段等于 POS 的第 N 个空格槽（N=剧本号），401/401 成立。 |
| 7 | 武将初始武器只有 4 种（直劍/銅殳/眉尖刀/短錐槍，即 ITEM 前 4 件 Lv1 武器），初始坐骑 401 人全是黃鬃馬（Lv1）。 |

## 8. 怎么用这批数据

```python
from parse_ini import IniFile, write_json

ini = IniFile.load(r"F:\sanguo\extract\pak\THINGS.INI")   # 自动探测 cp950
print(ini.encoding, ini.stats()["sections"])                 # cp950 623

sec = ini.sections[1]          # [DEFINE]
sec.get("TYPE_MAJOR")          # "4"
sec.getall("File")             # 同键多值全部取出
sec.num("TotalObjectDefine")   # 数字（支持 0x 前缀）

objs = ini.all("OBJECT")       # 同名段全部（620 个）
grp = ini.prefix_groups()      # {"KING": 19, "CITY": 60, ...}
write_json(r"F:\sanguo\extract\json\x.json", ini.to_dict())
```
