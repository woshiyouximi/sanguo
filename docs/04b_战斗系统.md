# 04b · 战斗系统（Battle System）

> **一句话结论**：《三国群英传2》的战斗不是一个"伤害公式函数"，而是一套**实体-组件式的 2D 格子战场**：每个战场物件（兵/将/箭/特效）是一个带 vtable 的 C++ 对象，通过 20 余种**对象消息**（`OM_ATTACK`/`OM_PAIN`/`OM_DEATH`…）驱动；**命中**由"本方战斗力 `unit+0x70` 对抗 `rand()%300`"一次性判定，**伤害落地**在各兵种/主将类自己的 `OM_PAIN` 处理器里；而兵种相克、阵法相克、地形、士气这四项**全部只以"加算"方式汇入那个战斗力数值 `unit+0x70`**，因此它们影响的是**命中率**，而不是逐次伤害数字。
>
> 本文证据全部标 VA（虚拟地址，ImageBase `0x400000`）。`.text` 段的 VA↔文件偏移 = `VA - 0x1000 + 0x400`；`.data`/`.rdata` 必须查 PE 段表（工具 `tools/pe_str.py`）。
> 相关文档：引擎总体 → [04_引擎架构与代码逻辑总览.md](04_引擎架构与代码逻辑总览.md)；武将技表 → [03a-武将技表MAGIC.md](03a-武将技表MAGIC.md)；物件/动画 → [03b-物件表THINGS.md](03b-物件表THINGS.md)。

### 1.3 对象消息协议（THINGS.INI `[DEFINE]` 原文，文件名 `extract/pak/THINGS.INI`）

```
OM_ALLOCATE=0x00000001  OM_TICK=0x00000002  OM_REMOVE=0x00000003
OM_ATTACK=0x00010000    OM_WALK=0x00010001  OM_WAIT=0x00010002
OM_DEATH=0x00010003     OM_PAIN=0x00010004  OM_TOUCHER=0x00010005

```
`0x43DDBF`(1032 B) 就是某个 Process 类的消息处理器：`msg-0x10001` 后 `cmp 0xc` 走 13 项跳表 `0x43E193`（= `OM_WALK`..`OM_FLEERUN`），`msg==0x10000` 单独走 `0x43DF43`（`OM_ATTACK`）。
→ **THINGS.INI 的 `Process` 字段（1..21）决定类，每个类实现自己的消息处理器**；这也是全 EXE 找不到"唯一伤害函数"的原因。

## 2. 伤害与命中（Q2）

### 2.1 ★ 命中判定 `0x43D400`（**本作真正的"伤害公式"**）

dump：`work/dis_battle_hitroll_43D400.txt`

```c
// int __cdecl HitRoll(obj* attacker, obj* target)   返回 1=命中
int HitRoll(obj* a, obj* t) {
    int p = a->unit(+0x40)->power(+0x70);          // 0x43D409 本方战力
    if (0x43B6A8(t) != 0) {                        // 推断：判定目标是否为"武将类"
        general* g = t->unit(+0x40)->general(+0x48);
        p = 150 - (g->STR(+0x34) * 20) / 100;      // 0x43D431..0x43D445：imul 0x14; idiv 0x64; 0x96 - q
    }
    if (0x43BE08(t) == 0)                          // 推断：目标状态检查
        p = p * 2 / 3;                             // 0x43D45A..0x43D467
    int roll = rand() % 300;                       // 0x450117(0x12c)
    if (roll < p) return 1;                        // ★ 命中
    if (a->status(+0x2c) & 4) {                    // 0x43D48C：连击/必杀位
        p = p * 2 / 3;
        roll = rand() % 300;
        if (roll < p) return 1;                    // 第二段判定
    }
    return 0;
}
```
**要点**
1. 分母固定 **300**，战力 `unit+0x70` 就是"命中权重"。
2. 打**武将**时改用 `150 − 武力/5`（武力 100 → 130，武力 20 → 146）：**武力越高越难被命中**。
3. `attacker->+0x2c & 4` 提供一次**额外 2/3 概率的补判**（连击）。
4. 随机数 = `0x450117(n) = rand32() % n`；`0x450132` 是自研 PRNG（状态 `0x4922FC`/`0x492300`，旋转+异或），**不是 MSVC LCG**（全文件搜 214013/2531011 命中 0）。

### 2.2 近战接触 `0x43D686`（谁被谁打）

dump：`work/dis_battle_hit_43D686.txt`

```c
int Melee(obj* a, int dir, int param) {
    obj* t = CellFind(a->+0x08 + dir, a->+0x0C);   // 0x43AF7A：取相邻格对象
    if (!t) { if (0x43B961(a) > 1) { 0x43D5BF(a); return 1; } }  // 无人 → 走位
    if (t && 0x43B663(a, t) != 0) return 0;         // 同阵营/不可打
    int hit = (param == 1) ? 1 : HitRoll(a, t);     // ★ 调 0x43D400
    if (hit == 1) {
        void* rev = t->+0x44;                       // 目标的消息接收者
        rev->vtable->msg(OM_PAIN, a->+0x44);        // ★ 只发"受击"消息
        return 1;
    }
    ... // 未命中：按 dir 继续判定/落空
}
```
→ **命中后不在这里扣血**，只发 `OM_PAIN`。真正的数值变化在**受击对象所属 Process 类**的 `OM_PAIN` 处理器里（多态分派）。这解释了为什么用"字段偏移扫描"找不到普攻伤害函数。

### 2.3 各类"血条"的真实含义

| 资源 | 存放 | 战斗中的变化 | 证据 |
|---|---|---|---|

| **帶兵數** | `general+0x44`（战场快照 `unit+0x14`） | 士兵阵亡 → 上限下降；结算用差值算战功 | `0x4104A3`；`0x410CA3` |

### 2.5 ★ 戰鬥力 `unit+0x70` 的五段加算（`0x442EFA` B 侧 / `0x443498` A 侧）

```c

u->+0x70 += TerrainMod (g->+0x8B, [0x4A6694]);          // 0x442FD5  地形 12×13
```

- 另有一个独立的士气惩罚函数 `0x43A14D`：`m = 士氣; if (m > 50) return -1; v = clamp(m,4,50); return v*120/20 = v*6;`（用于士兵行动节奏，推断）。

### 2.6 武将技（法术）路径

`0x43BAE3`（dump `work/dis_battle_magic_43BAE3.txt`）：

```c

    int mp     = MagicDef_MP(magicId);        // 0x40A38E 读取 +0x08
    int cost   = MagicDef_POWER(magicId) * 1200;   // 0x40A3B1 读 +0x0A；imul 0x1d4c0 后 idiv 0x64
```

```c
mode 3 平手：      scW += gL->+0x2E * 0x11;  scL += gW->+0x2E * 0x11;   // 等级 × 17
                   unitW->+0x04 = 2;  unitL->+0x04 = 2;
mode 4 大胜：      scW += gL->+0x2E*0x11;  scL += gW->+0x2E*0x11;  然后 scW*=2; scL*=2;
                   unitL->+0x04 = 6;
// 同时 0x4084C9(胜方, +1) / 0x4084C9(败方, -1 或 0)

// ③ 回写 士气/体力/技力
gW->+0x38 = unitW->+0x2C;                          // 士氣 = 战场累计
gW->+0x10 = unitW->+0x1C;  gW->+0x14 = unitW->+0x20;   // 體力/技力 = 战场剩余
if (gW->+0x12 > gW->+0x10) gW->+0x12 = gW->+0x10;      // 上限不小于当前
if (gW->+0x16 > gW->+0x14) gW->+0x16 = gW->+0x14;
// （另有一条：若 舊上限 > 战场上限 则把上限压到 unit+0x24/+0x28）

// ④ 功勋（+0x3A）
base = (bonus == -1) ? (rand()%8 + 15) : (bonus/10 + 15);       // 15..22 或 15+秒数/10
if (unitW->+0x34 & 0x1000) eW = 0x4103DE(base, unitW->+0x38);   // 军师技「經驗值增加%」
gW->+0x3A = min(gW->+0x3A + eW, 100);                           // 对 gL 对称

// ⑤ 经验倍率
if (unitW->+0x34 & 0x2000) scW = scW * (unitW->+0x3C + 100) / 100;

// ⑥ 落账
unitW->+0x08 += scW;   unitL->+0x08 += scL;                     // 条目+0x08 = 本场经验
```
`0x443F2A() = (0x2E68 - [0x4AC35C]) / 0x78 = (11880 − 倒计时)/120` —— **bonus 是"战斗时长"**，即**打得越久功勋越多**。

### 6.5 战后士气/忠诚 `0x447520(army)`（已按 04b5 更正）

## 9. ★ 新游戏可直接复用的规则清单

> 这一节是"抄规则"用的，按可直接落地程度排序。每条都注明原始实现位置，便于回查。

### 9.1 命中/伤害骨架（强烈建议照抄结构）

1. **用"单次命中判定 + 类内伤害"分离结构**：`命中率 = 战力 / 300`，命中后只广播 `受击` 消息，让兵种类自己决定死/伤。**好处**：兵种差异全部内聚，不需要一张巨型公式表。
2. **相克不做乘数，做加数**：战力 = 兵种相克 + 地形 + 阵法 + 士气修正，四项相加后除以 300 当命中率。**好处**：数值天然有界（±68+±25+±25），不会出现"相乘爆炸"。
3. **打武将用另一条判定**：`p = 150 − 武力/5`（武力 0..100 → 150..130），与士兵的"战力/300"分开。**好处**：武将的"闪避"由武力单独承担。
4. **连击位**：`状态 & 4` 时给一次 `×2/3` 概率的补判，等于"两次判定至少中一次"。

### 9.2 相克表（可直接搬数值）

5. **兵种相克用 13×13、±68 上限、对角 0、近似反对称**（表见 §3.1）。设计新表时保持：`sum(row) ≈ 0`（无万金油兵种）、极值 ±68。
6. **地形修正按"地形 × 兵种" 12×13，值域 ±25**（§3.2）。平地三行完全相同（0/0/0/10/0/…），**只有弓箭在平地上 +10** —— 这是"远程平地优势"的最小实现。
7. **阵法相克 9×9 + 2 个特殊阵，值域 ±25**（§3.3）。**亂陣（无阵）对所有阵 −25、所有阵对它 +25** —— 用一行"全 −25"实现"不设阵就是挨打"，非常省事。
8. 三条可套路化的设计约束：
   - 相克表**只被 4 个函数读**（2 个战力合成 + 1 个面板 + 1 个 AI）→ 新引擎也应把相克读取集中到 1~2 个出口，避免散落。
   - 相克值**同时用于 UI 展示**（面板 5 行）→ 数值即文档，玩家能看懂自己为什么强/弱。
   - 相克**不改伤害、只改命中** → 避免"高相克一刀秒"的体感问题。

### 9.3 资源与气条

9. **双资源**：`技力(MP)` 用于"能不能放"，`氣力(能量条 0..60000)` 用于"放得多快"。武将技同时消耗两者：`MP = MagicDef.MP`，`氣力 = POWER × 1200`（即满条的 1/50 为 1 点 POWER）。
10. **技表 8 槽 + {等级, id} 学习表**：`general+0x54`(已学武将技 8 个) / `+0x5C`(军师技 8 个) / `+0x65`(8×{等级,id})。升级时按等级扫表补学（`0x40A183`/`0x40A227`）→ **"等级到了自动学会"**，无需技能树。
11. **军师技用"位掩码 + 百分比"落到战场单位**：`unit+0x34` 每一位一个效果，`+0x38` 是强度。**好处**：一场战斗内军师技可叠加，且结算时可逐个 `if` 判定，不用维护对象列表。

### 9.4 成长与结算

12. **所有上限都是"等级 + 主属性"的线性式**（照抄即可）：
    - `帶兵上限 = BaseHP + level*2*STR/100`（下限 BaseHP，上限 32767）
    - `技力上限 = BaseMP + level*2*t/100`，`t = (STR>INT) ? (STR+INT)/2 : INT`（**注意：技力吃的是"武力与智力的较大者"**，鼓励双高）
    - `帶兵數 = min(5×level, 100)`，`騎兵數 = clamp((level−20)×5, 0, 100)` → **20 级前只有步兵，20 级后逐级转骑兵**，骑兵权重 2（战功分 ×12 vs 步兵 ×6）。
13. **升级保留溢出**：`新当前 = 新上限 + (旧当前 − 旧上限)` → 升级即回满，且不浪费溢出。
14. **战功分公式**：`分 = 击杀步兵×6 + 击杀骑兵×12 + 敌将等级×{51 歼灭 / 34 击退 / 17 平手 / 34 大胜再×2}`，败方分减半。**"杀兵得分"是主项，"杀将"是系数项** —— 这个权重让玩家愿意打消耗战。
15. **经验二次分配**：另有 `每人 += 敌方等级和 × 32 ÷ 我方人数` → **带的人越多，人均越少**，鼓励精兵。
16. **功勋 = 15 + 战斗秒数/10**（15..22），上限 100 → **拖时间也能涨功勋**，避免速推。
17. **战后惩罚**：全员 `士氣 −20`、`疲勞 = +(10 − CONSTANCY)×2` → CONSTANCY 高的武将更适合连战。
18. **俘虏判定是"一个参数"**：`0x40ED3A(g, g->+0xD7)`，君主另走"逃走"分支。**用单个随机参数决定，不需要复杂公式**。

### 9.5 战场结构

19. **格子战场**：71 列 × N 行，两套平行数组（占位指针 / 16.16 权重场），**7×7 金字塔核**（`7 − max(|dx|,|dy|)`）在对象入/出格时叠加邻域。**这是"拥挤/势"的最省实现**：一次 O(49) 的加减，就能让士兵自然散开、堆叠变慢。
20. **移动抖动**：目标点 `±24 px / ±18 px` 随机偏移后再 clamp 到战场矩形 → **同一指令下队列自然散乱**，无需寻路。
21. **随机受击者**：`rand() % 存活数` 选槽 → 攻击不必指定具体兵，**O(1) 选目标**。
22. **对象消息协议**（`OM_ATTACK/OM_PAIN/OM_DEATH/OM_TOUCHER/OM_TOUCHED`）：所有交互走 6 条消息，兵种差异由类实现。**这是本作最值得抄的架构**：新增兵种 = 新增一个类 + 一组动画，不改主循环。
