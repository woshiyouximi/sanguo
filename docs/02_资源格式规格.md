## 1. `.SHP` — TLHS 精灵（核心格式）

### 1.1 头部（0x24 字节，小端）

| 偏移 | 类型 | 含义 | 实测 |
|---|---|---|---|
| +0x00 | char[4] | 魔数 `"TLHS"` | 全部一致 |
| +0x04 | u32 | 保留 0 | 0 |
| +0x08 | u32 | 像素格式标识 | **恒为 2 = RGB565** |
| +0x0C | u32 | 保留 0 | 0 |
| +0x10 | u32 | **透明色键**（bit15 掩码前的 RGB565 值） | 见 §1.4 分布 |
| +0x14 | u32 | **宽 width** | 如 FACE001=100 |
| +0x18 | u32 | **高 height = 行数 = 偏移表项数** | 如 FACE001=120 |
| +0x1C | i32 | **offsetX**（绘制原点相对左上角） | 可为负 |
| +0x20 | i32 | **offsetY** | 可为负 |
| +0x24 | u32[height] | 每行数据的**文件内偏移** | `offs[0] == 0x24 + 4*height` |

**校验规则**：`offs[0] == 0x24 + 4*height`，10,969/10,969 个文件全部成立 —— 这条规则可以当作格式指纹。

### 1.2 行数据（RLE，按行压缩）

每行 = 一个或多个"片段"，片段之间用 `0xFFFF` 分隔，行结束也是 `0xFFFF`：

```
u16 x        ; 该片段起始 x（0-based）
u16 n        ; 像素个数
u16 color[n] ; 颜色，**从左到右**，每像素 RGB565
```

- 同一行可以有多个片段（即一段连续像素之后跳过若干透明像素再来一段），**因此 `x` 字段是稀疏间隔的来源**，不是行首省略。
- 加载器会做一次"修补"（VA `0x46B3D0`）：把 `x` 字段换成累加的起始偏移（`x_i += 前一片段的 x+n`），把 `0xFFFF` 终结符改写为 `0`，并按 `mode==2` 做 RGB565 通道校正（`and 0x1F` / `and 0x7FE0` / `or` 重组）。这一步在内存里做，**磁盘上的文件保持原始形态**。
- 极端情况：`DEFAULT.SHP`、`NULSHAPE.SHP` 每行只有 2 字节（`0xFFFF`），即全透明占位图。

### 1.3 一行数据的实例（FACE001.SHP 第 0 行）

```
00 00 | 64 00 | E9 61 FF 5A 7C 4E ... (100 个 u16) | FF FF
  x=0    n=100              100 个 RGB565 颜色            行结束
```
整行 100 像素全部不透明 → 头像没有镂空，符合"头像是一张完整矩形位图"的事实。

### 1.4 透明色键分布（全量统计）

| 色键值 | RGB565 解码 | 文件数 | 说明 |
|---|---:|---:|---|
| `0x07C0` | 绿 (0,63,0) | 9,536 | **主色键**，绿幕 |
| `0x0000` | 黑 | 551 | 黑色透明 |
| `0xFFFF` | 白 | 489 | 白色透明（头像多用） |
| `0x07E0` | 纯绿 | 121 | |
| `0x00DF` | 蓝 | 102 | |
| `0xA81F` | 品红系 | 28 | |
| `0x51A4` | — | 22 | |
| `0x07F0` | — | 18 | |

> 引擎**不存 alpha 通道**，只靠"色键 + 逐行 RLE"裁剪。新项目若改用 PNG/图集，可把这些文件的色键转成 alpha=0，视觉等价。

### 1.5 解码器

`F:\sanguo\tools\sango_shp.py`：

```python
import sango_shp
s   = sango_shp.load(r'...\SHAPE\FACE\FACE001.SHP')   # -> Shp(width, height, key, offx, offy, rows)
img = sango_shp.to_image(s)                            # PIL RGBA，色键像素 alpha=0
sango_shp.save_png(src, dst)
```

行数据在内存里表示为 `rows[y] = [(x, [colors...]), ...]`，导出时按 `x` 摆放，其余保持全透明。

## 2. 多帧动画怎么来的

**一个 .SHP 只是一张静止图**（`height` 行 = 图像高度）。动画由 `THINGS.INI` 的序列定义把**多个 SHP** 串起来：

```ini
[OBJECT]
Directory = FORCE\MA*        ; 目录通配
Sequence  = WALK, 0, 4       ; 动作名, 起始帧, 帧数
Sprite    = SH01             ; 造型编号
```

引擎里的动作名常量（EXE 0x48DEB0 起）：`WAIT / WALK / LOSE / ATTACK / DEFENSE / PAIN / DEATH / FIRST / ATTACK2..ATTACK8 / SPELL1 / SPELL2 / SHOT1..SHOT3 / CURSOR / STAFF / END1..END3 / HIT01 / SCROVER`。这 20 多个动作就是战斗状态机的状态名。

**复合造型不是靠 `COMBINE.INI`**：`COMBINE.INI`（27,534 B / 8 行，其中第 8 行是 27,388 个空格填充）实测**只有 4 条 `SHAPE=` 记录**，是把 `FACE001`–`FACE004` 按 2×2 网格（step 96，bbox 192×192）拼成一张图的**测试配置**。

真正的"武将一帧"是引擎里硬编码的三层装配：`MAJOR\BODY`（身体）+ `MAJOR\WEAPON`（武器）+ `MAJOR\HORSE`（坐骑，仅骑乘），每层用自己的 `offsetX/offsetY` 锚点叠加（详见 `05b_动画与造型目录.md`）。

## 3. `.TEX` — 整屏图（**标准 TGA，Pillow 直接可读**）

`.TEX` 的扩展名是骗人的：它**就是标准的 Truevision TGA 2.0 文件**，Pillow 的 `Image.open()` 能直接打开，不需要自己写解码器。

18 字节标准 TGA 头（7 个文件完全一致）：

| 偏移 | 类型 | 值 | 含义 |
|---|---|---|---|
| +0x00 | u8 | 0 | ID 长度 |
| +0x01 | u8 | 0 | 无调色板 |
| +0x02 | u8 | **2** | 未压缩真彩色 |
| +0x03 | u8[5] | 0 | 调色板规格（空） |
| +0x08 | u16×2 | 0,0 | X/Y 原点 |
| +0x0C | u16 | **640** | 宽 |
| +0x0E | u16 | **480** | 高 |
| +0x10 | u8 | **16** | 16 bpp |
| +0x11 | u8 | 0 或 1 | 描述符：bit0=属性位存在，bit5=顶向下（实测均底向上） |

之后 `640×480×2 = 614,400` 字节像素，**RGB555**：`R=bits10-14`、`G=bits5-9`、`B=bits0-4`、`bit15=属性位`；行序自下而上（TGA 惯例，Pillow 会自动翻正）。

| 文件 | 体积 | 结构 |
|---|---:|---|
| `POLICY\PALAIS01-05.TEX`、`POLICY\YIELD.TEX` | 614,420 | 18 + 614,400 + **2 字节尾巴**（打包工具的怪癖，忽略即可） |
| `MAP\TEXTURE.TEX` | 614,444 | 18 + 614,400 + **26 字节 TGA 2.0 页脚**（`TRUEVISION-XFILE`）→ 大地图地形噪声图 |

```python
from PIL import Image
Image.open('PALAIS01.TEX').save('PALAIS01.png')   # 就这样，无需自定义解码
```

> **踩坑记录（值得记的教训）**：这个 `.TEX` 我前后判错过两次——先判"自定义 R4G5B5"，又判"Pillow 能开但红通道是 4 位、所以不是标准 TGA"。两次都是被"用同目录同名的 `PALAIS01.SHP` 当基准算像素误差"带偏的：**两者确实是同一张画面**（都是内政大殿），但 `.SHP` 版明显更暖更亮（引擎载入时 555→565 的转换会把红色丢掉一位，且这两个资源本身经过了不同的色深保存），**逐像素误差永远不为 0，于是任何"误差最小"的判据都会指向错误的格式**。
>
> 最终判据只有两条硬证据：①头 18 字节的字段值与 TGA 2.0 规范逐项吻合（`imagetype=2`、`bpp=16`、`descriptor` 的 bit5 决定行序）；②反汇编里加载器 `0x41D2D4` 就是"读 18 字节头 + 读 `0x96000` 字节像素 + 调 `0x46B2D0` 转 565"——**引擎自己按 TGA 读**。
> **教训：判断一个未知格式，先看"引擎怎么读它"（反汇编 20 行就够），不要用图像相似度去反推位布局。**

### 3.1 与 `.SHP` 的关系：565 是引擎内部格式，555 是磁盘格式

引擎把 TGA/555 素材转成 DirectDraw 的 16bpp 表面时做了一次改造（反汇编 `0x46B3D0` 一带的载入修正里可见）：

```
565 = (v & 0xFFE0) << 1 | (v & 0x1F)     // 红色 5 位左移到高 6 位，最低位丢弃
```

所以：**磁盘上是 555，内存和 `.SHP` 里是 565**。`.SHP`（见 §1）本来就是 565，不需要转换。

## 5. `.MSK` — 大地图**地形类型图**（已完全解出）

4 个：`SHAPE\MAP\CHINAMAP1-4.MSK`（48-52 KB，对应 4 张地图）。**它不是"遮罩"，是一张 640×480 的逐像素地形编号图**：每像素 1 字节 = 地形类型 0..11（255 = 无）。EXE 里调用点在 `0x40DF43`，紧接着就是 `"%s Terrain=%d"`，语义即"按坐标查地形"，所以它就是大地图寻路/地形判定的数据源。

头部 **0x80 字节**：

| 偏移 | 类型 | 实测 |
|---|---|---|
| +0x00 | u32 | `0x0801050A`（字节序 `0A 05 01 08`，版本/标志） |
| +0x04 | u32 | 0 |
| +0x08 | u16 | 639（右边界 x） |
| +0x0A | u16 | 479（下边界 y） |
| +0x0C | u16 | 640（宽） |
| +0x0E | u16 | 480（高） |
| +0x10 | u8[48] | **16 色 RGB 调色板**（3 字节/项，实际只用了前 12 项；后 4 项为 0） |
| +0x40 | — | 少量标志 + 零填充，到 0x80 为止 |

调色板实测（`CHINAMAP1.MSK` +0x10 起，RGB 顺序）：`#000000 #FF0000 #CBB7FF #0000FF #00AB00 #FF8700 #836747 #AFBF00 #BBB7B7 #FFBF00 #00C3FB #FF00FF`，正好 12 色 ↔ 12 种地形。

像素数据从 **0x80** 起，是 **PCX 式 RLE**：

```
while 输出不足 w*h:
    b = data[i]; i += 1
    if b & 0xC0:              # 高 2 位有值 = 重复包
        n = b & 0x3F          # 低 6 位 = 重复次数
        v = data[i]; i += 1   # 下一字节 = 像素值
        输出 n 个 v
    else:                     # 否则是单像素字面值
        输出 b
```

`CHINAMAP1.MSK` 52075 B → 解码出 307,200 像素后只用掉 51,306 B，**尾部约 769 字节是冗余/索引数据，不影响解码**。解码后统计到的取值只有 `0..11` 与 `255`，与 12 色调色板严格吻合。渲染结果：`F:\sanguo\work\msk1_gray.png`（×16 灰度）。

> 注意：`SHAPE\MAP\CHINAMAP.SHP` 是 **1280×960** 的整屏地图位图（2,467,236 B），和 640×480 的 MSK 是 **2:1** 关系——显示时按 2 倍放大叠加。两者尺寸不同，不能逐像素直接对齐。

## 9. 渲染管线（从资源反推）

1. DirectDraw 创建 **640×480×16bpp** 主表面 + 离屏后台缓冲（DirectDraw 初始化区 VA `0x450984`）。
2. 全部绘制都是 CPU 直接往 16bpp 缓冲写像素：`dst[i] = color`，色键比较后跳过。
3. 精灵绘制参数：`(shape, x, y, offsetX, offsetY)`，`offsetX/offsetY` 用于"脚底对齐"和"武器挂点"。
4. 每帧末尾 `Flip` 到主表面（`0x47C67E` 是 `timeSetEvent` 包装，帧率由定时器驱动）。
5. 大地图是 640×480 整屏 + 滚动窗口 + 城市/部队图标叠加。

> 新项目可以直接用现代 2D 引擎复刻这套资源（PNG + 图集 + 色键转 alpha），但**不要**保留"每像素 CPU 写入 + 16bpp"的做法。
