# 04b3 单挑（武将 1v1）流程与规则

> 目标 EXE：`Sango2.exe`（三国群英传2 修正版 1.05+，PE32，ImageBase `0x400000`）
> 全部结论以反汇编为准，标注 `[确认]` / `[推测]` / `[未解]`。
> 本文只描述本 EXE 里真实存在的机制；与旧文档冲突处已在文中注明。

---

## 0 结论速览

**[确认] 本作没有独立的"单挑"子系统。** 玩家感知到的"单挑"，是双方**主将单位**（Process = 4，`ForceMajor`，处理器 `0x43EF64`）在战场上互相攻击时，走进了一条"武将对武将"专属的命中/伤害分支；它和兵战跑在同一个 Process 循环里，**兵战不暂停**，也没有独立的喊话/冲锋/胜负 UI。

四条支撑证据：

1. 全 EXE 按 cp950 搜索 `單挑 / 一騎 / 挑戰 / 喊話 / 決鬥` **0 命中**；`衝鋒` 只出现在阵法名 `0x48AFE8 '衝鋒之陣'`（无代码引用）。[确认]
2. Process → 消息处理器注册表 `0x430630`（`0x422BD0(index, handler)` × 21 条）里没有任何"单挑"类；主将 = 4 号，士兵 = 3 号。[确认]
3. 主将的攻击是**动作帧回调**驱动的：`0x43E964`（每帧）→ `0x43D0F1` 发 `OM_INITATTACK(0x10007)` → 动画命中帧回调 `OM_ATTACK(0x10000)` → `0x43F032` → `0x43D76C`（命中判定 `0x43D4CB`）→ `OM_PAIN(0x10004)` → `0x43F376` → 伤害 `0x43EC54`。整条链没有"单挑状态"变量。[确认]
4. 唯一与"一对一"有关的特判是 `0x43D76C` 的**隔一格追击**规则：距离 2 也能打，但**只对武将生效**（详见 §1.3）。[确认]

三条可直接落地的规则（细节见 §3）：

| 项目 | 结论 | VA |
|---|---|---|
| 武将对武将命中率 | `rand()%300 < 150 + (攻方武勇 - 守方武勇)/2` | `0x43D4CB` |
| 武将打武将伤害 | `r = rand[武勇/2, 武勇-1]; dmg = max(1, r/10)` | `0x43EC54` |
| 体力归零后果 | 发 `OM_DEATH` → 全军转 cmd 8 → 战斗结束（`[0x4A665C] |= 3`） | `0x43F376` / `0x43F27B` |

## 1 触发

### 1.1 谁在驱动主将

主将对象（ThingDef 里 `Process = 4`）的每帧更新走消息 `2`：

```
Process 循环 → call [obj+0x4C](obj, 2, 0)
  → 0x43EFC1  →  0x43E964(obj)        // ForceMajor 每帧更新，size 752
```

同族的小队/士兵单位走另一条：[确认]

```
call [obj+0x4C](obj, 2, 0)  →  0x43DE5E  →  0x43D125(obj)   // size 731
```

`0x43D125` 的唯一调用者是 `0x43DDBF+0x9F`，而 `0x43DDBF` 正是注册表里 **Process = 3（士兵/小队）** 的处理器。→ 由此可以确定：`0x43E964` 是主将更新器，`0x43D125` 是小队更新器，两者结构几乎相同（互为一对兄弟函数）。[确认]

### 1.2 出手条件链

`0x43E964` 的非死亡分支（简化伪代码）：[确认]

```c
u = obj->+0x84;                       // 该主将的战场 unit
if (0x42233D(obj) == 0x20) { /* DEATH 分支，见 §4 */ }
if (0x43B50D(u) & 0x8000) { /* 退场倒计时分支，见 §4 */ }

if (!0x43B574(u)) return;             // ① 行动冷却未到 → 本帧不动
u->+0x10 = u->+0x08;                  // ② 目标格 = 当前格
u->+0x14 = u->+0x0c;
dir = 0x43BCA7(u);                    // ③ 选攻击方向（±1 或 0）
if (!dir) { 0x43AF1A(u); return; }     //    无目标 → 走"当前指令"的空转分支
if (0x43BD64(u, dir) == 1) { 0x43AF1A(u); return; }   // ④ 方向校验失败
u->+0x38 = 1;                          // ⑤ 目标搜索冷却置 1
0x43CCE3(u);                           // ⑥ 主将 obj 对准格中心
0x43C1E7(u);                           // ⑦ 清 obj 速度分量
0x43D0F1(u, dir, 0);                   // ⑧ 发 OM_INITATTACK（第三参数恒 0）
0x43BE32(u);                           // ⑨ 记录本帧时间戳
```

`0x43B574(unit)` = 行动节奏计时器，**这是"每回合"的真实来源**：[确认]

```c
if (--u->+0x34 > 0) return 0;                 // u+0x34 = 冷却帧数
u->+0x34 = 0;
if (u->+0x3c != 0) {                          // 有位移待结算
    o = u->+0x44;
    if (o) { o->vt[0x4c](o, 0x1000D, 0); return 0; }
    return 1;
}
u->+0x34 = 0x28;                              // 普通：40 帧
if (u->+0x2c & 0x4000) {                      // 特殊状态 0x4000
    u->+0x34 = 0x2e;                          // 46 帧
    if (u->+0x2c & 1) {                       // 是武将 → 按与敌将的行动力差追加
        t = 0x43B9FC(u);
        u->+0x34 = 0x2e + 2 * (0x4429FD(t) - 0x4429FD(u));
    }
}
return 1;
```

其中 `0x4429FD(u)` = `[[u+0x40]+0x48] + 0x40`（signed word），即主将 general 记录的 `+0x40` 字段。[确认]

### 1.3 距离规则：什么情况才算"对上"

`0x43D76C(unit, dir)`（size 246）是主将的攻击落地函数，也是**唯一**给出"单挑距离"的地方：[确认]

```c
t = 0x43AF7A(u->+0x08 + dir, u->+0x0c);        // 相邻格（距离 1）
if (!t) {                                       // 距离 1 无人 → 试距离 2
    t = 0x43AF7A(u->+0x08 + dir*2, u->+0x0c);
    if (!t) return 0;
    if (!0x43B6A8(t)) return 0;                 // 距离 2 的目标必须是武将
    if (!0x43B67F(t)) return 0;                 // 且目标处于 0x4000 状态
}
if (0x43B663(u, t)) return 0;                   // 同阵营 → 不打
hit = 0x43D4CB(u, t);                           // 命中判定（§3.1）
if (hit == 1) {
    call [t->+0x44 + 0x4C](t->+0x44, 0x10004, u->+0x44);   // 向对方主将发 OM_PAIN
    return 1;
}
call [t+0x4C](t, 0x1000A, ...);                 // 未命中：发的动作消息
return 0;
```

三条可直接引用的规则：[确认]

- **相邻（距离 1）时，主将可以打任何敌人**（含士兵）。
- **隔一格（距离 2）时，只能打"敌将 + 目标处于 0x4000 状态"**——这是全作唯一"武将优先/追击"特判，也是玩家看到"主将隔空对砍"的原因。
- 命中后由对方**主将对象**（`unit+0x44` 指向的 obj）承接 `OM_PAIN`，伤害走武将专用公式；士兵被主将打中则走 `0x43F376` 里的分支（该 obj 的 unit 不是武将时 `0x43EC54` 会触发断言，见 §3.2）。

### 1.4 玩家侧：指令菜单（无"单挑"按钮）

战斗指令菜单是 `.data` 里一张 6 项描述符表，起始 `0x48F2A8`、stride `0x38`：[确认]

| # | 矩形 (x,y,w,h) | 绘制/执行函数 | 字符串 |
|---|---|---|---|
| 0 | 0x10,0xB9,0x64,0x1E | `0x4451C3` | `0x490408 保護主將` |
| 1 | 0x10,0xD4,0x64,0x1E | `0x4450AE` | —（`0x48F3F8` 表） |
| 2 | 0x10,0xEF,0x64,0x1E | `0x4453C2` | `0x490444 武 將 技` |
| 3 | 0x10,0x10A,0x64,0x1E | `0x445491` | `0x49045C 武將出擊` |
| 4 | 0x10,0x125,0x64,0x1E | `0x445282` | `0x490420 主將待機` / `0x49042C 主將後退` |
| 5 | 0x10,0x140,0x64,0x1E | `0x44554A` | `0x490474 全軍撤退` |

每个菜单项函数统一签名 `fn(arg)`：`arg == 1` 时做**可用性检查**，否则**执行**。命令最终都落到唯一写入器 `0x43ADED(army, which, value)`——它写的是军团结构里的**指令槽数组** `army+0x94 + idx*4`（idx = `unit+0x20`，0..7，槽 0 = 主将）：[确认]

```c
which == 0x100 → for i = 0..7  army+0x94+i*4 = value;   // 全军
which == 0x101 → for i = 1..7  army+0x94+i*4 = value;   // 除主将
which < 0 || which >= 8 → 同 0x100（全军）
else           → army+0x94+which*4 = value;              // 单个单位
```

实测到的写入点（`work\duel_pushes.py` 从 `call 0x43ADED` 前三条 push 解出）：[确认]

| 写入者 | (which, value) | 备注 |
|---|---|---|
| `0x444BA6` | (0, 1) | **武將出擊**（`0x445491` 内 3 处调用）→ 主将 cmd = 1 |
| `0x445282` | (0, 2) | **主將待機 / 主將後退** → 主将 cmd = 2 |
| `0x4447B7` | (0x100, **8**) | 全军 cmd = 8（**唯一**写 cmd 8 的地方） |
| `0x444C37` | (0x101, 9) | 全军（除主将）cmd = 9 |
| `0x444ACB` | (0x101, 0) | 全军（除主将）cmd = 0 |
| `0x4449A9/0x4449EA/0x444A35/0x444A80` | (1,1)/(1,2)/(1,5)/(1,6) | 阵形命令表中的 5 项回调 |
| `0x444B4C` | 调 `0x4447B7(0x4A8A60)` | **全軍撤退**：置 `[0x4A8AE0] |= 4` |

→ **玩家不能"发起单挑"**：菜单里没有这项，代码里也没有"宣告单挑"的写入点。玩家能做的只是给主将下 cmd（出击/待机/后退），让主将走到敌将旁边，之后由 §1.2/§1.3 的自动链决定是否交手。[确认]

### 1.5 概率

- 进入交手**没有概率**：只看格距（1 格任意目标；2 格需"敌将 + 0x4000"）与朝向校验 `0x43BD64`。[确认]
- 有概率的是**方向搜索**（`0x43BCA7`：非 0x4000 时用 `0x450132() & 1` 随机先试左右各一次）与**攻击动作变体**（`0x43F103`：`0x450132() & 7` 在 `4 / 0x100000 / 0x200000 / 0x400000` 里选）。[确认]
- `0x450117(n) = rand32() % n`，`0x450132()` 是自研 PRNG（状态 `0x4922FC` / `0x492300`）。[确认]

## 2 状态机

### 2.1 没有"单挑状态机"，只有三组正交计时器

**[确认] 主将/单挑期间没有任何"阶段号"变量。** 玩家看到的分阶段效果由下面三组计时器 + 动画动作号共同产生：

| 计时器 | 字段 | 语义 |
|---|---|---|
| 行动冷却 | `unit+0x34` | `0x28`(40) 常规 / `0x2E`(46) 当 `unit+0x2c & 0x4000` / 武将再加 `2*(敌将+0x40 - 自己+0x40)` |
| 目标搜索冷却 | `unit+0x38` | `0x43BCA7` 开头 `--u->+0x38`；命中发招后由 `0x406717(...)` 重设 |
| 动作/退场倒计时 | `obj+0x90` | 初值 `0x40`；每帧 `-1`；`obj+0x58 = obj+0x90 >> 2`（渐隐/淡出用） |

动画动作号 `obj+0x34` 是真正的"阶段载体"（`0x42233D(obj)` 就是读它）：[确认]

| 值 | 名称 | 设置点 |
|---|---|---|
| `0x01` | `FIRST` 登场/待机 | 对象工厂默认值 `0x4217FE`；`0x43F00D`(OM_WAIT)、`0x43F08B` |
| `0x02` | `WALK` | `0x43EFE8`(OM_WALK) |
| `0x04` | `ATTACK`（普通攻击） | `0x43F103` 分支 |
| `0x10` | `PAIN`（受击） | `0x43F376` / `0x43F41D` |
| `0x20` | `DEATH`（判定"已死"的哨兵值） | `0x43F4B4` 前的检查；多处用它提前 return |
| `0x40` | 阵亡倒地演出 | `0x43F27B`(OM_DEATH) |
| `0x800` | **背向攻击**（不是必杀，见 §3.4） | `0x43F103` 朝向相反分支 |
| `0x100000/0x200000/0x400000` | 攻击动作变体 | `0x43F103` 随机分支 |

### 2.2 推进方式：动画帧回调，不是纯帧计数

`OM_INITATTACK(0x10007)` 只是**起手**，真正判定命中要等动画播放到命中帧，由动画系统回调 `OM_ATTACK(0x10000)`：[确认]

```c
/* 0x43D0F1(unit, dir, flag)：起手 */
packed = ((dir & 0xFFFF) << 16) | (flag & 0xFFFF);
o = unit->+0x44;                       // 该 unit 的主将对象
call [o+0x4C](o, 0x10007, packed);     // → 0x43F103
```

```c
/* 0x43F103：决定动作 */
if (obj->+0x34 == 0x20) return 0;
if (packed < 0) {                       // 向左攻击
    if (obj->+0x2c == 0)  0x421E1B(obj, 0x800);   // 面朝右却向左打 → 背向动作
    else { r = 0x450132() & 7;
           r < 5 → 0x421E1B(obj, 4);
           r < 6 → 0x421E1B(obj, 0x100000);
           r < 7 → 0x421E1B(obj, 0x200000);
           else  → 0x421E1B(obj, 0x400000); }
} else { /* 对称：obj->+0x2c == 0x800000 → 0x800 */ }
obj->+0x68 = 0;
obj->+0x94 = packed;                    // 保存方向+标志
```

```c
/* 0x43F032 = OM_ATTACK(0x10000)：命中帧回调 */
dir   = (obj->+0x94 < 0) ? -1 : +1;
ret   = 0x43D76C(obj->+0x84, dir);      // §1.3 的距离+命中判定
if (ret == 1) 0x43D8D2(obj->+0x84);     // 命中后推进（仅 0x4000 状态）
```

`obj+0x94` 的低 16 位是 `0x43D0F1` 的第三参数（flag），高 16 位是方向；`0x43F032` 只用符号判方向。[确认]

### 2.3 消息表（ForceMajor = Process 4，`0x43EF64`）

二级跳表 `0x43F54F`，14 项，索引 = `msg - 0x10001`：[确认]

| 消息 | 处理器 | 作用 |
|---|---|---|
| `0x10001` OM_WALK | `0x43EFE8` | 动作非 2/0x20 → 置 `WALK` |
| `0x10002` OM_WAIT | `0x43F00D` | 动作非 1/0x20 → 置 `FIRST` |
| `0x10003` OM_DEATH | `0x43F27B` | 死亡链（§4） |
| `0x10004` OM_PAIN | `0x43F376` | 伤害落地（§3.2） |
| `0x10005/6` | `0x43F532` | 通用：`0x43E55C` |
| `0x10007` OM_INITATTACK | `0x43F103` | 起手选动作（§2.2） |
| `0x10009` OM_DEATHSTOP | `0x43F4B4` | `obj+0x8c=1; obj+0x90=0x40; obj+0x30|=0x40000; obj+0x58=0x10` |
| `0x1000A` | `0x43F532` | 未命中动作 |
| `0x1000B` | `0x43F245` | `obj+0x90=0x40; obj+0x30|=0x40000` |
| `0x1000D` | `0x43F08B` | `unit+0x34 += unit+0x3c; unit+0x3c=0`（结算位移） |
| `0x1000E` | `0x43F41D` | 固定伤害（读全局 `[0x4B4C3C]`） |
| `0x10000` OM_ATTACK | `0x43F032` | 命中帧（**注意：0x10000 不在跳表内，单独比较**） |
| `msg 2 / 3 / 4` | `0x43EFC1` / `0x43F524` / `0x43EFD2` | 每帧更新 / 销毁 / `0x43DD3E`+返回 `0x1234` |

### 2.4 一次"单挑回合"的完整伪代码

```c
/* ── 每帧，对每个主将 obj ─────────────────────────────── */
void ForceMajor_frame(obj_t *obj) {                       // 0x43E964
    unit_t *u = obj->unit;                                // obj+0x84
    if (anim(obj) == 0x20) { death_frame(obj); return; }   // §4 死亡分支
    if (0x43B50D(u) & 0x8000) { retreat_countdown(obj, u); return; }

    /* 气力（"集气"）*/
    if (u->+0x2c & 0x4000)  u->+0x4C -= 0x32;             // 该状态每帧衰减 50
    else if (anim(obj) != 0x20) {
        u->+0x4C += 0x43E72E(u->+0x40);
        if (u->+0x4C > 0x1D4C0) u->+0x4C = 0x1D4C0;       // 上限 120000
        0x43E847(u->+0x40);
    }

    /* 指令分派：cmd 从 army+0x94+idx*4 取出 */
    cmd = 0x43AF1A(u);
    if (0x43AF3B(u, cmd)) 0x43AF0C(u, cmd);                // 指令变化 → 清旧状态
    0x43CF07(u, cmd);                                      // 主将分派器（§2.5）

    /* 行动 */
    if (!0x43B574(u)) return;
    u->+0x10 = u->+0x08; u->+0x14 = u->+0x0c;
    dir = 0x43BCA7(u);
    if (!dir) { 0x43AF1A(u); return; }
    if (0x43BD64(u, dir) == 1) { 0x43AF1A(u); return; }
    u->+0x38 = 1;
    0x43CCE3(u); 0x43C1E7(u);
    0x43D0F1(u, dir, 0);                                  // 起手
    0x43BE32(u);
}
```

```c
/* ── 起手 → 命中帧 → 伤害 → 可能死亡 ───────────────────── */
0x43D0F1(u, dir, 0)        → OM_INITATTACK  → 0x43F103  (置动作 4/0x800/变体)
[动画命中帧]                → OM_ATTACK      → 0x43F032 → 0x43D76C
0x43D76C(u, dir)           → 0x43D4CB 命中? (rand()%300 < p)
  ├─ 未中 → 向目标发 0x1000A，return 0
  └─ 命中 → 向 t->主将obj 发 OM_PAIN(0x10004)，参数 = 攻方主将 obj
        → 0x43F376: d = 0x43EC54(victimObj, attackerObj)
                    g->+0x12 -= d                        // 武将体力
                    if (g->+0x12 <= 0) { g->+0x12 = 0; 发 OM_DEATH; }
                    else 置动作 0x10 (PAIN)
        → OM_DEATH(0x10003) → 0x43F27B（§4）
```

### 2.5 主将指令分派器 `0x43CF07`（9 项跳表 `0x43CF8D`）

`cmp cmd, 8; ja ret; jmp [cmd*4 + 0x43CF8D]`：[确认]

| cmd | 落地函数 | 行为 |
|---|---|---|
| 0 | `0x43C907` | `0x43C4C0(u, 0, 0, 0x48E6A0)` |
| 1 | `0x43C758` | `0x43C4C0(u, A?-1:+1, 0, 0x48E5C8)` |
| 2 | `0x43C795` | `0x43B51E(u, 0x100)`；再 `0x43C4C0(u, A?+1:-1, 0, 0x48E5C8)` |
| 3..7 | `0x43CF89` | 直接 return（无操作） |
| 8 | `0x43C7E3` | `0x43C4C0(u, A?+1:-1, 0, 0x48E658)`；再 `0x43B51E(u, 0x4000)` |

小队分派器 `0x43CFB1`（10 项跳表 `0x43D0C9`）：cmd0→`0x43C907`、1→`0x43C921`、2→`0x43C9EF`、3→`0x43CA7B`、4→`0x43CAB8`、5→`0x43CB87`、6→`0x43CAF5`、7→`0x43CDD3`+`0x43C888`、8→`0x43CC95`（置 0x4000）、9→`0x43C888(army+0x08, army+0x0c)`（回本阵）。[确认]

## 3 判定与伤害

### 3.1 命中：`0x43D4CB(unitAtk, unitDef)`（size 244）

**与 04b 记录的士兵命中 `0x43D400` 不是同一套。** 两者都用 `rand()%300 < p` 的形式，但 p 的来源完全不同：[确认]

```c
p = 150;
if (0x43B6A8(def))                       // 目标是武将
    p = 150 + (atk主将->+0x34 武勇 - def主将->+0x34 武勇) / 2;
else if (0x43B6C9(def))                  // 目标 unit+0x2c & 4
    p = 150 + atk主将->+0x34 / 3;
else
    p = 150 + atk主将->+0x34 / 2;

if (atk->+0x40->+0x84 & 0x200)           // 军团级命中加成
    p += atk->+0x40->+0x74;

if (0x43BE08(def) == 0)                  // 目标尚未到达其目标格
    p = p * 2 / 3;

return (0x450117(0x12C) < p);            // rand() % 300 < p
```

对照 04b 的士兵命中 `0x43D400`：`p = attacker->unit->+0x70`（战力），对武将时 `p = 150 - 武勇*20/100`。**两处数值口径不同，不要混用**。[确认]

### 3.2 伤害：`0x43EC54(objVictim, objAttacker)`（size 322）

两个参数都是**对象指针**（不是数值）。[确认]

```c
if (!victim || !attacker || !victim->unit || !attacker->unit) return 0;
if (0x43B6A8(victim->unit) == 0) 0x42FDA5(0x54);   // 断言：只有武将能走这条路径

if (0x43B6A8(attacker->unit)) {                    // ① 武将打武将
    h    = attacker主将->+0x34;                     // 武勇（signed word）
    half = h / 2;                                   // 向零取整
    r    = 0x450117(h - half) + half;               // rand 落在 [h/2, h-1]
    dmg  = r / 10;
} else {                                            // ② 士兵打武将
    p = attacker->unit->+0x70;                      // 战力
    if (0x43B6C9(attacker->unit)) p = p * 0x78 / 100;
    dmg = p * 4 / 0xC0;                             // = p / 48
}
return (dmg <= 1) ? 1 : dmg;                        // 最少 1 点
```

→ **武将之间的伤害只由武勇决定，与战力/兵力无关**；这也是"单挑"在数值上区别于兵战的核心。[确认]

落地点（`0x43F376` = OM_PAIN）：[确认]

```c
if (anim(obj) == 0x20) return 0;
u = obj->+0x84;
if (u->+0x40->+0x54 == 1) return 0;              // 该方已溃败 → 免疫
g = u->+0x40->+0x48;                             // 主将 general 记录
d = 0x43EC54(obj, arg2);                         // arg2 = 攻方主将 obj
g->+0x12 -= d;                                   // ★ 武将体力落在 general+0x12
if (g->+0x12 <= 0) { g->+0x12 = 0; call [obj+0x4C](obj, 0x10003, arg2); }
else 0x421E1B(obj, 0x10);                        // PAIN 动作
```

> 注意：`04c` 把 `general+0x10 / +0x12` 记为"体力 当前 / 上限"，**此处代码顺序相反**——`+0x12` 是被扣减的当前值，扣到 ≤0 触发死亡。以本文为准。[确认]

另有"固定伤害"通道 `0x43ED96(objVictim, dmg, objSrc)`：按攻方等级放大 `dmg = dmg + dmg * (主将等级) / 100`，把结果写全局 `[0x4B4C3C]` 再向受害人发 `0x1000E`；处理器 `0x43F41D` 做同样的扣血/死亡判定。这条通道供法术/固定伤害用，主将互殴不走它。[确认]

### 3.3 气力是有的，但它不参与命中/伤害

- `unit+0x4C` = 气力，`0x43E964` 每帧回复 `0x43E72E(军团)`，上限 `0x1D4C0`（120000）；处于 `0x4000` 状态时每帧 `-0x32`（50）。[确认]
- 气力**不进入** `0x43D4CB` / `0x43EC54` 的任何分支；它只被 `0x43E847` / `0x43EE09`（`imul eax, eax, 0x1D4C0`）等比例换算使用，具体消费点 `[未解]`。

### 3.4 "必杀"：主将没有，`0x800` 也不是必杀

- 主将起手固定 `0x43D0F1(u, dir, 0)`，第三参数（flag）**恒为 0**（`0x43EBD0` 处 `push 0`）。[确认]
- 动画 `0x800` 由 `0x43F103` 的"朝向与攻击方向相反"分支设置，语义是**背向/回身攻击**，不是必杀。[确认]
- 真正的 1/8 概率分支只存在于**小队路径**（`0x43D125` 内，`0x43D28C`）：

```c
[0x4A6668] = 0;
cnt = 0x43B961(u);                      // 武将 → 1；小队 → 兵数
if (cnt <= 1) {
    if (0x450117(8) == 0) { flag = 1; [0x4A6668] = 1; }   // 1/8
} else {
    flag = (0x46DA40(dir) == 1);
}
u->+0x38 = 0x406717(u->+0x1c, (0x43B6C9(u) ? 1 : 0), flag);
0x43CCE3(u); 0x43C1E7(u); 0x43D0F1(u, dir, flag);
```

`[0x4A6668]` 全 EXE 只有 3 处引用：写 `0x43D28E`/`0x43D2E5`，读 `0x43DFF9`（士兵处理器 `0x43DDBF` 尾部 `obj+0x94 = [0x4A6668]`）。→ 这个"必杀/暴击"标志属于小队/士兵，**主将单挑不参与**。[确认]

## 4 结果与影响

### 4.1 死亡链（顺序固定）

`OM_DEATH(0x10003)` 处理器 `0x43F27B`：[确认]

```c
if (anim(obj) == 0x20) return;                 // 已死，幂等
0x43DB9A(obj->+0x84);                          // ① 死亡标记
0x43DC56(obj, arg2);                           // ② 击退一格
0x421E1B(obj, 0x40);                           // ③ 倒地演出动作
/* ④ 用子对象 [obj+0x78] 回退 obj+0x3c 的位移分量 */
u = obj->+0x84;
0x4447B7(u->+0x40);                            // ⑤ 全军撤退/溃败处理
u->+0x40->+0x80 |= 4;                          // ⑥ 军团标志：主将殒命
[0x4A665C] |= 3;                               // ⑦ ★ 标记战斗结束
0x421AD2(obj, side);                           // ⑧ 阵亡演出
0x41F740(0, 0x39, side);                       // ⑨ 播消息 0x39（A 方 0 / B 方 1）
```

`0x43DB9A(unit)`（size 188）：`unit->+0x2c |= 0x2000`（bit13）；把主将 obj 的 x 坐标 `obj+0x10 += 0x360000`（向本阵方向偏移 54 像素）；播效果 `0x443CA8(4)`（A 方）/ `0x443CA8(8)`（B 方）；并预读 `general+0x8f/10` 供后续使用。[确认]

`0x43DC56(obj, attacker)`（size 232）：按攻方位置把主将**击退一格**并翻转朝向——`attacker->+0x08 >= obj->+0x08` 时 `x = unit+0x08 - 1`、`obj+0x2c = 0`（朝右）；否则 `x = unit+0x08 + 1`、`obj+0x2c = 0x800000`（朝左）；然后 `0x43BE42(u, x, unit+0x0c, 0x50, 0)` 落位；若 `unit+0x2c & 4` 再置击退速度 `obj+0x1c = rand()%0x10000 + 0x30000`。[确认]

### 4.2 `0x4447B7(army)`：败方全军处理

```c
0x43ADED(army, 0x100, 8);                              // ★ 全军指令 = 8
army->+0x2c |= 0x4000;
if (army->+0x84 & 0x40) {                              // 主将已阵亡
    call [army->+0x44 + 0x4C](obj, 0x1000B, 0);
    army->+0x2c |= 0x8000;
}
for (i = 0; i < army->+0x58; i++)                      // 小队数组：army+0xB4 起 stride 0x48
    (army + 0xB4 + i*0x48)->+0x2c |= 0x4000;
if (!0x43B556(army)) {                                 // 已无存活单位
    army->+0x44->+0x2c = (army == 0x4A8A60) ? 0 : 0x800000;   // 主将朝向复位
}
```

→ **败方影响**：全军转入 cmd 8 + `0x4000` 状态（退却），主将阵亡时再加 `0x8000`（退场倒计时）；不直接改士兵数与士气。[确认]

### 4.3 战斗结算（与兵战同一条路）

死亡只是把 `[0x4A665C]` 的 bit0 置起，真正的胜负与收益在主循环尾部：[确认]

```c
/* 0x447037(mode) */  返回 1 = 我方败 / 2 = 大胜 / 3 = 平手
/* 0x41048D(unitW, unitL, mode, bonus) */
   战功 = 击杀步兵数*6 + 击杀骑兵数*12 + 敌将等级*(51 歼灭 / 34 击退 / 17 平手 / 34 大胜×2)
   回写 general+0x38（士气）、+0x10（体力）、+0x14（技力）
   功勋 base = (bonus == -1) ? rand()%8 + 15 : bonus/10 + 15
/* 0x447520(army) */  仅对状态 3 的条目：general+0x3C -= (10 - CONSTANCY)*2；general+0x38 -= 0x14
/* 0x447424(armyA, armyB, mode) */ 按 mode 1/2/4/8 分派到 0x41048D
```

- **胜方所得**：战功（经验）+ 功勋，按上式。[确认]
- **败方**：士气/疲劳按 `0x447520` 与 `0x41048D` 回写；**没有"俘虏"或"直接斩将"分支**——主将阵亡只体现为军团标志 `army+0x80 |= 4` 与全军撤退。[确认]
- **是否直接结束战斗**：**是**。主将一死即 `[0x4A665C] |= 3`，战场场景更新 `0x441E61` 在 `0x441EC2` 处 `if ([0x4A6660]==1 || [0x4A6664]==1 || ([0x4A665C]&1)) goto 0x4422CB` 直接跳过，进入结算。[确认]

## 5 与兵战主循环的关系

### 5.1 不暂停

- 主将（`0x43E964`）、小队（`0x43D125`）、士兵（`0x43DDBF`）都是 Process 循环里各自独立的条目，**彼此不阻塞**。单挑期间兵战照常推进。[确认]
- 唯一的"暂停"语义是 `[0x4A665C]` bit0（战斗已结束）与初始化标志 `[0x4A6660]` / `[0x4A6664]`，二者都只由**结束/初始化**流程写入：[确认]
  - `0x444459`(mode 5) 战场初始化：`[0x4A665C]=0; [0x48CD2C]=0x8F; [0x4A648C]=1; [0x4A6670]=1; [0x4A8A28]=0; [0x4A6660]=1; [0x4A6664]=1; [0x4AC35C]=0x2E68;`
  - `0x43F27B`(OM_DEATH)：`[0x4A665C] |= 3`。

### 5.2 回到主循环的路径

```
主将体力 general+0x12 ≤ 0
  → 0x43F376 发 OM_DEATH
  → 0x43F27B：0x43DB9A / 0x43DC56 / 0x4447B7 / [0x4A665C] |= 3
  → 0x441E61 跳过战场更新
  → 战斗主循环 0x44759E 尾部 0x447CD2：
       if ([0x4A8A24] && [0x4A8A20]) { ... }        // 援军/第二战场分支
       else { mode = 0x447037(0); 0x410989(...); [0x4A8144] = 4; }
  → 0x447424 → 0x41048D 结算
```

- `0x447516` 是**空函数**（保留了 `sub esp,0x1c` 栈帧但无函数体），唯一调用点在 `0x447CD2`：`0x447516(*[0x4A8A20], *[0x4A8A24])`。→ 早期"`0x4A8A20/0x4A8A24` 是单挑双方指针"的假设**不成立**：它们是"可选第二战场/援军"的两个 army 指针，且在 `0x446A90` 战斗初始化时被清 0。[确认]

## 6 未解

1. **`cmd 8` + `0x4000` 的语义到底是"撤退"还是"出击/前出"** `[未解]`
   - 支持"撤退"：唯一写 cmd 8 的是 `0x4447B7`（`0x100, 8`），而 `0x4447B7` 被 `0x444B4C`（`0x44554A 全軍撤退` 的执行分支）和 `0x43F27B`（主将阵亡）调用；`0x43BD64` 在 0x4000 且方向与主将朝向相反时**拒绝攻击**。
   - 支持"出击"：`0x43D76C` 的隔格追击要求**目标**也处于 0x4000；`0x43D8D2` 在 0x4000 时命中后**再前进一格**；`0x43B574` 在 0x4000 时把行动间隔从 40 帧改为 46 帧并按"与敌将的行动力差"追加；`0x43E964` 在 0x4000 时每帧扣气力 50。
   - 两种读法都能解释现有全部调用点，需要动态调试（在 `0x43C7E3` 下断，观察菜单点"武將出擊"后 `unit+0x2c` 是否出现 0x4000 以外的新值）才能定案。
   - 一条弱旁证：`0x43C4C0` 传给 `0x43C2A5` 的 `arr`（= `desc+4` 起的 8 个 dword）在两个描述符里都近似"百分比权重"——`0x48E658` = `{1, 0x64, 0…}`（和 0x65）、`0x48E8E0` = `{0x50, 0xA, 0xA, 0…}`（和 0x64），像是"把单位按权重散布到周围 8 格"，这也更符合"散开/脱阵"而非"向前突进"的读法。
   - **倾向结论（`[推测]`）：`0x4000` = 脱阵/撤退状态，`0x8000` = 离场倒计时。** 依据是二者的接力关系：`0x43C4C0` 阶段四在"0x4000 且找不到敌人"时置 `0x8000`；`0x43E964` 把 `0x8000` 走成"倒计时 → `0x443CA8(1)/(2)` + `0x443CA8(0x1000)` → 销毁"；`0x4447B7`（主将阵亡 / 全軍撤退）同时置 `0x4000`（给全军）与 `0x8000`（给已阵亡主将那一路）。这条链只有"撤退 → 离场 → 战斗结束"读得通。若如此，则 §1.3 的"隔一格打 0x4000 的敌将"就是**追击撤退中的敌将**，`0x43D8D2` 是"追击时再向前压一格"。
2. **`0x43C4C0` 的 `side` 参数方向语义** `[未解]`：`0x43C2A5(a=side, b=0, arr, out)` 用 `idx = side + 4` 查表 `0x48E580`（值：idx3=4、idx4=−1(空表)、idx5=0），再链式展开成 8 组格偏移。`side = 0` 得空表（原地不动）、`±1` 得两组不同的偏移序列，但**哪一组朝敌方、哪一组朝本阵未证实**。
3. **"武將出擊"→ 主将 `cmd 1` → `0x43C758`** 是否真是"出击" `[推测]`：`0x445491`（`0x49045C 武將出擊` 的绘制/执行函数）内有 3 处 `call 0x444BA6`，而 `0x444BA6` 写的是 `0x43ADED(army, 0, 1)`（主将 cmd = 1）。cmd 1 落地为 `0x43C4C0(u, A?-1:+1, 0, 0x48E5C8)`，配合上一条的方向未解，无法确认它通向"接近敌将"。
4. **`0x43E55C(obj, 2, 0)`**（`0x43D3E6` 调用，当 `obj+0x88 != 0x468720()` 时）语义未解。
5. **`0x43B9E2` / `0x4429FD`**：`0x4429FD(u)` 读 `mainGeneral+0x40`（signed word），字段名未定（候选：行动力/速度/机动）；`0x43B9FC`→`0x43B9E2` 的"取敌将"路径未反汇编。
6. **主将是否也会走 1/8 必杀** `[未解]`：`0x43D125`（小队）里有 `0x450117(8)` 分支，而 `0x43E964`（主将）里 `0x43D0F1(u, dir, 0)` 第三参数恒 0；若"主将"另有一条未发现的入口（例如某类 ThingDef 的 `Process` 不是 4），则结论需修正。当前 `0x43E964` 是唯一注册的主将更新器，故记为"主将无必杀"。（`[推测]`）
7. **`general+0x8f`、`general+0x40`** 等字段在 `0x43DB9A` / `0x43B574` 中被读，命名未定。
