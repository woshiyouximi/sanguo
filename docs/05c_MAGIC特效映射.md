# 05c `SHAPE\MAGIC` 特效帧 ↔ 110 个武将技：映射表与证据

> **一句话结论**：`MAGIC.INI` 的 `Script` 字段（501–610）就是 `SCRIPT\MAGIC.SO`
> 符号表里的 `num`，对应函数 `Magic{num-500}`；该函数执行时用
> `PUSHS "magic\NNN\*"`（`syscall 0x007` 载入整个目录）或 `PUSHI <ThingID>`
> （`syscall 0x011` 创建单个特效对象，`ThingID = 10000 + 1000×NNN + k`）来取图形，
> 于是落到 `SHAPE\MAGIC\NNN\` 的帧上。**110 个武将技里 103 个能锁定到现存的特效目录**，
> 其余 7 个只引用磁盘上不存在的 `002`/`024`（伏兵类，兵由 `FORCE` 出），0 个完全无线索。

本文所有结论按 `[确认]` / `[推测]` / `[未解]` 标注。

## 1. 证据链（5 条）

### E1 `Script` = `MAGIC.SO` 符号表 `num`　`[确认]`

`F:\sanguo\extract\pak\SCRIPT\MAGIC.SO` 头 `"Smart Script"`，`+0x10` 起 6 个 dword：
版本 `0x100`、代码起点 `0x40`、符号表偏移 `0x3D548`、符号数 **463**、字符串表偏移 `0x3F238`、字符串数 **580**。
符号表每项 16 B = `off, argc, name_off, num`。`Magic1`…`Magic110` 的 `num` 恰好是
**501…610**（`Magic200` 的 `num = 700`），与 `F:\sanguo\extract\json\magic.json`
里 110 条 `script` 字段（值域 501–610）完全同集合、一一对应。

所以 `Script` 不是"技能序号"，而是**脚本函数号**：`Script=503` 的技能（火箭）调用的是 `Magic3`，
不是 `Magic4`；`Magic{n}` 的 n = `Script − 500`，与技能 `index` 不同序。

### E2 `MagicN` 是极薄的包装，真正干活的是效果函数　`[确认]`

`Magic1`（`Script=501`，命療術）整个函数体只有 3 条指令：

```asm
03AB20  0600000000000000 PUSHI     0
03AB28  04000000387F0100 CALL      Heal
03AB30  0200000000000000 RET       0
```

`Heal`（`@0x17F38`）开头就是取图形：

```asm
017F38  PUSHN
017F40  PUSHS    "magic\000\*"
017F48  SYSCALL  0x007            ; argc=1  -> 载入图形资源
017F54  PUSHS    "magic\016\*"
017F5C  SYSCALL  0x007
...
018058  PUSHS    "m016snd01"
018068  SYSCALL  0x301            ; 播放音效(name, vol)
```

`syscall 0x007` 在 `F:\sanguo\export\script\_syscall_table.md` 里记作
"载入图形资源，名字如 `magic\000\*`（106 次）"，宿主函数 `0x41F9E0`。
这就是"目录级"引用：一条 `PUSHS` 把整个 `MAGIC\016` 的帧全部装进资源表。

### E3 第二条路径：`PUSHI <ThingID>` 直接创建特效对象　`[确认]`

`CreateHolyLight`（`@0x17A4C`，被 `Heal` 调用）里：

```asm
017A8C  PUSHI   26001        ; CASE 0
017A94  STL     loc4
017A9C  PUSHI   26004
...
017B6C  SYSCALL 0x011        ; argc=4 -> 以单位坐标为基准创建对象
```

`26001` 是 `THINGS.INI` 里 `MAGIC\016` 目录第 1 个对象"聖光A"的 `Sequence`
（`Sequence = 10000 + 1000×目录号 + 目录内序号`，见 05b §3）：
`CreateHolyLight` 依次点名 `26001`–`26006`，正好是 `MAGIC\016` 的六帧聖光 A–F；
而调用它的 `Heal` 又用 `PUSHS "magic\016\*"` 把同一目录整批载入——两条路径互相印证。

"`PUSHI` 的那个数就是 `THINGS.INI` 的 `Sequence`"这一点是**实测**的，不是推断：
`syscall 0x011` 宿主 `0x41FADE` → `0x41FA7F` → `0x4217FE`，后者第一步就
`call 0x436871(第 5 参数)` 查对象定义；`0x436871` 是**对对象定义数组的线性查找**：

```asm
436871  mov  [ebp-4], 0                 ; i = 0
43687C  jmp  436887
43687E  inc  [ebp-4]                    ; ++i
436887  cmp  ecx, [0x4BBCA0]            ; i < TotalObject
436890  jge  4368B6                     ; 找不到 -> 返回 0
436892  imul edx, edx, 0x2C             ; 每条记录 44 B
436898  mov  eax, [0x4A6614]            ; 对象定义数组
43689D  mov  ecx, [eax+edx]             ; 记录第 0 个 dword = Sequence
4368A0  cmp  ecx, [ebp+8]               ; 与传入的 ThingID 比较
4368A3  jne  4368B4                     ; 不等 -> 下一个
```

即：传给 `syscall 0x011` 的第二个参数必须**精确等于** `THINGS.INI` 的 `Sequence`，
没有任何 `+10000` 之类的重定基。所以脚本可以绕过"整目录"，直接点名单帧对象。

### E4 目录级引用覆盖了全部现存目录　`[确认]`

`MAGIC.SO` 字符串表里以 `magic\` 开头的形状串共 **53 条**：42 条是 `magic\NNN\*`
（整目录通配，交给 `syscall 0x007`），11 条是具体文件名（如 `MAGIC\017\m017a40001`）。
把这 110 个 `MagicN`（含其调用链、含 `syscall 0x310`–`0x314` 的"按名字调用脚本"）
全部走一遍，引用到的目录编号是 `000`–`041` 共 41 个；磁盘上现存 40 个，
**现存 40 个目录里，除公共件 `000` 外的 39 个全部至少被一个技能引用**（`000` 本身被 109 个技能载入，见 §4.1），没有"孤儿目录"。

## 4. 特例与没对上的地方

### 4.1 `MAGIC\000` 是所有技能的公共资源　`[确认]`

110 个技能里有 **109 个**用 `PUSHS "magic\000\*"` 载入该目录（因为 `Heal`、`CastFail` 等公共子函数都带这一句；唯一例外是五雷轟頂，它的脚本只走对象号路径，见 §4.3），它是**施法通用件**，不承担某个具体技的表现，所以 §2 的"目录"列把它剔除，不计入 `103/110` 的判定。
该目录只有 18 个对象 / 32 帧，内容是"無形有重力、無形無重力、火球、集氣A–C"一类
通用光效，属于施法通用件，不承担具体技的表现，所以上表把它从"目录"列剔除了。

### 4.2 `002` / `024` 被引用但目录不存在　`[确认]+[推测]`

| 目录 | 引用它的技能 | 推测原因 |
| --- | --- | --- |
| `002` | 伏兵組陣、伏兵排陣、伏兵班陣、伏兵連陣（4 个） | 伏兵＝召唤己方士兵，兵的形象来自 `SHAPE\FORCE\`（`SOL`/`FLAG`），不需要 `MAGIC` 帧；脚本照样 `PUSHS "magic\002\*"`，资源不存在时载入静默失败 |
| `024` | 後伏連兵、後伏兵陣、後伏軍陣（3 个） | 同上（后排伏兵） |

这两个目录在 `05b` 里也被记为"缺失"，此处给出原因链：**不是解包丢了文件，是游戏本来就没有。**
上表 4+3=7 个技能就是 §0 里"只引用缺失目录的 7 个"；它们没有别的现存目录可用。

### 4.3 五雷轟頂：走对象号而非目录通配　`[确认]`

`Magic37`（`Script=537`）只有一句 `CALL BigThunder`。`BigThunder`（`@0x96F8`）里没有任何
`magic\NNN\*` 字符串，但它 `syscall 0x310`（按名字调用脚本）把 `LockTargetTime3` 连同
`15008` / `15009` 两个立即数传下去：

```asm
0098B8  PUSHS    "m005snd01"
0098C8  SYSCALL  0x301
009900  PUSHS    "LockTargetTime3"
009910  PUSHI    15008
009930  SYSCALL  0x310      ; argc=6，按名字调用脚本
009958  PUSHI    15009
009978  SYSCALL  0x310
```

`15008`/`15009` = `10000 + 1000×5 + 8/9` → 目录 **`005`（閃電）** 的第 8、9 个对象；
`LockTargetTime3` 内部再用 `syscall 0x011` 把它们创建出来。所以五雷轟頂的特效**是** `005`，
只是通过对象号引用，目录通配那条路上看不到。这也说明只按字符串做映射会漏掉这一类。

### 4.4 一个技跨多个目录 / 一个目录多个技　`[确认]`

- **跨目录的技 29 个**：拒陸馬(031、041)、絕命壩(031、041)、十面埋伏(031、041)、狂雷天牢(022、032)、天地無用(018、027、032)、連弩(009、019)、刀劍亂(026、036)、旋龍(001、011)。
- **目录复用**：`012` 同时被 分身斬 与 鬼哭神號 用；`025` 被 太極門/太極華陣/鬼哭神號 用；
  `031` 被 集火柱/鬼哭神號 用；`018` 被 黃龍天翔/天地無用 用；`027` 被 天地無用/火牛系 用。
  鬼哭神號 同时引用 `012`+`025`+`031`，与它"多段大招"的定位一致。`[推测]`

### 4.5 `Magic200`（`num=700`）没有对应武将技　`[未解]`

符号表末尾有 `Magic200`，`num=700`，不在 501–610 区间，`MAGIC.INI` 也没有 700。
推测是"合体技/召唤/特殊事件"脚本或旧版遗留，本文不做归因。

### 4.6 目录内帧序与播放时序　`[未解]`

本文只解决"技能→目录"。**目录内 819 张帧谁先谁后、每帧停多少 tick，在脚本里表现为
一串 `PUSHI <ThingID>` + `SYSCALL 0x011` + `WAIT n`，没有集中的"帧序表"。**
要得到逐帧时间线，需要按脚本控制流做符号执行（含 `WAIT` 语义、`sc0x303` 随机数分支），
超出本轮范围。可确定的只有：帧文件名尾号（如 `M038SWORD01..`）不是播放序，播放序由脚本决定。
