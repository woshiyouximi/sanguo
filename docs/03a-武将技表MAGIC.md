# 03a 武将技表 MAGIC.INI

> 源文件：`extract\pak\MAGIC.INI`，23,630 字节 / 1748 行 /
> 177 段，编码 **cp950(Big5)**。JSON：`extract/json/magic.json`。

## 1. 一个文件里装了两张表

| 段名 | 数量 | 字段数 | 含义 |
|---|---|---|---|
| `[MAGIC]` | 110 | 10 | 武将技（武将在战场上消耗技力施放） |
| `[WISE]` | 67 | 7 | 军师技（随军军师提供的被动/战术加成） |

合计 **177 条技能**。两类段字段完全不同（10 vs 7），
必须分开解析；用同一套字段签名去读会把军师技读成残缺的武将技。

字段签名（官方原样）：

```json
{
 "MAGIC": [
  "SEQUENCE",
  "NAME",
  "MP",
  "POWER",
  "ATTACK",
  "SCRIPT",
  "ATTRIB",
  "TITLE",
  "NOTE",
  "ACTIVE"
 ],
 "WISE": [
  "SEQUENCE",
  "NAME",
  "Level",
  "WiseLevel",
  "Execute",
  "ATTRIB",
  "ACTIVE"
 ]
}
```

## 2. 字段详解

### 2.1 `[MAGIC]` 武将技（10 字段）

| 字段 | 含义 | 取值域（实测） | 判读依据 |
|---|---|---|---|
| `SEQUENCE` | 技能编号 | 1..110 连续 | 与武将表 SKILL 第二列、MAGIC.SO 脚本数互证 |
| `NAME` | 技能名 | 110 个互不重复 | 中文，直接显示 |
| `MP` | 消耗技力 | 18..50，33 个不同值 | 均值 33.84、中位 35.0；与武将表 BaseMP 同量纲（34..99 的初始技力池） |
| `POWER` | 威力（推测） | **恒为 100** | 110 条全同 → 不是可变参数 |
| `ATTACK` | 攻击力 | 0..60，22 个不同值 | 均值 10.52；0 值常见（纯治疗/纯召唤类） |
| `SCRIPT` | MAGIC.SO 脚本号 | 501..610 连续、110 个各不相同 | 每个武将技一个入口；表序 ≠ 脚本号序（按开发顺序分配） |
| `ATTRIB` | 目标/效果自由标签 | 中間、主將、主將2、主將3、全體、兩側、四周、補兵、補血 | 自由中文串，可含多个标签（逗号分隔） |
| `TITLE` | 授予称号 | 填充 50 条 / 空 60 条 | 如 博士/議郎；武将习得该技后获得的官衔（推测） |
| `NOTE` | 注释 | 格式「说明,等级」如 `主將補血,L1` | 唯一带 L1..L5 的地方 |
| `ACTIVE` | 作用对象位掩码 | 1/2/4/8 及其组合 | 见 2.3，4 位含义可反解 |

### 2.2 `[WISE]` 军师技（7 字段）

| 字段 | 含义 | 取值域（实测） | 判读依据 |
|---|---|---|---|
| `SEQUENCE` | 军师技编号 | 1..67 连续 | 与武将表 WISESKILL 第二列互证 |
| `NAME` | 技能名 | 67 条 / 18 组重名 | 重名 = 同一技能的多档版本 |
| `Level` | 习得等级 × 10 | 120..490，步进 10，单调不减 | ÷10 得 12..49 级；同技多档时递增 |
| `WiseLevel` | 档位 | 0/1/2/3 | 第几档强化版本，与 Level 同向递增 |
| `Execute` | 效果/脚本索引（推测） | 1..67，**67 个值恰好把 1..67 用尽一次** | 67 条技能恰好是 1..67 的一个排列 → 更像索引而非消耗（消耗不会恰好无重复用尽） |
| `ATTRIB` | 目标码 | 纯数字 0(61)/3(3)/1(2)/2(1) | 军师技侧退化为数字码，含义未定 |
| `ACTIVE` | 作用对象码 | 1/2/4/8/12/15 等 | 与武将技同一套位掩码 |

### 2.3 `ACTIVE` 位掩码的还原

全表 177 条技能用到的位组合：

| 掩码 | 十六进制 | 位分解 | 条数 |
|---|---|---|---|
| 1 | 0x1 | 我方士兵 | 18 |
| 2 | 0x2 | 我方主将 | 32 |
| 4 | 0x4 | 敌方士兵 | 27 |
| 5 | 0x5 | 我方士兵+敌方士兵 | 3 |
| 8 | 0x8 | 敌方主将 | 19 |
| 12 | 0xC | 敌方士兵+敌方主将 | 72 |
| 15 | 0xF | 我方士兵+我方主将+敌方士兵+敌方主将 | 6 |

中文写法与数值的对应（只能按"能整除出 1/2/4/8"这一套唯一解）：

| 中文写法 | 掩码 | 位分解 |
|---|---|---|
| 我方士兵 | 1 | 我方士兵 |
| 我方主將 | 2 | 我方主将 |
| 敵方士兵 | 4 | 敌方士兵 |
| 敵我士兵 | 5 | 我方士兵+敌方士兵 |
| 敵方主將 | 8 | 敌方主将 |
| 敵方全軍 | 12 | 敌方士兵+敌方主将 |
| 敵我全軍 | 15 | 我方士兵+我方主将+敌方士兵+敌方主将 |

四位含义 = **我方士兵 / 我方主将 / 敌方士兵 / 敌方主将**。证据：数字写法只出现
1/2/4/8 及其组合；`敵方全軍`=12、`敵我全軍`=15、`敵我士兵`=5 都恰好是这套位的和。

## 3. 分类统计（7 类）

规则（写进 `magic.json.classification.rules`，按顺序命中）：

```
1) [WISE] 段 -> 军师技
2) ATTRIB 含 補兵 或 NOTE 含 召喚 -> 召唤/补兵
3) ATTRIB/NOTE 含 補血 -> 恢复
4) NOTE 含 退兵/阻礙/暫停/混亂 -> 控制/阻碍
5) ACTIVE 掩码 = 8 -> 伤害-单体主将
6) ACTIVE 掩码 = 4 -> 伤害-敌方士兵
7) 其余 -> 伤害-群体
```

| 分类 | 条数 |

| 伤害-群体 | 77 |
| 军师技 | 67 |
| 伤害-敌方士兵 | 13 |
| 召唤/补兵 | 8 |
| 伤害-单体主将 | 6 |
| 控制/阻碍 | 4 |
| 恢复 | 2 |

## 4. 数值分布

| 指标 | 样本 | 最小 | 最大 | 均值 | 中位 | 不同值数 |
|---|---|---|---|---|---|---|
| 武将技 MP（技力消耗） | 110 | 18 | 50 | 33.84 | 35.0 | 33 |
| 武将技 POWER | 110 | 100 | 100 | 100.0 | 100.0 | 1 |
| 武将技 ATTACK | 110 | 0 | 60 | 10.52 | 8.0 | 22 |
| 军师技 Level | 67 | 120 | 490 | 293.43 | 270 | 33 |
| 军师技 Execute | 67 | 1 | 67 | 34.00 | 34 | 67 |

**军师技 `Execute` 是一个排列，不是消耗值**：67 个值排序后恰好等于 `1,2,…,67`
（每值出现一次、无重复无缺口）。如果它是"技力消耗"，67 条技能把 1..67 各用一次
的概率极低 → 更可能是另一张表的索引（效果/脚本号），**`[WISE]` 段里根本没有消耗字段**（推测）。
另一条佐证：同一技能的三档 `Execute` 是**连号**的（鼓舞士氣 4/5/6、降敵士氣 1/2/3、
恢復體力 35/36/37、減緩集氣 65/66/67），说明它指向按「技能家族」顺序排布的脚本/效果表。

**ATTACK 的全部 22 个取值**：`0, 5, 6, 7, 8, 9, 10, 11, 12, 14, 15, 20, 25, 30, 32, 35, 40, 44, 45, 48, 50, 60`
—— 明显是"5 的倍数 + 零头"，最大 60，说明伤害是分段档位而不是连续值。

**技能等级（NOTE 尾码 L1..L5）**：

| 等级 | 条数 |
|---|---|
| L1 | 39 |
| L2 | 35 |
| L3 | 30 |
| L4 | 5 |

L5 只有 1 条 —— 全表唯一的 L5 是 `五嶽華斬`
（NOTE = `會集中攻擊武將的半月斬,L5`，MP=49，ATTACK=45），
它是"最高级武将技"的独苗，可作为新游戏技能分级的参考锚点。

## 9. 未确定（标注为推测）

| 字段 | 现状 | 推测与依据 |
|---|---|---|
| `POWER` | 110 条全为 100 | 像伤害基数/百分比定标（100%=满），而非每技不同的威力值 |
| `ATTRIB` | 自由中文标签（全體/主將/主將2/主將3/四周/中間/補兵/兩側/補血） | 引擎据此选目标组；`主將` 与 `主將2`/`主將3` 的差别未定（推测为第几号目标） |

| 军师技 `ATTRIB` | 纯数字 0..3（0 占 61 条） | 与武将技中文标签不同源，无法从数据侧反解 |
