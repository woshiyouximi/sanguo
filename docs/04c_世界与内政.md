## 1. 时间系统

### 1.1 三个时间全局（结论：**一回合 = 一个月**，游戏内只显示"年"）

| 全局 | 类型 | 含义 | 证据 |
|---|---|---|---|
| `0x4BD380` | i32 | `SYSTEM\YEAR` 装载的起始年 | `0x42C1AA`：`0x42C0D0(ini,"SYSTEM","YEAR",0)` 结果写入 |
| `0x4BD390` | i32 | **当前年**（= SYSTEM 结构 `+0x10`） | `0x42C208: mov edx,0x4BD380 / mov ecx,[edx] / mov [edx+0x10],ecx` |
| `0x4C30E0` | i32 | **月内倒计时 / 回合计时器**（读到 0 即推进一月） | `0x41BBF4: cmp dword ptr [0x4C30E0],0` |
| `0x4A64BC` | u16 | **月内状态标志**（本月是否已推进/已下令） | `0x4278AC`、`0x427903: cmp [0x4A64BC],0` |
| `0x4A64FC` | u16 | **年进位标志**（跨年时置 1） | `0x4238AF`、`0x41B69D` 均读写 |
| `0x4A6440` | i32 | 游戏阶段 / 结束状态机（0 正常，1/2/3 = 结局分支） | 写入点 `0x40EBDE`=2、`0x40ED0E`=2、`0x41B6FB`=1、`0x41B75E`=3、`0x41B7D1`=3、`0x41BB70`=0 |

界面上只有"年"：`0x48B100 "時間   %d年"`（xref `0x423D23`，引用 `0x4BD390`）。
结局处才打印真实日期 `0x4898E4 "%3d年%2d月%2d日"`（xref `0x41B8A4`）——**月/日只存在于内部计数器，不显示**。

⇒ **一个回合 = 一个月**：`0x4C30E0` 每帧/每次时间片递减，减到 0 时触发"月份推进"，累计 12 次推进后 `0x4A64FC=1`，下一次推进时年份 +1。月号本身没有独立的"月"变量，只有 `0x4A64BC`（0/1）与年进位标志，因此**月的绝对序号未定位**（推测由 `0x4C30D8`/`0x4C30DC` 承担，见 1.4）。

### 1.2 月度流水线：`0x41B69D`

反汇编事实（`0x41B69D` 起）：

```
if ([0x4A6440]) goto end;                       ; 结局/暂停阶段直接跳过
if ([0x487310] == 1) {                          ; ← 计时总开关
    if (--[0x4C30E0] <= 0) {
        [0x4A64FC] = 1;                         ; 请求跨年
        [0x4A64BC] = 0;
        显示(0x48984C);                          ; 换月提示串
        [0x4A6440] = 1;
    }
}
call 0x41B643;                                  ; 月度主处理（AI/内政/移动结算）
...
```

- `0x487310` 是**可翻转的总开关**（游戏内热键/调试）：`0x40E1F6: a1 10 73 48 00 / 83 f0 01 / a3 10 73 48 00` = `[0x487310] ^= 1`。
- `0x4C30E0` 的全部立即数写入点：
  - `0x40E216`：`= 0x0A(10)`（若 `ecx==0`）
  - `0x41BC1B`：`= 0x0E10(3600)`
  - `0x42C214`（剧本装载末尾）：`xor ecx,ecx; mov [0x4C30E0],ecx` ⇒ `= 0`
  - 读档 `0x433AA6`：从存档头 `+0x30` 回填
- **`0x4A64BC` 的全部写入点**：`0x41B6D5 =0`、`0x427923 =1`、`0x438415 =0`、读档 `0x433AA6`（存档 `+0x5C`）、存档 `0x432183`。
  `0x427923` 位于**内政命令执行区**（见 §2.3），判断点 `0x4278AC / 0x427903` 都在同一区 ⇒ `0x4A64BC` 语义为"**本月内政命令是否已下达**"，置 1 后内政菜单拒绝再次下令（**此点为代码结构推断，未做运行验证**）。

### 1.3 年推进：`0x4238AF` → `0x423885`

`0x4238AF`（唯一调用者 `0x423A4D`）：

```
if ([0x4A64FC] == 1) {
    [0x4BD390]++;          ; 年 +1
    call 0x423885;         ; 年度结算
    [0x4A64FC] = 0;
}
```

`0x423885` 的年度结算顺序（**这是"每年一次"的钩子序列**）：

```
call 0x423681;   ; 年度处理 1（未定位到具体语义）
call 0x423765;   ; 年度处理 2
call 0x42379E;   ; 年度处理 3
call 0x4237A6;   ; 年度处理 4
if ([0x4A6444] == 0) call 0x423824;   ; 年度处理 5（受 [0x4A6444] 抑制）
```

四个子函数各自的语义**未定位**（未见其引用可辨识字符串）。年度结算不含"季节"概念——**本作无季节系统**（字符串表无 春/夏/秋/冬 相关提示，`SYSTEM` 段无季节键）。

### 1.4 计时器 `timeSetEvent` 与游戏内时间的关系

| VA | 内容 | 说明 |
|---|---|---|
| `0x47C1C6`（705 B） | 主循环：`PeekMessageA` / `WaitMessage` / `timeGetTime` | 帧循环；`timeGetTime` 只用于**帧间隔/FPS 限制** |
| `0x47C67E`（115 B） | `timeSetEvent` 包装 | 多媒体定时器回调注册 |
| `0x4869A0` | 显示开关 | `0x43031D` 中用于 FPS/鼠标显示 |

**结论**：`timeSetEvent` / `timeGetTime` 服务的是渲染帧与动画节拍，**与游戏内"年月"无关**。游戏内时间完全由 `0x4C30E0` 这个"月内计数器"驱动，且只在 `0x487310==1` 时才递减（见 1.2）。
`0x4C30D8` / `0x4C30DC` 两个 dword 随存档保存（存档头 `+0x60/+0x64`），**语义未定位**（候选：月序号、回合序号）。

### 1.5 大地图"时间冻结"补丁对应哪个函数

"时间冻结"（停表，让 AI 与内政不推进）有三种改法，对应位置明确：

| 改法 | 目标 | 效果 |
|---|---|---|
| A. 关总开关 | `0x41B69D` 开头的 `cmp dword ptr [0x487310],1` 分支改成永不成立（或把 `0x40E1F6` 的 `xor` 改成 `mov eax,0`） | 月度流水线整体不跑（AI/内政/移动都不动） |
| B. 冻结计数器 | 把 `0x41B69D` 内 `--[0x4C30E0]`（`0x41BBF4` 附近）NOP 掉 | 时间不前进，但按键/查看界面正常 |
| C. 保底 | `0x42C214` 处 `[0x4C30E0]=0` | 剧本载入后计时器从 0 起（正常行为，不是补丁） |

**A 是"大地图时间冻结"的标准做法**：`0x41B69D` 是唯一的月度入口，且它内部第一句就是 `[0x487310]` 判定。

**金钱/粮草**：
- 城池结构里只有 `MONEY`（`+0x92`），**没有粮草字段**；`CITY%02d` 键集（`NAME/KING/MAJOR/WISE/POPULATION/DEFENSE/MONEY/POS/FLAGPOS/RATE/FLAGS`）也无粮草键；城市面板无粮草项 ⇒ **本作无粮草系统**（战前补给不占城库存）。
- 金钱的产出/消耗公式：`MONEY` 的加/减点**未定位**（`0x427A84` 只处理人口与防御；`0x423CB0` 一带的君主全局面板 `0x48B148 "金  錢 %d"` 只是汇总显示）。**未定位**。

### 2.4 人口 ↔ 兵源

`+0x82 = min(POPULATION/2500 + 110, 600)`（`0x42D8F0`，常量 2500/110/600）。
即：人口 79,500 的襄平（TIMES1.INI `[CITY01]` `POPULATION=79500`）⇒ 上限 `79500/2500+110 = 141`（未到 600）。
人口减少/增加只由「開發」与战乱改变，**人口自然增长公式未定位**。

### 2.5 城池升级条件

`Rate`（1..5）是**剧本数据给定**（`0x42D8F0` 只读不写）。全 EXE 内除装载器外**没有**对 `+0x6C` 的写入点 ⇒ **城池规模在游戏中不会变化**（无升级）。（依据：对 `+0x6C` 的 `mov [reg+0x6C]` 只出现在 `0x42D8F0`。）

### 3.3 等级与升级曲线

> **先纠正一个容易误读的点**：`0x40F46C: cmp eax,0x14 / jg` **不是等级上限**，而是升级提示的分档——该 `cmp` 位于拼提示串的代码里（`0x40F3C6` 内的 `0x40F462` 处），比较的是刚升上去的等级：
>
> | 条件 | 追加文案（`0x488C9C` / `0x488CB0`） | 对应机制 |
> |---|---|---|
> | `等级 ≤ 20` | `\n最大帶兵數增加5人` | 最大带兵数 = `min(等级×5,100)` |
> | `20 < 等级 ≤ 40` | `\n有5名士兵升為騎兵` | 骑兵上限 = `clamp((等级−20)×5, 0, 100)` |
> | `等级 > 40` | 无 | 两项都不再增长 |
>
> **升级本身没有任何封顶判断**（`0x40F27A` 直接 `add dx,1`），所以 `0x40F46C` 支持不了"等级上限 20"的结论；修正版把上限改到 99 与此处不矛盾。原版真正的上限值需另找（可能在经验/等级表或 UI 侧）。

升级函数 **`0x40F3C6`（577 B）**：

```
if (0x409F0F(gen) != 1) return;           ; 前置判定（未定位，疑"是我方武将"）
lvl   = (i16)[gen+0x2E];
hpNow = (i16)[gen+0x10];
mpNow = (i16)[gen+0x14];
0x40F23C(gen);                            ; ← 执行升级（见下）
if (0x40F3A1(gen) == 0) return;           ; 是否达成（未定位）
if (arg != 1) return;
if ([0x4A79C8] & 2) return;               ; 命令行/作弊开关抑制提示（-AIOFF 同一位段）
sprintf(buf, 0x488C88 "%s等級升為第%d級", 名, lvl);
if (lvl <= 0x14)      追加 0x488C9C "\n最大帶兵數增加5人";
else if (lvl <= 0x28) 追加 0x488CB0 "\n有5名士兵升為騎兵";
if (体力上限上升)     追加 0x488CC4 "\n體力最大值上升%d";
if (技力上限上升)     追加 0x488CD8 "\n技力最大值上升%d";
```

升级核心 **`0x40F23C`（357 B）**：

```
ovHP = (i16)[gen+0x10] - 0x40A020(gen);    ; 旧上限与"当前体力"的差
ovMP = (i16)[gen+0x14] - 0x40A098(gen);
[gen+0x2E] += 1;                           ; 等级 +1
[gen+0x42]  = 0x409FB6(gen);               ; 重算上限 A
[gen+0x46]  = 0x409FD8(gen);               ; 重算上限 B
if ([gen+0x44] > [gen+0x42]) [gen+0x48] += [gen+0x44] - [gen+0x42];
[gen+0x44] = max([gen+0x44], [gen+0x42]);  ; clamp
[gen+0x48] = min([gen+0x48], [gen+0x46]);  ; clamp
```

四个计算函数的**指令级公式**：

| 函数 | 公式（按反汇编逐条还原） |
|---|---|
| `0x409FB6` | `if (Level >= 20) return 100; else return Level * 5;` ⇒ **最大带兵数 = `min(等级×5, 100)`**（→ `+0x42`） |
| `0x409FD8` | `v = (Level - 20) * 5; if (v < 0) v = 0; if (v > 100) v = 100; return v;` ⇒ **骑兵数上限 = `clamp((等级−20)×5, 0, 100)`**（→ `+0x46`） |
| `0x40A020` | `v = BaseHP(+0x18) + (Level*2 * 武力(+0x34)) / 100; if (BaseHP > v) v = BaseHP; if (v > 0x7FFF) v = 0x7FFF;` ⇒ **最大体力 = `BaseHP + 等级×2×武力/100`（下限 BaseHP，上限 32767）** |
| `0x40A098` | `if (武力(+0x34) > 智力(+0x36)) v = (武力 + 智力)/2; else v = 智力;`（返回值再参与 clamp） |

⇒ **成长曲线**：`体力上限` 由 `BaseHP` 与 `武力×等级` 决定；`技力上限` 主要由 `智力` 决定（武力高于智力时取两者均值）。**经验→等级的阈值表未定位**：`BaseEXP(+0x2A)` 只在装载/战斗结算使用，未找到"经验表"数组（EXE 内无 20 项递增常量表被 `cmp` 引用）。

## 4. 君主与外交

### 4.1 KING 段字段（`0x42DD7F`，306 B）

| 键 | 写入 | 说明 |
|---|---|---|
| `KING%02d` | 段名 | `0x48C6F0` 附近；循环 `01..TotalKing` |
| `NAME` | `%s\NAME` | 君主名（如 `[KING01] NAME=何進`，TIMES1.INI L8） |
| `FLAGNUM` | — | 旗帜图像编号（`[KING01] FLAGNUM=26`，L9） |
| `SELECT` | — | 势力可选性/选择顺序（`[KING01] SELECT=8`，L10） |
| `Type` | — | 势力类型（`[KING01] Type = 1`，L11） |

King 节点：分配 `0x4092D1`（失败 `0x48659C "KING node overflow"`）、释放 `0x409354`；链头 `0x4A6194` / 空闲 `0x4A6198` / 尾 `0x4A619C`；next 在 `+0x346` ⇒ **记录大小 ≈ 0x34A (842 B)**。
已知成员：`+0x338` = **势力城池链头**（`0x40CBB6: mov ecx,[eax+0x338]`）。
King 记录的完整字段表**未定位**（`0x42DD7F` 只写前 4 个键，其余在 `0x42DEB1`(95 B) 与运行时逻辑中）。

### 4.2 势力归属判定

四处一致的判定链：
- 城 → 势力：`city+0x10`（君主编号，0=空城）
- 势力 → 城链：`king+0x338` → `city+0xA2` → …
- 玩家势力编号：**`0x4A64F0`**（`0x40C635`/`0x40CAF1` 都用它判"是不是玩家的城"；`0x43031D` 装载剧本后由 `0x4093F1` 写入）
- 玩家君主编号：存档头 `+0x50/+0x54` 保存 `0x4A64F0`/`0x4A64F4`（`0x409430` 变换）

### 4.3 有没有同盟？

**没有外交同盟系统。**
- 字符串表内**无** `同盟`/`結盟`/`外交` 任何条目（`str_big5.tsv` 全表搜索 0 命中）。
- AI 行动表里的 `0x4872AC "聯合"`（ACT=7）是**军事联合出兵**（同一君主的多城合击），不是跨势力同盟：`0x40C635` 里判定条件是 `neighbor->[0x10] == 本城君主`。
- 势力间只有"敌对/中立"二元（`city+0x10` 是否相等），**无关系值、无停战、无使者**。

### 4.4 招降与叛乱

- 招降见 §3.5。
- **叛乱**：字符串表无 `叛`/`謀反`/`獨立` 条目；未见 `city+0x10` 被"非战斗"改写（所有 `[city+0x10]` 写入点均在攻城/占领流程）⇒ **大概率无独立叛乱系统**（保留"未定位"）。忠诚低导致的**出走/被挖角**无法从字符串证据区分。

## 5. 移动与寻路

### 5.1 `PATH` 表（118 条）

装载器 **`0x42DF10`（803 B）**，键：`PATH%03d`、`%s\START`、`%s\END`、`%s\LENGTH`、`%s\POINT`。

`TIMES1.INI` 实例（L802-806）：

```ini
[PATH001]
Start=襄平
End=北平
Length=260
Point=1108,90 1066,66 1038,64 1013,70 1002,92 957,101 923,130 905,137 881,138 
```

- `Start`/`End` 是**城名**（装载时用 `0x406A0B` 查城池指针）。
- `Length=260` = **两城间路径长度（"距离"）**，AI 评分用它：`Rate = 80 / (Length + 1)`。
- `Point=` 是**空格分隔的 `x,y` 走点序列**，首点 = 起点城地图坐标（= CITY 段 `POS` 的前两数），末点 = 终点城坐标。部队沿这些点做线性插值移动。

### 5.2 邻接表：`city+0x46 .. city+0x66`（9 槽）

**这是大地图寻路的核心结构**，与 `PATH` 表互为索引：

```
0x4054B9(city, idx)                     ; idx ∈ [0,9)
{
    if (idx < 0 || idx >= 9) return 0;
    if (!city) return 0;
    n = -1;
    for (i = 0; i < 9; i++) {
        seq = city->[+0x46 + i*4];              ; 邻接城序号
        if (seq == 0) continue;
        c = 0x422FD7(city, seq);                ; 序号 → 城池指针
        if (c->[+0x9E] == 1) continue;          ; FLAGS==1 = 关卡，不可通行
        if (++n == idx) return c;               ; 第 idx 个"可通行邻城"
    }
    return 0;
}
```

证据：`0x4054B9` 起 120 字节（`mov eax,[edx+ecx*4+0x46]`、`cmp dword ptr [eax+0x9e],1`、`call 0x422FD7`）。
调用者 8 处：`0x4010F7`、`0x401803`、`0x401886`（地图/移动 UI）、`0x40C09A`、`0x40C234`、`0x40C3C7`（AI）、`0x40C917`（AI 攻击）、`0x40CB6F`（AI 攻城循环）。

### 5.3 部队移动力与地形

- **移动力字段未定位**：城池/武将结构内没有独立的"移动力"字段；AI 与 UI 都直接用 `PATH\Length` 作为代价（`0x40C7E8` 的 `0x50/(Length+1)` 评分、`0x489248 "請選擇兵團目的城市"` 的 UI 流程）。
- **地形影响未定位**：地形表由 `0x42E945`（535 B）装载，键 `TERRAIN`、`Sequence`、`SoundTrack`、`Name`、`Floor`、`Foreground`、`Midground`——**只有图像/音轨资源，没有移动代价或战斗修正字段** ⇒ **地形不影响移动，也不影响战斗数值**（仅视觉与音效）。
- 9 邻接 + `FLAGS==1` 关卡 = 唯一的"地形限制"（关卡城不可被穿越/作为通路）。

```ini
805 Length=260                    ; 路径长度（AI 距离代价；Rate=80/(Length+1)）
806 Point=1108,90 1066,66 ...     ; 走点序列（首点=起点坐标，末点=终点坐标）
```

### 6.6 `[GENERAL]` 段

512 个重复的 `[GENERAL]` 段（段名重复，靠 `SEQUENCE` 区分），键集见 §3.2 末尾。示例（丁奉）：
`SEQUENCE=001 STR=80 INT=68 BaseHP=83 BaseMP=40 Loyal=67 Spirit=67 BaseEXP=200 CONSTANCY=4 TYPE=1`。
盗贼模板：`STR=99 INT=99 BaseHP=99 BaseMP=99 BaseEXP=9999 CONSTANCY=9 TYPE=30`。

### 6.7 事件 / 脚本段

- `[SCRIPT]` 段：装载器 `0x42EB5C`（183 B），键 `File`、`SCRIPT`；字符串 `0x48C9AC/0x48C9C4 "SCRIPT"`、`0x48CC0C "Script"`、`0x48CADC "DESCRIPTION"`。
- `[TERRAIN]` 段：`0x42E945`，键 `Sequence/SoundTrack/Name/Floor/Foreground/Midground`（纯资源）。
- 事件触发器：**未定位**。没找到"年/月 → 触发事件"的表或脚本钩子（`0x423885` 的五个年度子函数即最可能的挂载点，但其内部无可辨识字符串）。
