# 04 · 引擎架构与代码逻辑总览

> **一句话结论**：《三国群英传2》是一个 **1999 年的纯 2D 软件渲染引擎**：640×480/16bpp DirectDraw 全屏，680 KB 的 32 位 EXE（MSVC 6.0，静态 CRT），所有资源（约 11110 个文件、112 MB）打包在一个 `.PAK` 里，游戏规则与内容几乎全部**数据驱动**（INI 文本表 + 自研字节码脚本 `.SO`），代码本身只有 2533 个函数、约 513 KB 代码段。
>
> 本文是**总体地图**：讲清"程序启动后发生什么、模块怎么分、数据怎么流"。各子系统的细节各有专文：
> - 战斗系统（伤害/相克/士兵 AI/结算）→ [04b_战斗系统.md](04b_战斗系统.md)
> - 世界与内政（时间/城池/武将/外交/移动）→ [04c_世界与内政.md](04c_世界与内政.md)
> - AI 与脚本引擎（-AIOFF/AI 评分/Smart Script 指令集）→ [04d_AI与脚本引擎.md](04d_AI与脚本引擎.md)
> - 存档格式 → [07_存档格式.md](07_存档格式.md)
> - 资源格式（SHP/TEX/MSK/字体/INI）→ [02_资源格式规格.md](02_资源格式规格.md)

## 1. 可执行文件结构

| 项 | 值 |
|---|---|
| 文件 | `Sango2.exe`，682,496 字节 |
| 格式 | PE32，ImageBase `0x400000`，Subsystem GUI |
| 入口 | RVA `0x6ED80` → VA `0x46ED80`（CRT 启动） |
| 编译器特征 | MSVC 6.0 时代的 CRT 序言（`55 8B EC` / `6A FF 68`），**不导入 MSVCRT**（CRT 静态链入） |
| 时间戳 | `923555340` = **1999-04-08** |
| 代码段 | `.text` RVA `0x1000`，虚拟大小 `0x7D38E`（≈ 501 KB），文件偏移 `0x400` |
| 其它段 | `.rdata 0x7F000`、`.data 0x81000`、`.idata 0xD4000`、`.rsrc 0xD6000` |
| 导出 | 无 |

### 1.1 依赖的系统库（=`引擎用到的技术栈`）

| DLL | 函数数 | 用途 |
|---|---:|---|
| KERNEL32 | 78 | 文件 IO（`_lopen/_lread/_llseek`）、内存、时间 |
| USER32 | 28 | 窗口、消息、光标、键盘 |
| ADVAPI32 | — | 注册表 `Software\ODINSOFT\Sango2\Settings` |
| GDI32 | 2 | 仅取 DC/设备信息（真正渲染走 DirectDraw） |
| DDRAW | 1 | `DirectDrawCreate`，**16bpp 640×480 全屏** |
| DSOUND | 1 | `DirectSoundCreate`（音效混音） |
| WINMM | — | `timeSetEvent` 定时器、`waveOut`、`aux*` 音量、`mciSendCommand`（MP3/CD 音乐） |
| AVIFIL32 / MSVFW32 | — | 片头 AVI 播放 |
| ole32 | — | `CoInitialize`（AVI/MP3 相关） |

> 结论：没有第三方引擎、没有 Direct3D、没有字体渲染库。**所有画面都是 16bit RGB565 像素直写 + 自研精灵解码**，所有文字都是自带点阵字体（见 02 文档 §6）。

## 2. 地址空间地图（按功能分区）

按 `funcmap3.tsv` 的 2533 个函数 + 字符串/导入交叉引用归纳。地址为**区间**，边界有 ±1 页误差，但分区是可靠的：

| 区间 | 内容 | 关键证据 |
|---|---|---|
| `0x401000–0x40AFFF` | **核心对象与规则层**：各类节点池、数值计算、通用工具 | `CITY node overflow`(0x4051EB)、`Free Invalid City node`(0x40526E) 等池管理 |
| `0x40B000–0x40BFFF` | **程序入口**：WinMain、窗口类/窗口创建、命令行、注册表 | `Sango2 for Windows`、`SANGO II`、`SANGO II Error Message`、`CoInitialize`、`LoadCursorA`；WinMain=`0x40B00A` |
| `0x413000–0x41AFFF` | **菜单/界面层**（主菜单、读档、开场、势力选择） | `MENU\D3_1A/D3_2H/D3_5`、`MENU\BUTTON05A/06A`、`ACCEPT` |
| `0x41B000–0x42AFFF` | **界面层续**：内政/外交/武将列表/物品界面（本作 UI 代码占比很大） | `MENU\D1_1B`、`MENU\D12B/D12C`、`MENU\D15` |
| `0x42C000–0x42DFFF` | **数据表装载**：武将/城池字段、物品 | `GENERAL/NAME/FLAGS/INT/STR/BASEHP/BASEMP/BASEEXP/CONSTANCY/TYPE/BLOOD/LOYAL`、`WEAPON`、`HORSE` |
| `0x42E000–0x42EFFF` | **SANGO.INI 系统段 + 剧本列表** | `SYSTEM\TotalTimes`、`SYSTEM\TotalGeneralType`、`SYSTEM\TotalThings`、`SYSTEM\TIMES%02d` |
| `0x42F000–0x42FFFF` | **SANGO.INI / MAGIC.INI / TIMES*.INI / SAVES / PAK 初始化** | `SANGO.INI`、`LoadMagicIni`=`0x42F3C8`、TIMES 装载=`0x43031D`、存档=`0x43207C`、资源初始化=`0x42FFC5` |
| `0x430000–0x433FFF` | **大地图**：地形、城市图标、地图绘制 | `SHAPE\MAP\TEXTURE.TEX`、MSK 地形解码器 `0x44FD1B` |
| `0x434000–0x437FFF` | **界面/剧情驱动**、战场准备 | `MENU\D15` |
| `0x437000–0x441FFF` | **造型与动画**：`Things.ini` 装载、动作序列、兵种/武将造型 | `FIRST/WAIT/WALK/ATTACK/DEFENSE/PAIN/DEATH/WIN/ATTACK2..8`、`Things.ini 装载`=`0x441E61`、`FORCE\MA* 造型装载`=`0x42AB50` |
| `0x446000–0x449FFF` | **战斗准备/战场 HUD** | `MENU\WARINFO01-05`、`MENU\WARPREP01/02/07`、`0x441212`(战斗界面) |
| `0x44B000–0x44FFFF` | **战斗逻辑、地图遮罩解码、内政画面** | `SHAPE\POLICY\YIELD.TEX`、MSK 解码 `0x44FD1B` |
| `0x450000–0x45AFFF` | **平台层**：DirectDraw/表面管理、窗口/焦点、音频设备、INI/文件 IO 包装 | `GetDC/GetDeviceCaps/ReleaseDC`、`SetFocus/SetCursor`、`auxGetNumDevs/auxGetVolume`、`_lopen` 包装 `0x455A23`、INI 包装 `0x4554EA/0x455662/0x45568D` |
| `0x467000–0x46EFFF` | **图形与媒体**：SHP/TEX/TGA/字体解码、声音、字符串 | SHP 修正 `0x46B3D0`、`SCREEN\SCREEN%02d.TGA` `0x467B50`、声音 `0x4695C0`、WAV `0x468BA0` |
| `0x46E000–0x47BFFF` | **静态链接的 CRT**（C 运行时，非游戏逻辑） | `HeapCreate/HeapAlloc/HeapFree`、`LCMapStringW/MultiByteToWideChar`、`FlushFileBuffers` |
| `0x47C000–0x47DFFF` | **应用框架**：消息泵 + 帧循环（含 AVI 播放器） | `timeGetTime/PeekMessageA/TranslateMessage/DispatchMessageA/WaitMessage`；循环体 `0x47C1C6` |

> **工程含义**：这是一个"**界面代码占一半**"的项目——0x413000–0x42A000 和 0x446000–0x449000 加起来近 200 KB 都是界面。而规则/战斗只占 ~100 KB。**对新项目的启示：这套游戏的复杂度主要不在算法，而在大量一次性 UI 流程**（这也是它难以移植、而适合"重写 UI 层、复用数据"的原因）。

## 3. 启动流程（逐跳已验证）

```
0x46ED80  CRT 入口
  └─> 0x40B00A  WinMain
        ├─ RegisterClass / CreateWindowEx("SANGO II", "Sango2 for Windows")
        ├─ CoInitialize
        └─> 0x42FDE0
              └─> 0x42FE90
                    ├─ 0x46D230   环境检查（返回假则直接退出：如缺 CD/PAK）
                    ├─ 0x42FFC5   资源系统初始化
                    │    ├─ 0x468A00(0x42FD40)   内存/池初始化
                    │    ├─ 0x42FDEA             读注册表（音量/显示/状态）
                    │    │    └─ 0x40BBA8 → 0x40BDCD/0x40BDE4/0x40BDFB/0x40BDB6
                    │    │       写全局 0x48CD1C / 0x48CD20 / 0x48CD28 / 0x4BD3A0
                    │    ├─ 0x42FF3D             **找 PAK 所在盘符**
                    │    │    从 'C'(2) 到 'Z'(0x1A)，拼 "C:\SANGO2.PAK" 到 0x48CD38
                    │    │    0x468450 试存在 → 0x453DE2 取盘 → 0x453DCB 切盘
                    │    │    全失败 → 弹 "Put [SANGO II] CD to CD-ROM."
                    │    ├─ 0x4501FD             平台层初始化
                    │    └─ 0x45209E             DirectDraw/表面创建
                    ├─ 0x43031D   TIMES*.INI 剧本数据装载
                    └─ 0x42FEAF   进入游戏主体
                          ├─ 0x46CDF0
                          ├─ 0x42FEEB → 0x46CB10 / 0x46CB30
                          ├─ 0x42FEFA → 0x46B530 → jmp 0x457E23
                          │             0x451211(表 0x4A66F0="TN", ...)
                          ├─ 0x42FF26   空桩（原版此处应有逻辑，修正版被 NOP 掉）
                          ├─ 0x46A030 / 0x469DC0
                          ├─ 0x41F8AF → 0x41F8B4("Magic01.o")   **载入脚本系统**
                          ├─ 0x469B10 / 0x43446B / 0x450220
                          └─ 0x42FE1C   收尾：反序释放 0x48CD1C/0x48CD20/0x48CD28/0x4BD3A0
```

要点：

1. **先找 PAK 再干别的**。原版是从光盘跑的，所以有"插光盘"提示；修正版把 PAK 放在 exe 同目录，这段逻辑仍保留（遍历盘符）。
2. 注册表里存的是**全局配置**（`Status/SoundVolume/MusicVolume/Effect`），不是存档。
3. `0x42FF26` 是个**空函数**——说明修正版（或某个官方补丁）把一段逻辑整段拿掉了。这是"版本差异可对比点"。
4. 脚本系统在游戏主体里才初始化（`Magic01.o`），说明**技能脚本是运行时按需加载的**，不是启动即全载。

## 4. 帧循环与时间系统

应用层循环体在 `0x47C1C6`（`__thiscall`，`this` 为应用对象）：

```
while (running) {
    if (!PeekMessage(&msg, 0,0,0, PM_REMOVE)) {
        if (quit_flag) break;
        if (paused)   continue;
        now = timeGetTime();
        if (mode_110 == 0)  frame = Convert(mode_188, now - last_time);  // 按真实时间折算
        else                frame = ++frame_counter;                     // 定步长
        if (frame >= limit_22C) break;
        if (frame > last_frame_35E) {
            last_frame_35E = frame;
            Update(frame);     // 0x47B93F
            Render();          // 0x47BA01
        }
    } else {
        TranslateMessage(&msg); DispatchMessage(&msg);
    }
}
```

应用对象（`this`）实测字段：

| 偏移 | 含义 |
|---|---|
| `+0x110` | 计时模式标志（0=按真实时间，非 0=定步长） |
| `+0x188` | 运行模式/循环标志（0 则直接退出） |
| `+0x22C` | 帧数上限（到则退出，用于 AVI/演示） |
| `+0x355` | 上一帧 `timeGetTime()` |
| `+0x359` | 暂停标志 |
| `+0x35E` | 已处理到的帧号 |
| `+0x362` | 当前帧号 |
| `+0x386` / `+0x38C` | 构造参数（模式、窗口句柄） |
| `+0x38A` / `+0x38B` | 运行中 / 已启动 |

> 注意：这段循环同时被**片头 AVI 播放器**复用（`0x47DE70` 是 `AVIStreamTimeToSample` 的 thunk），所以它是"应用框架"，不是游戏内战斗循环。游戏内的战斗/战略主循环是在此之上由**场景对象**驱动的（见 04b/04c）。

**速度控制**：命令行 `-SPEED`、游戏内 `S#`（修正版说明）都是改这个步长/倍率；`FPS=%d` 是调试输出。

## 5. 资源装载管线

```
磁盘 Sango2.PAK
   │  0x42FF3D 定位盘符 → 0x455A23(_lopen 包装) 打开
   ▼
PAK 索引（64B/项，名字 40B）——见 01 文档
   │  按需读取：整块读入内存（无压缩、无加密）
   ▼
┌─ .SHP  ── 0x46B3D0 载入修正：offsetX/Y 取负、行 (x,n) 语义化、0xFFFF→0、RGB565 校正
├─ .TEX  ── 标准 TGA（16bpp RGB555）→ 直接映射成 16bpp 表面
├─ .TGA  ── 标准 TGA（16bpp RGB555，512×512 无缝平铺地面材质）
├─ .MSK  ── 0x44FD1B 解码：0x80 头 + PCX RLE → 640×480 地形编号表
├─ 字体   ── SANGO.15/.20 点阵 + SANGO.IDX 索引 + SANGO.INI 字体参数
├─ .WAV  ── 0x468BA0（DirectSound 缓冲）
└─ .SO   ── Smart Script 字节码（MAGIC.SO / SYSTEM.SO）
```

内存中的资源**不是引用计数，而是"定长节点池 + 自由链表"**（见 §6）。载入后写进全局表，按 `SEQUENCE` 序号索引。

## 6. 对象模型：定长节点池 + 自由链表

全游戏没有用 C++ 的 `new/delete` 做对象管理，而是**自研池**。实测（`GENERAL` 为例）：

| 全局 | 含义 |
|---|---|
| `0x4A6184` | 已分配链头 |
| `0x4A6188` | 自由链头（分配时从这里摘） |
| `0x4A618C` | 链尾 |

- **`next` 指针在节点 `+0xF3`**（不是 4 字节对齐！结构体是 `pack(1)` 的），因此 **GENERAL 节点 = 247 字节**。
- 分配 = 从自由链摘头；池耗尽时扩容，失败才报错。
- 溢出/错误串（同时也证明池的种类）：`GENERAL node overflow`、`CITY node overflow`、`KING node overflow`、`TROOP node overflow`、`Free Invalid Troop node`，还有 `ObjectNode` / `TemporyaryLink`（原文拼写错误）/ `Menu` 的 `node overflow`。
- 各池的分配/释放函数（可作为"从对象反查代码"的入口）：CITY `0x4051EB`、GENERAL `0x4068EB`、KING `0x4092D1`、TROOP `0x43866A`。

**对新项目的含义**：这是 1999 年"避免 malloc 碎片 + 可寻址存档"的经典做法。存档时直接**整池落盘**，读档时整池恢复——这也解释了为什么存档文件里对象是定长的。

## 7. 数据驱动：内容全在文本表里

| 文件 | 大小 | 作用 | 装载函数 |
|---|---:|---|---|
| `SANGO.INI` | 27 KB | 系统参数 + 12 种战场 + 脚本注册 + 77 件物品 + 7 套字体定义 | `0x42C21E`/`0x42F3C8` 一带 |
| `MESSAGE.INI` | 23 KB | 529 条文本消息（`[MESSAGE]` 单段） | — |
| `MAGIC.INI` | 24 KB | 177 个技能：`[MAGIC]`(武将技) + `[WISE]`(军师技) | **`0x42F3C8` `LoadMagicIni`** |
| `Things.INI` | 600 KB | 620 个 `[OBJECT]`：兵种/造型/动画序列/特效 | **`0x441E61`** |
| `TIMES1-5.INI` | 各 210 KB | 5 个剧本：君主、武将归属、城池归属与数值 | **`0x43031D`** |
| `COMBINE.INI` | 27 KB | 8 条复合造型拼合规则（武将=身体+头+武器+马） | — |
| `SANGO.IDX` | 38 KB | 19,000 个 u16 的字形索引表 | — |

**关键设计**：`MAGIC.INI` 里每条技能只有 `SEQUENCE/NAME/TITLE/POWER/Attack/Script/Attrib/Active` 这 8 个字段——**技能的实际效果不在这张表里，而在 `Script` 指向的 `.SO` 字节码里**。也就是说：

> 技能 = 声明式元数据（数值/耗蓝/属性）+ 命令式脚本（特技演出与特殊效果）。

这是这套引擎最"现代"的地方，也是**新项目最值得继承的架构**（见 08 文档）。

`MagicDef` 结构（实测内存布局，`pack(1)`；`04b` 用访问器族 `0x40A322`–`0x40A46F` 逐字段复核，stride 实测 **0x16 = 22 B**、全局基址 `0x4A61A0`、最多 128 项）：

```c
struct MagicDef {          // 22 字节
    char*  name;           // +0x00
    char*  title;          // +0x04
    u16    mp;             // +0x08  技力消耗（原以为是 sequence，04b 已更正）
    u16    power;          // +0x0A  能量(氣力)消耗权重 = power×1200，满条 60000
    u16    attack;         // +0x0C  攻击力 → 施放时写入全局 0x4A6888 供特效读
    u16    attrib;         // +0x0E  位域（目标/属性）
    u16    active;         // +0x10  位域（触发方式）
    u32    script;         // +0x12  指向 .SO 的偏移
};
```

> `SEQUENCE` 只是 `MAGIC.INI` 的**查找键**（1–110 / 501–610），不是结构字段。

`WiseDef`（军师技）另有 `ATTRIB/ACTIVE/Rate/Execute/WiseLevel` 五个字段，通过 `0x40A50F`(建) / `0x40A550` / `0x40A593` / `0x40A5D6` / `0x40A619` / `0x40A65C` 六个 setter 写入——**这组 setter 是"字段→取值语义"的最佳切入点**。

全局表：`0x4A64D0`（MagicDef 数组）、`0x4A64D4`（WiseDef 数组）、`0x4A64D8`（已分配数），单块 `0x4000`，扩容失败报 `MsgReallocateMemory : resize fail !!`，遍历上限 `0x3E8`(1000)。

### 7.1 `SANGO.INI` 其实是一个"大杂烩"配置：98 段 = 5 种段

一开始按段名前缀以为它是"98 个字体段"，实测拆开是 **5 种完全不同的段**（脚本 `F:\sanguo\work\sango_secs.py`）：

| 段名 | 数量 | 内容 |
|---|---:|---|
| `[SYSTEM]` | 1 | `TotalTimes=6`、`TotalGeneralType=3`、`TotalThings=99`、`TotalForce=11`、`FontDirectory=FONTS\`、`DefaultFont=1`、`Times01..05 = Times1.INI, 黃巾之亂 / 討伐董卓 / 群雄割劇 / 赤壁之戰 / 三國鼎立` |
| `[TERRAIN]` | 12 | **12 种战场**（见下） |
| `[SCRIPT]` | 1 | `File = script\system.so`、`File = script\magic.so`——脚本全局注册表 |
| `[ITEM]` | 77 | **物品表**（与宝典 Excel 的 77 行物品一一对应） |
| `[FONTS]` | 7 | 7 套字体（中文点阵源/宽高/字节数/英文点阵源） |

> 注：`TotalTimes=6` 但包里只有 `TIMES1-5.INI` 五个剧本——**多出来的第 6 个剧本位是空的**，可能是被砍掉的剧本或留给 MOD 的位置。这是"用计数驱动遍历"的典型坑：读第 6 个会失败，引擎必须容错。

**12 种战场（`[TERRAIN]`）**：每段用 4 组图层拼出一个可滚动的战场背景，`SoundTrack` 还决定该地形放哪首 BGM（只有 4/5/6 三首）：

> `Floor` 是 **512×512 的无缝平铺地面贴图**（标准 TGA、RGB555），不是整屏背景——战斗时按滚动坐标循环取样；`FG/MG/BG` 各两层（A/B）是视差层。缩略拼版见 `F:\sanguo\docs\img\terrains_12.png`。

| # | Name | 层文件 | BGM |
|---:|---|---|---:|
| 0 | 城 | `FLOOR00.TGA` + `BG\FG00A/B.SHP` + `MG00A/B` + `BG00A/B` | 6 |
| 1 | 城 | `FLOOR01.TGA` + `FG01A/B` + `MG01A/B` + `BG01A/B` | 5 |
| 2 | 城 | `FLOOR02.TGA` + `FG02A/B` + `MG02A/B` + `BG02A/B` | 4 |

**77 件物品（`[ITEM]`）**字段：`Sequence / Name / Attrib / TYPE / WeaponType / WeaponObject / SearchType / Sort / Level / Sprite / Rate / STR / INT / MaxHP / MaxMP / Force / Battle / Skill / Speed / HP / MP / Spirit / Loyal / Tire / Description`。
关键样本（证明字段语义）：朴刀兵兵符 `Sort=51, Force=1, Sprite=JEWEL\BOOK01, Description=可使用朴刀兵`；長槍兵兵符 `Force=2/Sort=52`；大刀兵兵符 `Force=4/Sort=53`；弓箭兵兵符 `Force=8/Sort=54` → **`Force` 字段就是兵种编号**（1/2/4/8 是位标志，不是序号）。

## 8. 脚本引擎（Smart Script）

- 两个脚本文件：`SCRIPT\MAGIC.SO`（259 KB，全部武将技）、`SCRIPT\SYSTEM.SO`（21 KB，系统/剧情），另有 `SYSTEM.SO.OLD`（原版备份，可用于对比修正版改了什么）。
- 格式：`"Smart Script"` 头 + 版本 `0x100` + 代码起点 `0x40`，之后是 **DWORD 记号流**（操作码/操作数），含负数记号（相对跳转）。
- 预处理：支持 `define` / `include`（EXE 里有 `"sload script"`、`"Can't open script %d"`、`"Can't find Script file : %s."`）。
- 与 C 代码的接口是 **SYSCALL 号**：修正版说明提到 `0x213-0x219` 用于读内存、`0x119` 召唤伏兵高级兵——说明**整个游戏的能力（改属性、召兵、放特效）都通过 syscall 暴露给脚本**。
- 细节见 [04d_AI与脚本引擎.md](04d_AI与脚本引擎.md)。

## 9. 运行模式与调试开关

命令行（0x4870D8 起，WinMain 里解析）：`-VER -AUTO -AUTODEMO -ONCE -BATTLE -SPEED -MAPMODE -AIOFF -INFO -FULLSCREEN -WINDOW -SOUND -MOVIE -SOUNDOFF -MOVIEOFF -DIRECT_ON -DIRECT_OFF -VFW`

- `-BATTLE`：直接进战斗（**做数值实验的入口**）。
- `-AIOFF`：关 AI（**用来分离"规则"与"AI"的黄金开关**）。
- `-AUTO/-AUTODEMO/-ONCE`：自动演示/跑一次（可做无头回归）。
- `-MAPMODE/-INFO/-VER`：调试显示。
- 另有隐藏串 `cheat`、`player`，以及 `ACT=%s`、`ARate=%d`、`FPS=%d`、`X=%d Y=%d`、`%s Terrain=%d`、`Ax=%d y=%d Angle=%d` 等调试输出。

注册表：`HKCU\Software\ODINSOFT\Sango2\Settings` → `Status`(窗口/全屏) / `SoundVolume` / `MusicVolume` / `Effect`。

## 10. 存档

- 目录 `SAVES\`，函数 `0x43207C`（851 B，存/读档同一入口）。
- 另有临时文件 `"\%sPAK%05d.TMP"`（打包临时文件，重打包时用）。
- 存档格式见 [07_存档格式.md](07_存档格式.md)。本仓库的 `SAVES\` 是空的（发行包未带存档），因此存档格式只能从代码反推——**这也是最值得用"跑一遍游戏存个档"来验证的一项**。
