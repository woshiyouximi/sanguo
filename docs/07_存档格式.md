# 三国群英传2 存档格式（SAVES/SANGOxx.SAV）

> 对象：`Sango2.exe`（682,496 B，PE32/MSVC6，ImageBase `0x400000`）
> **文件偏移换算**：`文件偏移 = VA − 0x400000 − 0x1000 + 0x400`（`.text` RVA 0x1000 / raw 0x400）
> 证据约定：`VA=0x...`、`文件偏移=0x...`、引用字符串（cp950 繁中）。
> 存档目录：游戏目录下 `SAVES\`（实测本机安装为 `…\三国群英传2 修正版 1.05+\SAVES\`，**为空目录**，故本文全部由代码逆出，未做字节级取样比对）。

---

## 1. 文件名规则与槽位

| 项 | 值 | 证据 |
|---|---|---|
| 目录 | `SAVES` | `0x455C67("SAVES")`（切当前目录），xref 在 `0x43207C` 内 |
| 文件名模板 | **`SAVES\SANGO%02d.SAV`** | 字符串 `0x48D8xx "SAVES\\SANGO%02d.SAV"`；生成代码 `0x433D1C`(281 B)、`0x433E68`(64 B)、`0x433EA8`(72 B) |
| 槽号 | 2 位十进制（`%02d`） | 同上 |
| 存档槽描述串 | **`0x48D840 "%-6s 城數%02d 武將%03d 時間%3d年"`**（xref `0x43212A`） | 用头部缓存的统计量填写（`城數`/`武將`/`時間`） |

`%02d` 的上界（最多几个槽）**未定位**——模板串只给宽度，槽号来自调用参数，未在 `0x433D1C` 一带看到范围校验。

## 2. 全局缓冲与"游标"模型

写档时**先把整个存档在内存里拼好，再一次性写盘**：

| 全局 | 含义 | 证据 |
|---|---|---|
| `0x4BD224` | 存档缓冲区基址（`malloc(0x36710)` = **223,248 B**） | `0x43207C` 开头 |
| `0x4BD268` | **头部起点**（= `0x4BD224`） | `0x4320xx: mov [0x4BD268], eax` |
| `0x4BD274` | **累计长度游标**（初值 `0x1D0`，每段写完后 `+= 段长`） | 七个段函数入口都读它、出口都写它 |
| `0x4BD218` | 段1 记录基址 | `0x4308D0: mov [0x4BD218], [0x4BD224]+[0x4BD274]` |
| `0x4BD270` | 段2 记录基址 | `0x430BD5` |
| `0x4BD26C` | 段3 记录基址 | `0x4310F3` |
| `0x4BD220` | 段5 记录基址 | `0x431E4E` |
| `0x4BD21C` | 段6 记录基址 | `0x431F6D` |

`[0x4BD274]` 初值 **`0x1D0` = 464**（头部长度），即文件第一段永远是 464 字节的头。

**段函数的统一模板**（七段完全一致，可作为格式识别的钥匙）：

```
[0x4BD268]->[base_field] = [0x4BD274];                    // 本段在文件中的起始偏移
[0x4BD2xx]              = [0x4BD224] + [0x4BD274];        // 本段在内存中的写入基址
... 逐条填记录 ...
[0x4BD268]->[count_field] = 记录条数;
[0x4BD274] += 条数 × stride;                              // 游标前移
```

⇒ **头部里 `count` 与 `base` 成对出现，且 `count_field = base_field − 4`。** 这一条规律在七段上都成立（见 §4 表）。

| `+0x04` | u32 | **版本 `0x00020000`（2.0）** | `0x4320xx` |

| `+0x1A0` | i32 | `0x4387C2(0x438880())` | 同上 |

## 4. 七个数据段

七段的序列化函数按地址顺序依次调用（`0x43207C` 内的 7 个 `call`，地址升序）：

| 段 | 序列化函数 | 函数大小 | 记录 stride | count 字段 | base 字段 | 对象 | 识别证据 |
|---|---|---|---|---|---|---|---|
| 1 | `0x4308B0` | 770 B | **0x352 (850)** | `+0x68` | `+0x6C` | **势力 / 君主（King）** | 唯一调用 `0x40945B(i)`（King 池取节点）；内存 King 记录 0x34A + 8 B 对齐 = 0x352 |
| 2 | `0x430BB2` | 1310 B | **0xB2 (178)** | `+0x7C` | `+0x80` | **城池（City）** | 调 `0x405336`（城池池代码区）；内存 City 记录 0xAA + 8 = 0xB2 |
| 3 | `0x4310D0` | 902 B | **0x70 (112)** | `+0x190` | `+0x194` | **第三类对象（0x4388xx 池）** —— 候选：出阵部队/兵团 | 调 `0x43884C`、`0x4387C2`（该池唯一） |
| 4 | `0x431456` | **2517 B**（最大） | **0x11F (287)** | `+0x1A4` | `+0x1A8` | **武将（General）** | 调 `0x406A75`、`0x46DC60`(strcpy，名字)；内存武将记录 0xF7 + 扩展 = 0x11F |
| 5 | `0x431E2B` | 287 B | **0x18 (24)** | `+0x1B8` | `+0x1BC` | **地图/格子状态类** | 调 `0x422DAB`、`0x422DCA`、`0x422E52`（0x422Dxx 地图辅助区） |
| 6 | `0x431F4A` | 182 B | **8** | `+0x1C0` | `+0x1C4` | **地图/格子状态类 2**（每项 2 个 dword） | 出口 `lea eax,[edx+ecx*8]`；调 `0x422E1D`、`0x422E3B` |
| 7 | `0x432000` | 124 B | — | `+0x1C8`（**固定 0x80**） | `+0x1CC` | **全局固定块 128 B** | 出口 `[eax+0x1C8]=0x80` + `[0x4BD274]+=0x80`；调 `0x408EC3` |

调用证据（`0x43207C` 内 7 个 call 的目标）：`0x4308B0`、`0x430BB2`、`0x4310D0`、`0x431456`、`0x431E2B`、`0x431F4A`、`0x432000` —— 各 1 次。

### 文件整体布局

```
偏移 0x00000                头部 0x1D0 (464 B)          ← 魔数 "SSAV" / 版本 2.0 / 时间 / 玩家 / 段目录
偏移 0x001D0                段1  势力  count1 × 0x352
偏移 0x001D0 + c1*0x352     段2  城池  count2 × 0xB2     （c1 实测 = 32 ⇒ 段2 起始 = 0x6C10）
                            段3  第三类 count3 × 0x70
                            段4  武将  count4 × 0x11F
                            段5  地图  count5 × 0x18
                            段6  地图2 count6 × 0x8
                            段7  固定 0x80
```

写盘：**单次 `write`**（`0x455AB2(handle, buf, [0x4BD274])`，`0x43207C` 内只出现一次），随后 `0x455A36` 关闭。
缓冲区上限 `0x36710` = 223,248 B；按 32 势力 + 64 城 + 512 武将估算实际约 190–210 KB。

### 段1 记录内部（唯一已读到字段级的一段）

`0x4308B0` 循环 32 次（`[ebp-8] = 0x20`），每条记录：

| 记录内偏移 | 类型 | 含义 | 证据 |
|---|---|---|---|
| `+0x00` | u32 | **恒为 `0x352`**（自描述记录长度） | `0x4308xx` 写常量 |
| `+0x04`–`+0x0F` | 12 B | `memcpy` 自 King 节点 `0..0xC`（前 3 个 dword） | `call 0x46DF10`（memcpy） |
| `+0x10` | u32 | `0x406A75(King->[+0x10])` —— 名字/索引转换结果 | `0x4309xx call 0x406A75` |
| `+0x14` | u32 | 0（保留） | — |
| `+0x18` | u32 | 0（保留） | — |
| `+0x1C` | u32 | `0x406A75(King->[+0x1C])` | — |

（对应读档侧 `0x4323CF` 的逆操作：`memcpy(King, base+i*0x352+4, 0xC)`、`King->[+0xC] = 0x406A75(base+i*0x352+0x10)`、`King->[+0x10]=0`、`[+0x14]=0`、`[+0x18]=0x406A75(base+i*0x352+0x1C)`、`[+0x1C..+0x28] = base+i*0x352+0x20..0x2C`。）

⇒ 记录里存的是**指针的"序号化"形式**（`0x406A75` 把内存指针转成可持久化的编号，读档时反向解析），这是存档能跨进程重载的关键设计。

段2/3/4 的记录内部布局**未逐字段还原**（每段分别有 1310/902/2517 字节的存取代码，工作量远大于本文范围）。已知段4 会用 `0x46DC60`（strcpy）写武将名字符串，说明**武将名以文本形式存在于段4 记录内**，而势力/城池名是否同样内联**未定位**。

## 5. 读档路径

| 步骤 | 代码 | 说明 |
|---|---|---|
| 打开/读入 | `0x455A10`（open）、`0x455A5F`(read 类) | 读满 `[0x4BD274]` 长度到 `0x4BD224` 缓冲区 |
| 段1 回填 | **`0x4323CF`** | `count=[hdr+0x68]`；`base=[0x4BD218]=[0x4BD224]+[hdr+0x6C]`；`for i<count { rec = 0x40945B(i); memcpy(rec, base+i*0x352+4, 0xC); … }` |
| 时间回填 | `0x433AA6` | 从 `+0x30`（月内倒计时）、`+0x58`（年）、`+0x5C`（月）、`+0x5E`（年进位）恢复 |
| 玩家回填 | `0x4329xx` 一带 | `+0x50/+0x54` 经 `0x409430` 反向变换回 `[0x4A64F0]`/`[0x4A64F4]` |
| 段2..7 回填 | 未逐个定位 | 结构应对称（段函数附近存在对应的反向函数） |

`0x409430` / `0x406A75` / `0x40530B` 是**双向变换函数**（指针↔序号），写档时正向、读档时反向，因此它们是理解整份存档的钥匙。

| 类别 | 是否入档 | 证据 |
|---|---|---|
| 全局状态（时间） | ✔ 年 `+0x58`、月 `+0x5C`、年进位 `+0x5E`、月内倒计时 `+0x30`、`+0x60/+0x64` | 头字段 |
| 全局状态（玩家） | ✔ 玩家势力 `+0x50`、玩家君主 `+0x54` | 头字段 |

| 事件标志 | **未定位**（既不在头（保留区全 0），也未见独立段；候选：段7 的 128 B 或段5 的格子状态位） | — |
| 已加载脚本/`.SO` 状态 | ✘ 不入档（`0x4A6498`/`0x4C2C20` 脚本表不在头部字段中） | — |

## 7. 未定位清单

1. `%02d` 槽号上界（最多几个存档位）。
2. 头部 `+0x08`、`+0x60`、`+0x64`、`+0x4C` 的确切语义。
3. 四类对象"三项统计量"（`+0x70..+0x78` 等）各自的定义。
4. 段2（城池，0xB2）与段4（武将，0x11F）的**逐字段布局**（本文只给出 stride、count/base 位置与数据来源）。
5. 段3 对象的身份（0x4388xx 池是什么）。候选：地图上的"出阵部队/兵团"（字符串有 `出陣中!!`、`部隊徵兵`、`請選擇兵團目的城市`）。
6. 段5/段6 的格子坐标编码方式。
7. 段7 那 128 字节的内容。
8. 读档侧段2..7 的反向函数地址（未逐个定位）。
9. **文件级取样验证**：本机 `SAVES\` 为空，全部结论来自写档代码，未与真实 `.SAV` 字节比对。

## 8. 复现建议（最小验证方案）

1. 启动游戏，新建一个剧本存档，退出到大地图后存盘 → `SAVES\SANGO00.SAV` 生成。
2. 用 `xxd`/Python 检查：`+0x00` 必须是 `53 53 41 56`，`+0x04` 必须是 `00 00 02 00`（小端 0x20000）。
3. 读 `+0x1D0`（= 段1 起点）起 `0x352` 字节，首 dword 应为 `52 03 00 00`（0x352，自描述长度）。
4. 读 `+0x68`（段1 条数）应为 32；`+0x6C` 应为 `0x1D0`。
5. 读 `+0x7C`（段2 条数）应等于该剧本的 `TotalCity`（TIMES1.INI 为 64）；`+0x80` 应等于 `0x1D0 + 32*0x352 = 0x6C10`。
6. 改 `+0x58`（年）为 +1，重新进游戏读档，看 HUD `時間 %d年`（`0x48B100`，读 `0x4BD390`）是否变化 —— 这是验证头部时间字段最直接的方法。
