## 1 体检方法（本机没有 python / ffmpeg，三层全部自造互校）

先探测工具链，结论是**一个都没有**：

```
python  --version   → "Python was not found"（只有 Microsoft Store 的占位 exe）
python3 / py / conda、ffmpeg、ffprobe → 均不存在
game/node_modules 里 → 无 mutagen/music-metadata/fluent-ffmpeg 之类
```

所以做了三层，互相校验（单靠任何一层都不够）：

| 层 | 工具 | 能回答什么 | 局限 |
|---|---|---|---|
| **A 静态帧解析** | `work/audio_check/static_scan.mjs`（纯 Node 手写 MPEG-1/2/2.5 Layer III 帧头走帧） | 帧数、时长、码率、采样率、声道、是否失步、尾部残字节、ID3v2 跳过、每帧 payload 的 0x00 占比（静音代理） | 不解码，判不了响度与内容对错 |
| **B 浏览器真解码** | `work/audio_check/decode_probe.mjs`（CDP 驱动 headless Edge，页面里 `fetch + decodeAudioData`） | 解码成功与否、PCM 时长、RMS/峰值/削波、最长静音段、首尾静音 | 慢；Edge 对 mp3 的容错比规范宽 |
| **C 原作 WAV 真值** | `work/audio_check/wav_check.mjs`（解析 `extract/pak/SOUND/*.WAV` 的 RIFF `fmt `/`data`） | 原作曲长/响度/格式、重复组、逐对时长差 | 原作是 8/16-bit PCM，不能与 MP3 逐样点比 |

**A 层踩过的坑（写下来免得后人重犯）**：

1. layerIdx→比特率表下标用错 → 109 个全部误报"第 2 帧失步"；
2. MPEG-2/2.5 的单声道帧长系数应是 **72**（1152/2 样本）而不是 144 → 否则 22.05 kHz 的 99 个 sfx 全失步；
3. `(h & 0xffe00000) !== 0xffe00000` 在 JS 里**恒真**（`&` 结果转 int32 是负数），要写 `(h >>> 21) !== 0x7ff`；
4. 原作 17 首 mp3 头上有 **11 字节非 MPEG 前缀**（`00 06 00 00 00 ce b4 d6 aa 00` 后才见 `ff fb`），走帧要按字节跳而不是直接读偏移 0。

**复现命令**（都在 `F:\sanguo`）：

```powershell
node work\audio_check\static_scan.mjs      # → static.json      （帧级体检）
node work\audio_check\decode_probe.mjs     # → decoded.json     （Edge 真解码，需自己先起 Edge）
node work\audio_check\wav_check.mjs        # → wav_vs_mp3.json  （原作 WAV 真值）
node work\audio_check\build_csv.mjs        # → files.csv        （109 行汇总表）
node work\audio_check\magic_snd.mjs        # → magic_snd.json   （技能音 CALL 图可达性）
node work\audio_check/orig_bgm.mjs         # → orig_bgm.json    （原作 17 首 mp3）
node work\audio_check/build_map_table.mjs  # → map_table.md     （映射对表，现读现算）
```

## 3 重复 / 静音 / 异常清单

### 3.1 重复档：6 组 13 档

按整文件 sha256：

| 组 | 成员 | 时长 | 说明 |
|---|---|---|---|
| 1 | `att08` = `m003snd03` | 0.235 s | 原作同一段波形，两个用途（攻击命中 + 技能音） |
| 2 | `m001snd01` = `m009snd01` = `m018snd03` | 1.750 s | 三档同波形 |
| 3 | `m005snd03` = `m005snd05` | 1.515 s | **同一个目录内的重复** |
| 4 | `m017snd01` = `m023snd01` | 3.866 s | 两档同为 −39 dBFS（最安静的活音效） |
| 5 | `m018snd01` = `m018snd02` | 4.807 s | 同目录内重复 |
| 6 | `m036snd02` = `m038snd01` | 0.601 s | 跨目录重复 |

**证明这不是转码事故**：拿原作 `extract/pak/SOUND/*.WAV` 按 `fmt` 块 + PCM 数据一起 sha256，重复组**恰好也是这 6 组，成员完全一致**。也就是说原作素材本身就是复用的（三国群英传2 的 SOUND 目录里同一段声音挂在多个编号下），转码链忠实地保留了它。

| 文件 | 时长 | RMS | 判定 |
|---|---|---|---|
| `sfx/silence.mp3` | 0.157 s | −999 dBFS（整段 0） | **占位音**（1881 B，190 帧全 0）。`audio.js` 里没有调用点，`index.json` 里正常登记 |

### 3.3 时长 <0.3 s 的 8 档（逐个核到原作，全是"本来就短"）

| 文件 | MP3 时长 | 原作 WAV | WAV 格式 | 差 | 判定 |
|---|---|---|---|---|---|
| `arrow` | 0.157 | 0.098 | 16bit/22050/2ch | +59.2 ms | 编码器起止 padding（2–3 帧），正常 |
| `att03` | 0.157 | 0.081 | 16bit/44100/2ch | +76.2 ms | 同上 |
| `att04` | 0.235 | 0.157 | 16bit/22050/1ch | +78.3 ms | 同上（本组最大差） |
| `att07` | 0.287 | 0.221 | 16bit/22050/1ch | +66.4 ms | 同上 |
| `att08` | 0.235 | 0.161 | 16bit/22050/2ch | +74.0 ms | 同上 + 与 `m003snd03` 重复 |
| `m003snd03` | 0.235 | 0.161 | 16bit/22050/2ch | +74.0 ms | 同上 |
| `m041snd01` | 0.261 | 0.185 | 8bit/11025/1ch | +76.1 ms | 同上（原作是 8-bit 低频段素材） |
| `silence` | 0.157 | 0.100 | 8bit/11025/1ch | +56.8 ms | 占位音（两边都是静音，差 56.8 ms） |

99 对 MP3↔WAV 的时长差全部落在 **[52.2, 78.3] ms**（中位 66.2 ms），正好是 **2–3 个 Layer III 帧的编码器起止 padding**（每帧 26.12 ms：22.05 kHz 的 MPEG-2 是 576 样本/帧、44.1 kHz 的 MPEG-1 是 1152 样本/帧，都是 26.12 ms）；**|差| > 90 ms 的 0 个** → 没有截断、没有采样率搞错、内容长度全对。

### 3.4 一个差点误判的假警报（记下来）

`att03.WAV` 的 PCM 数据与 `att08.WAV`/`m003snd03.WAV` **逐字节相同**，但 `att03` 的头是 `44100/16/2ch`、另两个是 `22050/16/2ch` —— 同一段波形按不同采样率解释，播放速度差 2×。MP3 侧 `att03`=0.157 s、`att08`=0.235 s，都等于"自己的 WAV 时长 + 各自的编码 padding（56.8 / 74.0 ms）"。**结论：转换按各文件头里的采样率正确重采样了，原作的变调怪癖被忠实保留**，不是内容错。

### 3.5 响度损失（不是损坏，但要交代）

99 对里 RMS 差（MP3 − WAV）：中位 **−0.80 dB**、p10 −2.00、p90 −0.50。**>3 dB 的只有 4 个**：

| 文件 | 差 | 实测原因 |
|---|---|---|
| `horse02` | −8.8 dB | 原作是 11025 立体声且**左右反相**（相关系数 **−0.765**；L −24.0 / R −19.0 / 单声道和 −28.5 dBFS）→ 单声道化必然抵消 9.5 dB |
| `m035snd01` | −4.7 dB | 立体声且**几乎不相关**（corr **−0.079**）→ 单声道化损失 3.6 dB |
| `att03` | −3.4 dB | 44100→22050 重采样，80 ms 的瞬态击打高频被切 `[推测]`（依据：仅这一档同时满足"短瞬态 + 44.1k 源 + 22.05k 成品"） |
| `arrow` | −3.1 dB | 左右声道电平差 6 dB（L −25.8 / R −19.7，corr 0.993）→ 混单后落在中间值 |

其余立体声文件 corr 0.44–0.998，损失 ≤2.5 dB。**这些都是"合成立体声→单声道"的正常损失，不是文件坏**；判"内容对不对"用的是时长对齐 + 重复组 + 帧对齐三条硬指标，全对。

### 3.6 结论

**109 档没有 1 个真损坏**。要修的不是文件，而是映射（第 4 章）。

### 4.2 战场底噪：旧表 12 个地形里 10 个错，已按字节码改

真值来自 `export/script/system_so.dis.txt:1058` 起 func #19 `LoadingBattleMap`（id=0x32 argc=1 @0x1D54），`LDSL arg1` 后 12 路 `CASE`：

|---|---|---|

| 3 | `PUSHS "BG03A"; PUSHI 255; SYSCALL 0x301,0x2` | **bg03a** |
| 4 | 只 `SYSCALL 0x212` + `CALL EnterWar4` | 无 |
| 5 | `PUSHS "BG04A"; PUSHI 255; SYSCALL 0x301` + EnterWar5 | **bg04a** |
| 6 | 无 | 无 |

> 顺带否掉一个"命名巧合"的推理依据：`terrains.json` 的 `Background` 是 `BG\BG03A.SHP`/`BG\BG04A.SHP`…（**每个地形都跟自己的序号同号**）。地形 3/8/9 的底噪名与自己的 BG 名同号，但地形 5 的底噪是 `bg04a` 而 BG 是 `BG05A` → **"同号"只是巧合，不是分桶依据**。

> 另一个孤证：素材里有 `bg07a.mp3`（`assets/audio/sfx/` 与 `extract/pak/SOUND/` 都有），但 `SYSTEM.SO` 的字符串表里只有 `BG03A/BG04A/BG08A/BG09A` 四个（`indexOf('BG07A') = −1`）→ **森林静音是原作行为，`bg07a` 无脚本引用**（`[未解]`：原作可能另有入口，但没有 exe 无法确认）。

var TERRAIN_AMB = ['', '', '', 'bg03a', '', 'bg04a', '', '', 'bg08a', 'bg09a', '', ''];

### 4.4 武将技音效：改 5 条 + 补 1 条

### 6.6 操作踩坑（留给下一轮）

- `Start-Process -PassThru` 拿到的 PID 只是 launcher，`taskkill /PID <launcher> /T /F` **杀不掉真正的浏览器树**（这轮一度残留 32 个 `msedge`）。要按 **CommandLine 匹配 profile 路径**逐个杀：
  `Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" | Where-Object { $_.CommandLine -like "*$profile*" } | ForEach-Object { taskkill /PID $_.ProcessId /T /F }`。
- **同一个 `--user-data-dir` 二次启动会 join 旧实例并忽略新的 `--remote-debugging-port`** → 表现为"调试端口没起来"。每次用带时间戳的独立 profile。
- 带 `--virtual-time-budget` 时页面定时器被虚拟时间接管，**CDP 里的 `await new Promise(setTimeout)` 可能永远不 resolve**；所以 12 地形扫描放在**不带**该参数的 map 页跑，战场页只用同步读取。
