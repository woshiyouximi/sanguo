# 219 · R231 抵達＝戰前準備（隊伍鎖定）＋ 裝備＝庫存

> 兩個實機 bug：「行軍抵達後彈的是『重新派兵』編成屏、我派出的武將不見了」與「裝備給 A 之後還在背包、還能給 B 裝」。兩個都改在 Cocos 正式版，APK **3.9**（versionCode 29）。

## 0. 一句話

抵達敵城／關卡不再走「重新派兵」，改成 **攻城戰前準備**：參戰部隊＝剛到的那支（將／兵／站位全鎖），按「出 戰」直接進戰鬥；裝備改成 **庫存語義**：裝上就離開背包、同一件不能同時掛兩個人。

## 1. 抵達 bug 的三條根因

| # | 位置 | 舊行為 | 後果 |

| A | `CampaignRoot.startArrivalSiege()`（舊 :4410-4436） | `removeArmy(army.id)` 之後只寫 `setDeployMarch({from,target,pathIndex})` | `DeployMarch` 不含主將／隨軍／兵數，Deploy 屏只能回出發城重新組候選池 ⇒ 玩家看到「武將不見了」 |
| B | `DeployRoot.march()`（舊 :1915-1935） | 看到 `peekDeployMarch()` 就 `dispatchMarch(...)` | 造一支**新兵團**（`progress=0`）並**再扣一次城兵** ⇒ 新兵團走到目標又觸發抵達 ⇒ 每次抵達都彈一次、每次多扣兵 |
| C | `CampaignRoot`（舊 :2836-2875，城下已有部隊點城） | 先 `removeArmy` 再判「是否接壤」 | 不接壤時部隊白丟，成功時也沒有部隊快照 ⇒ 同樣進「重新派兵」屏 |

## 2. 修法

- **`GameState.ts`**：新增 `DeploySiege` 內存快照
  `{ from, target, pathIndex, armyId, general, officers, troops, advisor }`
  ＋ `setDeploySiege / peekDeploySiege / clearDeploySiege` ＋ `refundSiegeTroops()`（退回出發城、cap 600，對齊 web `campaign.html:4967-4972 refundArmy`）；`resetCache` 一併清快照。
- **`CampaignRoot.ts`**：抵達改為 `removeArmy → clearDeployMarch → setDeploySiege(snapshot)`；第二入口（城下部隊點城）把「接壤守衛」移到撤隊之前並寫快照；四個進 Deploy 的入口都清另一模式殘留。
- **`DeployRoot.ts`**：新增「攻城戰前準備」模式——
  - 將列／兵數／出陣順序全部來自快照且**鎖定**（換將、兵數滑桿、快捷鍵、存槽全禁，隊列顯示「隨軍」）；
  - 標題「攻 城 編 成」、按鈕 **「出 戰」** → `fight()` 直接 `startBattle({... armyId })`，**不呼叫 `dispatchMarch`**；
  - 「返回大地圖」→ `abandonSiege()`（退款 + 清快照）回大地圖；
  - 勝 → 佔城；敗 → 部隊消耗（沿用 `recordBattleResult`，`armyId` 已不在時 no-op，避免雙刪）。

## 3. 裝備＝庫存

`ItemsPanel.setEquip()` 舊寫法無論裝或卸最後都 `this.bag.add(seq)`，等於裝上去又放回背包；列表按 `bag.has(seq)` 過濾，所以同一件能同時裝給兩個人。

現在：
- **裝上**：先把別的武將身上的同一件解除（`equippedSlot(table, seq)` 命中 → `unequipSlot`）→ 本槽原本那件回背包 → `bag.delete(seq)`；
- **卸下**：`bag.add(seq)`；
- 列表仍只列背包內 → A↔B 切換自動重建。

> 口徑確認：制作人選「背包＝庫存，裝上就不在背包」。web 調試台 `items.html` 的 bag 是「已解鎖目錄」（`unlockAll` 填滿它），語義不同，**未改**。

## 6. 坑

1. **`DeployMarch` 不是部隊快照**：它只有 from/target/pathIndex，任何「用 `peekDeployMarch()` 決定畫面」的路徑都會退回「重新派兵」——新增模式時必須同時寫完整快照。
2. **`dispatchMarch` 會扣兵、會造新兵團**：在「抵達」路徑上再叫它等於每循環多扣一次兵；戰前準備模式只能用 `startBattle`。
3. **`removeArmy` 先落盤**：快照只在內存，若在戰前準備屏殺進程，兵將會丟（見 §7 風險）。
4. **測試 harness 過期會擋人**：`work/cocos_items/panel_headless.mjs` 的 mock 缺 `ui/*` 貼圖且 mock `Color` 沒有 `fromHEX`，本次改動後它跑不起來（與本次無關）；行為改由源碼契約 + 真跑 `GameState` 的 harness 覆蓋。
5. **`edit` 大段替換容易留雙括號**、`Set-Content -NoNewline` 會把整檔粘成一行——改大文件一律用 python 補丁 + `newline='\n'` 寫回，改完跑 `scan_utf8`。

## 7. 剩餘風險 / 待辦
