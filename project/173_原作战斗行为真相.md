## 1. 战斗开始那一刻，命令字默认是多少？在哪初始化？

### 原作事实 `[确认]`

**(a) 命令数组只有一个写入者。** 全 EXE 扫描「目的操作数是 `[reg+0x94]`」的写指令只有 9 条，其中 5 条全在 `0x43ADxx` 这一族里：

```
0043AE26  mov [edx+ecx*4+0x94], eax     ; which==0x100 → 槽 0..7
0043AE5B  mov [eax+edx*4+0x94], ecx     ; which==0x101 → 槽 1..7
0043AE93  mov [ecx+eax*4+0x94], edx     ; which<0      → 全 8 槽
0043AEA7  mov [ecx+eax*4+0x94], edx     ; 0<=which<8   → 单槽
0043AED4  mov [edx+ecx*4+0x94], 0       ; ★0x43AEB2 清零循环
```
`0x43AEB2(army)` 把 8 个槽全写 0，**只有两个调用点**：`0x4430FE`（我方）与 `0x44369C`（敌方），都是"某方 army 的初始化尾段"（前面 `0x406501(...)`/`0x42C049(...)` 取名字串，后面写 `+0x58/+0x5c/+0x60` 兵力字段）。

```
004430FE  push [ebp-0x14] ; call 0x43aeb2
004430xx  [ebp-0x14]+0x60 = [ebp-0x30] ; +0x58 = [ebp-0x10]+[ebp-0x34] ; +0x5c = +0x58
```
⇒ **开场那一刻双方 8 个命令槽全部 = 0（待機）。**

**(b) 单位自己的字段。** 单位槽初始化器 `0x43A1C4`（唯一调用点 `0x44873F`，由战斗单位工厂 `0x4486xx` 逐个槽调用）：

```
0043A27D  mov [edx+0x24], ecx      ; +0x24 = [def+0x12]   ← 命令缓存初值（0）
0043A29B  mov [ecx+0x2c], eax      ; +0x2c = [def+0x38]   ← 状态字（movsx word）
0043A2A1  mov [edx+0x34], 0        ; ★行动倒计时 = 0
0043A2AB  mov [eax+0x38], 0        ; ★攻击锁定剩余 = 0
0043A2B5  mov [ecx+0x3c], 0        ; ★脚本接管标志 = 0
```
敌方同构初始化在 `0x43A36A/0x43A374/0x43A37E`（同一函数内另一条分支）。

**(c) 首帧的行为。** 闸门 `0x43B574`：
```
0043B57A  mov eax,[ebp+8]
0043B57D  mov ecx,[eax+0x34] ; 0043B580 sub ecx,1 ; 0043B586 mov [edx+0x34],ecx
0043B58C  cmp [eax+0x34],0 ; 0043B590 jg 0x43B65D(return 0)
0043B599  mov [ecx+0x34],0
0043B5A3  cmp [edx+0x3c],0 ; jne → vcall 0x1000d（脚本接管）
0043B5DE  mov [ecx+0x34],0x28        ; 复位 40 帧
0043B5F1  and eax,0x4000 ; ... 0043B5FD mov [eax+0x34],0x2e (46) ; 再加 2*(速度差)
```
`+0x34 = 0` → 首帧 `--` 得 −1 → **不开 `jg` → 立刻行动一次**，然后复位 40。
这一帧走的是 cmd 0 → 主将 `0x43C907+0x43C47E`、小队 `0x43C907` = `0x43C4C0(u,0,0,0x48E6A0)`；`0x48E6A0` 两组权重全 0，`0x43C2A5` 的 `mode == -1` 早退填 8 个 (0,0)，`0x43B467` 全部落在自己格 → **一格不走**。

⇒ **"开局不动"是原作行为**（且不是"没行动"，是"行动了但命令是待機"）。

## 3. 谁写命令字？AI 什么时候发 前進/突擊？

### 原作事实 `[确认]`

**(a) 写入者只有 `0x43ADED(army, which, val)`**，34 个调用点全部落在 `0x4447D1–0x445381`，army 实参恒为 `0x4A8A60`（或存它的寄存器）。三条关键命令：

```
0x44497F 全軍前進:  0x43ADED(army, 0, 1)        ; ★只写槽 0（主将），小队不动
                    army->+0x80 |= 2
0x4448B2 全軍突擊:  0x43ADED(army, 0x101, 7)    ; ★只写槽 1..7，主将不动
                    army->+0x80 |= 1 ; army->+0x78 = 0x450410() ; army->+0x64 = 0
                    音效 0x41F740(0, 0x3B) ; [0x4A6664]=1
0x4447B7 全軍撤退:  0x43ADED(army, 0x100, 8)    ; 8 槽全 = 8
                    + 0x4000 状态（军团 + 每个小队，stride 0x48）
```
⇒ **AI 的"进攻"是两条命令的组合**：主将 cmd=1（前進）、小队 cmd=7（突擊）。**没有任何一条 AI 命令**把槽 0 和槽 1..7 写成同一个值。

**(b) AI 的节拍 = 每 60 帧一次。** `0x444385`（唯一调用点 `0x44452A`，在战斗主循环里每帧调一次）：
```
004443E4  if(!([0x4a79c8] & 0x10)) {
004443EB    [0x4b041c]--                 ; = 敌方 army(0x4B03A0)+0x7C
004443FA    if([0x4b041c] <= 0){ 0x402EA5(0x4B03A0); [0x4b041c] = 0x3C; }   ; ★60 帧
0044441A  }
0044441F  if([0x4a79c8] & 0x102) {
00444428    [0x4a8adc]--                 ; = 我方 army(0x4A8A60)+0x7C
00444437    if([0x4a8adc] <= 0){ 0x402EA5(0x4A8A60); [0x4a8adc] = 0x3C; }
0044444D  }
```
两个倒计时变量**除了"递减 / 归零重置 0x3C"没有任何写入点** ⇒ .data 零初始化 ⇒ **入场第一帧就会做一次决策**，之后每 60 帧一次。[`[0x4A79C8]` 的 bit 语义未逐位证明 → `[推测]`]

**(c) `0x402EA5(army)` 是加权随机的"軍令选择器"**（函数体 `0x402EA5–0x403D12`）：
```
0x402FB4  mov [0x4c6bc0], 0x64          ; w0（什么都不做）默认 100，其余 0
0x403C73  push -1 ; push w6..w0
0x403CA3  call 0x4687A0                 ; 加权无放回抽样
0x403CB4  cmp [ebp-0x50], 6 ; ja → 无动作
0x403CBD  jmp [edx*4 + 0x403D13]        ; 7 项跳转表
   case0 什么都不做     case1 0x4027FB    case2 0x4448B2 全軍突擊
   case3 0x402A79       case4 0x44497F 全軍前進   case5 0x44493D 全軍撤退

```
0x4030EC  if(army->+0x5c <= 0) 清 bit1|bit2|bit8      ; 没兵不能突擊/前進
0x40313D  if(bit & 2 && 0x43B6E4(army)==8)  w1 += 0x3C(60)

## 4. 攻击动作播哪几帧、多少帧？与 `+0x34`/`+0x2E` 的关系？

### 原作事实 `[确认]`

**(a) 出手时的动画命令。** 小队 `0x43D378` / 主将 `0x43EBB2` 调 `0x43D0F1(u, dir, flag)`：
```
eax = flag&0xffff ; ecx = (dir&0xffff)<<16 ; eax |= ecx
obj = u->+0x44 ; obj->vcall[0x4c]`(obj, 0x10007, eax)`     ; dir 在高 16 位
```
`0x43E55C`（对象消息处理器）的 `0x10007` 分支在 **`0x43E64F`**：
```
if (arg > 0) obj->+0x2c = 0        ; 朝右
else         obj->+0x2c = 0x800000 ; 朝左
if (0x42233D(obj) != 0x20) 0x421E1B(obj, 4)   ; ★播 4 号动画 = ATTACK
obj->+0x68 = 0
```
`0x421E1B(obj, 4)` 从 `animset->+0x28` 的指针数组取指针，写 `obj->+0x78 = anim; obj->+0x34 = 4; obj->+0x54 = anim->+4`（帧数）。

**(b) 帧数在数据里。** `project/48_武将小人装配.md:59` + `:158`：MAJOR/BODY 的 `Attack` = **10 帧**，每帧停留 `h=[3,3,3,3,3,3,3,3,3,3]`（3 tick/帧）⇒ **Attack 一次占 30 tick**；`Wait` = 6 步 `h=[16,8,8,16,8,8]`（循环）。

**(c) 出手冷却与 `+0x34`/`+0x2E` 的关系。** 三个字段是**三件事**，别混：
| 字段 | 含义 | 谁写 |
|---|---|---|
| `u+0x34` | 行动闸门倒计时（40，撤退态 46） | `0x43B5DE` / `0x43B5FD` |
| `u+0x38` | **攻击锁定**（跳过之后 N 个行动周期的探敌） | `0x43D314`（表 1..3）/ `0x43EBA7`（恒 1） |
| `u+0x2c` | 状态字（`0x4000` 撤退、`0x1/0x4` 分类位等） | 多处 |
出手帧数表 `0x4862BC + 0x1C`，`0x406717(mask, cls, variant)` 查 13 条记录（本轮实测值：只有 `3/2/3/2`、`1/1/2/1`、`2/1/2/1`、`3/2/1/1`、其余全 `1/1/1/1`）。
`0x43BCA7` 开头 `if (--u->+0x38 > 0) return 0;` ⇒ **每个行动周期只减 1**，所以 `+0x38 = N` 表示「本次出手后，接下来 N 个周期内探不到敌人（= 照常走位）」。主将恒 1 ⇒ 每个周期都能出手；小队 1..3 视兵种。

**(d) 出手窗口占比。** 消息在出手那一 tick 发出、动画同 tick 起播（`[确认]`）。Attack 的 10 帧按 `project/48:158` 的 `h=[3,3,3,3,3,3,3,3,3,3]` 折算 = **30 tick**（"`h` = 每帧停留 tick 数"这一步是 `[推测]`，见 §存疑 2）。若成立：一个行动周期 40 tick ⇒ **出手动作占 75%**，其余 10 tick 是 Wait 的首帧。

### 证据文件
`work\orig_battle_behavior\08_msg_10007_handler.txt`、`05_anim_len_406717.txt`、`07_anim_table_4862D8.txt`

### 我们现在
- 主将：`game/src/view/generalAtlas.ts:289` `const attack = !dead && u.cd <= swingWindowOf(u) && u.cd > 0;`，`swingWindowOf`（:247）= `floor(间隔*0.25)` = **10 tick**。

## 8. 战斗 pacing：开局到接敌多少帧？

### 原作事实 `[确认]`（数据来自表格，算式自推）

**基本参数**：一格 96×72 px（`0x43A4E0`）；**一个行动周期 40 帧走一格**（`0x43B5DE` 复位 40）；战场 71×14（`0x43AF54`）。

# §10 R178 复核：主将速度 / 开局命令 / 同排扫描

> 触发：`project/176` §8 的录像逐帧复核——原作主将连续滑动、47 帧均值 5.59 px/帧，换算 1.75 格/s；士兵 0.92 格/s；比值 1.90×（另一套标定 1.40×）。我们实现里两者同速。下面只回答问题本身，**不改任何代码**。

## 10.1 主将的行动闸门与小队是否不同？——**相同，40 帧，且没有 2 格步进** `[确认]`

**(a) 同一个函数，同一对常量。** 全 EXE 只有一处"每帧 −1、归零开闸"的代码，就是 `0x43B574`；它的调用点只有两个：

| 调用点 | 所属帧 | 单位 |
|---|---|---|
| `0x43D24B` | `0x43D125` | 士兵小队 |
| `0x43EB50` | `0x43E964` | 主将 |

所以主将和小队走的是**同一个闸门函数**，不存在"主将专用间隔"：

```
0043B58C  83 78 34 00              cmp  dword [eax+0x34], 0
0043B590  0F 8F C7 00 00 00        jg   0x43b65d            ; >0 → return 0（本帧不动）
0043B599  C7 41 34 00 00 00 00     mov  dword [ecx+0x34], 0
0043B5DE  C7 41 34 28 00 00 00     mov  dword [ecx+0x34], 0x28   ; ★40，两处共用
0043B5FD  C7 40 34 2E 00 00 00     mov  dword [eax+0x34], 0x2e   ; 撤退态(0x4000)→46
```

**(b) `+0x34` 的全部写入点（0x43A000–0x446000 扫描）里没有"按兵种/按主将"的常数**：

| 地址 | 值 | 含义 |
|---|---|---|
| `0x43A2A1` / `0x43A36A` | `0` | 单位出生（我方/敌方），`C7 42 34 00 00 00 00` |
| `0x43B599` | `0` | 闸门归零 |
| `0x43B5DE` | `0x28`(40) | 闸门复位（两处共用） |
| `0x43B5FD` | `0x2E`(46) | 撤退态复位 |
| `0x43ACF3` / `0x43AD31` / `0x43AD9E` / `0x43ADDC` | `+0x34 += arg + +0x3c − 0x270F` | **全军统一平移**计时器（两军都遍历，不区分兵种），`+0x3c` 同帧清零 |
| `0x443725` | `0x14`(20) | 特殊进场（同时 `+0x3c=0`、`0x43B51E(u,1)` 置状态位 1、`[0x4A8A44]=0x80`），不是常规节奏 |
| `0x43DFEE` | `4` | **对象**结构（`obj+0x34`=动画 id），不是 unit |
| `0x43B586` / `0x43B653` | 寄存器 | 闸门自身递减/位移补偿 |

⇒ 反汇编层面**没有任何"主将 34 帧 / 骑兵更快"的写法**。

**(c) 没有"一次走 2 格"。** `0x43BF26`（落位）只有两个调用点 `0x43C567` / `0x43C65A`，是走位器 `0x43C4C0` 的 phase1/phase2 各一次（**同一 tick 至多命中一次**，命中即 `ret`）；落点写死逻辑格：

```
0043BFA5  8B 4D 08 8B 55 0C 89 51 08   mov edx,[ebp+0xc] ; mov [ecx+8], edx   ; u+8  = gx
0043BFAE  8B 45 08 8B 4D 10 89 48 0C   mov eax,[ebp+8]   ; mov [eax+0xc], ecx ; u+0xc = gy
```

没有乘 2、没有循环、没有 `+8 ± 2`。

**(d) 滑行时长也写死 40，且不区分单位。** `0x43BF5F push 0x28` 就是 `0x43BE42(u,gx,gy,dur,jitter)` 的 `dur`；`0x43BEF9 idiv dword [ebp+0x14]` 证明第 4 参是**除数**（`v = Δpx / dur`）。另一个滑行器 `0x43C084`（没走成→滑回格心）除数恒 40；`0x43D968` 用 `push [u+0x34]`（剩余帧）作除数、`0x43DCBD` 用 `push 0x50`(80) 作除数——**都是撤退/离场路径**，不是常规移动。

**(e) 算术对照（给录像标定用）。** 一格 = `0x60`×`0x48` = **96×72 世界 px**，滑行 40 帧 ⇒ **恒速 2.4 世界 px/帧**（主将、士兵同）。所以"主将连续滑动、格与格之间零停顿"本身是对的（每 40 帧一格、滑动占满整个周期），但**屏幕上每格不是 96 px**。设游戏 60 fps、录像 30 fps（每个视频帧 = 2 个游戏帧）、屏幕格宽 W：预期 px/视频帧 = `2.4 × 2 × W/96`。代入实测 5.59 ⇒ **W ≈ 112 px**（若按 W=96 只有 4.8 px/帧，比实测低 14%）。
同一套标定下士兵 2.93 px/视频帧 ⇒ 每格 `112 / (2.93/2) ≈ 76 游戏帧 ≈ 1.9 × 40`，即**士兵平均每两个行动周期才真的挪一格**，另一半周期是"抽到的格子全不可入 / 让位失败 / 攻击帧"。`[推测]`，但它与"闸门相同"并不矛盾：**主将慢在"走"，士兵慢在"空转"**。
→ 要在我们实现里复刻这个 1.9×，正确做法不是给主将加速度倍率，而是确认"落点全被占"时我们是否也**整周期空转**（我们 `chooseStepCell` 失败时 `cd` 已重置，理论上同频；但 `yieldFriend` 是我们的加强版，可能把本该空转的周期变成了一次成功移动）。

## 10.2 开局 8 槽清 0 之后，第 1 帧到第一次 AI 决策之间谁写槽？——**玩家方没人写（真待機），AI 方第 1 帧就可能写** `[确认]`

**(a) 清槽**：`0x43AEB2`（`0x43AED4 mov [edx+ecx*4+0x94], 0` 循环），两个调用点 `0x4430FE`（我方 army 初始化尾段）/ `0x44369C`（敌方）。

**(b) 唯一写者仍是 `0x43ADED`**，34 个调用点全部落在 `0x4447D1–0x445381`（18 个菜单/AI 包装函数），**没有任何一处位于战斗初始化或单位出生路径**。这些包装的调用者只有四类：

| 调用者 | 例子 | 写谁的槽 |
|---|---|---|
| 战斗菜单（玩家输入） | `0x444B3D → 0x4448B2` | `0x4A8A60`（我方） |
| AI `0x402EA5` | `0x403CD8 → 0x4448B2`(突擊)、`0x403CF9 → 0x44497F`(前進) | 传入的 army（敌方 `0x4B03A0`，或自动战斗时的我方） |
| 每帧处理器"自动突擊"支路 | `0x4443B6` / `0x4443CF → 0x4448B2` | 双方各一次（`[0x4A79C8]&2 && &0x100` 时） |
| 脚本/事件 | `0x442538 → 0x4448B2(0x4B03A0)` | 敌方（`[0x4A6764]&0x8000000` 触发） |

**(c) AI 的时机**：`0x444385`（唯一调用点 `0x44452A`，战斗主循环每帧）
```
004443E4  if(!([0x4a79c8] & 0x10)) { 0x4b041c--; if(<=0){ 0x402EA5(0x4B03A0); [0x4b041c]=0x3C; } }   ; 敌方
0044441F  if([0x4a79c8] & 0x102)  { 0x4a8adc--; if(<=0){ 0x402EA5(0x4A8A60); [0x4a8adc]=0x3C; } }   ; 我方（自动战斗）
```
`0x4B041C = 0x4B03A0+0x7C`、`0x4A8ADC = 0x4A8A60+0x7C`，**除递减/归零重置 0x3C 外无写入点** ⇒ 零初始化 ⇒ **第 1 帧就决策一次**，之后每 60 帧一次。玩家方 AI 只在 `[0x4A79C8]&0x102`（自动战斗）时才跑。

**(d) 但"第 1 帧决策"≠"第 1 帧就前进"**：`0x402EA5` 每次决策都先清零 7 个权重，再 `0x402FB4 mov dword [0x4c6bc0], 0x64` 把 **w0（什么都不做）= 100**；突擊 w2(`0x4C6BC8`) 只有 `+0xC` 的基础加成（`0x4031BB add eax,0xc`，条件块 `[ebp-0x14]&4`），前進 w4(`0x4C6BD0`) 无基础值、由 `0x4035F9 add eax,0x190` 等条件块给。⇒ 首帧大概率仍是"什么都不做"（100 : 12），发令要等条件满足。

**(e) 结论**：**"观感上双方主将立刻动"不是原作的开局默认**。玩家方在没有任何输入前，8 个槽确实全是 0（待機），表现就是站桩；能动只有三种情况：① 玩家点了前進/突擊；② 开了自动战斗（`[0x4A79C8]&0x102`）或演示支路（`&0x2 && &0x100`，会给**双方**直接发全軍突擊）；③ 脚本事件发令。**若录像里我方主将没下命令就冲出去，那基本可以断定是自动战斗/脚本模式。** `[确认]`（代码路径）/ `[推测]`（`[0x4A79C8]` 位语义）

## 10.3 同排扫描不到敌人时：不动还是按命令抽格前进？——**按命令走位，不是不动** `[确认]`

```
; 士兵帧
0043D282  83 7D F0 00           cmp  dword [ebp-0x10], 0     ; dir
0043D286  0F 84 06 01 00 00     je   0x43d392               ; ★dir==0 → 走位分支
; 主将帧
0043EB87  83 7D F4 00           cmp  dword [ebp-0xc], 0
0043EB8B  74 59                 je   0x43ebe6               ; ★dir==0 → 走位分支
```

`0x43D392`：`cmd = 0x43AF1A(u2)` → `0x43CFB1(u2,cmd)`（小队命令派发）；`0x43EBE6`：`cmd = 0x43AF1A(u2)` → `0x43CF07(u2,cmd)`（主将命令派发）。

⇒ **扫描不到敌人 ≠ 原地不动**，而是"这一 tick 不走攻击序列，改走命令对应的抽格"。
- 真的不动只有两种：① `cmd == 0`（待機，desc `0x48E6A0` 两组权重全 0，`0x43C2A5` 抽不出格）；② 抽到的格子全被占（`0x43B467` 返回 0 且 phase2 `0x43C20D` 也没让出位）。
- 附带一条容易踩的：`0x43BCA7` 开头 `if(--u->+0x38 > 0) return 0` ⇒ **攻击锁定期间也走 dir=0 这条路**，即"刚打完的那 1..3 个行动周期里会正常移动、只是不打人"。主将锁定恒 1（`0x43EBA7 mov [u2+0x38],1`），士兵查表 1..3。
