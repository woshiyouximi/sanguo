# 35 · 疲勞系統

> 狀態：已落地。原作《三國群英傳 2》的 `general+0x3A` 疲勞；本作只還原數值與間接影響，
> 不把它接進戰力/命中。反彙編證據見 `docs/04b5_战力基准与疲劳反汇编.md` §Q2。

## 1. 原作事實（帶地址）

- 欄位：`general+0x3A` = 疲勞（0..100）；`+0x38` = 士氣；`+0x3C` = 忠誠。
- 初始：`0x42D471` 疲勞 = 0；`0x42D47A` 忠誠 = `0x5A` = 90；`0x42D468` 士氣 = `0x50` = 80。
- **不進攻力/命中**：`0x442EFA`（B 側）、`0x443498`（A 側）、`0x43D400` 對 `+0x3A` 零命中。
  戰力五段只讀 `+0x38` 士氣：`150 + 相剋 + 地形 + 陣形 + (unit+0x30+50)/100 + trunc((士氣−50)/5)`。
- **戰後**（`0x41048D`）：雙方主將各 `+= 15 + 秒數/10`（`idiv 0xa; add eax,0xf`）；
  秒數未知時 `15 + rand()%8`（`push 8; call 0x450117; add eax,0xf`）；增量 15..22。
  上限 100（`0x4108DA..0x4108FB cmp eax,0x64 / jle / mov word [..+0x3A],0x64`）。
- **每月**（`0x41B1BF`）：疲勞 > 0 → `-1`（`0x41B302 sub dx,1`，下限 0）；
  **先減，再判** `>= 0x3C`（`0x41B34E cmp ecx,0x3c / jl`）→ 士氣 `-1`（`0x41B377`）；
  否則士氣 < `0x46`(70) → `+1`；士氣 < `0x28`(40) → 忠誠 `-1`，否則忠誠 < `0x5A`(90) → `+1`。
  所以 60 → 59 不觸發，61 → 60 才觸發士氣懲罰。
- **間接影響**：疲勞 ≥ 60 → 每月士氣 -1；士氣每點讓戰力第 5 段 -0.2（`Math.trunc` 向 0 截斷）。

## 2. 我們怎麼實現

| 位置 | 改動 |
|---|---|
| `game/web/main.js` | `// [[FATIGUE_CORE]]` 純函數塊；`readConfig().atire`；createWorld 後掛 `world.sides.A.general.tire`；結算狀態條顯示；`writeBackCampaign()` 寫回疲勞 |
| `game/web/campaign.html` | 同一個 `FATIGUE_CORE` 塊；`normalizeCampaign()` 補 `tire = {}`；`advanceMonth()` 每月衰減 + 士氣 |
| `game/web/city.html` | 頂部 HUD 新增「疲勞」chip，顯示太守（主將）疲勞 |
| `game/web/deploy.html` | 主將卡新增「疲勞 x/100」；出征 URL 帶 `atire=` |
| `game/tests/fatigue.test.ts` | 13 條測試，直接從兩個頁面抽 `FATIGUE_CORE` 源碼執行 |

- 純函數：`tireGain(sec, rng)`、`tireAdd(cur, gain)`、`tireNormalize(raw)`、`tireOf(save, name)`、
  `tireBattle(save, a, b, sec, rng)`、`tireMonthly(save, officersByCity)`。`TIRE_MAX=100`、`TIRE_HIGH=60`。
- 戰後：`settle()` 的 `durationSec` 有值 → 雙方 `15 + trunc(sec/10)`；無值 → 各自 `15 + floor(rng()*8)`。
  RNG 用 `mulberry32(state.seed)`，同一場戰鬥可重現；寫回後同步更新 `world.sides.*.general.tire`，
  狀態條立刻看到新值。沒有 `?city=`（不在戰役裡）時整段跳過。
- 每月：`advanceMonth()` 在俸祿後、軍事事件前執行；先在職武將 `-1`（下限 0），再用減後值判 ≥60；
  有 `st.morale` 數字才扣士氣，沒有就記 skipped；`save.tire` 裡殘留的敵將/離隊名字也一併衰減。
- 顯示：city.html 讀 `M.majorOf()`；deploy.html 讀 `save.tire[gen.NAME]`；兩處 ≥60 都用橙色 `#E2914E`。

## 3. 存檔欄位

```json
{ "owned": ["代縣"], "cities": { "代縣": { "troops": 1200, "pop": 80000, "money": 300 } },
  "tire": { "關羽": 37, "張角": 15 } }
```

- `tire` 只存在戰役存檔（槽 snapshot / 舊鍵 `sanguo_campaign_v1`）裡，**不改 `saves.js` 的結構**。
- 老檔缺 `tire`：`tireNormalize(undefined)` → `{}`，每名武將按 0 讀；值統一夾成 0..100 整數。
- `deploy.html` 本來就只讀舊鍵，所以 `campaign.html` 的 `persist()/autosave()` 鏡像時必須已含 `tire`。

## 4. 測試清單（`node --test tests/fatigue.test.ts`）

1. 秒數已知：`15 + trunc(sec/10)`，且不呼叫 rng（0/9/10/19/37/99/180）。
2. 秒數未知：15..22，同種子可復現；兩個頁面的結果一致。
3. `tireAdd`：取整、下限 0、上限 100。
4. `tireBattle`：雙方各加一次、寫回 `save.tire`、同種子逐位一致。
5. 老檔缺欄位：補空物件、不崩。
6. 值容錯：字串/負數/超上限/壞 key。
7. 每月 `-1`、下限 0、只計真的減了的。
8. 先減再判：60→59 不觸發，61→60 觸發士氣 -1。
9. 城沒有 `morale`：只記 skipped，不憑空造士氣。
10. 同城多名高疲勞：士氣按人數扣，且不扣成負數。
11. `save.tire` 裡非在職名字也衰減，但不計士氣。
12. 疲勞不影響 `powerOf()`：同 seed 只差 tire，初始與 300 tick 後逐位相等。
13. 兩份 `FATIGUE_CORE` 行為一致（防頁面各寫一套）。

## 5. 和原作還不一致的地方

1. **士氣欄位不存在**：`saves.js` 的 `cityState` 只有 troops/pop/money，戰役存檔也沒有 morale。
   所以「疲勞 ≥60 → 士氣 -1」在正常遊玩時**只記 skipped 並在戰報註明**，不會真的改士氣；
   只有存檔裡本來就有 `morale` 數字時才扣。這是本次唯一因缺欄位而近似的一條。
2. **每月只掃我方在職武將**（`save.owned` 各城 officers）＋ `save.tire` 裡已有名字；
   原作是掃全勢力所有武將。敵將沒有存進 `tire` 時不會被每月衰減。
3. **戰後只有雙方主將**：與 `0x41048D` 的兩次 `+=` 對齊；原作是否還掃替補武將未驗證。
4. **未知秒數的 RNG** 用戰鬥種子（可重現），原作是全域 `rand()`；數值範圍同為 15..22。
5. **再戰**：`makeWorld()` 每次用 URL 的 `atire` 重設 A 疲勞，所以同一頁連打第二場，
   顯示會回到出征時的舊值，再從那裡加；重新進 deploy 頁才會拿到最新值。
6. 未接：道具/事件對疲勞的加減、每月忠誠增減、疲勞對 AI 出戰選擇的影響。
7. `docs/04b_战斗系统.md` 的 §1.1 表行（戰後處理）與 §9.4 第 17 條仍沿用「疲勞 = +(10−CONSTANCY)×2」
   的舊說法；本次授權只改 §1.2 與 §6.5，這兩處留待後續清理。

## 6. 後續：士氣已改為武將級（2026-11）

- 本文 §2/§5 說的「城沒有 `morale` 就記 skipped」是歷史近似；現在士氣已改成**武將級**
  `save.morale = { 武將名: 0..100 }`，疲勞 ≥60 → 該武將士氣 −1，不再看城池欄位。
  見 `project/36_武将级士气.md`。
- `tireMonthly()` 本身**沒改**（仍回 `{decayed, high, moraleLoss, moraleSkipped}`，`fatigue.test.ts` 13 條全綠）；
  新的士氣結算走獨立的 `[[MORALE_CORE]]` 的 `moraleMonthly()`，`advanceMonth()` 兩者都呼叫。
- 城池級 `cities[*].morale`（若有）在 `normalizeCampaign()` 遷移時改名 `cityMorale`，不搬成武將士氣。
