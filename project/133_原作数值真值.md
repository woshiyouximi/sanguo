## 3. 起始等级 —— `[确认]`（**不是** STR+INT 公式，**也不需要** SSAV）

### 3.1 `+0x2E` 确实是等级（字段级确认）

`gen+0x2E` 的写入点整份 `.text` **只有 3 条**（`LEVEL_excerpt.txt` 末尾有全清单）：

| 地址 | 场景 |
|---|---|
| `0x40F281 mov word ptr [eax+0x2e],dx` | 升级（`add dx,1` 之后；**无封顶判断**，修正版才夹 99） |
| `0x42D39D mov word ptr [ecx+0x2e],ax` | **新开局/装载 TIMES** |
| `0x4330DA mov word ptr [ecx+0x2e],ax` | 读档 |

读档那条证实了存盘布局：`0x4330E1 imul ecx,ecx,0x11f` → `mov ax,word ptr [[0x4BD214]+ecx+0x4E]` → `gen+0x2E`，
即**存盘武将记录 stride 0x11F、相对 gen 结构偏 +0x20**（`SAV+0x4E`↔`gen+0x2E`、`+0x46`↔`+0x26`、`+0x48`↔`+0x28`、
`+0x4A`↔`+0x2A`、`+0x50`↔`+0x30`）。⇒ `project/123` 说的「起始等级在 SSAV `+0x2E`」**方向对、结论错**：
`+0x2E` 是等级字段没错，但**开局那一刻它的值不是从存档读的，是算出来的**。

### 3.2 等级从 BASEEXP 反推（关键三步）

```
0042D38B  mov dword ptr [ecx+0x2a],eax      ; BASEEXP 写 gen+0x2A
0042D391  push edx ; call 0x409F73          ; 等级 = f(gen)    ← 就这一句
0042D39D  mov word ptr [ecx+0x2e],ax        ; 写回等级
0042D3A5  call 0x40A020                     ; 再用等级重算 HP

00409F73(gen):                              ; 等级 = 反推门槛表
  for (i = 0; i < 99; i++)
      if (gen->exp[+0x2A] < 0x409EE0(i)) return i - 1;
  return 99;

00409EE0(k):                                ; 升到 k 级所需累计经验
  if (k > 99) return 0x98967F;
  return ((k-1)*0x89 - 0x22) * k / 2 + 0x11;    ; = ((k−1)×137 − 34)×k/2 + 17
```

装载器邻接的字串 `0x48C530 "BASEMP"`、`0x48C538 "BASEEXP"` 就在这一段里。
⇒ **新开局武将等级 = level_of(BaseEXP)**，与 STR/INT **无关**。

## 4. R20 搜索随机性 —— `[确认]`：**一条全局流**

### 4.1 乱数发生器本体（自製，不是 MSVC6 CRT 的 rand）

- `rand()` = **`0x450132`**：状态 `[0x4922FC]`(A) 与 `[0x492300]`(B)；
  `A += 1; B -= 1;` 然后 `B = ror(B, A & 31)`、`A = rol(A, B & 31)`，返回 `A + B`
  （`0x4501C6 mov eax,[0x4922fc]; add eax,[0x492300]`）。
- `rand()%n` = **`0x450117`**（`n==0` 直接回 0，再 `div [ebp+8]` 取余）；**90 个调用点**。
- `srand(a,b)` = **`0x4500E7`**：`[0x4922FC]=a; [0x492300]=b`。
- **零命中**：MSVC6 的 `0x343FD` / `0x269EC3` 两个常量在整份 `.text` 各 **0** 次；
  148 个导入里没有 `rand`/`srand`。⇒ 这是游戏自带的 RNG，与 CRT 无关。

### 4.2 只有 2 次播种，都在新开局，种子是时钟

```
0040B583  push 0x12345678
0040B588  call 0x450410          ; GetTickCount 派生值（见下）
0040B58D  push eax
0040B58E  call 0x4500e7          ; srand(派生值, 0x12345678)      ← 调用点 #1
...
0040B681  call 0x450410
0040B686  push eax
0040B687  call 0x4500e7          ; srand(派生值, 另一参数)         ← 调用点 #2
```

`calls_to(0x4500E7)` 全 EXE 就这两个（`['0040B58E','0040B687']`），都在新开局初始化段
（邻近 `[0x4A79C8]` / `[0x4A6694]`）。

`0x450410` 内 `call dword ptr [0x4D43E0]`，该 IAT 槽 = **`KERNEL32!GetTickCount`**
（`rd.imports()` 已核），再经 `fild/fmul/fdiv + 0x46DAB0` 转 int ⇒ **每次运行种子不同**。

RNG 状态的两个 dword，写入点全 EXE 只有 **6** 条：`0x4500ED`/`0x4500F5`（srand 那两句）
+ `0x450140`/`0x45014E`/`0x450188`/`0x4501C1`（rand 自身）⇒ **没有任何按城、按势力、按事件的重播种**，
存档里也没有 RNG 状态字段。

### 4.3 搜索路径用的是同一条流

- 搜索命令派发：`0x4020D7 call 0x426D8C`（`0x426D8C` = 416 B 的掉落函数）。
- 掉落抽取：`0x426E06 push ecx`（ecx = `count+2`）、`0x426E76 push ecx`（`count+1`），都进 `0x450117`。
- 邻近的加成：`0x426BEE push 0x1e`（`rand()%30 + 90`，写 `gen+0x2A` 经验）。
- 表选取：按 `city+0x6C`（RATE 城规模）索 `0x48A260 + RATE×0x14`，`0x4687A0` 选表。

⇒ 原作**没有**「按城种子」也没有「按搜索次数种子」，全部从同一条全局流里取数。
玩家看到的现象会是：同一个月里先做别的随机事（战斗判定、AI 内政、登用）会改变随后的搜索结果。

### 4.4 与本作的差异

- `game/web/city_model.js:927` `seed = searchSeed(city, save.month, count, searchNonce(save))` →
  `mulberry32(seed)`：**同一档、同城、同月、同第 n 次 ⇒ 结果必然相同**（可复现），
  与 `save.searchSeq`（`:991-997`）配合成「按城计数器」。
- 因此本作与原作的差异是**结构性**的（确定性 vs 全局流），不是某个常数写错：
  既不会因为先打了一仗而改变搜索产出，也不会因为跨城顺序不同而变。
- `save.searchNonce`（`:289-305`）给每档一个 32 位真随机 nonce，让不同存档不同、同一存档可复现 ——
  这是**自觉设计**（`project/` 可查），不属于「猜错的原作公式」。

### 4.5 建议本作怎么改

1. 若目标是「像原作」：**`game/web/city_model.js:927-928`** 改成消费全局流 ——
   `const rng = rngNext;`（`:250-259` 已经是 `crypto.getRandomValues` 兜底），删掉 `searchSeed/searchNonce/bumpSearchSeq`
   的种子作用（`searchSeq` 仅留作日志/统计）。这样先做的其它随机行为会自然影响搜索，与原作同构。
2. 若目标是「可复现」（现有测试大量依赖）：**保留现状**，但在 `project/108` / `project/123` 把 R20 的标签从
   「🟡 待证」改成「✅ 已定位，本作**故意**用确定性种子（偏差已登记）」，并把本条真值（`0x450132`/`0x450117`/
   只有 2 次 GetTickCount 播种）写进 `docs/` 的乱数一节，避免下次再查。
3. 无论选哪条，都建议把 `mulberry32` 的调用点收敛到一处（`city_model.js:928`），
   这样换口径只改一行。
