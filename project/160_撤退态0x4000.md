# 160 撤退态 `0x4000` 考古报告（只读反汇编）

> 目标：把「撤退/溃退态」`status |= 0x4000` 的**触发条件**、**清除点**、**可见行为**钉死在地址上，
> 并给 `game/src/core/battle.ts` 的落地建议。
> 证据目录：`F:\sanguo\work\re4000\`（10–31 号旧证据 + 40–58 号本轮证据）。
> 样本：`Sango2.exe`（1.05+ 修正版），VA = 文件内 RVA + 0x400000。

---

## 0. 结论摘要（TL;DR）

| 问题 | 结论 |
|---|---|
| `0x444858` 是「整军团溃退」吗 | **是**。它是 `0x4447B7` 里 `for(i<army+0x58) SetState(army+0xB4+i*0x48, 0x4000)` |
| 与 `0x4447E2` 什么关系 | **同一函数的上下两层**：先给军团对象置位（`0x4447E2`），再逐个给小队记录置位（`0x444858`）。一次「全军撤退令」，两层都打 |
| `0x43C827`/`0x43CCD9` 是「无路可走/被围攻/士气崩溃」吗 | **不是**。两者都是 `cmd==8` 动作处理器的**无条件尾句**（`0x43C7E3` / `0x43CC95` 里 `call 0x43C4C0` 之后紧跟 `or [u+0x2c],0x4000`）。条件只有一个：**这个单位这一步执行的是 cmd 8** |
| 有没有清除 `0x4000` 的地方 | **没有**（五重证据见 §2）。全程序无 `ClearState(…,0x4000)`、无 `and …,~0x4000`。唯一的「赋值型清零」在**单位创建**：`0x43A29B`/`0x43A364` `[u+0x2c] = (int16)[[u+0x00]+0x38]` ⇒ 一场战斗内 `0x4000` **不可逆** |
| 画面上是什么 | ①行动间隔 40→**46** 帧；②每个行动周期位移 **2 小步→1 小步**，且只能朝**朝向的反方向**走（倒退）；③**不再主动接敌**；④会被敌人**主动追着打**；⑤走不动/出界时置 `0x8000`（离场） |
| 补丁一行摘要 | `battle.ts` 不用改置位条件（`requestRetreat` 已等价于 `0x4447E2/0x444858`），**要补的是「cmd 8 动作即置位」**（`battle.ts:2072` 用 `plan.kind==='retreat'` 兜住），并且**永远不要写清除**；顺带修 `battleView.ts:717-719` 那个「主将=46」的过时分支 |

## 1. 四个写入点逐条判定

先把**命令字**这一层钉住，否则四个写点读不出语义。

### 1.0 命令槽写入 API `0x43ADED(army, which, cmd)`

`F:\sanguo\work\re4000\14_fn_43ADED.txt`（上一轮已读，不重复）：

```
[army + 0x94 + which*4] = cmd     ; which ∈ [0,8)
which == 0x100 → 槽 0..7 全写     ; which == 0x101 → 槽 1..7
which < 0 或 >= 8 → 槽 0..7 全写  ; 其余 → 只写单槽
```

⇒ `army+0x94..0xB0` = **8 个命令槽**（槽 0 = 主将，槽 1..7 = 小队组，见 `0x4448B2` 突击写
`0x43ADED(army,0x101,7)` = 只写 1..7、槽 0 留待机）。`0x43ADED` **只写命令字，不碰 `[u+0x2c]`**。
（槽号 ↔ `army+0xB4+i*0x48` 小队记录的字符映射 **[未解]**，见 §5。不影响本文结论：`0x444858` 是直接遍历
小队记录，没有经过槽。）

### 1.1 写点 A：`0x4447E2` —— 军团对象，撤退令下达那一刻

**函数 `0x4447B7(army)`，size=228（`0x4447B7..0x44489B`），全文见 `41_fn_4447B7_annotated.txt`。**

```
0x4447BB  cmp [ebp+8],0 ; jne 0x4447C6        ; 空指针保护
0x4447C6  0x43ADED(army, 0x100, 8)            ; ← 8 个命令槽全写 8（撤退）
0x4447D9  0x43B51E(army, 0x4000)              ; ← 【写点 A】军团对象 state |= 0x4000
0x4447EA  if (army->+0x84 & 0x40) {           ;   主将阵亡标志
             [[army+0x44]+0x4C](army->+0x44, 0x1000B, 0)   ; 给随从对象发 OM 0x1000B
             0x43B51E(army, 0x8000)           ; ← 附带：军团置 0x8000
          }
0x444825  for (i = 0; i < army->+0x58; i++)   ; ← 小队记录数
0x444858      0x43B51E(army+0xB4+i*0x48, 0x4000)   ; ← 【写点 B】逐小队
0x444862  if (0x43B556(army)) return          ;   army->+0x2c & 0x2000 → 直接返回
          else if (army == 0x4A8A60) [army+0x44]+0x2c = 0        ; 0x444881
          else                       [army+0x44]+0x2c = 0x800000 ; 0x444890
```

**触发条件**：只要 `army != NULL` 被调用就**无条件**置位——它不是一个「判定」，而是「**全军撤退**」
这个动作本身。三个调用点决定「谁在什么条件下发起这个动作」：

| 调用点 | 所在函数 | 条件 / 语义 |
|---|---|---|
| `0x444B7E` | `0x444B4C(t)` | **命令面板「撤退」按钮**。`t != 1` 分支 = 执行：`0x4447B7(0x4A8A60)`；`[0x4A8AC4]=0`；`[0x4A8AE0] \|= 4`；返回 1。`t == 1` 分支 = 可用性询问：`[0x4A8AE0]&4` 或 `[0x4A8AE4]&4` 已置 → 返回 0（不可再撤）。见 `42_callers_of_4447B7.txt` C 段 |
| `0x444956` | `0x44493D(army)` | **幂等守卫**：`if (army->+0x80 & 4) return;` 否则 `0x4447B7(army)`、`army->+0x80 \|= 4`、`army->+0x64 = 0`。B 段 |
| `0x43F2FB` | `0x43EF64`（1571 字节，军团指令执行器） | 分支入口 `cmp [army+0x34],0x20 / je 0x43F371`（即 `[army+0x34] != 0x20` 才进入本块）。块内先 `0x43DB9A(army->+0x84)`、`0x43DC56(army,[ebp+0x10])`、两次 `0x421E1B(army,0x40/0x20)` 并用 `army->+0x78` 做时间差写 `army->+0x3c`（=「等一步动作/动画同步」，语义 **[未解]**），随后 `0x4447B7([army+0x84]+0x40)`，再 `[army+0x80] \|= 4`、`[0x4A665C] \|= 3`、按阵营播语音 `0x41F740(0, 0x39, …, 0)`（我方）/另一路。A 段 |

⇒ 三个调用点最后都落在「`army+0x80` bit2（`0x4`）= **全军撤退中**」这个军团级标志上（`57_army_flags_80.txt`），
和单位级 `0x4000` 是**两层**：`0x4` 是「这个军团已经下过撤退令」（防重复下令），`0x4000` 是「这个单位跑不动了」。

### 1.2 写点 B：`0x444858` —— 逐小队，与 A 同一事件的下层

见 1.1 的 `0x444825..0x444860`。

- 遍历对象：`army+0xB4 + i*0x48`，`i < [army+0x58]`，`0x48` = 小队记录大小（同一 stride 在
  `0x43D125` 小队更新器里也用）。**这是「军团里每一个小队记录」，不是 8 个命令槽**。
- 条件：无。循环无 break、无 if —— 所有小队一律置位（哪怕它已经死了/已离场 **[推测]**：
  `0x4447B7` 里没有存活检查；离场单位随后靠 `0x8000` 被摘掉）。

**⇒ 直接回答 Q1**：`0x444858` 就是「整军团溃退」的**小队级写法**，`0x4447E2` 是**军团级写法**，
两者是**同一个函数、同一次调用里的两层**，不是两个不同事件。原作把「军团」和「小队」都当成同一种
actor（字段布局 `+0x2c` 状态 / `+0x34` 行动计时器 / `+0x40` 军团指针 / `+0x44` 随从对象 全同构），
所以撤退要把两层都标一遍。

### 1.3 写点 C：`0x43C827` —— 主将 cmd 8 的动作处理器

分派链（`58_cmd8_dispatch.txt`）：

```
主将更新器 0x43E964 ──0x43EBFD──> 0x43CF07(unit, cmd)   ; jmp [cmd*4 + 0x43CF8D]
                                    表 @0x43CF8D: [8] = 0x43CF63
0x43CF67  call 0x43C7E3(unit)        ; ← cmd==8 唯一入口
```

`0x43C7E3` 全文（上一轮已读）：

```
cmp [u+0x40], 0x4A8A60          ; u 属于我方军团 A ？
  → dir = +1                    ;   是：往 +x 撤
  → dir = -1                    ;   否：往 -x 撤
0x43C4C0(u, dir, 0, &0x48E658)  ; 走一格；0x48E658 = {1,100,0,0} 直线 100%
0x43C827 0x43B51E(u, 0x4000)    ; ← 【写点 C】无条件
```

**条件**：`u->cmd == 8` 且轮到 `u` 行动（`0x43B574` 计时器到期，`0x43EB50`）。
每执行一次撤退动作就再置一次，所以是**幂等的每步重置**，不是「新事件」。

> 反面确认：`0x43C7E3` 里没有任何 `cmp/jne` 门（无「被围攻」「无路可走」「士气 < X」判定）。
> 唯一的分支是**判阵营取方向**。所以写成「no-path / surrounded / morale-collapse」都是误读。

### 1.4 写点 D：`0x43CCD9` —— 小队 cmd 8 的动作处理器

```
小队更新器 0x43D125 ──0x43D3A9──> 0x43CFB1(unit, cmd)   ; jmp [cmd*4 + 0x43D0C9]
                                    表 @0x43D0C9: [8] = 0x43D0B9
0x43D0BD  call 0x43CC95(unit)        ; ← cmd==8 唯一入口
```

`0x43CC95` 与 `0x43C7E3` **逐字节同构**，只换了参数块与常量：
`0x43CCC8 = call 0x43C4C0(u, dir, 0, &0x48E8E0)`、`0x48E8E0 = {0,80,10,10}`（锥形 80/10/10）、
`0x43CCD9 = 0x43B51E(u, 0x4000)`。

**⇒ 直接回答 Q2**：`0x43C827` / `0x43CCD9` **不是**战场内核的「发现无路可走 / 被围攻 / 士气崩溃」，
而是 **cmd 8 动作处理器的无条件尾巴**，分别对应**主将**和**小队**——
即 1.1/1.2 的写入点 C/D 与写入点 A/B 构成「**下令那一刻打标**」+「**此后每步重打**」两处，
语义完全一致（同一个位、同一个含义），差别只是执行时机。

## 2. 清除点：**不存在**（五重证据）

**证据 1（API 层）**：状态字只有两个写 API —— `0x43B51E SetState` (`|=`) 与 `0x43B538 ClearState` (`&= ~`)。
`ClearState` 全程序**只有 2 个 caller**：

```
0x43C63A  ClearState(u, 0x1000)   ; 在 0x43C4C0 内，与 0x43C612 SetState(0x1000) 成对（占用/落子标记）
0x444CC5  ClearState(u, 0x100)    ; 在 0x444C94 内（取消指令）
```

⇒ **不存在 `ClearState(…,0x4000)`**。（`50_state_api_and_clear_exhaustive.txt`）

**证据 2（位运算层）**：全程序 `or/xor` 立即数 `0x4000` 各 **0 条**；`and` 立即数 `0x4000` 的 7 处
**全是「读」**（`0x43B5F1/0x43B694/0x43BCD8/0x43BD74/0x43C684/0x43D8E4` + 无关的 `0x442424`）。
`~0x4000 = 0xBFFF` 形态 0 条（`0x43A58F` 的 `and eax,0x3FFF` 是**坐标回绕**：
`x - [0x4AC370] + 0x400` 取 14 位再和 `0x1000` 比，与状态字无关；`0x475xxx` 两处在内核外）。
（`51_imm4000_and_masks.txt`）

**证据 3（直接写内存层）**：战场内核 `0x43A000–0x446000` 内所有 `mov dword ptr [x+0x2c], …` 共 65 条，
`mov […+0x2c], 0` / `, 0x800000` 的**成对出现**共 **11 组**，全部作用在 `[u+0x44]+0x2c`
（= 随从对象的朝向字段，取值只有 `0` 与 `0x800000` 两个）：

```
0x43BF3A/0x43BF54  0x43BFFB/0x43C015  0x43C1A1/0x43C1AD  0x43C4A8/0x43C4B7
0x43DC8B/0x43DCA3  0x43DF98/0x43DFA4  0x43E658/0x43E664  0x43FA16/0x43FA22
0x43FBCE/0x43FBDA  0x444881/0x444890  0x443FE4/0x44401F
```

另有两条单独的 `mov [x+0x2c], 0`：`0x442A74`（在 `0x442A1A`）与 `0x442BD8`（在 `0x442B08`），
紧跟 `mov [x+0x10],arg` / `mov [x+0x14],arg` 之后 —— 那是**另一个结构体的初始化**（同偏移复用，
字段组合 `+0x10/+0x14/+0x2c` 不是单位布局），同样不是单位状态字清零。

对照：`0x43C47E(u)` 是它们的样板 —— `cmp [u+0x40],0x4A8A60` → 我方写 `0x800000`、敌方写 `0`，
**作用对象是 `[u+0x44]`，不是 `u`**。所以早期把 `0x444881` 当成「清单位状态」是列错位误读
（它清的是随从对象的朝向）。（`52_disp2c_accesses_in_kernel.txt`）

**证据 4（唯一的「赋值型」清零 = 单位创建）**：`0x43A1C4` 内有两段同构代码（`53_unit_init_43A1C4.txt`）：

```
0x43A292  edx = [u + 0x00]                    ; u+0x00 = 兵种/单位定义表项指针
0x43A294  movsx eax, word ptr [edx + 0x38]    ; 定义里的「初始状态字」（int16，符号扩展）
0x43A29B  mov [u + 0x2c], eax                 ; ← 状态字 = 模板值（覆盖，不是 |=）
0x43A2A1  mov [u + 0x34], 0                   ; 行动计时器清 0
0x43A2A8  mov [u + 0x38], 0                   ; 步进计时器清 0
```

`0x43A364` 是同一段对另一个入参（`[ebp+0xc]`）的复制。`0x43A1C4` 的 caller 只有 `0x44473F`（战斗初始化）。
⇒ **能「清掉 0x4000」的只有「单位被创建/重刷」这一件事**，即**新的一场战斗**。
旁证：全程序没有任何地方在初始化时写 `[u+0x34]=0x28`（`0x43B5DE` 是唯一一处，且在计时器里），
说明单位结构是**整体零初始化**后再逐字段填 —— 状态字初始 0，`0x4000` 自然不成立。

**证据 5（取消命令也不清）**：`0x444C94(army)`（取消/复位指令）：

```
0x43ADED(army, 0, 0)              ; 8 个命令槽全清 0（待机）
army->+0x80 &= ~0x10              ; 清「保护主将」
0x444CC5 ClearState(army, 0x100)  ; 只清 0x100
```

**不清 `0x4000`**。随后 `0x444881` 又把随从朝向按阵营写回。所以「下过撤退令之后再把命令改回待机/前进」，
`0x4000` 仍然在，节奏仍是 46、位移仍是半步、仍不主动接敌。

**⇒ 结论**：`0x4000` 在**一场战斗内是单向、不可逆**的粘性位。这正好解释原作「撤退令没有反悔」的设计：
面板上 `0x444B4C` 的可用性分支只判断「**是不是已经撤过了**」（`[0x4A8AE0]&4`/`[0x4A8AE4]&4`），
根本没有「取消撤退」这条路。

## 3. 与原作可见行为的对应（只列有地址的）

| # | 表现 | 地址与数据 |
|---|---|---|
| 1 | **行动变慢：40 → 46 帧** | `0x43B5DE mov [u+0x34],0x28`(40) → `0x43B5F1 and eax,0x4000` → `0x43B5FD mov [u+0x34],0x2e`(46)。同一个字段、两条分支，间隔 +15% |
| 2 | **每次行动只挪「一小步」（正常的一半）** | `0x43BCA7`：`[u+0x38]--`；到 0 时取 count —— 非撤退 `count = 2`（`0x43BD06`），撤退 `count = 1`（`0x43BCE1`），再循环 `count` 次 `0x43BBE6(u, dir)`（每次一个像素级小步，`0x43BD3E`） |
| 3 | **只能「倒着走」** | 撤退分支的 `dir` 不是随机也不是朝敌：`dir = ([u+0x44]+0x2c == 0) ? +1 : -1`（`0x43BCEB..0x43BCFB`）；`0x43BD64(u,dir)` 更严：撤退态下**只允许** `+0x2c==0 且 dir==-1` 或 `+0x2c==0x800000 且 dir==+1`，其余一律返回 0（=不许走这步） |
| 4 | **不再主动接敌/靠近** | `0x43C084`（`0x43C4C0` 体内 `0x43C740` 调用）：先 `0x43A4E0` 找最近目标、算落点，发 `0x42249B(随从,0,0,0)` + OM `0x10002`；紧接着 `0x43C132 isRetreating(u)` → **`jne 0x43C1B4` 直接返回**，跳过 `0x43B6A8` 判定、`0x43BBE6` 步进、`0x43B9E2` 朝向更新。即：**会转向/摆姿势，但不往前压** |
| 5 | **反而会被敌人「追着打」** | `0x43D76C(u,dir)`：`0x43AF7A` 在 `x+dir`、再 `x+dir*2` 两格内找单位 `t`；若 `t && (t->state & 1) && isRetreating(t)`（`0x43D7B7 0x43B6A8` + `0x43D7C7 0x43B67F`）→ 且 `0x43B663` 判**不同军团** → 进入 `0x43D4CB` 的后续（追击/背刺序列）。这是**唯一**用 `isRetreating` 去找「受害者」的地方，语义与 4 相反 |
| 6 | **走不动/出界 → 离场标记 `0x8000`** | `0x43C684`：`GetState(u)&0x4000` 且 `0x43AF54(x,0)==0`（落点探测失败）→ `0x43C6B0 0x43BFE7(u, x, u->+0xc, 0)`（直接落位 + 按 x 定朝向）+ `0x43C6C1 SetState(u,0x8000)`。与 1.1 里「主将阵亡 → 军团 `0x8000`」是同一个位 = **退出/失效**。原作把「撤退走出场地」处理成 `0x8000` 而不是阵亡 |
| 7 | 面板/语音层 | `0x43F30F or ecx,4`（`army->+0x80 |= 4`）、`0x43F324 or ecx,3`（`[0x4A665C] |= 3`）、`0x43F34C 0x41F740(0, 0x39, …, 0)`（我方语音 0x39）；`0x444B96 or edx,4`（`[0x4A8AE0] |= 4`）、`0x444B86 mov [0x4A8AC4],0` |

> 关于「撤退时**不还手**」：**不充分**。目前能证明的是「不主动接敌」（第 4 条）。真正的伤害结算在
> `0x43D400`（命中判定，读 `防御方 [x+0x2c]&4` 做 2/3 补判）与 `0x43D76C/0x43D870/0x43DA08` 三处调用，
> 我**没有**在这三处的入口看到 `0x4000` 门（见 §5 `[未解]`）。所以「撤退单位挨打时会不会还手」
> 不能下结论；可以确定的相反现象是第 5 条（**敌人专门找撤退单位打**）。

## 4. 给 lead 的补丁建议（不改文件，只给文字 + 伪代码）

### 4.1 现状核对（谁已经对了）

### 4.2 建议的改动（3 处，按优先级）

**(1) `battle.ts:2071-2072` —— 把「撤退态」的来源从 `u.flee` 改成状态位，并在选择撤退计划时补置位。**
（对应 `0x43D0B9 → 0x43CC95 → 0x43CCD9`：**cmd 8 动作的固有副作用**，与谁下令无关）

> 先说清今天的影响面：`army_cmd.ts` 目前**没有单槽命令层**（`0x43ADED` 的 8 槽模型未移植，命令是
> 「整侧」的：`applyArmyCmd()` → `requestRetreat()`），所以「每步重置位」**今天不会产生可见差异**。
> 它是一行零风险的保真补丁；一旦将来接 `0x43ADED`/单槽命令（原作 `0x4447B7` 就是整片 8 槽写 8），
> 就变成必须 —— 否则「AI 只把某几个槽写成 8」的小队会缺 `0x4000`，节奏仍是 40、还会继续往前压。

```ts
// battle.ts ~2071（现在：if (u.flee) plan = retreatStepPlan(u);）
const retreating = ((u.status ?? 0) & 0x4000) !== 0;
let plan: StepPlan | null;
if (retreating || u.flee) {
  // 原作 0x43CCD9（小队）/ 0x43C827（主将）：cmd 8 的动作处理器无条件 `or [u+0x2c],0x4000`。
  // 这里补置位，覆盖「命令字被单独写成 8、没走 requestRetreat」的路径；幂等，无副作用。
  u.status = (u.status ?? 0) | 0x4000;
  u.flee = true;
  plan = retreatStepPlan(u);
}
```

配套把同文件里其余 `u.flee` 判据改成「位优先、`flee` 兜底」，共 3 处：
`:1900`（`chooseStepCell` 的 `exit` 允许）、`:1942`（`generalStepPlan` 跳过撤退单位）、`:2072` 本身。
建议加一个最小 helper，避免三处判断漂移：

```ts
/** 原作无 ClearState(0x4000)：这个位一场战斗内不可逆，只能靠单位重建清零（0x43A29B）。 */
export function isRetreating(u: Unit): boolean {
  return ((u.status ?? 0) & 0x4000) !== 0 || u.flee === true;
}
export function markRetreating(u: Unit): void {
  u.status = (u.status ?? 0) | 0x4000;   // SetState 0x43B51E 语义
  u.flee = true;
}
```

`requestRetreat()`（`:2219-2223`）改成 `markRetreating(u)`，注释补上 `0x4447E2/0x444858`。

**(2) `battleView.ts:717-719` —— 删掉「主将 = 46」的过时分支（这是当前的真 bug）。**

```ts
// 现在
const interval = Math.max(1, u.isGeneral ? ACTION_INTERVAL_TICKS : ATTACK_COOLDOWN);
const slow = Math.max(interval, u.isGeneral ? GENERAL_SLOW_INTERVAL : interval);
// 建议
const interval = actionIntervalOf(u);       // core 已经是 0x4000 → 46 / 否则 40
const slow = interval;                      // 46 只属于撤退态，主将非撤退也是 40
```

理由：`battleView.ts:695-701` 的注释写着「core 还没实现 `0x4000` 分支」，但 core 从 R158 起已经实现了
（`battle.ts:114`）。现在这个分支的后果是：**主将的行动条永远只走到 40/46 ≈ 87% 就跳回**，
而士兵条走满 100% —— 视觉上主将"永远差一点"。改成 `slow = interval` 后两者的满格语义才一致。
（`GENERAL_SLOW_INTERVAL` 这个常量名建议保留但改注释为「撤退态间隔」，因为 core 也导出了同名常量。）

**(3) `army_cmd.ts:672` 的注释**：把「同时置 `0x4000`（由 `requestRetreat` 做）」改成
「cmd 8 的动作处理器每步都会置 `0x4000`（`0x43C827/0x43CCD9`），本作由 `markRetreating()` 在
`step()` 选到 `retreatStepPlan` 时补置」。

### 4.3 需要新增的测试断言

> 下面 `unitsOf / runUntilOver / cancelArmyOrder / setSquadCommand` 是**示意名**（本作没有后两个，
> 见 4.2(1) 的说明），落地时按 `battle.ts` / `army_cmd.ts` 现有导出改写。

```ts
// 1. 撤退令 → 位与间隔（对应 0x4447E2 + 0x444858 + 0x43B5F1）
requestRetreat(world, 'A');
for (const u of unitsOf(world, 'A')) {
  assert(u.status & 0x4000);
  assert.equal(actionIntervalOf(u), 46);      // 主将也是 46，士兵也是 46

// 2. 非撤退的主将间隔必须是 40（回归：抓 battleView/常量名带来的误会）
assert.equal(actionIntervalOf(generalOf(world, 'B')), 40);

// 3. 不可逆（对应 §2 的五重证据）：整场跑到结束，位只增不减

assert.deepEqual(unitsWithBit(world), snapshot); // 只增不减

// 4. 取消命令不清位（对应 0x444C94 —— 本作尚未移植，实现时必须有这条断言）
//    cancelArmyOrder(world, 'A');  assert(u.status & 0x4000);

// 5. cmd 8 动作即置位（对应 0x43CCD9 / 0x43C827）
//    现在本作只有 requestRetreat 一条路能产生撤退计划，所以直接构造：
const s = squadOf(world, 'A', 0);
s.flee = false; s.status = 0;                    // 假装它是"被单独写成 cmd 8"的单位
world.armyStepPlan = () => retreatStepPlan(s);   // 或等将来有单槽命令层时直接写槽

assert.equal(actionIntervalOf(s), 46);

// 6. 撤退单位仍会被打（对应 0x43D76C 专门找撤退中的敌 unit）
assert(world.stats.attacksB > before);          // 敌方攻击数增加

// 7. 撤退单位不主动接敌（对应 0x43C084 的 early return）—— 这条当前会 FAIL，
//    要先决定是否改 step() 的 `if (foe)` 分支：撤退单位不应进入 intents
const t = fleeingUnit.lastAttackTick;
for (let i = 0; i < 200; i++) step(world);
assert.equal(fleeingUnit.lastAttackTick, t);

// 8. 视图量程（对应 4.2(2)）
assert.equal(actionGaugeOf(nonRetreatingGeneral).slow, 40);
```

**关于「半步」的落地（可选，做的话建议单独一单）**：原作第 3 节表格第 2 条是**像素级**位移减半
（`0x43BCA7` 的 count 2→1），不是「行动间隔×2」。本作 `step()` 是「一次行动走一格」，
所以等价换算有两条路：
(a) 撤退单位 `cd = interval * 2` —— 最省事，但把 46 的对外可观测节奏改掉了（46 会变成 92 的"一格周期"）；
(b) 在 `advanceSlides()`/`commitStep()` 的像素插值里让撤退单位每周期只推进半格（`u.x` 是连续量，可行）。
**建议先做 (b) 并在报告里标 `[推测]`**（原作 `0x43BBE6` 的"一小步"是像素还是半格，我没能直接证明，见 §5）。

## 5. `[未解]` 清单（缺哪一段 / 哪张表）

1. **[未解] `u+0x44` 到底是什么对象。** 它有三处不同构的用法：`[+0x2c]` ∈ {`0`,`0x800000`}（朝向对，
   `0x43C47E`/`0x43BD64`）、`[+0x4c]` = 消息函数（`0x444808`、`0x43D8C6`）、`[+0x94]` 取符号做方向
   （`0x43D8FD`）。我按「随从/显示对象」处理，但需要一张 **unit 结构字段表**（`+0x00/0x08/0x0c/0x2c/0x34/

3. **[未解] 「撤退单位挨打时是否还手」。** 三处攻击入口 `0x43D70A / 0x43D870 / 0x43DA08`（都 call
   `0x43D400`）我只看过 `0x43D76C` 这一支（它查的是**对方**是否在撤退）。要回答「不还手」，
