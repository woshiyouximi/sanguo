## 1. 一句话结果

一局打完，`settle()` 现在多返回一个 `post`：`captures[] / executed[] / released[] / drops[] / expBonus / meritBonus`。

## 4. 口径取舍：`t >= 2` 的"宁死不降"

汇编里 `t += 2` 写在掷骰**之前**，而 `if (t>=2) return 0` 写在掷骰**之后**：

```c
if (t < 0) { … if (rand()%100 >= L) return 1; … }      // 这里会先 return 1
...
if (t >= 2) { [0x4C6CEC] = 0x10; return 0; }           // 永远走不到
```

严格按控制流执行，节操 ≥3 且原势力健在的武将仍会在掷骰成功处 `return 1`，漏出 `1/3` 的成功率。
但 04b2 §2.2 的注释写的是"★ 宁死不降（**覆盖**上面的成功）"，等价概率表也直接给 0。
**本实现取文档口径：`t>=2` 一律 0，不掷骰。** 代码注释（`capture.ts:143-146`）留了这段说明，改口径时不用再翻一遍反汇编。

## 5. 概率表（代码即此表）

| 条件 | 成功率 |
|---|---|
| 君主 | 0 |
| `L < 25` | 100%（不掷骰） |
| 情义势力即招降方 / 旧主已降 | 100%（不掷骰） |
| `C < 3` 且原势力已亡（t=-1） | `1-(L/100)²` |
| `C = 3~4` 且原势力已亡（t=0） | `1-L/100` |
| `C ≥ 5` 且原势力已亡（t=1） | `(1-L/100)/3` |
| `C ≥ 3` 且原势力健在（t≥2） | 0（宁死不降） |

`L` 取 `generals.json` 的 `Loyal`，`C` 取 `CONSTANCY`；缺数据回落到 50 / 5。
`LOYAL`（情义势力）在现有 401 条数据里**全为空**，所以 `lordAlive / sameForce / lordSurrendered`
只能由调用方显式给（测试与 campaign 侧），战场层默认全 false。

## 6. 掉落与 ONLYONE

- 04b2 §5.1 是**负证据**：原作战斗流程完全不掉落，77 件物品只能靠城池"搜索"。本作按需求把轮盘接回战后，
  判定本身照抄 `0x408EE2`，没有自创概率。
- `Rate=0` 的 5 件（Seq 14/15/16/17 武器 + Seq 56 马）权重恒 0，永不掉落。
- `Attrib === "ONLYONE"` 的 16 件：`taken` 里已有该 seq → 权重 0。账本是 `state.dropTaken: string[]`，
  `settle()` 目前不传（战场层没有存档），campaign 侧接进来时要传 `save.drops`，否则唯一物品会重复出。
- 胜方每次结算**只掷一次**，用胜方主将等级当 `g->+0x2E`。

## 7. 未解 / 本作自定

| 项 | 状态 |
|---|---|
| `0x40ED3A` 被俘/逃脱公式 | **未解**。最小模型：基础 55%，败方残兵占比越低越高，被围 +20%，夹在 5%~95% |
| `expBonus` / `meritBonus` | 反汇编没有"处置奖励"这一项，是本作接的：招降 `等级×16 / 功勋+15`，斩首 `等级×32 / 功勋+10` |
| 战后补兵 | 04b2 §4：补兵发生在**势力刷新**（每 120 计数），不在战后。本模块不做 |
| 君主判定 | `isKing` 是显式入参。战场层不带势力信息，`resolvePostBattle` 默认 false；campaign 侧要把 `kings[]` 接进来 |
| 招降后的忠诚 `×2/3` | 只体现在 `post` 的 `loyal` 里，**不回写** `data/*.json`（本轮只读数据） |

## 10. 存档字段

`endBattle()` 在 `writeBackCampaign()` 之后把结果打进消息栏（`main.js:282-289`），
`writeBackCampaign()` 在 `save.ts = Date.now()` 之后追加两个字段（`main.js:316-324`）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `captured` | `string[]` | 招降成功的武将名，去重追加 |
| `drops` | `string[]` | 物品 `Sequence` 的字符串，去重追加 |

已有字段（`owned / cities / wins / losses / last / ts / defWins / log`）一律不碰。
