### 1.1 为什么旧表会错（根因，不是"猜错了一条"）

两个坑叠在一起：

1. **技能号 ≠ MagicN**。`data/magics.json` 每条技能有 `fx_func` 字段，才是真正的效果函数：
   43→`Magic43`、80→`Magic94`、102→`Magic107`（还有 75→`Magic80`、107→`Magic102`、63→`Magic51`、88→`Magic92` 等）。
   按"技能号 = MagicN"去反查，43 就永远找不到播放点。
   全表见 `docs/05c_MAGIC特效映射.md:144-209`。
2. **`MagicN` 只是薄包装**（`PUSHI 参数` + `CALL 效果函数` + `RET`），音效不在 `MagicN` 里，在它调的效果函数里。
   旧脚本 `work/sfx84/map5.mjs` 的 `backName()` 解析 `CALLS` 时取 `cands[fn.length-1]`（**最远**那个 `PUSHS`），
   正确方向是 `cands[0]`（**最近**的）。这一错让 `Pa@0x27DE0` 的 `CALLS` 被认成 `HoldAllDelay` 而不是 `CreatePa`，
   于是 080 的 `CreatePa`（真正的播放点）够不着——三条 `[X]` 就是这么来的。

改法：先用 `fx_func` 定位 `MagicN`，再顺着 `CALL` 链下到效果函数，然后在**效果函数的第一条指令**上找
`PUSHS "mNNNsndNN"` + `SYSCALL 0x301`（音效播放系统调用）。

### 1.1b 为什么"dir 号 = 音效号"这条约定会错

旧表的隐含假设是"`fx_dir_primary` = 音效号"。它在多数技能上成立，但不是规则——**一个 dir 会被多个技能共用**：

| dir | 共用它的技能 | 谁在这个 dir 里播音 |
|---|---|---|
| 021 | 054 旋燈火、077 烈火旋燈、089 神火旋張、**102 集火柱**、103 神火怒張 | `FireRing` → `m021snd01` |
| 022 | **043 狂雷天牢**、063 冰柱刺、076 冰柱群鋒、097 冰嵐刃舞 | `Ice` → `m022snd01` |

043 / 102 恰好是"主目录是共享段、本体在第二目录"的那种：043 的 `[022, 032]`、102 的 `[021, 031]`。
按主目录猜，就借到了 `Ice` / `FireRing` 的家族音；而雷电本体（`CreateSparkle`）和火柱本体
（`CreateFirePillar`）播放的是 032 / 031。**音效号要跟着效果函数真正 `load` 的目录走，不是跟 `fx_dir_primary` 走。**

另外已排除第二来源：`THINGS.INI` 里 `magic\021`、`magic\022`、`magic\029`、`magic\032` 四个目录**都没有任何
`$` 或 `!` 物件动画播放点**（`work/sfx_tempo/audit.mjs` 扫出的结果是 0 处），所以这三条音只有脚本 `SYSCALL 0x301`
一个来源，不存在"物件动画那边还有一份"的可能。

## 二、士兵行动间隔：120 → **40 帧**

### 2.1 证据（决定性，主将与士兵共用同一个计时器）

逐条来自反汇编 `work/dis_battle_units.txt`（行首是"两空格 + 8 位十六进制地址"，下面同时给地址与行号）：

**(a) 行动节奏计时器 `0x43B574` 与兵种无关，复位值硬编码 0x28 = 40**

```
:1592  int f(Unit* u)              ; 参数 [ebp+8]
:1596  [u+0x34] -= 1               ; 倒计时
:1601  cmp [u+0x34], 0
:1602  jg  0x43b65d                ; 未到期 → 走 :1664 xor eax,eax; 返回 0
:1604  [u+0x34] = 0                ; 到期先清零
:1606  cmp [u+0x3c], 0
:1607  je  0x43b5db                ; +0x3c == 0（脚本未接管）走下面这条
:1624  0043B5DE mov dword ptr [ecx+0x34], 0x28    ; ← 复位 40 帧（唯一硬编码点）
:1629  and eax, 0x4000              ; 0x43B50D 返回的状态字
:1633  0043B5FD mov dword ptr [eax+0x34], 0x2e    ; 命中 0x4000 位时改 46 帧
:1659  lea edx, [ecx+edx*2]        ; 再按与敌将行动力差追加
:1662  mov eax, 1                  ; "本帧该行动"
```

函数体里**没有任何 `cmp [u+兵种], ...` 分支**，复位值恒为 `0x28`。

**(b) 小队（士兵）更新器 `0x43D125` 直接用它**

```
:4051  0043D125 push ebp                     ; 小队更新器起点
:4055  ecx = [u+0x84]                        ; 该小队的"代表兵"指针
:4056  [ebp-0x14] = ecx
:4136  0043D24B call 0x43b574                ; 参数就是代表兵
:4138  test eax, eax
:4139  je   0x43d3b3                          ; == 0（未到期）只做逐帧动画更新
:4140-4147  缓存位置 → :4150 0x43BCA7 选目标 → :4205/:4216 0x406717 掷伤/取攻击值
            → :4234 0x43D0F1 发动画事件 → 0x43BE32
```

**也就是说：移动是逐帧的，但"选目标 + 掷伤 + 发动画事件"这一整套行动块，40 帧才走一次。**
这与本作 `battle.ts` 的分工完全一致（移动每 tick、攻击由 `actionIntervalOf` 把闸），是 1:1 的对应关系，
不是新调的手感值。

**(c) 主将更新器 `0x43E964` 是同一个调用，逐行同形**

```
:6060  0043E964 push ebp                     ; 主将更新器起点
:6205  0043EB50 call 0x43b574
:6207  test eax, eax
:6208  je   0x43ec07
:6210-6239   后续与小队侧逐行同形
```

⇒ **原作士兵没有独立值，与主将同为 40 帧。**

### 2.4 时长对拍（同 seed 20 局，只差这一个常量）

口径：`TICK_HZ = 30`，seed 1000..1019，上限 180 s（`work/sfx_tempo/durations.ts`）。
两次测量在同一棵树上背靠背跑，唯一变量是 `ATTACK_COOLDOWN`（唯一改动处 `battle.ts:78`）。

| 场景 | 120 帧 中位 / 最快 / 最慢 | 40 帧 中位 / 最快 / 最慢 | 变化 |
|---|---|---|---|
| `troop2v10`（troop 2 vs 10，form 0/0，与 `tests/battle.test.ts:118` 同配置） | **17.55** / 16.37 / 19.77 s | **11.63** / 10.90 / 12.77 s | 中位 −33.7% |
| `mixed`（troop `i%5` vs `(3i)%11`，form `i%9` vs `(4i)%9`） | **19.29** / 15.17 / 36.93 s | **12.47** / 10.43 / 16.13 s | 中位 −35.4%，最慢局 −56.3% |

尾段占比（`tailC` = 某一方存活兵数跌破自身起始 10% 之后到结束的 tick 占比，即"清残兵段"）：

| 场景 | 120 帧 中位 / 最大 | 40 帧 中位 / 最大 |
|---|---|---|
| `troop2v10` | 0.140 / 0.163 | **0.091** / 0.138 |
| `mixed` | 0.149 / **0.376** | **0.115** / **0.158** |

- 结论：40 帧把中位时长压到 12 s 上下（原型手感期是 17~19 s），**尾段占比同时下降**——
  `mixed` 最慢局从 36.93 s（尾段吃掉 37.6%）收敛到 16.13 s（尾段 15.8%），
  这正是 40 帧想要的效果：清残兵不再拖。
- `tailD`（全场存活兵数 ≤ 4 之后的占比）两种节奏下都是 **0**：单位是成排死的，会直接跳过该状态。
  （另有 `tailA`/`tailB` 两个候选定义恒为 0，原因见 2.5。）
- 基线单局（seed 7, troop 2 vs 10）：**21.17 s → 11.63 s**，仍落在 `tests/battle.test.ts:118` 断言的 8~60 s 区间内。
- 原始数据：`work/sfx_tempo/dur_120.json`、`work/sfx_tempo/dur_40.json`。

### 2.5 尾段定义踩的坑（供后来者省一次弯路）
