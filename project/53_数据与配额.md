## 1. 守军兵力：`bsoldiers = 守军/6` → 原作 `帶兵數`

### 1.1 旧口径是估值，而且事实上是个常数

旧代码（`garrison.ts` 改前）与网页（`game/web/campaign.html:1610`、`deploy.html:382`）：

```js
bsoldiers = max(60, min(100, round(守军 / 6)))
```

`garrison.json` 的守军范围是 **110..282**（`min(floor(POP/2500)+110,600)`，实测 300 城 min=110/max=282），`round(守军/6)` = 18..47，**全部低于 60** ⇒ 开局时这条公式对 300 座城**恒等于 60**（守军涨到 360 以上才会突破 60，封顶 100；网页两处的取值源不同：`deploy.html:382` 用 `garrisonOf().garrison`，`campaign.html:1610` 用存档 `save.cities[城].troops`——后者开局等于 `troopCapOf(POP)` 同式，会随徵兵 +40 增长到 600）。标注：`[新设计]`（我方网页估算，根 `project/32_大地图真值接线.md` §5.2 已自认）。

### 1.2 原作口径（证据链）

1. 战场兵力来自**武将**，不是城池：`0x43A1C4`（`docs/04b_战斗系统.md:31`）把 general 的 `體力/技力/士氣/帶兵數` 复制进战场单位 `0x4A8A60`(A)/`0x4B03A0`(B)，并置 `unit+0x70 = 150`；`unit+0x58 = 带兵 + 骑兵`（`docs/04b5:45`）。
2. 两个上限都在武将身上（`docs/04c:213-215`，`0x409FB6`/`0x409FD8`）：
   - `general+0x42` 帶兵上限 = `min(等级×5, 100)`
   - `general+0x46` 騎兵上限 = `clamp((等级−20)×5, 0, 100)`
   - 当前值 `+0x44`/`+0x48` 由补兵逻辑回填，开局等于上限（`0x40F23C` 升级时也重置为上限，`docs/04b:266`）。
3. 等级由经验反推：`0x409F73`（`docs/04b:216-240`），经验表 `0x409EE0`。`generals.json` 的 `BaseEXP` 只有两档（见 §5.3）⇒ 普通武将 **2 级 → 10 兵**，盜賊 12 级 → 60 兵。
4. 城池侧的两个数**不是**战场兵力：
   - `city+0x30`「城内总兵数」在出兵函数 `0x40C635` 里参与 `n = min(dst[+0x30]+rand(3)+1, limit, 5, ...)`（`docs/04d_AI与脚本引擎.md:107-137`）——被 `min(…,5)` 夹，量级是"部队/将数"，不是士兵数。
   - `city+0x82` 预备兵上限 / `+0x86` 现有预备兵是**补兵池**：`0x401910`（`docs/04b2:349-399`）按缺口从 `c+0x86` 扣，`不读人口`；城破时 `0x40F7BB` 直接把 `+0x86 = 0`（`docs/04b2:406`）。

**结论**：守城战的战场敌人兵力 = 守将 `帶兵數 + 騎兵數`，上限 `min(5×L,100) + clamp((L−20)×5,0,100)`（最大 200）；城内守军/预备兵只决定"打完还能不能补"，不直接上场。

### 1.3 实现

`garrison.ts:487-544` 的 `battleSetup(data, scenario, city, soldiers, { troopMode })`：

| 分支 | `enemyTroops` | `enemyTroopsBasis` |
|---|---|---|
| 默认（`troopMode` 省略 = `'exe'`）且有守将 | `clamp(params.soldiers, 1, 200)` | `'exe:帶兵數'` |
| 默认、有守将但查不到武将行（`BaseEXP` 缺失） | 同上，按 1 级 → 5 兵 | `'estimate:帶兵數缺等級'` |
| 默认、空城（无守将） | `round(我軍×0.6)` | `'estimate:我軍六成'` |
| `troopMode:'reserve'`、守军 >0 | 旧公式 `min(100,max(60,round(守军/6)),守军)` | `'estimate:守軍/6'` |
| `troopMode:'reserve'`、守军 =0 | `round(我軍×0.6)` | `'estimate:我軍六成'` |

同时把 `enemyParams`（完整的 `DefenderBattleParams`）挂进返回值，调用方要 STR/INT/体力/技力/命中都不用再算一遍。`enemyGeneral` 的形状**没动**（仍是 `{name,str,int}`），避免破坏既有 `deepEqual`。

|---|---|---|---|---|
| 襄平 | 141 | 閻圃 42/80 | 60 | **10** |

300 城全表：旧恒 60；新恒 10（因为 400 名武将的 `BaseEXP` 都是 200，见 §5.3）。**这不是 bug，是数据决定的**：原作里武将靠打仗升级（`0x40F23C`），而本仓库的存档至今没有 `level`/经验字段（`project/52_武将技与军师技.md:266` 已记），所以重制版里守将永远停在 2 级。要让守军随剧本变强，前置工作是给存档补等级进度，不是调这条公式。

## 2. 守将属性 → 战斗参数

### 2.1 结论：原作**没有**"武力/智力 → 兵种强度/技力"的换算层

`docs/04b5_战力基准与疲劳反汇编.md` §3 把 `0x430000–0x455000` 里真正读 general 武力/智力的函数全列了，只有 7 个，没有一个把 STR 变成"兵种强度"或"伤害倍率"：

| 函数 | 用途 | 公式 |
|---|---|---|
| `0x43D400` | 兵 → 将 命中 | `150 − 武力×20/100` |
| `0x43D4CB` | 将 → 将 命中 | `150 + (STRa − STRb)/2`；将→兵 `150 + STR/2`（补漏 `0x43B6C9` 分支 `150 + STR/3`） |
| `0x43E72E` | 武将技效果值 | ×{130,150,200,76,66,50}%（按技，不按智力） |
| `0x44D3E0` | AI 选目标 | 只做比较 |
| `0x441212` / `0x449900` / `0x44EEA6` | UI 显示 | 只读 |

兵种强度完全由**兵种相克表** `0x48CD88`（13×13，−68..+68）决定；技力上限 `0x40A098` 里 **INT 只对"武力低于智力"的人生效**（`t = STR>INT ? (STR+INT)/2 : INT`），这是本仓库唯一被忽略的智力用法，已在 `mpMax` 里照抄。

### 2.2 已确认字段（全部实现进 `defenderBattleParams`）

| 字段 | 公式 | 出处 |
|---|---|---|
| `level` | 存档 `level` → 否则由 `BaseEXP` 反推（`0x409F73`） | `docs/04b:216-240` |
| `troopsMax` | `level ≥ 20 ? 100 : level×5` | `0x409FB6`，`docs/04c:213` |
| `cavalryMax` | `clamp((level−20)×5, 0, 100)` | `0x409FD8`，`docs/04c:215` |
| `soldiers` | `troopsMax + cavalryMax`（战场单位 `unit+0x58`） | `docs/04b5:45` |
| `hpMax` | `BaseHP + level×2×STR/100`（≥BaseHP，≤0x7FFF） | `0x40A020`，`docs/04b:233` |
| `mpMax` | `BaseMP + level×2×t/100`，`t = STR>INT ? (STR+INT)/2 : INT` | `0x40A098`，`docs/04b:236` |
| `hitVsSoldiers` | `150 + STR/2` | `0x43D4CB`，`docs/04b5:31` |
| `hitFromSoldiers` | `150 − STR×20/100` | `0x43D400`，`docs/04b5:30` |
| `powerBase` | 150（硬编码） | `0x43A3AD`/`0x43A3B7` `mov [slot],0x96`，`docs/04b5:14-18` |
| `morale` | 80（TIMES 默认 `0x42D468`） | `docs/04b5:19` |
| `moraleTerm` | `trunc((士气−50)/5)` = 6 | `0x442EFA`，`docs/04b:258` |

`hitVsGeneral(attacker, otherStr) = 150 + trunc((str − otherStr)/2)` 也导出了（`garrison.ts:472`），web 现在拿 STR 直接塞给战斗核心是**对的**，不是估值。

### 2.3 未知/无映射字段清单（`NO_MAPPING_FIELDS`，随每个 params 返回）

1. **兵种强度**：原作没有"武力 → 兵种数值"的换算，强度只来自相克表 `0x48CD88`。
2. **技力伤害/效果倍率**：`0x43E72E` 按**技**取系数，不按智力；智力只参与 `mpMax`。
3. **战力倍率**：战力五段全是**加法**（`docs/04b5:39-44`），没有 `(1 + 武力/100)` 这种乘法项。
4. **装备数值**：`+0x34/+0x36`（含装备的武力/智力）我们只有裸值 `STR/INT`，武器/马/宝物的加成没有映射。
5. **地形/阵形对个人的加成**：`0x4307AE`/`0x4307E5` 按**兵种/阵形 id** 查表，跟武将属性无关。

### 2.4 web 现有兜底公式的定性

| 位置 | 现在的写法 | 定性 |
|---|---|---|
| `campaign.html:1612-1613` | `bstr: enemy.enemyGeneral.str`、`bint: …int` | **正确**（原作将→将命中确实直接用裸 STR），不是估值 |
| `main.js:565` / `campaign.html:1616` | `level: 5` 写死 | `[新设计]`：只为让战斗核心算骑兵/站位，和原作等级无关；接 `defenderBattleParams().level` 即可 |
| 士气 | `moraleOf()` 从存档算 | `[新设计]`，原作 `+0x38` 由 `0x4017E1` 重算（未反汇编） |

## 3. R28：阵形只有 9×9

### 3.1 原作是 11 阵

- 相克矩阵 `0x0048D2A0`，**11×11**，stride `0x2C`（`docs/04b:331-343`）；`XLS` 只导了 9×9，EXE 里是 11。
- 索引 9 = 特殊陣型（名串 `0x48B00C`）、索引 10 = 亂陣（`0x48B000`）；亂陣对任何阵 −25，任何阵对亂陣 +25（`docs/04b:345`）。
- 站位表 `docs/04b1_阵形站位表.md` 也是 11 槽（`a0..a8` 常规 + `a9 亂陣` + `a10 特殊陣型`）。

### 3.2 现状：数据已经是 11×11，测试也在（上一轮补的）

`game/data/formations.json`（29328 行）里 `matrix` 11 行、`slots` 11 项、`matrix_names` 11 项、`matrix_source.va = 0x0048D2A0`；`game/tests/formation11.test.ts`（7 条）逐项 `deepEqual` 了 `docs/04b:331-343` 的 11×11 金标准、反对称、亂陣行/列、接口越界回 0。**本轮核对：数值与文档逐格相同，不需要改数据**。

### 3.3 两个索引空间的命名矛盾（本轮没改，写清原因）

| 来源 | 索引 9 | 索引 10 |
|---|---|---|
| `matrix` / `matrix_names`（相克表，依 `docs/04b:331-345` + 行语义） | 特殊阵型 | 乱阵 |

## 4. R56：斩首/被俘武将不出池

### 4.1 三个真问题

1. `capture.ts` 的斩首分支只加经验/战功，**没有任何池子变更**——被斩的人下次还能被招降。
2. `roster.ts` 的 `applyCapturesToRoster` **只加不删**，招降者进了新城、旧城名单里还留着同名副本（`web/city_model.js` 靠 `_moved` 才不显示，但数据是脏的）。
3. **君主会被俘甚至被斩**：`captureChance()` 不排除君主，`isKing` 只让招降率=0 ⇒ 君主照样进 `captures`，然后 50% 走斩首。这违反 `0x40975E`（`docs/04b:526-569`：君主被围只是"我們俘虜了敵方君主，但被逃了"，条目状态 7）。

### 4.2 修法

**capture.ts**
- `PostBattleReport` 增 `kingsEscaped: string[]`（`capture.ts:82-97`），`emptyReport()` 同步。
- `isKingOf(g, data)`（`:150-159`）：`g.isKing === true` 或名字出现在任一 `scenarios[].kings[].NAME`。
- `resolvePostBattle` 循环第一步就拦（`:408-415`）：`alive === false` 跳过 → 君主进 `kingsEscaped` 跳过 → 才轮到被俘掷骰。
- 顺手修掉**字段透传丢失**（`:390-406`）：构造败方 roster 时原来只复制 `name/str/int/level/alive/loyal/constancy`，`isKing/lordAlive/sameForce/lordSurrendered` 全丢，调用方显式标 `isKing` 也不生效。

**roster.ts**
- `DEAD = '陣亡'`（`:38`）+ `removeFromPools(save, names)`（`:117-135`）：从**所有城**名单删掉，并写 `roster._moved[name] = DEAD`；即使此人不在任何城名单里也记死（守将可能在野外/敌城数据里）。
- `applyPostBattle(save, post, homeCity)`（`:173-189`）：先 `removeFromPools(post.executed)` → 招降者从别城名单摘掉 → 再 `applyCapturesToRoster`，返回 `{added, removed}`。
- `applyCapturesToRoster` 增一条 `isDead()` 守卫，且**不再创建空的 `roster[homeCity]`**（旧行为会给没打过仗的城建出空名单）。
- 新增只读入口 `movedOf(save)`/`deadNames(save)`/`isDead(save,name)`，避免调用方对 `CampaignSave.roster` 做 `as any`。

### 4.3 为什么用 `roster._moved[name] = '陣亡'` 而不是 `save.dead[]`

`game/web/city_model.js:509-542` 的 `rosterOf()` 与 `:548-567` 的 `stationedNames()` **只认 `_moved`**：

```js
const moved = save?.roster?._moved || {};
...
const movedTo = moved[NAME];
if (movedTo && movedTo !== cityName) continue;   // 既不在原城，也不进 wildPool
```

新增 `save.dead` 字段 web 读不到 = 没修；而空串会被 `moved[name] || ''` 当成"没调动"，所以哨兵值必须非空。用"陣亡"，UI 的调动记录也能直接显示。

### 4.4 君主规则没被破

`capture.test.ts` 第 ⑩ 条：掷骰全 0（换成普通将必被俘并斩首）时，君主 `kingsEscaped = [king]`、`captures/executed/released` 全 0；显式 `world.sides.B.general.isKing = true` 等价；同一个 rng 的普通将仍然 `captures 1 + executed 1`。第 ① 条另测君主招降率恒 0（即使忠诚 5）。

## 8. 没定位到的部分（附证据）

1. **`captureChance` 的掷骰式**：`04b2` 全文（320-430 行）只有"被围/残兵影响"的定性描述；`0x410CA3` 是战损、`0x40ED3A` 只返回"俘/不俘"（0/非 0），中间的概率计算没有伪码。保持最小模型并标 `[推测]`。
2. **招降/斩首/释放的处理函数**：`0x40452E+0x1CF` 引用了 `0x491D8C "抓到敵將，如何處理?"`、`0x491DDC/DE8/DF4`、`0x4811F8 "%s將軍被斬首了!!"`，但函数本体没反汇编出来（`04b:560` 明写"处理函数未定位"）。所以"斩首后从池移除"这一步是按**语义**补的（`04c:308-316`："斩将 → 从池中释放（死亡不可复活）"），不是按指令。
3. **`unit+0x30` 的写入点**（`04b5` §5 未解）：它参与战力第 4 段 `(unit+0x30+50)/100`，但写它的指令没找到，所以这段本轮没有实现（`04b5` §4 也建议先不加）。
4. **城池字段偏移矛盾**：`07b_存档字段详解:206-207` 说 `+0x086` = 预备兵上限、`+0x08A` = 现有预备兵，与 `04c:137-141` 的 `+0x82/+0x86/+0x8A` 差 4 字节。本轮以 `04c` + `0x42D8F0` 常量（`0x9C4/0x6E/0x258` = 2500/110/600）为准，因为公式能对上数据（300 城 0 处不符），`07b` 那份疑似整体偏移 4 字节未校正。
5. **`+0x42/+0x44` 的方向矛盾**：`04b:59-60` 与 `04c:213` 说 `+0x42` 上限、`+0x44` 当前；`04b4` §4.3 说反了。本轮按前者（有 `0x409FB6` 公式佐证，且 `0x401910` 的缺口算是 `+0x42−+0x44`）。
6. **等级进度**：存档没有 `level`/经验字段（`project/52:266`），所以 `defenderBattleParams` 只能从 `BaseEXP` 反推开局等级；想让守军随剧本成长需要先做升级系统。
7. **`0x40C511`（出兵上限 `limit`）的语义**：`04d:107-137` 只写了它被调用，没反汇编；不影响本轮的 `enemyTroops`（走武将带兵），只影响 AI 出兵数。
