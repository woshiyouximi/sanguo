**时间**：2026-11-25 19:22:57–19:23:25（损坏），19:35–19:40（还原完成）
**影响**：`game/src/core/battle.ts`（1962 个 U+FFFD）、`game/src/view/layout.ts`（150 个 U+FFFD）

## 1. 成因（单条命令）

```powershell
(Get-Content src\view\layout.ts -Raw) -replace '\[6\.31, 64\.49\]', '[6.29, 64.49]' | Set-Content src\view\layout.ts -NoNewline
(Get-Content src\core\battle.ts -Raw) -replace '≈ \[6\.31, 64\.49\]', '≈ [6.29, 64.49]' | Set-Content src\core\battle.ts -NoNewline
```

Windows PowerShell 5.1 的 `Get-Content`/`Set-Content` **默认按 ANSI（CP936）读写**，而源文件是 UTF-8：读出时非法字节被替换成 `?`(0x3F)，写回时中文与部分换行一起丢失。**字节级不可逆**——重新按 UTF-8 解码救不回来（battle.ts 585 行非法、layout.ts 47 行非法）。

同样的坑此前已发生过两次：`work/fidelity/gen_expect.mjs`（project/192 §六）、`tests/yearsettle_r7.test.ts`（更早）。**这是第三次，已写进交接简报坑表首条。**

## 5. 教训（已写进清单）

1. **改任何 `.ts`/`.js`/`.html` 只用 `write` / `edit` 工具**，或 python 显式 `encoding='utf-8'`；PowerShell 只用来跑 `node`/`tsc`/构建/读日志。
2. 若必须用 pwsh 批处理，先 `Get-Content -Raw -Encoding utf8` + `Set-Content -Encoding utf8`，且做「写前备份 + 写后 U+FFFD 计数」两道校验。
3. **同步脚本必须有跳过名单**，且键要与 `walkTs()` 的相对根一致。
4. 交付前跑一遍 `grep -c $'\ufffd'`（或 python 扫描）作为编码烟测；本次事故若早有这道，能当场发现。
