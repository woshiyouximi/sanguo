### 2.1 三条同一根因：逐帧兜底改成按 g3 结算（改实现）

文件：`game/src/core/smartscript/runtime.ts` → `resolveFrameHits()` 末尾的逐帧兜底。

**改前**
```ts
if (pts.length === 0 && !this.isHeal && !this.isSummon
    && (this.lastFrameEndedScript || this.framesSeen >= 3) && !this.fallbackApplied) {
    this.fallbackApplied = true;

```
**改后**
```ts
if (pts.length === 0 && !this.isHeal && !this.isSummon
    && (this.lastFrameEndedScript || this.framesSeen >= 3) && !this.fallbackApplied) {
    this.fallbackApplied = true;
    const g3 = this.generalOf(this.targetHandle) || this.targetHandle;
    const victim = this.byHandle.get(g3);
    if (victim && victim.alive)
        pts.push({ x: victim.x, y: victim.y, r: 1.4 });
    else
        pts.push({ x: this.castAim.x / 96, y: this.castAim.y / 72, r: 1.4 });
}
```
**依据**
- `Hurt @0x12B8`（`magic_so.dis.txt:0012D8-0012E8`）：非主将受害者只放 `Hit01` 音效就 `RET`，主将才落到 `0x125` 扣血。端口里 `Hurt` 的受害者来自碰撞回调的 `victim = generalOf(standing)`（`0x40AB65` 取 `hitUnit[+0x44]`）⇒ **引擎把伤害指向"目标单位"，不是"落点"**。

- `G[3]` 的唯一写者 `0x43BA59`（`0x43BA8C`/`0x43BA9D` 写 `[0x4a6878+8]`/`+12`），`project/154 §1.2`。

## 4. 金标准两条的处理（含存疑）

### 4.1 606 帧数：562 → 559（已证明"562 属于旧布局"）

- 金标准出处：`work\_m4_baseline.txt:1099`（len=562, sum=15, 击杀帧 `2:2 53:2 60:1 122:2 123:2 124:2 367:1 561:3`），同值还在 `work\test_r170b.log:1096`、`work\test_r171.log:1097`、`work\n3_tests_base.txt:1098`、`work\era_ui_baseline.log:1098`。

- **漂移归因**：562 出现在 m4 的 baseline（`work\_m4_baseline.txt`），m4 改落位之后它自己的日志（`work\_m4_after_fixtures.txt:24`、`work\_m4_after_items.txt:3323`、`work\_m4_final_full.txt:1815`）全部变成 556；n3 的 `work\n3_tests_*.txt` 也是 556。R183 之前仓库的 556 就是 m4 那一轮的产物，本轮换兜底目标后是 559（同一 fixture 下确定性值）。
