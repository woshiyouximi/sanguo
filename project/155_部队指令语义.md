# 155 部队指令语义（18 个执行入口 → 精确数值 + 引擎等价）

> 范围：第二层 6 条子菜单（串表 `0x48F94C`–`0x490294`，指针表 `0x48EB60`，执行表 `0x48EE78`）
> 的 18 个入口，以及它们在**同一帧**里被哪个函数消费、每一步走多远。
> 全部结论都给了 VA；`[推测]` 只在拿不到常量/拿不到分支尾部时出现。
> 反汇编基座：`work/re_speed/insn.json`（166,200 条，0x401000–0x47E3FE）+ 手写 PE 解析
> `work/army_step/rq.py`（无 capstone/pefile 环境下的查询器）。原作 EXE：
> `三国群英传2 修正版 1.05+/Sango2.exe`（682,496 B）。

---

## 0. 一句话结论

**18 个入口全部只是「命令字写入器」**：把 0..9 的整数写进
`army+0x94 + idx*4`（idx = 0..7，槽 0 = 主将，1..7 = 部队），**没有任何一个入口**
直接改坐标、改速度、改状态位、改 AI 目标。

真正决定"这一步走多远、往哪走"的是**消费端**：

```
每帧 unit 更新器
  └─ 0x43B574(u)            行动节奏闸门：u+0x34 每帧 −1，归零那一帧才"行动"
       ├─ 有邻敌 0x43BD64(u,dir)==1?  → 攻击序列（本帧不移动）
       └─ 无邻敌                      → 0x43CF07(u,cmd)（主将）/ 0x43CFB1(u,cmd)（小队）
             └─ 9~10 项 handler → 0x43C4C0(u, sx, sy, desc)  通用走位器
                   └─ 0x43C2A5(sx,sy,desc+4,out[8])  加权**随机**抽样出 8 个候选方向
                         └─ 命中空格 0x43B467 → 0x43BF26(u,tx,ty,desc[0]) 设"目标格"
                               └─ 0x43BE42 用 (目标格像素 − 当前像素)/0x28 设速度
```

因此：**位移 = 每行动 tick 恰好 1 格（8 邻域之一），不是速度倍率、不是自由向量，
也不是"点到点的目标格"。** 视觉上是 40 帧滑过去（`speed=0x28=40`），与行动间隔 40 帧严丝合缝，
所以整段运动看起来是连续匀速的——这是最容易误判成"改速度"的地方。

### 1.3 `0x43C2A5` 方向抽样器（`[确认]`，纯计算，无副作用）

```c
void gen(int sx, int sy, int *accum, short out[8][2]) {
    int t = 3*(sy+1) + sx + 1;                    // sx,sy ∈ {-1,0,1} → t ∈ 0..8
    if (t < 0 || t >= 9 || g_48E580[t] == -1) {   // t==4 → 全 0（这就是"待機"）
        for (i=0;i<8;i++) out[i] = (0,0); return;
    }
    int mode = g_48E580[t];
    int bucket[8], sum = 0;
    for (i=0;i<8;i++) { bucket[i] = accum[i]; sum += accum[i]; }
    int pick[8];
    for (i=0;i<8;i++) {
        if (sum <= 0) { pick[i] = -1; continue; }
        int r = 0x450117(sum);                     // ★ rand() % sum
        for (j=0;j<8;j++)
            if (r < bucket[j]) { pick[i]=j; sum-=bucket[j]; bucket[j]=0; break; }
            else r -= bucket[j];
    }
    for (i=0;i<8;i++) {
        if (pick[i] == -1) out[i] = (0,0);
        else { int k = (mode + g_48E5A8[pick[i]]) & 7;
               out[i] = (g_48E560[k].dx, g_48E560[k].dy); }
    }
}
```

- 权重桶 `j` = "相对基准方向旋转 `rot[j]` 的候选"，**无放回抽样**；
- `pick[i] == -1` 就是候选列表结束（走位器遇到 `(0,0)` 即 break）；
- 所以 `accum[0]=80,accum[1]=10,accum[2]=10` 的语义是：
  **80% 先试正前，10% 先试 −45°，10% 先试 +45°**（后面的桶是"第一个被占时"的备选）。

### 1.4 `0x43C4C0(u, sx, sy, desc)` 通用走位器（`[确认]`，size 664）

```c
x0 = u->+8; y0 = u->+0xc;
gen(sx, sy, desc+4, off);                                  // 第一组：直行/锥形
for (i=0;i<8;i++) {
    if (off[i] == (0,0)) break;
    tx = x0+off[i].dx; ty = y0+off[i].dy;

        0x43BF26(u,tx,ty,desc[0]); 0x43BE32(u); return;     // 落到该格（1 格！）
    }

gen(sx, sy, desc+0x24, off);                               // 第二组：主方向被堵时的「更宽扇形」
for (i=0;i<8;i++) {
    if (off[i] == (0,0)) goto after;
    tx = x0+off[i].dx; ty = y0+off[i].dy;
    if (0x43AF54(tx,ty)) {                                 // 该格在战场内
        0x43B51E(u,0x1000);                                // 置「试探攻击」位
        r = 0x43C20D(u,tx,ty);                             // 该格能否进入（只放行己方空位）
        0x43B538(u,0x1000);                                // 清位

        0x43BFE7(u,tx,u->+0xc,0); 0x43B51E(u,0x8000); 0x43BE32(u); return; // 真的走出场 → 退场倒计时
    }
    if (0x43B6A8(u) && (0x43B50D(u) & 0x100) && !0x43AF54(tx,0)) {         // 主将 && 後退旗标 && tx 已越界

after:
```

`0x43B467(x,y)`：`if (!0x43AF54(x,y)) return 0; return 0x43AF7A(x,y) == 0;`（`0x43B467` @ `0x43B467..`，见 §1.4 调用点 `0x43C549`）
⇒ **第一组候选项必须落在界内且没有其他单位**（占位数组 `0x4B3CA0`，行 stride `0x11C`）。
⇒ **第二组候选项只要在界内就交给 `0x43C20D` 判**（它才是"这格能不能进"的判定，`0x43C626`）。
`0x43AF54(x,y)` = 纯边界检查（`0x43AF57..0x43AF79`）：`0<=x<0x47(71) && 0<=y<0xE(14)` → 1，否则 0。
`0x43B50D(u)` = `return u ? u->+0x2c : 0`（状态字 getter，`0x43B50D..0x43B51D`）。

**`0x43C20D(u,x,y)`（第二组候选的准入判定，`0x43C20D..0x43C2A1`，返回 1 = 可进入该格）** `[确认]`：

```c
other = 0x43AF7A(x,y);                        // 占位数组里该格的 unit
if (!other) return 1;                          // 空格 → 可走
if (other->+0x30 == 0x468720()) return 0;      // 对方本帧刚动作过 → 让
if (other->+0x40 != u->+0x40) return 0;        // ★ 不同阵营（敌人）→ 拒绝（走位器不踩敌格）
if (other->+0x2c & 0x1001) return 0;           // 对方处于 0x1000(被试探) 或 0x1 → 拒绝
obj = other->+0x44; obj->vcall`0x4c`(obj,2,0); // 通知友军"让位/被挤"
return 0x43AF7A(x,y) == 0;                     // 再看一次真空出来了没
```

⇒ **第二组权重（60/15/15/5/5 的宽扇形）实际是「挤友军位」通道**：正前方那格被己方单位占着时，
会横向找 45°/90° 方向的己方空闲单位请它让开，然后占那格；对敌格一律拒绝（打不打由
`0x43BD64` 的邻敌判定单独管，见 §3）。

### 1.5 落位三件套（`[确认]`）

```c
0x43BF26(u,gx,gy,jitter):
    obj->+0x2c = (gx > u->+8) ? 0 : (gx < u->+8 ? 0x800000 : 保持)   // 朝左/朝右
    0x43BE42(u,gx,gy,0x28,jitter)                                    // speed = 40 帧/格
    0x43B028(u->+8,u->+0xc,0)                                        // 释放旧格
    u->+0x10 = u->+8; u->+0x14 = u->+0xc;                            // 记"上一格"
    u->+0x8 = gx;     u->+0xc = gy;                                  // ★ 逻辑格瞬移

0x43BE42(u,gx,gy,speed,jitter):
    0x43A4E0(gx,gy,&px,&py);                    // px = gx*0x60+0x30, py = gy*0x48+0x24
    if (jitter == 0) { px += rand()%0x30 - 0x18; py += rand()%0x24 - 0x12; }
    dx = (px<<16) - obj->+8;  clamp ±0x780000;   // 120 px
    dy = (py<<16) - obj->+0xc; clamp ±0x5a0000;  // 90 px
    0x42249B(obj, dx/speed, dy/speed, 0);        // 设速度（16.16 定点）
```

- **一格 = 96 × 72 像素**（`0x43A4E0`），格中心 = `(0x30,0x24)`；逆变换 `0x43A51D/0x43A542`；
- `unit+0x8/+0xc` = 当前逻辑格；`unit+0x10/+0x14` = 目标格 / 上一格（`0x43BE08` 拿它判"已站定"）。

### 1.6 行动节奏闸门 `0x43B574`（`[确认]`，这就是"每 tick 位移"的来源）

```c
int 0x43B574(unit *u) {              // 返回 1 = 本帧可以行动
    if (--u->+0x34 > 0) return 0;
    u->+0x34 = 0;
    if (u->+0x3c != 0) { obj = u->+0x44; obj->vcall`0x4c`(obj,0x1000d,0); return 1; }
    u->+0x34 = 0x28;                                   // ★ 40 帧
    if (0x43B50D(u) & 0x4000) {                        // 撤退态
        u->+0x34 = 0x2e;                               // ★ 46 帧
        if (0x43B6A8(u))                               // 武将额外惩罚
            u->+0x34 += 2 * (0x4429FD(0x43B9FC(u)) - 0x4429FD(u));
    }
    return 1;
}
```

⇒ 普通单位 **每 40 帧行动一次**，每次最多走 1 格；撤退态 46 帧，主将撤退再加
`2*(敌将+0x40 − 自己+0x40)`。**"移动速度"这个概念在 EXE 里不存在。**

### 1.7 随机源（若要逐位一致）

`0x450117(n)` = `if (n==0) 0 else rand32() % n`；`0x450132()` 自研 PRNG，状态 `0x4922FC`(c)/`0x492300`(s)：

```c
c = c + 1; s = s - 1;
s = (s >> (c&31)) + (s << (32-(c&31)));   // = ROR(s, c&31)（x86 移位计数 &31，
c = (c << (s&31)) + (c >> (32-(s&31)));   //   c&31==0 时不变，实为 s+=s ⇒ 2s）
return s + c;
```

## 3. 生效时机（三段时间轴）

1. **T0 按下菜单**：入口把命令字写进 `army+0x94+idx*4`（`0x43ADED`），立即生效的是
   *军团的命令表*，不是单位。
2. **T0..T0+40 帧的每个 unit 更新帧**：`0x43AF1A(u)` = `return army->[0x94/4 + u->+0x20]`（读本槽命令字，
   `0x43AF1E..0x43AF3A`）；`0x43AF3B(u,cmd)` = `return cmd != u->+0x24`（是否变化，`0x43AF44 cmp/jne`）；
   变了就 `0x43AF0C(u,cmd)` = **`u->+0x24 = cmd`（只是把"上次命令"存进 `unit+0x24`，不清任何状态位）**
   `[确认，`0x43AF0C` 全体只有 4 条指令]`；随后 `0x43B574(u)` 闸门
   —— 只有 `u+0x34` 归零的那一帧才真正执行。
3. **行动帧内二选一**：`0x43BD64(u,dir) == 1`（邻格**没有**敌人）→ 执行移动命令；
   否则走攻击序列（`0x43CCE3` / `0x43C1E7` / `0x43D0F1(u,dir,0)` / `0x43BE32`）。
   即**"能打就不走"**，移动与攻击在同一个行动 tick 里互斥。
4. **落格**：`0x43BF26` 立即把 `u+0x8/+0xc` 改成新格（逻辑瞬移），
   `0x43BE42` 用 `(目标像素−当前像素)/0x28` 设速度，视觉上 40 帧滑到位 —— 下一行动 tick 恰好接上。
5. **持续性**：槽值不清零，命令**一直有效**（待機就永远不动，前進就一直每 40 帧走一格），
   直到玩家改令、或死亡链 `0x4447B7` 强写 8、或 `0x4A8AE0` 状态位改变让入口不可用。

## 4. 给我们引擎的等价实现建议

### 4.1 单位换算（原作 → `game/src/core/`）

| 量 | 原作 | 我们 | 换算 |
| --- | --- | --- | --- |
| 网格 | 71 列 × 14 行 | `GRID_W=71`、`GRID_H=14` | **完全一致**（`docs/04b1` 已核） |
| 1 格像素 | 96 × 72（`0x43A4E0`） | `ROW_PX = 96*SCALE`、`LANE_PX = 750/GRID_H` | x 同源；y 是竖屏压缩 72→53.57（0.744×），**格数不变** |
| 行动间隔 | 40 帧（`0x43B574` 写 `0x28`） | `ACTION_INTERVAL_TICKS = 40`（`TICK_HZ=30`） | **一致**（1 tick = 1 帧已是既有口径） |
| 每步位移 | **1 格 / 40 帧 = 0.025 格/tick** | `MOVE_PER_TICK = 0.09`（连续） | 我们快 **3.6×** |
| 速度倍率 | **不存在** | `ARMY_MOVE_SPEED.{back,spread,focus,shift}` 全 1.0 | 应删除（不是"未知"，是"没有这个概念"） |

"每 tick 位移"的等价公式（若要连续插值）：

```
step_per_tick = 1 / ACTION_INTERVAL_TICKS = 0.025 格/tick
   → x: 96px/40帧 = 2.4 px/帧      y: 72px/40帧 = 1.8 px/帧（原作坐标）
   → 我们竖屏: 0.025 * ROW_PX / LANE_PX 同理
但方向必须**每 40 tick 才重算一次**并落到整格，中途只做线性插值。
```

### 4.2 要改的函数（`game/src/core/army_cmd.ts`）

```ts
// ① 删：ARMY_MOVE_SPEED 四个倍率（原作无此概念）
// ② 删：armyAdjustMove() 里 back/spread/focus/shift 的"连续向量"分支
// ③ 加：整数格步长 API（替代上面的位移向量）

/** 一次行军步（格），只在行动 tick 上返回；null = 本 tick 不动 */
export interface ArmyStep { dx: -1|0|1; dy: -1|0|1 }

/** 复刻 0x43C2A5：sx,sy ∈ {-1,0,1}，返回 8 个候选 (dx,dy)，按权重无放回抽样 */
function pickOffsets(sx: number, sy: number, accum: readonly number[], rnd: () => number): ArmyStep[]

/** 复刻 0x43C4C0：按候选顺序找落点 —— 先第一组（必须是空格 0x43B467），
 *  再第二组（交给 0x43C20D：只放行「己方空闲单位的格」，对它请其让位）；全失败 → 原地 */
function chooseArmyStep(world: World, u: Unit, sx: number, sy: number, desc: DescIdx): ArmyStep | null

/** 命令 → (sx,sy,desc) 的几何，逐条对齐 §2.2 表 */
function planStep(world: World, side: Side, u: Unit, cmd: number): { sx: number; sy: number; desc: DescIdx } | null
```

`planStep` 的伪代码（与 handler 一一对应）：

```ts
switch (cmd) {
  case 0: return { sx: 0, sy: 0, desc: D_48E6A0 };                    // 待機 → gen 全 0 → 原地 + 面向敌
  case 1: {                                                          // 前進（槽 1..7 通用）
    if (reachedFrontline(world, side, u)) return towardArmy(world, u, foeArmy(world, side), D_48E808);
    if (u.slot === 1 && isStraightAdvance(world, side)) return { sx: dir(side), sy: 0, desc: D_48E730 };
    return { sx: dir(side), sy: 0, desc: D_48E6E8 };                 // 锥形 80/10/10
  }
  case 2: return { sx: -dir(side), sy: 0, desc: isFirstSquad(u) ? D_48E7C0 : D_48E778 };
  case 3: return { sx: 0, sy: +1, desc: D_48E7C0 };                  // 上移（+y）
  case 4: return { sx: 0, sy: -1, desc: D_48E7C0 };                  // 下移（−y）
  case 5: {                                                          // 分散
    if (reachedFrontline(...)) return towardArmy(...);
    const y = u.y;
    if (!(y > 3 && y < 10)) return { sx: dir(side), sy: 0, desc: D_48E6E8 };
    return { sx: dir(side), sy: y >= 7 ? +1 : -1, desc: D_48E6E8 };
  }
  case 6: {                                                          // 集中（目标行 6！不是 6.5）
    const dy = 6 - u.y;
    if (dy === 0) return { sx: dir(side), sy: 0, desc: D_48E898 };   // 35/5/…/35
    return { sx: 0, sy: Math.sign(dy), desc: D_48E850 };
  }
  case 7: return towardUnit(world, side, u, rushTargetOf(world, side), D_48E808);
  case 8: return { sx: -dir(side), sy: 0, desc: D_48E8E0 };          // 撤退（另置 0x4000）
  case 9: return towardArmy(world, side, u, ownArmy(world, side), D_48E808);
}
```

```ts
// ④ 加：行动 tick 状态（原作 unit+0x34；我们 step() 没有这个概念）
interface Unit { armyStepAt?: number }         // 下次可行动的 world.tick（初始 0）
// ⑤ 加：突擊目标缓存（原作 army+0x38F4）
interface ArmyOrderState { rushTarget: Unit | null; rushTargetIdx: number }
// ⑥ 加：撤退态 46 帧 + 主将追加惩罚（0x43B574 的后半）
const stepInterval = (u: Unit) => (u.status & 0x4000) ? (u.isGeneral ? 46 + 2*(…) : 46) : 40;
```

`stepWithArmyOrders()` 的调用时机要改：**不要每 tick 调 `armyAdjustMove` 改 `m`**，改成

```ts
for (const u of sideUnits) {
  if (world.tick < (u.armyStepAt ?? 0)) continue;         // 未到行动帧
  if (hasAdjacentEnemy(world, u)) continue;               // 原作"能打就不走"
  const plan = planStep(world, side, u, cmdOf(u));
  const step = plan && chooseArmyStep(world, u, plan.sx, plan.sy, plan.desc);
  if (step) snapToCell(u, u.x + step.dx, u.y + step.dy);  // 1 格，整格
  u.armyStepAt = world.tick + stepInterval(u);
}
```

> 若要保持我们引擎"连续走位"的观感，`snapToCell` 换成
> `startWalk(u, target, ticks = 40)`，中途不重算方向；这等价于原作的
> "逻辑瞬移 + 40 帧视觉滑动"，只是把插值放在我们这一侧。
