# R245 状态与存盘台账（重新梳理「武将在哪」）

制作人反馈（m07969）：攻下城后武将消失、AI 围城不点守城战就永远悬着、守城战能编入 AI 的将。
结论：不是某一处写错，而是**「武将在哪」有四五份互相冲突的真相**。这一轮不补丁，改成单一台账。

## 一、现状：四份真相

| # | 真相 | 存在哪 | 谁写 | 谁读 |
|---|---|---|---|---|
| 1 | 在城武将 | `save.roster[城]` | 派兵 `march()` 摘人、落城 `absorbArmyPeople()` 补人、招降、月初 AI | 出征候选、名册、搜索执行人、城面板 |
| 2 | 城守将快照 | `save.cities[城].officers` | `garrison.json` 播种、AI 月结回写 | AI 判定、城情 |
| 3 | 在途兵团 | `save.armies[].general/officers` | `dispatchMarch()` / `pushReturnArmy()` | 行军、遭遇战、守城战敌情 |
| 4 | 抵达待战 | `save.siege`（快照） | `startArrivalSiege()` | 攻城战编成 |
| 5 | 剧本表现算 | `generals.json` / `garrison.json` | —— | `ownedCityNames()` 的回落、`enemyIntelOf()` |

冲突点：
- 同一名将可以同时出现在 1 与 3（没摘干净）、1 与 4（快照与名册都写）、1 与 2（旧主名单没清）。
- 5 会「凭空生成」驻将：我方打下的城如果名册为空，回落剧本表就把**前主人**的将当成我方守将（R244 已加 `takenOver` 挡住，但保底本身没拆）。
- 攻城战胜利后谁来写 1：`recordBattleResult()`（按 `armyId`）与 `absent 的兵团` 相互错位，于是 R244 才需要 `returnGeneralsToCity()` 这种补丁。

## 二、目标模型：一名武将恰好在一个位置

```
city:<城>   在城     → save.roster[城] 里有名字
army:<id>   在途     → save.armies[id].general/officers 里有名字
siege:<城>  抵达待战 → save.siege 快照里有名字（短暂，进战斗即消费）
gone        已死/俘  → save.generalStatus[名] = '死' | '俘'
```

四条不变量（可机械检查）：
1. **不重叠**：一个名字最多出现在上述一个位置。
2. **不失踪**：健在的将至少在一个位置（开局播种之后）。
3. **不复活**：`generalStatus` 为死/俘的名字不出现在任何位置。
4. **不改写历史**：`cities[城].officers` 只描述**敌方城**（AI 用），我方城一律读 `roster`。

## 三、落地（代码）

### 3.1 新模块 `game/cocos/assets/scripts/RosterLedger.ts`
纯函数 + 只对 `CampaignSave` 操作，不 import `cc`（可被 Node 测试直接跑）：

- `seedOwnedCity(save, city, names)`：开局把剧本站将写进 `roster`（写一次，之后只读存档）。
- `namesInArmies(save)` / `namesInSiege(save)`：在途/待战名单。
- `locate(save, name)`：返回上面四个位置之一或 `'nowhere'`。
- `audit(save)`：`{ dupes, ghosts, missing, revived }`，四条不变量的检查结果。
- `handoffCapture(save, city, survivors)`：攻城胜利交接——清旧主（`roster[城]`、`cities[城].officers`）、
  记 `takenOver[城]`、写存活者；返回被清掉的名字（给战报）。
- `resolvePendingSieges(save, opts)`：月结处理「已抵达我方城、玩家没点守城战」的敌军。

### 3.2 接线
| 位置 | 改动 |
|---|---|
| `CampaignRoot.start()` | 载入剧本后对每座 `owned` 城 `seedOwnedCity()`（已有 `takenOver` 的城跳过） |
| `OfficersOfCity.ownedCityNames()` | 删掉「回落剧本表」分支（播种已在开局完成） |
| `BattleRoot` 结算 | 胜→`handoffCapture(城, 存活者)`；败→存活者回 `launch.home` |
| `DeployRoot` 守城候选池 | 只取 `roster[城]`；并把**任何**兵團（含 side B）里的将排除（修「能编入 AI 的将」） |
| 月末推进 | `resolvePendingSieges()`：围城满一个月未应战 → 按兵力/城防自动结算（城破=守将俘、君主死则灭国；守住=攻方退兵） |

### 3.3 测试
- `game/tests/roster_ledger.test.ts`：四条不变量（重叠/失踪/复活/我方城回落）。
- `game/tests/defense_pool.test.ts`：守城候选池不含敌方兵团将。
- `game/tests/siege_autoresolve.test.ts`：围城一月后自动结算，两种结果各一例。

## 四、验收（制作人可复测）
1. 攻下城 → 三个将出现在**那座城**的名册里，出征/搜索都能看到；
2. 不点守城战 → 过一个月，城要么守住（敌退）要么丢（守将被俘），不会永远悬着；
3. 守城战编成 → 候选池只有本城驻将，勾不到 AI 的将。
