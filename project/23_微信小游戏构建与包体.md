# 23 微信小游戏构建与包体

> 目标：能不能过微信小游戏包体上限（主包 4 MB）。
> 结论：**已过**。首包 31.72 MB → **1.72 MB**（4 MB 上限的 43%），`webp/mp3/png` 27.28 MB 整体改走 CDN 远程 bundle。
> 数字全部本机实测（Creator 3.8.8 headless，2026-11-24）。

## 1. 构建命令

```powershell
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
& 'F:\sanguo\tools\cocos\cc388\CocosCreator.exe' --project F:/sanguo/game/cocos `
  --build "platform=wechatgame;debug=false;md5Cache=true;buildPath=F:/sanguo/game/cocos-build;startScene=0b007000-1a2b-4c3d-8e4f-000000000001;server=https://cdn.example.com/sanguo/"
```

- 必须后台跑（`Start-Process … -PassThru -NoNewWindow` 再 `WaitForExit`）；前台会被 SIGTERM 带走。
- `$p.ExitCode` 恒为空，成功看日志 `build Task (wechatgame) Finished in (20 s)`；增量 20~45 s，冷启 127 s。
- `startScene` 必填。`server=` 就是 Build 面板的「资源服务器地址」——**顶层参数**，写成
  `packages.wechatgame.remoteServerAddress=…` 会被静默丢弃（日志里 `Check and complete build options` 可验证）。
- `game.json` 里没有 `subpackages`：远程 bundle 不算分包，不受分包配置影响。

## 3. A 引擎裁剪（`settings/v2/packages/engine.json`）

**坑：只写 v1 风格的 `{"modules":{"cache":{},"includeModules":[…]}}` 会被完全忽略**（bullet/spine 还在，
cocos-js 仍 4.95 MB）。必须写完整 v2 结构，以
`F:\sanguo\tools\cocos\cc388\resources\templates\empty-2d\settings\v2\packages\engine.json` 为底：

```json
{"__version__":"1.0.12","modules":{"configs":{"defaultConfig":{
  "cache":{"physics-cannon":{"_value":false}, "spine-3.8":{"_value":false}, "audio":{"_value":false}, "…":{"_value":false}},
  "includeModules":["base","gfx-webgl","gfx-webgl2","2d","ui","graphics","affine-transform","intersection-2d","custom-pipeline"]}},
  "globalConfigKey":"defaultConfig"}}
```

关掉（`_value:false`）：`3d` `animation` `skeletal-animation` `particle` `particle-2d` `physics-*`（含 cannon/physx/ammo/builtin）
`physics-2d-*` `rich-text` `mask` `tiled-map` `spine-3.8/4.2` `dragon-bones` `audio` `video` `webview` `terrain`
`light-probe` `profiler` `xr` `primitive` `geometry-renderer` `debug-renderer` `marionette` `websocket*`。

保留理由（逐个 grep 过 `assets/scripts/**` 的 `from 'cc'`）：只用到 `Graphics`（画城池连线/兵牌）、`Label`、
`UITransform`、`Sprite/SpriteFrame/Texture2D`（立绘）、`JsonAsset`、`director/input/sys/assetManager`；
没有任何 `PhysicsSystem`/`sp.Skeleton`/`Animation`/`AudioSource`/`tiledMap` 引用。
`audio` 也关掉了——现在没有 BGM/音效代码（`mp3` 只是资源，先在 CDN 躺着），将来加音乐要把它打开。

实测：`cocos-js` 4.95 → **1.33 MB**，`bullet.release.{wasm,asm.js}` 与 `spine.{wasm,asm.js}` 全部消失；
`assets/internal` 0.65 → 0.15 MB（internal 的大头是 3D 默认材质）。
副作用：`profiler` 被裁 → `cc.debug.setDisplayStats()` 失效，截图/自测脚本不要依赖它。

## 4. B 资源外置（远程 Asset Bundle）

1. 目录：`assets/resources/**` → `assets/bundles/res/**`；`assets/bundles/res.meta` 的 `userData` =
   `{"isBundle":true,"bundleName":"res","priority":1,"compressionType":"merge_dep","isRemote":true}`（`ver 1.2.0`，directory）。
2. 代码：`DataLoader.ts` 导出 `getResBundle()`（`assetManager.getBundle('res')` → `loadBundle('res')` → 失败退回 `resources`）
   与 `loadRes()`；`loadJson` 走 `bundle.load('data/<name>', JsonAsset)`。`DeployRoot` 立绘改 `loadRes('hero/<NAME>')`。
3. **CDN 目录结构有坑**：引擎拼的是 `<server>remote/<bundle>/…`（日志里实测请求
   `http://127.0.0.1:8904/remote/res/index.js`），所以上传目录必须是 `https://cdn.example.com/sanguo/remote/res/`，
   不是 `…/sanguo/res/`。
4. **CLI 限制**：`bundleConfigs`（承载 `isRemote`/`compressionType`）无法从命令行注入，`res.meta` 的 `isRemote:true`
   也不会被 headless 构建采纳 → 用 `F:\sanguo\work\pack_remote.mjs` 做后处理，等价于面板勾选：
   `node pack_remote.mjs <buildDir> <serverUrl> res`，它把 `assets/res` 搬到 `<buildDir>-remote/remote/res`，
   并把 `src/settings*.json` 的 `assets.server` 与 `assets.remoteBundles` 写好。
5. 端到端验证：web 产物 `settings.json` 改指向 `http://127.0.0.1:8904/`，`8903` 只服务首包（无 `assets/res`），
   `8904` 扮演 CDN → Boot 从 CDN 拉到 `res` 后进 Campaign，console 零错误，截图与本地包**逐字节相同**。

## 8. 上线前必须替换的三处

1. **appid**：`project.config.json` / `game.json` 里还是 Cocos 占位 `wx6ac3f5090a6b99c5`。
2. **CDN 域名**：`server=https://cdn.example.com/sanguo/` 是占位；真地址还要配 CORS 与 `Content-Encoding`（json/js gzip）。

## 6. 两种包的产出与用法（2026-11-24 实测）

包体瘦身完成后，**一个项目要出两种包**，别再混用——混用就是"game.json 未找到 / Unexpected end of JSON input"的直接原因。

| 包 | 命令 | 体积 | 目录 | 用途 |
|---|---|---|---|---|
| **预览包**（资源内嵌） | `-NoRemote` | 29.00 MB / 1133 文件 | `F:\sanguo\dist\wechat-preview`（构建后另存的稳定副本） | 开发者工具扫码、真机测帧率；**不能上传** |
| **上传包**（资源远程） | 默认 | **1.72 MB / 27 文件** | `F:\sanguo\game\cocos-build\wechatgame` | 上传发布；需先把 `wechatgame-remote\remote` 传 CDN |
| 远程资源 | 同上 | 27.28 MB / 1106 文件 | `F:\sanguo\game\cocos-build\wechatgame-remote\remote\res` | 传到 `<server>remote/res/…`（**带 remote/ 前缀**） |


### 6.1 导入开发者工具的三条铁律
1. **目录选到 `wechatgame` 这一层**（或 `dist\wechat-preview`），不要选父目录——父目录没有 `game.json`。
2. **项目类型选「小游戏」**。选「小程序」会去找 `app.json`，报的就是 `game.json: 未找到`。
3. **别在构建过程中导入**：构建会先清空目录，这期间读到的 `game.json` 可能是空文件 → `Unexpected end of JSON input`。所以预览包要拷到 `dist\wechat-preview` 这种"构建不碰"的位置。

### 6.2 预览包自检清单（导不进去时按顺序查）
- `dist\wechat-preview\game.json` 存在、首字节是 `{`（无 BOM）、含 `deviceOrientation: portrait`；
- `project.config.json` 里 `compileType === "game"`、`appid` 是你的测试号、`miniprogramRoot === "./"`；
- `src\settings.*.json` 里 `assets.server` 必须是**空串**（预览包），`launch.launchScene === "db://assets/scene/Boot.scene"`；
- `assets\res\` 存在（预览包应有 1106 个文件；上传包里应该**没有**这个目录）。

## 10. 无 CDN 可上传包（分包方案，2026-11-24 实测）

背景：开发者工具点「上传」报 `80051 source size 16473KB exceed max limit 4MB` —— 传的是**预览包**
（`dist\wechat-preview`，29.00 MB，资源全内嵌、`game.json` 无 `subpackages`）。CDN 那条路的包只有 1.72 MB，
但资源在占位域名上，真机白屏。所以补一条**不依赖 CDN** 的路：资源压到 20 MB 内、用微信分包装。

### 10.1 资源压缩（脚本 `F:\sanguo\work\compress_assets.py`，可重跑）

| 资源 | 压前 | 压后 | 做法 |
|---|---|---|---|
| `hero` 400 张 webp | 13.26 MB | **3.03 MB** | 480×701 → **224×327**，`quality=72, method=6`，Pillow LANCZOS |
| `fx` 41 张 png | 3.62 MB | **2.82 MB** | 宽高各减半 + `optimize=True`（保留 alpha） |
| `audio`（3 BGM + 99 sfx） | 9.22 MB | 9.22 MB | **没压**：本机没有 ffmpeg，无法转 64 kbps 单声道 |
| `data` 13 个 JSON | 1.62 MB | 1.62 MB | 不动 |
| `anim` | 0.31 MB | 0.31 MB | 不动 |
| 合计 | 28.04 MB | **18.17 MB** | 省 9.87 MB |

原图备份在 `F:\sanguo\dist\_backup\{hero,fx}`（逐字节可回滚）。只动了 `assets/bundles/res/{hero,fx}` 的图片字节，`.meta` 与 uuid 未变。

### 10.2 分包结构（Cocos 3.8 的硬约定）

构建（**不要带 `server=`**，让 `res` 留在本地）后跑：

```
node F:\sanguo\work\pack_subpackage.mjs <buildDir> <outDir> res
```

1. `assets/res/` → **`subpackages/res/`**；
2. 每个分包根补一个空的 `game.js`（微信要求，否则报 `未找到 ["subpackages"][0]["root"] 对应的 …/game.js`）；
3. `src/settings*.json`：`assets.server=""`、`remoteBundles=[]`、`subpackages=["res"]`，`projectBundles` 保留 `res`；
4. `game.json`：`"subpackages":[{"name":"res","root":"subpackages/res/"}]`；
5. `project.config.json`：appid → `wxf631d432ca7abcee`。

**目录名不是随手起的**：`subpackages/<bundle>/` 是构建产物 `engine-adapter.js` 里写死的——
`_[name]="subpackages/"+name`（读 `settings.assets.subpackages`）、`n.base="subpackages/"+name`。
放到 `sub/res/` 引擎会去别处找 → 白屏。

## 11. 一键出包（`tools/build_wechat.ps1`，2026-11-25 实测）

> 需求里这一节叫「§7 一键出包」，但 §7 已被「功能回归」占用（本文件不在本轮允许重排编号的范围内），
> 所以落成 §11；内容就是那条一键命令。

一条命令做完五件事：**构建（wechatgame + web-mobile）→ 按 Mode 处理资源 → 注入 AppID → 体检 → 打印体积表**。
任一项不过就 `exit 1` 并列出未通过项，**不会留下一个"看起来成功"的半成品包**。

### 11.1 用法

```powershell
# 本机执行策略禁止直接 .\xx.ps1，必须用 powershell -File 起
powershell -NoProfile -ExecutionPolicy Bypass -File F:\sanguo\tools\build_wechat.ps1 `
  -AppId wxf631d432ca7abcee -Mode upload
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-AppId` | **必填** | 微信 AppID（`wx` + 16 位十六进制）；构建后覆写 `project.config.json` 并回读校验 |
| `-Server` | `https://cdn.example.com/sanguo/` | 只在 `-Mode remote` 用：写进 `settings.assets.server` |
| `-Mode` | `upload` | `preview` / `upload` / `remote`，见 11.2 |
| `-SkipWeb` | 关 | 只出小游戏包，不重建 `web-mobile`（约省一半时间） |
| `-KeepAudio` | 关 | 保留音效（默认剔除，见 11.4） |
| `-Open` | 关 | 出包后打开产物目录 |

三种 Mode 的产物目录：`dist\wechat-preview` · `dist\wechat-upload` · `dist\wechat-remote`（CDN 负载另放 `dist\cdn\remote\`）。

### 11.2 三种 Mode 与实测体积

- **preview**：资源内嵌 `assets/res`，不拆分。给开发者工具扫码预览用，主包 > 4 MB 属正常，**不能上传**。
- **upload**：`work/pack_subpackage.mjs` 把 `assets/res` → `subpackages/res/`，`game.json` 加 `subpackages` 声明。
  主包只剩引擎 + 代码，可直接上传。
- **remote**：`work/pack_remote.mjs` 把资源搬成 `<buildDir>-remote/remote/res`，写 `assets.server` / `remoteBundles`，
  再把负载收拢到 `dist\cdn\remote\`。包内不含资源，资源走 CDN（请求路径是 `<server>remote/res/…`，注意 `remote/` 前缀）。

| Mode | 主包 | 资源位置 | 合计 | 能否上传 | 耗时 |
|---|---|---|---|---|---|
| `preview` | 10.95 MB / 1046 文件 | 内嵌在 `assets/res` | 10.95 MB | ❌（>4 MB） | 60 s |
| `upload` | **1.81 MB / 27 文件** | `subpackages\res` **9.14 MB / 1020 文件** | **10.95 MB / 1047** | ✅ | 101~169 s |
| `remote` | **1.81 MB / 27 文件** | `dist\cdn\remote\` 9.14 MB / 1019 文件 | 10.95 MB | ✅（需先传 CDN） | 61 s |

`preview`/`remote` 两行是 `-SkipWeb` 跑出来的（省一次 web-mobile 重建，包体数字不受影响）；`upload` 那行是完整跑
（两次构建都在，空载 101 s、同时有别的构建在跑时 169 s）。三个 Mode 的退出码都是 **0**。

**音效剔除前**同一条命令的 upload 实测是：主包 1.81 MB + 分包 18.33 MB = **20.14 MB / 1149 文件 → 超 20 MB 上限，退出码 1**。
这就是 11.4 默认剔音效的直接原因。

### 11.3 体检项（每一条都是踩过的坑）

| 检查 | 判据 | 不通过说明 |
|---|---|---|
| 构建成功 | 日志 `build Task (<platform>) Finished` **且** 产物 `game.json`/`index.html` 存在 | `$p.ExitCode` 恒为空，**不能拿它判断** |
| 主包体积 | < 4 MB | 微信上传直接拒 |
| 总包体积 | < 20 MB（主包 + 分包 + CDN 资源） | 微信总配额 |
| `game.json` 编码 | 首字节必须是 `0x7B`（`{`） | 带 BOM 时 IDE 报 JSON 解析错误 |
| 分包声明 | `game.json.subpackages` 含 `subpackages/res/` | 引擎找不到分包 |
| 分包入口 | `subpackages\res\game.js` 存在 | 报 `未找到 ["subpackages"][0]["root"] 对应的 …/game.js` |
| 分包内容 | 分包里 ≥ 10 个文件 | 资源没搬进去 |
| remote 配置 | `settings.assets.server == -Server` 且 `remoteBundles` 含 `res` | 资源会 404，真机白屏 |

### 11.4 音效默认剔除（`-KeepAudio` 可保留）

`assets/bundles/res/audio` 是 9.20 MB / 102 个 mp3，**Cocos 版脚本里零引用**（`grep audio|AudioSource|mp3` 无命中），
音频引擎模块在 §3 也已裁掉。留着只吃配额，所以 `upload`/`preview`/`remote` 三种 Mode 都在打包后按扩展名
（`.mp3/.ogg/.wav/.m4a/.aac`）删掉，并在体积表下面单列一行「（已剔除音效）… 不占配额」。

- 剔除后 upload 从 **20.14 MB（超限）** 降到 **10.95 MB**，余量 9 MB。
- 要接音效时先加 `-KeepAudio` 跑一次，会立刻看到总包回到 20 MB 以上——那时候该走 `-Mode remote`（CDN 不限体积）。

### 11.5 脚本自身的两个坑

1. **文件必须存成 UTF-8 with BOM**。Windows PowerShell 5.1 按 ANSI 读无 BOM 的 `.ps1`，中文注释变乱码、
   报一堆假语法错误（`Unexpected token '}'`、`字符串缺少终止符`）。本轮用 write 工具改完脚本后，
   用 `[System.IO.File]::WriteAllText($p,$txt,(New-Object System.Text.UTF8Encoding($true)))` 重新加 BOM 才通过。
2. **`Write-Host '...' -f a,b,c -ForegroundColor X` 会被解析成参数绑定错误**：
   `Cannot bind parameter 'ForegroundColor'. Cannot convert value "…"`。必须把 `-f` 运算括起来：
   `Write-Host ('  {0,-26}' -f $name) -ForegroundColor DarkGray`。
   另外体积表里中文名按 2 列宽算（CJK 宽度），否则表头会歪。
3. 顺带一个 PowerShell 陷阱：`$json.subpackages` 缺失时（键不存在 → `$null`），`@($null | ForEach-Object {…})`
   得到的是**长度 1 的数组**，`if ($declared.Count -gt 0)` 会走进不存在的分支，打出「game.json 里还有 subpackages 声明：」空的。
   改成 `if ($gameJson.PSObject.Properties.Name -contains 'subpackages' -and $gameJson.subpackages)`。

### 11.6 与旧流程的关系

- §10 的 `pack_subpackage.mjs` / §4 的 `pack_remote.mjs` 仍是底层工具，一键脚本只是把它们串起来 + 加体检。
- §10.4「换过包布局要杀 46032 端口的 IDE server」仍然成立；脚本只负责出包，**导入/上传仍在开发者工具里**。

  不会混进上一轮的残留文件。
