## 1. 一句话

**把 1999 年《三国群英传2》"大地图 + 月循环内政 + 100 人实时兵战"完整搬到竖屏微信小游戏：系统与数值一个字不改，只把 UI 与美术全部重做、并按竖屏重新组织操作。**

> **范围已定死（m01592）**：v1 不做任何系统变动——不加玩法、不改公式、不砍内容、不重设计流程。唯一的改动面是：**画面（美术全换）＋ 版式（竖屏重排）＋ 操作（拇指化）**。

---

## 2. 做什么 / 不做什么

| 做 | 不做（v1） |
|---|---|
| **系统零改动**：原作怎么打、怎么内政、怎么算，照搬 | 不新增/删除/重设计任何玩法、公式、流程 |
| **内容全量**：5 剧本 / 60 城 / 400 将 / 110 武将技 / 67 军师技 / 77 物品 | 不砍剧本、不砍武将、不砍技能（砍内容=改数据=违反"零改动"） |
| **美术全量重做**：400 头像 + 15 造型 × 2 阵营 + 13 兵种 + 110 技特效 + UI + 12 地形 | 不使用原作任何一张图、一个图标、一段音频 |
| **竖屏重排**：横屏 640×480 的版式 → 750×1334，信息分三档折叠 | 不做横屏版、不做"横屏缩放到竖屏"的偷懒方案 |
| **拇指化操作**：点选/长按/纵向滚动替代鼠标 | 不做端游式多面板同屏 |
| 广告变现（免版号期）＋ 内购接口预留 | 不做 PvP、不做公会、不做赛季（v2 再议） |

## 3. 为什么现在做这个

1. **玩法被验证过 27 年**：原作 1999 年发售，社区至今还在出补丁、改数值、换头像包（见 `docs/08 §5.4`）。核心循环没有过时。
2. **"只换皮"把风险从设计转移到产量**：系统零改动意味着**没有玩法赌注**——不用验证"这样改好不好玩"，只要忠实还原；剩下的问题是"美术产得出来吗、竖屏好不好用"。
3. **产量问题已经有解**：本机 Qwen-Image 2.1 + Wan 2.2 已跑通"出图 → 图生视频 → 序列帧"全链路（`06`），实测 51 s/张图、51~90 s/条动作片。**11,000 张原作资产拆下来，真实重画单元只有 15 套身体 + 26 套兵种 + 400 张头像 + 110 个特效**。

## 4. 核心循环（一局的形状）

```
大地图（点城 → 自动寻路）
   ↓
城池内政（每月 1 次动作：征兵/训练/搜索/开发）
   ↓
出征编成（选将、配兵、选阵形、选军师技）
   ↓
战斗（100 人实时兵战，3~5 分钟）
   ↓
结算（招降/斩首/战利品/经验/声望）
   ↓
回到大地图（下一个月）
```

**竖屏要解决的不是"玩法太长"，而是"一屏装不下"**：原作一个回合能同时看到 60 城与 6 个面板，竖屏只显示当前视野的 3~5 城 + 1 个主面板，其余靠纵向滚动与二级页。**规则不动，动的是"看到多少、点几下"**。

## 5. 竖屏改造的三条主轴

| 主轴 | 原作（横屏 640×480） | 本项目（竖屏 750×1334） |
|---|---|---|
| **信息密度** | 一屏 6 个面板、20+ 属性同屏 | 一屏 1 主面板 + 1 次级面板，属性分三档（必显/折叠/二级页），**但每个原作可见的数值仍必须可查** |
| **操作** | 鼠标点选，左右横排菜单 | 单手拇指，右下热区，纵向滚动卡片，长按看详情 |
| **战斗构图** | 71 列 × 14 行横向推演，双方左右对峙 | **逻辑坐标不动，呈现转 90°**：14 行车道上屏幕左右、71 列推进轴上屏幕上下；我方在下、敌方在上；一屏 **14 车道 × 12.6 行**，镜头纵向跟随（`PROJECT_BRIEF §6.1`） |

详细方案见 `01`（界面）与 `02`（战斗，内容已改为"移植 + 竖屏表现适配"）。

## 11. 美术生产方式（本地 Qwen + Wan 已跑通）

本机 **ComfyUI 0.43 + Qwen-Image 2.1（Q8_0 GGUF）+ Wan 2.2 TI2V 5B + RTX 3090** 已跑通"静态出图 → 图生视频 → 序列帧"全链路，实测：**Qwen 832×1216/20 步 = 51 秒一张**；**Wan 832×480 / 33 帧 = 51 秒、65 帧 = 90 秒**；抽帧+抠像+归一 ≈ 2 秒/条。风格直接命中"新国风厚涂"。

完整产量与算力方案见 **`06_美术量产与云算力方案.md`**（765 张静态 + 172 条动作视频 + 约 4,900 帧序列帧；22 GPU·h）。**云已改为立即开启**（用户 m01938），环境、V0 验证包与 10 天冲刺见 **`07_云GPU提速与快速验证方案.md`**。

五张验证样张在 `F:\sanguo\project\art_ref\`：

| 样张 | 用途 | 结论 |
|---|---|---|
| `hero_general.png` | 武将立绘 | 质感/打光/甲胄细节达标，可直接当金标准 |
| `soldier_sheet.png` | 战场单位三视图 | 结构正确（正/侧/背），比例可读 → 能当拆帧参考 |
| `battlefield.png` | 竖屏战场背景 | 纵深与光位合理，城墙远景可用 |
| `ui_panel.png` | UI 面板材质 | 竹简/青铜边框可用，**但图上的字全是乱码** |
| `worldmap.png` | 大地图 | 俯视城池+路径+旗帜，构图直接可参考 |

**三条硬教训**（已写进 `03` / `06`）：

1. **AI 不出文字**。`ui_panel` 图里的"汉字"全是无意义字形——所有文字必须由引擎/设计稿排版，UI 图只出**底材与框体**。
2. **文本编码器选错会直接报错**：`qwen_2.5_vl_7b` 的 hidden 是 3584，Qwen-Image 2.1 要 4096，必须用 `qwen3vl_8b_int8_convrot.safetensors`（type=`qwen_image`），否则 `normalized_shape=[4096] ... got [1,43,3584]`。
3. **动作不要手绘，要"视频转帧"**：Wan 图生视频 → 抽帧 → 抠像 → 固定 scale 归一（方法论继承 `F:\时空旅行者\docs\50-美术\角色动作管线.md`）。归一按序列做、不按帧做；落尺寸按画布、不按 bbox。

生产流程定为：

```
① 策划给"角色卡"（身份/年龄/气质/主色/道具）
② Qwen 批量出 8~12 张候选（同一 seed 族 → 挑 1）
③ 原画师精修（统一笔触、修手、补细节、分层）
④ 拆部件（头像/立绘/战场小像）
⑤ 入库（命名规范见 03 §7）
```

**这改变了美术预算**：一张立绘从"外包 3~5 天"变成"AI 20 秒 + 精修 3~4 小时"，40 张立绘的产能瓶颈从"画不起"变成"审图审不过来"。**风险转移到"风格一致性"和"法律相似度"**——所以 §12 的把关流程比出图能力更重要。
