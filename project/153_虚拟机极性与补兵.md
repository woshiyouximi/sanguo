## 2. 8 处读点自洽论证（0x3D = 比较为假时跳 / 0x3C = 比较为真时跳）

前提：本 VM 的比较/逻辑指令压 **1 = 真、0 = 假**（`vm.ts:500-567`，本次未改）。
反汇编器把 **0x3D 印成 "JNZ"、0x3C 印成 "JZ"**，那是"比较压 0=真"的旧约定下的助记符 —— **读 dis 时必须把 `3D JNZ` 读成"比较为假时跳"**，否则每一条都读反。这也是端口原来写反的源头（`docs/04-脚本引擎SmartScript.md:361-362` 同样记错）。

| # | 地址（MAGIC.SO） | 字节码 | 落空分支在做什么 | 正确语义下必须 |
|---|---|---|---|---|
| 1 | `0x550C` MoreSoldier | `GT(loc6,40); 3D L05524` | `PUSHI 40; STL loc6` | loc6 **≤**40 时跳（跳 = 不夹），否则夹成 40 ⇒ **3D=假时跳** |
| 2 | `0x556C` MoreSoldier | `LT(loc7,0); 3D L05584` | `PUSHI 0; STL loc7` | loc7 **≥**0 时跳，负数才落空夹 0 ⇒ 假时跳 |
| 3 | `0x5598` MoreSoldier | `GT(loc7,arg2); 3D L055B0` | `LDSL arg2; STL loc7` | loc7 **≤**arg2 时跳，超出才夹 ⇒ 假时跳 |
| 4 | `0x55C4` MoreSoldier | `NE(loc7,0); 3D L05778` | 落空直落 `PUSHS "ProduceSoldier" … CALLS`；`L05778` 经复核确为 `LDSL loc1; LDSL loc2; CALL CastFail` | need**≠**0 才生产、need==0 才弃技 ⇒ **假时跳**（这条是 ironclad：反过来则"need 有值就 CastFail"，伏兵永不生效，正是改前现状） |
| 5 | `0x4FF4` ProduceSoldier | `EQ(loc3,0); 3D L05118` | 落空 → `0x119` 生成兵 + `StepShow` | loc3=`0x113` 的占用者句柄，**空格(0) 才生成** ⇒ 假时跳（被占才跳去试另一行）。铁证：往有人格子里生成没有意义 |
| 6 | `0x5108`/`0x5304` ProduceSoldier | `GE(loc4,arg1); 3D L05118`（两次，两行各一） | 落空 → `INCL loc4` 继续 | 已补够(arg1) 才交回外层 ⇒ 假时跳 |

## 3. 未解矛盾：Hurt 的首门与 MoreSoldier 的第四门互斥（**这是本次最需要判的一条**）

### 3.1 Hurt @0x12B8（argc=3）原文

```
0012CC LDSL arg2; 0012D4 LDG 2; EQ      ; arg2 == g2 ?
0012DC LDSL arg2; 0012D4 LDG 3; EQ      ; arg2 == g3 ?
0012E4 LOR
0012E4 3D00000064130000 JNZ L01364      ; ← 跳去"只放 Hit01 音效"
001314 LDSL arg1; PUSHI 0; LE
001328 3D00000038130000 JNZ L01338      ; ← 跳去 0x125(arg2, 0, arg1) 真正的伤害
001330 RET 3
L01338 0x125(arg2, 0, arg1)  ; 伤害
L01364 0x300(arg2,"Hit01",255); RET 3   ; 只音效
```

- `arg1` = 伤害量（`LE(arg1,0)`、`0x125(arg2,0,arg1)`），`arg2` = 受害者句柄。87 处 `CALL Hurt` 站点压栈式样一致：`[受害者, 伤害, 来源]`。
- **`g2`/`g3` 在魔法通道里恒为 0**：`runtime.ts:1622` 只有 system-so 宿主写 `global(2)=SYSTEM_SO_GENERAL_HANDLE`；全仓 `globals[` 只有 `vm.ts:151/158`（读写器）与 `runtime.ts:422`（读），**没有任何代码在魔法施法时写 `globals[2]/[3]`**。
- 于是两种语义的结果：

| 0x3D 语义 | 普通受害者（g2=g3=0，LOR=0） | 后果 |
|---|---|---|
| **假时跳**（本次改法） | LOR==0 → **跳到 L01364 只放音效** | 普通单位永远拿不到 `0x125` 伤害 |
| **真时跳**（改前端口） | LOR==0 → 不跳 → `arg1>0` 再跳 L01338 → **吃 0x125 伤害** | 合理 |

这就是 `R67 ×5`（`0x125 必须被调用一次，actual 0`）、`金标准：神鬼亂舞(104)`（范围技应命中 ≥3，实际 1）这几条红的直接原因。

### 3.2 为什么不能"各修一半"

`0x3C/0x3D` 是**同两条操作码**，`0x55C4` 与 `0x12E4` 的字节都是 `3D`（4 字节操作数编码 `3D000000`，没有"取反位"可利用）。所以：

- 全用"假时跳" ⇒ 伏兵生效，Hurt 只放音效（现状态，12 红）
- 全用"真时跳" ⇒ Hurt 正常，伏兵**永远 CastFail**（改前，1270 pass / 2 红）

**矛盾的规模不对称，这点很重要**：要求"假时跳"的有 **9 个读点**（`0x550C`、`0x556C`、`0x5598`、`0x55C4`、`0x4FF4`、`0x5108`、`0x5304`、`0x534C`、`0x5370`，另有 `InitializeBattle`、`劍輪舞` 两处同类），要求"真时跳"的只有 **1 个**（`Hurt` 的 `0x12E4`）。若原作操作码语义统一，只能是有 9 个读点的那一边对、那 1 个读点需要另一种解释。

**再补一条**：`Hurt` 的第二道门 `0x131C-0x1328`（`LDSL arg1; PUSHI 0; LE; 3D L01338`）在**修完 binop 之后只有"假时跳"才对**：
- 修后 binop：`LE(arg1,0)` = `arg1 <= 0`；假时跳 ⇒ 伤害 ≤0 时 RET、>0 时跳去 `0x125` ✓
- 若保留"真时跳"：伤害 ≤0 时跳去 `0x125`（给 0 或负数伤害）、>0 时 RET ✗

也就是说 **binop 修复与极性修复是一套**（152 §3 原话），而矛盾被压缩到 `0x12E4` 这**一个** EQ/LOR 门上。

### 3.3 三个候选解释（我无法在剩余时间内证伪任一条）

- **(a) `Hurt` 的 `g2/g3` 在原作里不是 0**，而是"本次施法的施法者/目标"；那么"假时跳"语义下 `Hurt` 的真实语义是：**只有 g2/g3 这两个单位吃 `0x125` 伤害，其他只放音效** —— 这在原作里未必荒谬（群英传的杂兵死亡可能由另一条"扣兵"通道处理，`0x125` 只负责主将/目标）。**端口从未给魔法通道接过 g2/g3 的线**，所以现在所有人都走音效分支。若这条成立，正确修法是：接线 `globals[2]=施法单位`、`globals[3]=目标单位`，并把 R67 的 5 条断言改成"给 g2/g3 赋值后 0x125 被调用"。**这是我认为最可能的解释。**
- **(b) 端口某些比较指令的布尔约定与原作相反**（例如 EQ/NE 族压 0=真、GT/LT 族压 1=真）。已排除：`0x4FF4` 是 EQ、`0x55C4` 是 NE、`Hurt` 首门也是 EQ/LOR —— 同族，一起反等于没反。要救 Hurt 就得让 EQ 与 NE 的约定不同，无证据。
- **(c) 我的某个读点错**：已逐条复核 `0x12CC-0x1330`、`0x5498-0x55F4`、`0x4F1C-0x5370` 原文，字节与落空分支见 §2/§3.1，没有转录错误。

**补充证据（上一轮已经踩过这个门）**：`game/tests/r50_r67.test.ts:395` 的断言注释写的是
`'Hurt 只有 victim 是 g2/g3（自己/主目标）时才放 Hit01 音'` —— 这是**"真时跳"读法**（= 端口旧极性）。
也就是说上一轮已经把 g2/g3 解成"自己/主目标"，并按"真时跳"钉了 5 条 R67。同一文件的 `:488` 还交叉确认了
`Hurt` 的实参顺序是「受害人 / 0 / 伤害」、`arg1` 是正伤害量（与 §3.1 一致）。
这条注释是很重要的旁证：**R67 那 5 条红不是新发现的 bug，而是上一轮按旧极性写下的语义**。谁对谁错取决于
§3.3(a) 与 §2 第 4/5 条哪一边的读法成立 —— 而 §2 第 4/5 条背后是"伏兵在原作里能不能出兵"这个不可回避的事实。

## 5. 分级

**[确认]**（字节码 + 运行时双证）

- 0x3C/0x3D 在端口里是反的，且 `0x4FF4`（空格才生成）与 `0x55C4`（need==0 才弃技）只有"0x3D=假时跳"才自洽。
- 二元运算必须"先压=左"：`5*loc6 − 0x10C`、`loc6-1-loc1`、`loc7/2` 三处反推。
- `SYSCALL` 的 `args[0]`=最深，`0x119` 的 a(0)=阵营、a(1)=x、a(2)=y，原实现顺序没错。
- 0x119 在原作里就是"往格子里新建一个兵"（`0x113` 探空 → `0x119` 生成 → 返回值直接喂 `StepShow`），`summon` 语义不符。
- `battle.cast()` 原来用"己方尸体减少量"当补兵数是错的（补兵不产生尸体）。
- 补兵生效需要 CALLS 取参也一起改（否则 `ProduceSoldier` 的 arg1=0）。

**[推测]**

- `spawnSoldier` 的 200 活兵上限：152 报告的骨架给的，未见字节码直接证据。
- `0x10C` = "该方当前兵力"（于是 `5*maxHp − 当前` = 补到 5 倍上限的差额）。152 §5 说 `0x10C` 的实现地址 `0x43A795` 未反汇编。
- `Hurt` 的 `g2/g3` 原作里非 0（§3.3a），这是唯一能让"假时跳"与 Hurt 共存的解释。
- CALLS 采用"块底 argc 个 + 反转"而 CALL 采用"arg1 先压"：两套约定并存，反汇编证据支持，但没找到文档解释为什么。

**[未解]**
