## 0. 一句话结论

旧实现「按 `fx_dir_primary` 查 `m<目录>snd01`」**不是原作的做法**。把它逐技能对一遍真值：
**76 个碰巧对、28 个错、6 个整组静默（006 系 6 条）**（错例：雷擊系 5 个应为 `m005snd02` 却放 `m005snd01`；
連弩 dir009 应为 `m019snd01` 却按目录放 `m009snd01`；冰柱刺 dir012 应为 `m022snd01`）。
原作里技能音效有两个来源，都按**技能自己的特效目录号**（`fx_dir_primary`）关联，但**具体是哪一条串，要看脚本/物件里真正 `PUSHS` 了什么**：

| 来源 | 形态 | 数量 |
|---|---|---|
| MAGIC.SO 脚本 | `PUSHS "mNNNsndNN"` + `SYSCALL 0x301`（播放音效 name,vol） | 116 个调用点（97 条是 m 串，55 个不同名） |
| THINGS.INI 物件动画 | `$mNNNsndNN`（播放音效）/ `!nnnn`（回调 MAGIC.SO 里 num=nnnn 的函数） | 263 个 `$`（12 种，其中 9 种是 m 串）、15 个 `!nnnn` |

结果：**110/110 个技能都有具体串，无据 0**；证级 A=70、A2=13、C=24、X=3；
110 行里 21 行不是 `snd01`（旧表只有 6 行例外），涉及 38 个不同音效文件。

## 1. 三条证据边（为什么能确证）

### 1.1 MagicN 是薄包装：技能音在「效果函数」里，不在 MagicN 里

`export/script/magic_so.dis.txt` 里 111 个 `MagicN`（Magic1..Magic110 + Magic200）每个只有
1–2 条 `PUSHI` 参数 + 1 条 `CALL <效果函数>` + `RET`，**自身没有任何音效调用点**：

```
Magic3  @0x3AB58: PUSHI 17 / PUSHI 1 / CALL ArrowSupport / RET 0
Magic4  @0x3AB58 附近: PUSHI 0 / CALL Spout / RET 0
Magic1  @...: PUSHI 0 / CALL Heal / RET 0
```

所以「技能音」= 该单一效果函数调用图里的音效。直证例（`docs/05c_MAGIC特效映射.md:36-68` 同款证据）：

```
0x018058  PUSHS 209 ; "m016snd01"      <- Heal 里
0x018068  SYSCALL 0x301, 0x2           <- 播放音效("m016snd01", 255)
```

`docs/04-脚本引擎SmartScript.md:546` 定义了这个 syscall：
`| 0x301 | 103 | 2 | 0 | 0x420B77 | 播放音效(name, vol)（0x4699A0） | MAGIC/SYSTEM |`

**A 级**（depth<=1，MagicN → 效果函数第一层就播）：70 条。

### 1.2 CALLS / 0x310–0x314：按名字调用脚本（补齐 25 个「够不着」的音效函数）

只沿 `CALL` 走调用图会漏掉 25 个带音效的函数（`CreatePowderBreak`、`CreateFirePillarSource`、
`sc3604`、`SwordBomb`、`SwordBomb` 系…）。真正的边是**按名字调用**：

```
006ED8  PUSHS 68 ; "FlyLight"   ...   006F20  SYSCALL 0x310, 0x6   <- 6 参按名调用
```
`docs/04-脚本引擎SmartScript.md:548-552`：`| 0x310 | 110 | 6 | 0 | 0x420BE9 | 按名字调用脚本，6 参数 |`
（`:660` 说明 0x310–0x314 与 `CALLS`（4 参）都是 `0x4653F0` 的包装）。
`CALLS` 形态：`PUSHS name; a; b; c; d; CALLS`。

坑：`CALLS` 的参数表达式里可能嵌 `SYSCALL 0x303`（rand）。`PowderCallback` 内
`magic_so.dis.txt:25566` `02CFB4 PUSHS 373 ; "CreatePowderBreak"` … `02CFF0 CALLS`，
中间夹着 `02CFD4 SYSCALL 0x303`。所以「往回扫函数名」**只能以 `JMP/JZ/JNZ/RET/RETV` 为界**，
不能以 SYSCALL 为界（早期版本在这里丢了 `CreatePowderBreak`）。

**A2 级**（depth<=4 间接，且音效号 == 该技能 `fx_dir`）：13 条。

### 1.3 THINGS.INI 物件层：`$` 播放、`!nnnn` 回调（004/007/033 的裁决依靠）

`extract/pak/THINGS.INI` 是 **Big5** 编码（Node `new TextDecoder('big5')`，623 段）。动画串里：

- `$xxx` = 播放音效（`docs/03b-物件表THINGS.md:237`：`| $\`xxx\` | 263 | 播放音效 |`）
- `!nnnn` = 调 MAGIC.SO 里 `num == nnnn` 的函数（`:238`，全库恰好 15 处，`:297-313` 有列表）

实测「m 音效 → 物件」精确表（`work/sfx84/things.mjs`，Big5 解码后按 `$(\w+)` 抽）：

| 音效 | 物件 Sequence | 目录 |
|---|---|---|
| `m004snd01` ×2 | 14001 | `\magic\004` |
| `m005snd02` ×4 | 15001 / 15002 / 15003 / 15010 | `\magic\005` |
| `m005snd03` / `m005snd04` / `m005snd05` | 15008 / 15005 / 15009 | `\magic\005` |
| `m007snd01` ×2 | 17002 / 17023 | `\magic\007` |
| `m010snd01` ×2 | 20001 / 20002 | `\magic\010` |

`!nnnn` 的实例：`\magic\006` 的 `16001.Wait` 第 16 帧 `!6003` → `FlyArrowLU`（num 6003），
`16002` → `!6004` → `FlyArrowRU`，两者都 `SYSCALL 0x300` 播 **`"arrow"`**
（`magic_so.dis.txt` 0x9FA8 / 0xA134）；`28005.Death !18002` → `sc3604` 播 `m018snd03`；
`43001.Wait !33002` → `ShootCannon`。对照 `docs/03b-物件表THINGS.md:310-311`（物件 435/442 火柱

**C 级**（THINGS 结构证据）：24 条。

### 1.4 为什么「音效号 == 目录号」

`game/data/magic_so.symbols.json` 里 172 个函数 `num != 0`，且恒为 `<目录号>000+k`；
THINGS 里 `\magic\NNN` 目录的物件 `Sequence = 10000 + NNN*1000 + k`。
所以 **`num` = ThingID − 10000 = 目录号*1000 + k**，`!nnnn` 就是按这个号回调。
目录回调块（001..043）与目录一一对应，例：

```
001 NoMoreSoldierCallback#1000 / HalfMoonCallback#1001
005 ThunderCallback#5001 / BigThunderCallback#5002
006 ArrowCallback1#6001 / ArrowCallback2#6002 / FlyArrowLU#6003 / FlyArrowRU#6004
020 FireRingCallback#20001      033 FireWorkCallback#33001 / ShootCannon#33002
034 PowderCallback#34001        043 XFirePillarCallback#43001 / XTaiChiCallback#43002 / XDuplicatorCallback#43003
```

这也是「音效文件叫 `m<目录号>sndNN`」的由来：**编号是特效目录号，不是技能号**。

只剩 `m028snd02`、`m039snd02` 两个孤儿文件（MAGIC.SO 与 THINGS 都没有播放点，判为素材包遗留，不使用）。

## 5. 给 lead 的 main.js 补丁（**必须打**，否则技能音会串号）

现状 `game/web/main.js:179-187` 把 `fx_dir_primary`（目录号）传给 `emitMagic`：

```js
/** 技能音：按 data/magics.json 的 fx_dir_primary 查 mNNNsnd01；查不到就静默。 */
function skillSfx(seq, volume) {
  const magic = (state.data && state.data.magics || []).find((m) => m.SEQUENCE === seq);
  const dir = magic && (magic.fx_dir_primary
    || (Array.isArray(magic.fx_dir) ? magic.fx_dir[0] : '')) || '';
  if (!dir) return;
  // [[AUDIO]] 技能起手也进总线（进日志、可被 ?sfxdbg=1 数到），由 sink 转给 audio.magic
  emitMagic(dir, volume == null ? 0.7 : volume, 'skill:cast');
}
```

改成（**整段替换 179–187 行**）：

```js
/** 技能音：按技能编号查具体音效串（audio.js 的 MAGIC_SFX，见 project/96）；查不到就静默。 */
function skillSfx(seq, volume) {
  const id = String(Number(seq) || 0).padStart(3, '0');
  if (!id || id === '000') return;
  // [[AUDIO]] 技能起手也进总线（进日志、可被 ?sfxdbg=1 数到），由 sink 转给 audio.magic
  emitMagic(id, volume == null ? 0.7 : volume, 'skill:cast');
}
```

只改这一个函数即可，`installAudioSink()`（`main.js:158-176`）的 `magic: (dir, opts) => a.magic(dir, ...)`
是纯接线，**不用改**（参数名想改成 `seq` 只是可读性）。

可选的两处注释同步（不影响行为）：
- `main.js:1092-1093` 注释「按 magics.json 的 fx_dir_primary 放 mNNNsnd01」「11 条技能静音」已过时；
- `main.js:1540` 行尾注释「方便单独验某条技的目录音」→「技能音」。

> ⚠️ **不打这个补丁的后果**：新表的键是技能号，`skillSfx` 仍在传目录号，会**串到别的技能**。
> 例：虎咆震（技能 16，dir 008）会传 `'008'`，被解析成技能 8「火雷」→ `m034snd01`。
> 已在浏览器里实测到这个串号（见 §6 的 `dirPitfall`）。
