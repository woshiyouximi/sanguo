# 217 · 面板按钮全灭的根因、roster 单源收编、调试门禁

**轮次**：R224（2026-11-26 14:00）｜**上一份**：`project/216_双端差距收口.md`

**一句话**：「所有面板按钮点不动」不是坐标错位，是**暗幕节点上的 `BlockInputEvents` 把全局 input 事件吞掉了**；修完出原生包 **2.9**，同时把 `roster.ts` 收编成单源、修掉「189 剧本复活张角」、新增调试痕迹门禁。

## 1. 触控总根因（本轮最值钱的发现）

### 1.1 现象

打开 `城池一覽` / `勢力圖` / `存檔` / `名冊` 之后，**面板内所有按钮都失效**，但画面照常渲染、`tick` 仍是 60fps。用户原话：「这种界面打开后，所有的按钮都无效卡死在界面内了？什么原因？」

### 1.2 根因

`game/cocos/assets/scripts/CampaignRoot.ts` 的 `showSheetScrim()` 给全屏暗幕节点挂了 `BlockInputEvents`：

```ts
n.addComponent(BlockInputEvents);   // ← 元凶
```

Cocos 3.8 的 `PointerEventDispatcher` 优先级（`priority` UI=1）**先于**全局 `input`；它在暗幕节点上认领 TOUCH 后返回 `false`，`Input._emitEvent()` 里：

```ts
if (!dispatcher.dispatchEvent(event)) break;   // 直接中断，后面的全局监听全收不到
```

于是本项目所有面板与大地图的**唯一输入入口** `input.on(Input.EventType.TOUCH_END, this.onTouch)` 再也收不到事件。

### 1.3 证据链（`work/hitfix/REPORT.md`，30 张实机截图）

| # | 证据 | 结论 |
|---|---|---|
| 1 | 探针实测：关闭按钮 `ui=(661,1269) local=(286,602) design=(661,65)`（期望 661,60）；己方 `(270,158)`；下一頁 `(673,1142)`；點行 `(371,300)` | 坐标公式与父节点空间都对 |
| 2 | 像素量 2.8 截图：`LIST_BUTTON` 画在设备 y=1489..1558 = 设计 771..807，与常量 `y=776..812` 一致 | **布局/坐标常量一个字都没错** |
| 3 | 插桩：大地图点击有 `touch-start/touch-end/campaign onTouch entered`；打开面板后再点「關閉」**连 touch-start 都没有**，而 tick 仍 60fps | 事件没进 JS 派发，不是卡死 |

> 教训：我上一轮判断的「装裱带矩形差 110 设计 px / `getUILocation` 在原生返回视口像素」**两条都是错的**，被实机探针否掉。以后「UI 全灭」先查「谁吃了事件」，再怀疑坐标。

### 1.4 修法（只碰输入层，不动布局）

- `CampaignRoot.ts:4420 showSheetScrim()`：移除 `addComponent(BlockInputEvents)`，暗幕只负责画（半透明黑）。
- `CampaignRoot.ts:3407 onTouch()`：开头挡穿透
  ```ts
  if (this.node.children.some((c) => c.name.startsWith('Scrim_'))) return;
  ```
- `CampaignRoot.ts:4531 openCityList().onPick`：不再提前 `hideSheetScrim('list')`（提前收暗幕会让上面的守卫失效 → 地图穿透）。

## 2. roster.ts 收编成单源

- 问题：`work/cocos_sync/sync_core3.mjs` 的 `SKIP_FILES = ['roster.ts','field.ts']` 让这两个文件**从不参与同步**，而 `--diff-only` 只报「相同 25 / 差异 0」⇒ `check_parity` 的 core 行是**假绿**，capture（招降/斩首/释放）逻辑双端各走一套。
- 考古：`game/src/core/roster.ts` 1014 行 vs Cocos 镜像 1169 行（仅 web 有 172 行 / 仅 cocos 有 300 行）。Cocos 多的约 300 行确认是**纯逻辑**（R197 招降十栏的存档读取层：generalRecord/generalLevel/morale/tire/equip），不是 Cocos 胶水。
- 收编：整层并入 web 唯一源（`game/src/core/roster.ts` 1014→**1257 行**），`SKIP_FILES` 清空，镜像改由同步器生成（`roster.ts 1168→1264 行`，sha16 `03BF858B35B7595F`）。
- 结果：`--diff-only --strict-skip` = **文件 27 / 相同 27 / 差异 0 / SKIP-DIFF 0 / EXIT 0**；`cocos_sur/assert_sur` **94/94**；`verify_core3` **165/165**。

## 7. 坑（本轮新增，已写进交接简报 §5）

1. **`BlockInputEvents` 会掐断全局 `input`**——要挡穿透请用「自绘暗幕 + `onTouch` 开头查 `Scrim_*`」，不要用这个组件。
2. **`SKIP_FILES` 的「不同步」不等于「一致」**——`--diff-only` 报 0 差异也可能是假绿；现在有 `--strict-skip` 与 `⚠ SKIP 分叉` 兜底。
3. **别用像素差去反推布局常量**——先量常量对应的绘制位置，再决定是不是坐标问题（本轮两次判断都被探针推翻）。
4. **模拟器是独占资源**——两个智能体并行时，谁在跑 tap 探针谁独占；交接靠 `work/hitfix/NOTES.txt`。
