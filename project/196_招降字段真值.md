## 1. 原作面板怎么读这些数（反汇编，函数体 `0x44E8xx..0x44F44E`）

## 2. 勝/敗場是按将持久化的（推翻「恒灰 —」的旧结论）

累加函数 `0x4084C9`（亲读反汇编）：

```
kind == 1  (勝): 0x4084D5 mov cx,[g+0x9F]  0x4084DC add cx,1  0x4084E3 mov [g+0x9F],cx
                 0x4084FB [g+0xA3]++      0x408520/27  if (+0xA3 > +0xA5) [+0xA5]=+0xA3
kind == -1 (敗): 0x408539/40/47  [g+0xA1]++   且 0x408551 [g+0xA3]=0
```

写档 / 读档（段4 = 512 × `0x11F`，缓冲 `[0x4bd214]`，见 `docs/07b:268`/`:350`）：

```
写: 0x431A7A mov dx,[gen+0x9F] → 0x431A81 mov word ptr [ecx+eax+0xC7],dx
    0x431A9B/A2  mov dx,[gen+0xA1] → mov word ptr [..+0xC9],dx
    0x431ABC/C3  mov dx,[gen+0xA3] → mov word ptr [..+0xCB],dx
读: 0x43348B mov dx,[rec+0xC7] → 0x433493 mov [gen+0x9F],dx
    0x4334AC/B4  [rec+0xC9] → [gen+0xA1]
```

文档同一映射：`docs/07b:325-326`（`+0x0C7/+0x0C9` ← `+0x9F/+0xA1`，原文标注「未定名」，本轮由面板指令定名）。

⇒ **勝場數 / 敗場數是「跟将走、进存档」的字段**，招降面板读的就是这个记录。
`project/191_HUD體与招降对齐.md:130-135` 里「勝/敗場无来源、恒灰—」的结论**不成立**（该处依据的
`game/src/core/battle.ts:466-473` 的 `BattleRecord` 只是本作的单场战报，不等于原作字段）。

## 3. 士氣/疲勞：战斗内状态 + 战后回写 ⇒ 面板显示的是战后残值

- 开打时战场 unit 从 General 复制：`docs/04b:85` `unit+0x2C = g+0x38`；
- 战后回写：`docs/04b:498-499` `gW->+0x38 = unitW->+0x2C`；
- 疲劳战后累加：`docs/04b5:10`（`0x41048D`，双方主将 `+=15+秒/10`）；
- 被俘惩罚只动忠诚/士气：`docs/04b2:89/93`、`docs/04b2:344-347`（`g->+0x38 -= 0x14`，`0x447589..0x447594`）。

所以原作面板上的士氣/疲勞**不是**"战场瞬时值"而是"打完这一仗、已经回写进 General 记录的值"。
这一点决定了本作只要 `save.morale` / `save.tire` 里有该将的条目，显示的就是同口径的真值。

> 别把 `unit+0x34` 当士气：`project/190:145-155` 已证它是行动闸门倒计时。
