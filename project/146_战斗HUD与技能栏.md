## 3. 技能格 4 → 8：两种布局的取舍

原作 `general+0x54` 是 `byte[8]`，**上限 8、无翻页**；`game/data/generals.json` 里 SKILL 对数上限也正好是 8（張角/關羽/盜賊都是 8），所以 8 是数据上限，不是拍脑袋。

可用宽度：`SKILL_SLOT_X0=116` 到第 4 格右沿 498，共 **382px**；高度可用区间是氣力文字基线 1094 到提示框顶 1224，共 **130px**。

### 方案 A：一行 8 小格（未采用）

- 每格宽 `(382 - 7×4) / 8 ≈ 44.25px`（4px 间距）或 `(382-7×6)/8 = 42.5px`（6px 间距）。
- 名字：4 字技能名（地獄之門/炎牆烈燒/神鬼亂舞）13px 约 52px，塞不进 44px；必须降到 **9px**（4×9=36）才勉强放下，750 设计稿上 9px 汉字在手机屏已经糊成一块。
- 费用行 `技18 · 氣20%` 10px 约 55–60px，44px 宽完全放不下；只能删掉费用/类型，信息量比现在 4 格版还少。
- 结论：省高度但牺牲可读性与信息量，**否决**。

### 方案 B：4 列 × 2 行（采用）

- 列宽/列距完全沿用老节奏 `88 + 10`，行高压到 **56**，两行 y=**1100** / **1162**，行距 6，底边 **1218**（提示框 1224 之上 6px）。
- 名字仍 13px（4 字 52px < 80px 可用宽），费用行 10px，类型 9px 右上，序号 10px 左上；实测截图里 8 个名字全部可读（含「炎牆烈燒」4 字）。
- 高度账：`2×56 + 6 = 118 ≤ 130`。若坚持 88 高两行需要 182px，塞不下，所以必须压到 56。
- 4 格及以下**完全不进这个分支**：`skillSlotRects(n<=4)` 直接返回 `skillSlotRect(i)`（y=1124、88×88），R82 的 4 格窗格装饰也仍然对得上。
- 8 格时序号 1..8 即数组下标，第 5..8 格在第二行，`hitTest` 与绘制共用 rects，不会出现「画第 5 格、点第 5 格命中第 6 个技」。

截图对比：`after_4skills.png`（4 格老版式 + R82 窗格对位）vs `after_8skills.png`（4×2，8 格）。

## 4. 序号 / 命中区 / 置灰：三处同源

这是本次唯一「一漏就全错」的地方，做法是把几何收进一个纯函数：

```ts

export function castBlockReason(world: World, slot: SkillSlot): CastReason | null  // 355（原有）
export function hitTest(world, opts, sx, sy): Hit | null // 1706
```

- `drawConsole`：`const rects = skillSlotRects(skills.length)`，循环体用 `rects[i]`、`skills[i]`（`battleView.ts:1477-1481`）。
- `hitTest`：同一个 `skillSlotRects(skills.length)` 与 `skills[i]`（`battleView.ts:1714-1721`），命中即返回 `index: i`。

- 测试 ②③（`hud_slots.test.ts:122,136,151`）分别钉「8 格每格中心命中」「mp=0 时 reason 与 castBlockReason 一致」「3 格时第 4 格位置返回 null」。

- 视图不推进 `u.cd`，也不自己判 40/46 哪个生效；`cd` 全是 core 的。

### 5.2 core patch（≤5 行，需 core 主人合）

`src/core/battle.ts:85` 附近：

```ts
export function actionIntervalOf(u: Unit): number {
  if (u.isGeneral) return ((u.status ?? 0) & 0x4000) ? 46 : ACTION_INTERVAL_TICKS;
  return ATTACK_COOLDOWN;
}
```

- `[推测]` `Unit` 目前没有 `status` 字段；`0x4000` 这个状态位在本作叫什么、由谁置位，g8 只给了「主将另有 `0x4000` 状态位时 46 帧」这一条。落地时要么给 `Unit` 加 `status: number`，要么改成 `actionIntervalOf(u, status)`。
- 若 core 改了，视图无需再改：`actionGaugeOf` 的 `interval` 读的就是 `ACTION_INTERVAL_TICKS`，届时 46 帧分支会自动变成「`interval=46`、`slow=46`、刻度消失」；但 `GENERAL_SLOW_INTERVAL=46` 与 `ACTION_INTERVAL_TICKS` 的常量化建议一起收口。
