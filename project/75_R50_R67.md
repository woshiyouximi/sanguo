### 1.3 三个真消费点

1. **`cast()` 目标门** — `battle.ts:1744-1748`
   ```ts
   const activeMask = activeMaskOf(m);
   if (activeMask > 0 && activeTargetCount(world, side, activeMask) === 0) return { ok: false, reason: 'no-target' };
   ```
   掩码范围内一个**存活**目标都没有 ⇒ 技能根本不派发，**连 MP 与气力都不扣**（原作取目标走 `0x4868A8` 子表，子表返回空时技能不派发）。实测：清空敌方士兵后 `cast('A', 3=地泉衝 (敵方士兵))` → `{ok:false, reason:'no-target'}`，`mp/qi` 与施法前一致。
2. **`activeAim()` 选点** — `battle.ts:862-872`
   掩码里**一位敌方位都没有**（纯己方技，如 `命療術` = 我方主將 `0x2`）时，玩家点在敌方半场也把落点改成己方主将位置；含敌方位的技能原样用玩家给的点。
   实测：`A` 侧在 x≈55（纵深大的一头）、`B` 侧在 x≈15，`GRID_W = 71` ⇒ `ownHalf = side === 'A' ? tx >= 35.5 : tx <= 35.5`。
3. **`hitRoll()` 二段判定** — `battle.ts:1280-1285`（`unit+0x2C & 4`）
   ```ts
   const p = hitChance(world, from, to);
   if (world.rng() * 300 < p) return true;          // 首掷
   if (!statusBitOf(from, UNIT_STATUS.DOUBLE_HIT)) return false;
   const p2 = Math.trunc((p * 2) / 3);              // 0x43D48C: p = p*2/3
   return world.rng() * 300 < p2;                   // 补掷
   ```
   把 `step()` 阶段 3 原来内联的 `world.rng()*300 < p` 换成它（`battle.ts:1446`）。`Unit.status` 缺省 `0` ⇒ 只掷一次、`world.rng()` 不多抽一次 ⇒ **既有对局逐位不变**（有专门测试包一层计数 rng 断言只调 1 次）。

### 1.4 行为变化面（会不会把老对局改歪）

- `hitRoll()` 缺省路径与旧代码逐位等价（`rng()*300 < p`），只是挪进函数。
- `cast()` 门是**新增的拒绝条件**：只有"该技能 ACTIVE 范围内活目标数 = 0"才会被拒。这需要场上同类目标全灭，正常对局只在残局出现；全量 773 条测试（含所有既有战斗/军师/单挑/UI 契约用例）0 fail，说明没有把既有对局改歪。
- `activeAim()` 只影响"纯己方技点在敌半场"这一种输入，且改动方向是"仍然治自己"，不会漏放技能。

## 2. R67 — 伤害结算走脚本 syscall

### 2.1 分派链（一次普攻命中到底走了什么）

- 宿主函数两个入口都收口到 `DamageHost`：脚本侧 `SYSCALL 0x125` → `ctx.damage`；SYSTEM.SO 侧 `SysoHost.hurt()`（`syso_host.ts:948`，记 `hpDeltas`/`events`）。

- 通道自带 PRNG（`mulberry32((world.tick+1) ^ 0x51c0)`，`battle.ts:1050`），**不消耗 `world.rng`**，否则脚本里一次 `rand` 会把整局骰序推歪（有测试包 rng 计数断言 0 次）。

### 2.3 关键发现：`0x125` 第 3 参是**正数伤害量**（旧映射的符号约定是反的）

`Hurt` 的字节码（`F:\sanguo\game\data\magic_so.bin`，`Hurt` @`0x12B8`，argc=3）：

```
001314 LDSL arg1 / 00131C PUSHI 0 / 001324 LE / 001328 JNZ L01338
001330 RET 3                                    ; 不满足就返回，不扣血
L01338 001338 LDSL arg2 / 001340 PUSHI 0 / 001348 LDSL arg1 / 001350 SYSCALL 0x125 argc=3
001364 ... PUSHS "Hit01" / PUSHI 255 / SYSCALL 0x300 argc=3   ; arg2==g2/g3 时只放命中音
```

`vm.ts:847-852` 的 `binop` 是"先弹的当左操作数"（`a = pop(); b = pop(); f(a, b)`），`vm.ts:575-577` 的 `JNZ(0x3d)` 是"非 0 就跳"。所以 `LDSL arg1; PUSHI 0; LE` 实际算的是 **`0 <= arg1`** ⇒ 只有当伤害量 **≥ 0** 才走 `0x125`，负数直接 `RET`。

实测（真 `magic_so.bin` + `ScriptVm` 的 syscall 探针，`runByName('Hurt',[amt, 0x400002, 0])`）：

| `arg1` | 实际发出的 syscall |
| --- | --- |
| `-7` | 只有 `0x2b(arg3, 0x05000000)` |
| `0` | `0x2b(...)` + `0x125(4194306, 0, 0)` |
| `7` | `0x2b(...)` + `0x125(4194306, 0, 7)` |

而 `DecreaseHP` 也是 `0x125(g3, 0, 1)` 每 4 帧扣 1 点，`IncreaseHP` 走 `0x117/0x118` 另一条路 ⇒ **`0x125` 的第 3 参是「伤害量」，正数才扣血**。

仓库原有 `syscalls.ts` 的 `case 0x125: ctx.applyHpDelta(a(0), a(2))` 把它当**差值**（负数=伤）用 —— 符号约定与原作相反。因为 `runtime.ts` 在禁改清单里，处理方式是：
- **旧路径一位不改**（`runtime.ts` 不注入 `damage` ⇒ 仍走 `applyHpDelta`，法术伤害数字与改前完全一致）；
- **新通道用真语义**：`ctx.damage(h, 伤害量, src)`，`DamageHost.hurt(h, -伤害量, src)`。

这条查证同时是"`Hurt` 到底怎么调"的实证（原本按文档猜"伤害必须 ≤0"，会让脚本通道永远走 `RET`、静默不掉血；首版对拍就是在 tick 171 分歧暴露的）。

## 4. `[推测]` 清单

1. **`unit+0x2C & 4` 的二义性**（`battle.ts:726-733`、`:797-800`）：`docs/04b:168` 把 `0x43D48C` 注成"连击/必杀位"，`docs/04b4:203` 把同一位注成"骑兵/特殊兵"。本仓库早先把 `kind === 'cavalry'` 当骑兵位（`isCavalryBit()`），为避免破坏骑兵判定，另开 `Unit.status` 字段承载二段判定、取值仍用 `0x4`。`BATTLE_BITS` 里这条 `speculative: true`。
2. **`0x4868A8` 子表内容未知**（`battle.ts:853-861`）：纯己方技的选点用"点在敌半场就改成己方主将位置"近似，原作是"取目标走子表、不由玩家点地"。
3. **"掩码范围内 0 个活目标 ⇒ 技能不派发"**（`battle.ts:1744-1746`）：原作是子表返回空时不派发；本仓库把它落成 `cast()` 早退且不扣 MP/气力。是否该扣 MP 属推断。

5. **`Hurt` 第 3 参（法术物件）**：近战没有物件，传 `0`；`Hurt` 里对它的 `0x2b`（命中状态/硬直）因此是 no-op。原作对投掷物会真的打 `0x05000000`。

7. **无 git**：改动未提交，`dist/` 已重建但未打包。
