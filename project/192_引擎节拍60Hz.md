# 192 引擎节拍 60 Hz：把「40 tick = 1 格」从 1.33 s 拨回 0.67 s

> 一句话：原作单位 `+0x34` 的 40 tick 闸门**一帧都不该改**，错的是我们把这 40 tick 当成 1/30 秒来放。本轮把 `TICK_HZ` 30→60、`BATTLE_TICK_LIMIT` 5940→11880（原作 `0x2E68` 本身），并把所有「按墙钟秒数设计」的时长常量改成按 `TICK_HZ` 推导；原作帧数字面值（40/46/60/40）一个没动。

## 一、证据（先读，别重推）

`project\190_主将与士兵速度裁决.md` p5：

- `+0x34` 的单位是**引擎 tick**，不是毫秒也不是像素：
  - `0x43AC79 call 0x468720` 取全局 tick `[0x4A79C4]`；
  - `0x43AC89 lock sub eax,[0x4B7B14]` 得 dt；
  - `0x43ACF3 mov [ecx+0x34],eax` 累加进 `+0x34`。
- 闸门：`0x43B574` 每单位帧 `0x43B580 sub ecx,1` 递减，到期 `0x43B5DE mov dword ptr [ecx+0x34],0x28` 重置 **40**；撤退态 `0x43B5FD` 置 `0x2E` = **46**。
- 录像实测 tick 率 **66–79 Hz**（两段战场倒计时分别 1.75 s / 1.53 s 跌破一格，差 14%）。
- 主将帧 `0x43E964` 与士兵帧 `0x43D125` **共用同一条 `0x43B574` 闸门**，滑行 `0x43BF5F push 0x28` 也是写死 40 tick，**没有主将倍率**；1.89× 像素比 = 透视 1.59 × 行动失败 1.19。
- 因此一格墙钟：主将 0.507 s、弓兵 0.602 s（实测），60 Hz 下 40/60 = **0.667 s**（最接近的可整数实现）。30 Hz 下 40/30 = 1.333 s —— 这就是「兵走得比原作慢一半」的根因。

`project\180_战斗HUD对齐.md`：

- `[0x4AC35C]` 初值 `0x2E68` = **11880**，`0x444126` 每帧 −1；显示 `0x443F2A() = (11880 − cd) / 0x78`，`0x78` = 120。
- ⇒ 起始 99、**0.5 单位/秒**、整场 `11880 / 60 = 198 s`。30 Hz 时代我们把 11880 折成 5940 tick，虽然墙钟仍是 198 s，但把「1 单位 = 120 tick」写成了「= 60 tick」。

**结论**：`ACTION_INTERVAL_TICKS = 40`、`ACTION_SLIDE_TICKS = 40`、`ATTACK_COOLDOWN = 40`、`GENERAL_SLOW_INTERVAL = 46`、`AI_PERIOD = 60` 全部**保持字面值**（甲类），改的是 tick 的物理单位。
