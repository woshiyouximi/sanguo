## 1. 原作口徑（直接採用，未重新考古）

| 事實 | 位址 | 出處 |
|---|---|---|
| 上陣兵數 = `min(帶兵數,帶兵上限) + min(騎兵數,騎兵上限)` | `0x443118` / `0x443124` | `project/168` §4 第 295 行 |
| 騎兵上限那一欄獨立存在（`general+0x46`，帶兵上限是 `general+0x42`） | `0x409FB6` / `0x409FD8` | 同上 |
| 士兵槽上限 `0xC8` = 200（= 100 步 + 100 騎） | `0x43AA44` | 同上 |
| 寫回 unit：`unit+0x58` = 步+騎、`unit+0x5C` = 總數 | `0x443118` / `0x443124` | 同上 |

原作是**兩欄相加**，兩欄互不包含：等級 26 的將是 100 步 + 30 騎 = **130** 兵上陣。
本作改前是 `cavalry ⊆ soldiers`（`battle.ts` 舊 `mk()`：`cavalry = min(soldiers, cavalryCapOf(level))`），
所以低等級（<20 級）騎兵恆 0，且總兵力永遠 ≤ 100。

## 2. 選的實現方案與理由

### 2.1 引擎層：`soldiers` 恆為總兵力，`cavalry` 只是其中的騎兵計數

不改 `createWorld` 的「單位數 = soldiers」契約，理由是**既有守門測試把這條釘死了**，而且 web 戰鬥入口被禁改：

- `game/tests/stepcav.test.ts:104-118`：`{soldiers:30, cavalry:40}` ⇒ `sides.B.cavalry === 30`、`sides.B.start === 30`（騎兵不得多於帶兵數）
- `game/tests/stepcav.test.ts:123-135`：`{soldiers:100}` 與 `{soldiers:100, cavalry:0}` 的 `units.length` 與逐個座標必須相同
- `game/tests/strategy.test.ts:475-486`：援軍進場後 `sides.B.soldiers === 60 + troops`
- `game/web/main.js:505,506,637,647`（**禁改**）只讀 `soldiers=` / `bsoldiers=`，根本沒有 cavalry 參數

所以本輪把「兩欄相加」落在**上限與調用方**，而不是引擎的單位生成：

| 位置 | 口徑 |
|---|---|
| `levels.ts` `troopCapOf(lv)` | 步兵欄上限 = `max(1, min(lv*5, 100))`（原樣不動） |
| `levels.ts` `cavalryCapOf(lv)` | 騎兵欄上限 = `max(0, min((lv−20)*5, 100))`（原樣不動） |
| `levels.ts` `troopCapSumOf(lv)` | **新增**：兩欄相加，上夾 `TROOP_COLUMNS_MAX = 200`（原作 `0xC8`） |
| `levels.ts` `troopColumnsOf(lv)` | **新增**：`{ inf, cav, total }` 一次取兩欄，編成頁用 |
| `battle.ts` `splitTroops(level, soldiers, cavalry?)` | **新增**：`soldiers` 是總數、`cavalry` 只是其中騎兵數（缺省按 `cavalryCapOf` 推），並把騎兵截在總數內 |
| `garrison.ts` `defenderBattleParams()` | 上陣兵 = `troopCapSumOf(level)`（原本就是 `troopsMax + cavalryMax`，改成單一來源） |
| `battleSetup()` `troopMode:'exe'` | 敵方上陣兵上夾 `TROOP_COLUMNS_MAX`（200），不再硬編 200 |
| `city_model.js` `armCaps()` | 騎兵欄 = `Σ cavalryCapOf(lv)`，不再被 `troopMaxOf(lv)` 截斷 |

`splitTroops()` 與舊式 `max(0, min(soldiers, round(cavalry ?? cavalryCapOf(level))))` **數值完全等價**
（`total = max(0, round(soldiers))`，騎兵 `min(total, round(...))`），
所以不傳 `cavalry` 的舊調用（含全部既有測試與 `main.js`）逐位不變。

### 2.2 編成頁：真的給兩條滑桿

- **web** `game/web/deploy.html`：兵力區從 1 條 `#numrange` 變成「步 `#numrange` + 騎 `#cavrange`」兩條，
  各自夾自己的上限（`SOLDIER_CAP` / `CAV_CAP`），下面 `#numtotal` 寫「上陣 N 兵 = 步 a + 騎 b」，
  出陣 URL 傳 `soldiers=步+騎`（`main.js` 只認總數），另附 `cav=` 供後續接線。
- **Cocos** `DeployRoot.ts`：同一行畫兩段軌道（步 `SLIDER_X0..340` 金、騎 `400..SLIDER_X1` 銀），
  拖曳時按落點決定拖哪一欄（`sliderColumnAt()`），標籤寫「步 a/A · 騎 b/B = 總 兵」，
  出陣參數與隊列第 1 槽都存**兩欄之和**。
- 兩端都用 `troopColumnsOf()` 取上限，**同一個 core 口徑**，不再各抄一份。
