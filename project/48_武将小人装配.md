## 1. 素材与命名（已核实）

| 层 | 文件数 | 体积 | 对象数 | 命名 |
|---|---|---|---|---|
| BODY | 3600（+1 个 `NULSHAPE.png`） | 17.08 MB | 120（L 60 + R 60） | `{L\|R}{造型}{动作码}{武器位}{帧4}` 9 字符；`{L\|R}{造型}{A5\|A6\|FS}{帧4}` 8 字符 |
| WEAPON | 2584（+1 NULSHAPE） | 4.92 MB | 34（A 剑 11 / B 槍 8 / C 矛 7 / D 刀 8） | `{A..D}{武器序号}{动作码}{类别数字}{帧4}`，类别数字恒 = 类别（1..4） |
| HORSE | 184（+1 NULSHAPE） | 1.81 MB | 8（HA..HH） | `H{马代号}{动作码}1{帧4}` |

- **BODY 有两种长度**：9 字符带武器位、8 字符不带（`A5`/`A6`/`FS`）。第一版用一条正则吃掉全部，直接漏 300 帧 —— 正确做法是「剥末尾 4 位当帧号，剩下 2~4 字符做结构判定」。
- **`A2/A3/A4` 是武器位 2/3/4，不是招式号**（对象 601 的 Attack 帧就是 `L1A20002`）；`A5/A6` 才是招式码。这条用 `things_parsed.json` 的 600–603 号对象交叉验证过。
- 造型号 `1..9,A..E,0` 共 15 种；序列号 `600 + 4×造型序号 + (武器位−1)`（L 侧），R 侧从 800 起同序；`656 = L0`。
- PNG 尺寸 == SHP 头里的 width/height（`L1W10001` PNG 72×102 == SHP 72×102），**没有裁边**，所以不需要「拼回原坐标」这一步。
- alpha 全图集只有 **2 个取值**（原作是色键透明，key `0x07C0`）→ 可以直接做单索引 + tRNS 的 PNG-8。

## 3. 三层 offx/offy 到底怎么解（核心）

### 3.1 五个候选公式

以 `P` = 单位脚下地面点、y 轴向下：

| 记号 | 公式 |
|---|---|
| **F1** | `draw = P − (offx, offy)` |
| F2 | `draw = P + (offx, offy)` |
| F3 | `draw = P + (−offx, +offy)` |
| F4 | `draw = P + (+offx, −offy)` |
| F5 | `draw = P − (w/2, h)`（完全不用 off） |

几何全部在**世界坐标点集**上算（像素坐标 + 公式给出的偏移），不铺大画布；跨层最近距离用「包围盒分轴间隙下界预筛 + 栅格化 8 邻域膨胀计步（cap = 14 px）」。

样本：武器对 **210** 组（2 阵营 × 15 造型 × 4 武器位 × (Wait 0001/0006/0009 + Attack 0002/0006/0009)），坐骑对 **240** 组（2 × 15 × 8 匹马）。

### 3.2 六项检验（数字都是中位数 / 比率）

| 检验 | 判据 | F1 | F2 | F3 | F4 | F5 |
|---|---|---|---|---|---|---|
| **T1** 坐骑蹄底 y（应 ≈ 0） | 越小越好 | **+6.0**（IQR 1.0） | +241.0 | +241.0 | +6.0 | 0.0（构造使然） |
| **T4** 武器↔身体接触率 | 越高越好 | **85.7 %**，距 0 / p95 5 | 31.4 %，距 9 | 68.6 %，距 0 | 45.7 %，距 2 | 100 %（但位置乱） |
| **T4b** 身体↔坐骑接触率 | 不区分 | 100 % | 100 % | 100 % | 100 % | 100 % |
| **T2** 死亡 10 步底边 y | 应单调落到地面 | **55→51→39→22→7→8→8→9→10→10** | 145→…→68 | 145→…→68 | — | 恒 0 |
| **T3** 各动作底边 y | 应稳定 | A −42 / A5 −41.5 / A6 −40.5 / D −39 / R −40 / S −41 / W −39 / H −39 / L −39 | 全偏 +200 量级 | 全偏 +200 量级 | — | 恒 0 |
| **T5** 握把端位置（n=180） | 重叠应在武器端部 | p 中位 **0.135**，p<0.15 占 **66.7 %**，p<0.25 占 **100 %** | — | — | — | — |

`p` = 重叠质心到武器最近端点的归一化距离（0 = 端部，0.5 = 剑身中央）。**没有任何一次是「剑身穿胸」**；重叠面积占武器 ink 中位 7.4 %、p95 59.3 %，都是拳头包住握把的量级。

### 3.3 装配残差（F1）

- 武器到身体最小距离：**中位 0.0 px**，**p95 5.0 px**，**max 8.0 px**。
- 坐骑蹄底到地面线：中位 **+6.0 px**，IQR 1.0（原作马匹自带地面阴影，阴影比蹄底再低几个像素，这就解释了 +6 而不是 0）。
- 站立类动作（W/R/A/A5/A6/D/H/L/S）的 ink 底边稳定落在 **−39 .. −42 px**，IQR ≤ 2 px —— 这是**骑在马上的鞍高**，不是误差。

> 一句话：F1 把 3 层拼成了「骑手坐在鞍上、兵刃握在手里、尸体躺在地上」的三张自洽的图。F2/F3 偏 241 px（图上完全散架），F4 把 x 镜像后武器掉手（接触率 85.7 % → 45.7 %），F5 位置自洽但完全忽略 off（10 个造型的头部会互相错位）。

### 3.4 锚点语义（最终表述）

```
draw_top_left_x = unitX − offx
draw_top_left_y = unitY − offy
```
`unitX/unitY` = 该单位**脚下地面点**（屏幕坐标）。三条独立证据：
1. 坐骑蹄底/阴影落在 **+6 px**；
2. FS（地面阴影剪影）底边落在 **+7/+8 px**；
3. 尸体躺平后底边收敛到 **+10 px**。

三者互相印证：**锚点就是地面点**，而站立动作的 −40 px 是「马背上的骑手」，不是「浮空」。

> ⚠️ 这条对渲染有硬约束：**主将必须画在马背上**。只画 BODY 不画 HORSE，小人会离地悬空 40 px。原作没有「下马站立」的身体帧（FS 是阴影）。

### index.json 结构

```jsonc
{
  "meta": { "version":1, "count":3270, "sheets_bytes":5302687, "page_size":[1024,2048],
            "padding":1, "palette_colors":256, "tiers":[1,2],
            "anchor":"draw top-left at (unitX - ox, unitY - oy); 1px = 1 world unit at scale 1" },
  "pages": [ { "file":"sheet_02.png", "w":1024, "h":1024, "unit":"L1",
               "sprites":[ {"name":"L1W10001","x":276,"y":152,"w":72,"h":102,"ox":37,"oy":141} ] } ],
  "groups": { "L1:Wait:1":["L1W10001","L1W10002","L1W10003","L1W10004","L1W10003","L1W10002"],
              "L1:Walk":[…9], "L1:Attack:1":[…10], "L1:Walk"…, "W700:Wait":[…], "H900:Walk":[…] },
  "actions": { "L1:Wait:1": {"d":null,"h":[16,8,8,16,8,8],"loop":1},
               "L1:Walk":   {"d":4,"h":[4,4,4,4,4,4,4,4,4],"loop":1},
               "L1:Attack:1":{"d":3,"h":[3,3,3,3,3,3,3,3,3,3],"loop":0} },
  "objects": { "600": {"name":"主將L1 (主體) - 劍","kind":"BODY","seq":600,"side":"L","shape":"1","slot":1} }
}
```

- **`groups` 语义照抄 `units.json`**：`动作名 → 帧名数组`，直接喂给现有的 `pushSpriteFrames(rects, walk, atk, …)`。
- **`actions`** 是 `things_parsed.json` 的动作 → 帧序列 + `#N` 停留 tick：`d` = 行首默认延时（`null` = 未写），`h[i]` = 第 i 帧的停留 tick（`null` = 用 `d`），`loop` = 该动作是否循环。共 **512 条**，覆盖 index 里全部 groups。
- `ox/oy` **等于原始 offx/offy**（裁 bbox 是 no-op：BODY 帧的 ink 包围盒平均占满 102.6 % 面积）。
- 键格式：主体 `L1:Wait:1` / `L1:Walk`（W/A 带 `:slot`，其余不带）；武器 `W700:Wait`；坐骑 `H900:Walk`。

## 6. 武将 → 造型 / 武器 / 坐骑 映射

### 6.1 TYPE → 造型（覆盖率 400/400 = 100 %）`[推测-强视觉证据]`

`generals.json` 每条有 `TYPE`（1..15，另有 1 条 `id:0` 模板为 30）。`TYPE n` → 造型表第 n 个：

```ts
const SHAPE_OF_TYPE = ['1','2','3','4','5','6','7','8','9','A','B','C','D','E','0'];
//                      ↑TYPE1                                            ↑TYPE15
```

依据（三条互相独立）：

1. **结构**：15 个 TYPE ↔ 15 个造型符号 `1..9,A..E,0`，正好是一个 0-based 下标映射（第 15 个符号写作 `0`）。
2. **语义**：TYPE 分组的人数 21/100/14/10/10/10/19/39/81/9/23/14/22/**6**/**22**，与造型的视觉特征对得上 ——
   - TYPE 14（n=6，**大喬/小喬/孫尚香/祝融夫人/貂蟬/關鳳，全是女性**）→ **LE 是唯一的女性造型**（长发、无鬚）；
   - TYPE 9（n=81，諸葛亮/荀彧/魯肅等**文官**）→ **L9 是唯一紫袍官帽、无甲的文官造型**；
   - TYPE 6（n=10，張飛/許褚/典韋/文醜）→ **L6 是赤膊巨汉 + 黑鬚 + 绿裤**；
   - TYPE 12（n=14，張梁/張寶/程遠志/管亥等**黄巾系**）→ **LC 是金黄袍 + 金冠**；
   - TYPE 10（n=9，呂布/趙雲/周瑜/孫策）→ **LA 是蓝金甲 + 高冠橙翎**。
3. **对齐**：`extract/pak/TIMES{1..5}.INI`（big5）的 `[GENERAL]` 段 `TYPE` 与 `xls_群英2` 的 `图形的类型` 400 条全等（05b §4.2 已验证）。

对照图：`work/gen_sprites/shapes15.png`（15 造型 × 2 阵营首帧）、`work/gen_sprites/zoom_types2.png`（6 个判别类型的上半身 6 倍放大）。
**未**读游戏二进制里那张 TYPE→图形序列的表，所以标 `[推测]`；但 5 个判别性类型全部吻合，实际风险很低。

TYPE1..15 的人数：`21 / 100 / 14 / 10 / 10 / 10 / 19 / 39 / 81 / 9 / 23 / 14 / 22 / 6 / 22`，合计 400。

| 銅殳 | 73 | C（矛） | **3** | `740 銅殳` |
| 眉尖刀 | 91 | D（刀斧） | **4** | `760 眉尖刀` |

链路是**数据闭合**的，不是猜的：`game/data/items.json` 的 77 条物品里，`TYPE = JEWEL_WEAPON` 的 34 条同时给出 `WeaponType`（0..3）与 `WeaponObject`（= WEAPON 序列号 700/720/740/760…），`Sprite = JEWEL\WEAPONA1` 之类；`TYPE = JEWEL_HORSE` 的 8 条给 `WO = 900..907`。所以：

- **BODY 槽位 = 武将当前装备武器的 `WeaponType + 1`**
- **武器图形 = 该武器的 `WeaponObject`**（34 把里任选，`W{seq}:Wait` / `W{seq}:Attack`）
- **坐骑图形 = 马物品的 `WeaponObject`**（900..907 = HA..HH）

唯一的名实不符：TIMES 写 `短錐槍`，物品/图形叫 `圓錐槍`（同一个槽位 2，不影响装配）。
8 匹马：900 黃鬃馬 / 901 褐鬃馬 / 902 黑鬃馬 / 903 大宛馬 / 904 鐵騎馬 / 905 的盧 / 906 爪黃飛電 / 907 赤兔馬。

> 注意：`generals.json` / TIMES 里的 `Horse` 全是「黃鬃馬」—— 那是**初始装备**，实际坐骑要读物品。别拿这个字段当坐骑图形。

## 7. 没解决的 / 有风险的

1. **Win(FS) 不可用**：300 帧纯黑剪影（§2）。没有胜利动作。要么复用 Wait + 特效，要么另找素材。
2. **引擎 tick 时长未知**：图集给的是**停留 tick 数**（`actions[*].h`），不是毫秒。原作一 tick 多少 ms 没找到（反汇编没做）。demo 里暂按 **33 ms/tick** 播（`[新设计]`），battleView 接的时候应该用引擎自己的 tick（`world.tick`），而不是墙钟。
3. **武器只有 Wait / Attack 两套动作**（`W*:Wait`、`W*:Attack` 各一，34 × 2 = 68 组）。Walk / Death / Defense 时武器没有对应帧。demo 里在非 Wait/Attack 动作下**借 Wait 第 1 帧**（`[新设计]`，代价：走路时兵刃僵在待机姿势）。原作引擎大概是「没有就不画」。
4. **BODY 没有「下马站立」姿势**：所有站立类动作的脚都在锚点上方 40 px（鞍高）。要下马演出必须另配。
5. **TYPE → 造型仍是 `[推测]`**（§6.1），没读游戏码里的映射表。
6. **Attack2..Attack8 的语义没定**：只有 05b 的「A6 = 後攻擊、A5 = 半月斬」两条，哪些招式播哪条动作没对到 `magics` 表。
7. **14.3 % 的武器对接触不上**（85.7 % 接触率，距离 > 14 px 的被截断）：集中在 Attack 中后段（挥空、脱手）。是原画如此还是帧索引错，没有逐帧核对。
8. **`things_parsed.json` 里武器/坐骑的帧名为 `NULSHAPE`**（武器 Shot1/Shot3）= 射击时武器确实不可见，这点是对的，但意味着「弓箭手主将」手里不会有弓。

## 8. battleView 该怎么画（接线说明，可直接照抄）

现状：`game/src/view/battleView.ts` 的 `drawGeneral()`（第 727 行起）是纯矢量画的（阴影椭圆 + 旗 + 方框身体 + 菱形将徽）。目标是**只替换「身体」那一段**，阴影/旗/名字保留 —— 这样即使图集没加载好，也能降级回矢量小人。

### 8.1 新建 `game/src/view/generalAtlas.ts`

```ts
// 武将战场小人图集（game/web/anim/general/）。与 atlas/units 并列，互不干扰。
export interface GFrame { x: number; y: number; w: number; h: number; ox: number; oy: number; page: string }
export interface GeneralAtlas {
  base: string;
  pages: Map<string, HTMLImageElement>;
  frames: Record<string, GFrame>;
  groups: Record<string, string[]>;
  actions: Record<string, { d: number | null; h: (number | null)[]; loop: number }>;
  objects: Record<string, { name: string; kind: string; seq: number; side?: string; shape?: string; slot?: number }>;
}

export async function loadGeneralAtlas(base = 'anim/general/'): Promise<GeneralAtlas | null> {
  try {
    const r = await fetch(base + 'index.json', { cache: 'no-store' });
    if (!r.ok) return null;
    const j = await r.json();
    const frames: Record<string, GFrame> = {};
    for (const p of j.pages) for (const s of p.sprites) frames[s.name] = { ...s, page: p.file };
    const pages = new Map<string, HTMLImageElement>();
    for (const p of j.pages) {
      const im = new Image();
      im.src = base + p.file;
      pages.set(p.file, im);
    }
    return { base, pages, frames, groups: j.groups, actions: j.actions, objects: j.objects };
  } catch { return null; }
}
```

`ViewOptions` 加一个可选字段（与 `atlas` / `units` / `fx` 同构）：

```ts
general?: GeneralAtlas | null;      // anim/general/index.json
```

`buildFrame()` 里把它传进 `drawActors(out, world, camX, opts.atlas ?? null, opts.units ?? null, opts.general ?? null)`。

### 8.2 `drawGeneral()` 里替换身体那一段

原代码第 754–782 行（`// 身体` 到胸前菱形）整块替换为：

```ts
const S = 1.0;                    // 1 原作像素 = 1 屏像素（车道宽 LANE_PX=53.57，马宽 140 ≈ 2.6 车道）
const SHAPE_OF_TYPE = ['1','2','3','4','5','6','7','8','9','A','B','C','D','E','0'];

function shapeSymbol(type: number | undefined): string {
  const i = Math.min(15, Math.max(1, Number(type) || 2)) - 1;
  return SHAPE_OF_TYPE[i];
}
function holdOf(a: GeneralAtlas, key: string): number[] {
  const meta = a.actions[key];
  const nul = meta?.d ?? 8;
  return (meta?.h ?? []).map((v) => (v == null ? nul : v));
}
/** tick → 该动作的第几帧（按停留 tick 累计；loop=0 时钳到末帧） */
function frameIndexAt(a: GeneralAtlas, key: string, tick: number): number {
  const h = holdOf(a, key);
  if (h.length === 0) return 0;
  const total = h.reduce((s, v) => s + v, 0);
  let t = a.actions[key]?.loop ? ((tick % total) + total) % total : Math.min(tick, total - 1);
  for (let i = 0; i < h.length; i++) { if (t < h[i]) return i; t -= h[i]; }
  return h.length - 1;
}

function pushGeneralLayers(
  out: DrawCmd[], a: GeneralAtlas, u: Unit, ax: number, ay: number, s: number,
): boolean {
  const g = world.sides[u.side].general;                   // 拿到 TYPE / 装备
  const side = u.side === 'A' ? 'L' : 'R';                 // L=蓝(我方) R=红(敌方)
  const shape = shapeSymbol((g as any).TYPE);
  const slot = 1;                                          // = WeaponType + 1，见 §6.3
  const wseq = 700;                                        // = 该武器物品的 WeaponObject
  const hseq = 900;                                        // = 该马物品的 WeaponObject

  // 动作选择：出手窗口 → Attack，死亡 → Death，移动 → Walk，否则 Wait
  const act = !u.alive ? 'Death'
            : u.cd > 96 ? 'Attack'
            : u.moving ? 'Walk' : 'Wait';
  const bodyKey = (act === 'Wait' || act === 'Attack')
    ? `${side}${shape}:${act}:${slot}` : `${side}${shape}:${act}`;

  const names = a.groups[bodyKey];
  if (!names || names.length === 0) return false;
  const bi = frameIndexAt(a, bodyKey, world.tick);

  // 画三层：坐骑 → 身体 → 武器（顺序不能反，武器要压在身体上）
  const horseAct = act === 'Walk' ? 'Walk' : (act === 'Attack' ? 'Attack' : 'Wait');
  const hk = `H${hseq}:${horseAct}`;
  const wk = `W${wseq}:${act === 'Wait' || act === 'Attack' ? act : 'Wait'}`;

  const push = (name: string | undefined, idx = 0) => {
    if (!name) return;
    const f = a.frames[name];
    if (!f) return;
    const img = a.pages.get(f.page);
    if (!img || !img.complete || img.naturalWidth === 0) return;
    const w = f.w * s, h = f.h * s;
    out.push({
      kind: 'sprite', img,
      sx: f.x, sy: f.y, sw: f.w, sh: f.h,
      // execute() 把 (x - w/2, y - h) 当左上角画；这里反解，让左上角正好落在
      // (ax - ox*s, ay - oy*s)，也就是图集约定的锚点语义。
      x: ax + (w / 2 - f.ox * s),
      y: ay + (h - f.oy * s),
      w, h,
    });
  };

  const hg = a.groups[hk], wg = a.groups[wk];
  push(hg?.[Math.min(bi, hg.length - 1)]);
  push(names[Math.min(bi, names.length - 1)]);
  push(wg?.[act === 'Attack' ? Math.min(bi, wg.length - 1) : 0]);
  return true;
}
```

### 8.3 三个必须记住的点

1. **锚点是脚底地面点，`(x,y)` 不是左上角**。渲染器 `execute()`（第 1548 行）用的是 `(x - w/2, y - h)`，所以必须按上面的公式反解，否则整层会偏 `(w/2, h)`。
2. **主将必须画在马背上**。BODY 的站立姿态本身就在锚点上方 40 px（鞍高）。只画 BODY 会浮空；只画 HORSE 会看到一匹空马。
3. **靠 `groups` 的键选动作**，不要自己拼帧名：`Wait`/`Attack` 要带 `:slot`（1..4），其余动作不带；武器/坐骑的键前缀是 `W{seq}:` / `H{seq}:`。

### 8.4 验收自测

- 打开战斗，主将应表现为「骑将 + 持械」的小人，约 2.6 个车道宽、1.5 个车道高；
- 停住时播 Wait（4 帧 6 步），移动时播 Walk（9 帧，每帧 4 tick），出手瞬间（`u.cd > 96`）播 Attack（10 帧，每帧 3 tick）；
- 阵亡时播 Death（10 帧，从鞍上落到地面，底边 +55 → +10 px）；
- 砍掉 `index.json` 或让 sheet 404，应自动回退成原来的矢量小人（不报错、不空白）。
