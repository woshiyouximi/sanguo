## 12.3 `animSelect.ts` API

```ts
export interface Rect { x: number; y: number; w: number; h: number }
export type ActionAtlas = { img: HTMLImageElement | null; frames: Record<string, Rect[]> };
export interface ActionPick { key: string; index: number }

export function pickActionFrame(u: Unit, world: World, atlas: ActionAtlas): ActionPick | null;
export function isDying(u: Unit, world: World): boolean;
export function usesActionFrames(u: Unit): boolean;
export function actionSpriteCmd(act: ActionPick | null, x: number, y: number, atlas?: ActionAtlas): ActionSpriteCmd | null;
export function pushActionSprite(out: { push(cmd: ActionSpriteCmd): void }, act: ActionPick | null, x: number, y: number): boolean;
export function loadActionAtlas(jsonUrl?: string, imgUrl?: string): Promise<ActionAtlas>;
export function ensureActionAtlas(): ActionAtlas;
export const actionAtlas: ActionAtlas;
export const ACTION_KEYS: readonly ['attack_back', 'hit_back', 'death_back'];
export const ACTION_SIDES: readonly Side[];  // 默认 ['A']
export const ATTACK_TICKS = 10;
export const HIT_TICKS = 8;
export const DEATH_TICKS = 12;
```

语义（依据：本次需求；窗口长度与优先级为（新设计））：

1. **阵亡优先**：`!alive` 且 `world.tick - lastHitTick ∈ [0,12)` → `death_back`，播完停末帧；
   窗口外返回 `null`，调用方跳过不画（尸体消失，等同旧行为）。
   士兵命中即死（`core/battle.ts:355`），所以 `lastHitTick` 就是阵亡 tick，不需要第三个字段。
2. **受击**：活着且 `tick - lastHitTick ∈ [0,8)` → `hit_back`。
3. **攻击**：`attackAnimT ∈ [0,10)`；没有该字段时用 `tick - lastAttackTick ∈ [0,10)` → `attack_back`。
4. 其余返回 `null`，调用方沿用走路序列。

帧映射：`index = clamp(floor(t * (n-1) / (T-1)), 0, n-1)`，窗口最后一 tick 一定落末帧，
所以 17 帧的攻击/死亡、10 帧的受击都会完整播完，不会卡在中段。

字段容错：`lastAttackTick` / `lastHitTick` / `attackAnimT` / `world.tick` 全部先 `in` 判断再取
`number`，缺失、类型不对、`NaN` 一律当「没有动作」。`pickActionFrame` 对 `atlas.frames` 缺 key
也返回 `null`，不抛异常。

阵营：素材只有背视，`ACTION_SIDES` 默认 `['A']`，敌方 B 继续用 `walk_front` / `attack_front`
（依据：`project/PROJECT_BRIEF.md` 的「我方差背视、敌方正视」）。要临时让敌方也复用背视帧，
把 `'B'` 加进 `ACTION_SIDES` 即可，旧的攻击分支会自动让位（`usesActionFrames()`）。

图集加载：模块 import 时若检测到浏览器环境（有 `document` / `Image` / `fetch`）就自动
`fetch('anim/actions.json')` + `Image('anim/actions_00.png')`，写进单例 `actionAtlas`；
Node 下静默跳过，所以 `node --test` 与自测不会碰网络。**因此 `main.js` 一行都不用改。**

## 12.7 已知限制 / 后续

- **敌方 B 不接**：没有正视动作帧，强上背视帧朝向会反（依据：`PROJECT_BRIEF.md`）。

  主将虽然会挨打，但走 `drawGeneral`，不走 `drawSoldier`。保留它是给后续「格挡 / 非致命伤 /
  主将动作」用（新设计）。
- **节奏偏快**：`ATTACK_TICKS=10` 在 30Hz 下是 0.33s，17 帧 ≈ 51fps；`DEATH_TICKS=12` 是 0.4s，
  17 帧 ≈ 42fps。按需求写的窗口；如果嫌快，只改常量（例如 `ATTACK_TICKS=24` 正好等于旧
  `u.cd > 96` 的 24 tick 窗口），帧映射会自动重新铺满。
- **主将死亡不接**：无素材，`isDying()` 对 `isGeneral` 直接返回 false，阵亡仍立即消失。
- 图集是异步加载的，第一帧网络 RTT 内仍走旧逻辑；加载失败只在 console 警告一次，不阻塞战斗。

| 其它 | — | 返回 `null`，调用方走 `atlas.json`（行为不变） | | |

- 兵种号取 `world.sides[side].troop`（`core` 的 `Unit` 目前不带兵种号），单位自带 `troop` 时优先
  用单位的 —— 留给「骑兵按单位带兵种」这类改法。
- **骑乘这一轮不接**：骑兵在原作里没有独立兵种号，是「兵种造型 + 马」的变体，`troop` 里没有它的下标。
  等 `General.Horse`（马）接进数据后，再在 `GROUP_BY_TROOP` 里按「兵种 + 有无马」映射到 `ride`。
- **`walk_side` 这一轮不接**：素材已备，等朝向系统（还没有「侧向移动」的判定）。
- 只读、无副作用；任何输入缺失（没图集 / 没 side / 没兵种号 / 组缺失 / 帧名查不到）一律返回 `null`，
  绝不抛错 —— 这是可测的降级入口，`tests/units.test.ts` 里逐条覆盖。

### 12.8.4 视图接线（`game/src/view/battleView.ts`）

- `ViewOptions` 加 `units?: UnitsAtlas | null`（`battleView.ts:219`，与 `atlas` 并存）；
  `buildFrame` 把它传给 `drawActors(..., opts.atlas ?? null, opts.units ?? null)`（`battleView.ts:491`）。
- `drawSoldier(..., atlas, units)`（`battleView.ts:607`）的绘制顺序变成**三级降级**：

  ```ts
  const set = pickUnitFrames(world, u, { units });        // 兵种图集（弓/弩）
  // 背视动作帧（受击/阵亡/攻击）优先；但弓兵有自有拉弓帧时让开 attack_back
  const act = set && set.attack.length > 0 && act0?.key === 'attack_back' ? null : act0;
  if (pushActionSprite(out, act, fx, fy)) return;
  if (!u.alive) return;
  if (set && pushSpriteFrames(out, set.img, units?.frames ?? {}, set.frames, set.attack, u, world.tick, set.hold, fx, fy, true)) return;
  if (atlas) { /* 老路径：walk_back / walk_front + atlas.attack，行为与合并前一致 */ }
  // 再兜底：色块 + 朝向三角
  ```

- 抽出了 `pushSpriteFrames(out, img, rects, walk, atk, u, tick, hold, fx, fy, allowSwing)`（`battleView.ts:685`）：
  走路相位 `Math.floor(u.x * 7 + u.y * 13) + Math.floor(tick / max(1, hold))`、攻击帧用「剩余 `cd`」
  铺满 `cd 120→96` 的 24 tick，与旧代码同一套数学；帧名查不到就返回 `false` 让调用方继续降级
  （不把 `NaN` 塞进 `drawImage`）。**旧兵种走的是同一个函数、同样的参数，行为没变。**
- **一处必须让位的地方**：`animSelect.ts` 的 `attack_back` 是朴刀挥砍的背视帧，而 `ACTION_SIDES = ['A']`
  —— 如果不管，我方弓兵出手后 10 tick 会「拉弓拉到一半突然换刀」。所以 `pickUnitFrames` 命中且该组有
  自有攻击帧时，`attack_back` 那条动作指令被丢掉，攻击窗口交给弓兵自己的 `attack` / `attackEnemy`。
  受击 / 阵亡仍然走动作帧（那两样素材弓兵还没有）。

### 12.8.5 降级三层（都实测过）

1. `units.json` 拉不到 / 图 `onerror` / 组缺失 → `state.units` 保持 `null`，`pickUnitFrames` 返回 `null`，
   全体退回 `atlas.json` 的 `walk_back` / `walk_front` / `attack_front`；console 只 warn 一次。战斗照常推进。
2. `units` 在但某组/某帧缺失 → `resolveNames` 过滤掉查不到的帧名；连走路帧都空就返回 `null`（同上退回 atlas）。
3. 两套图集都没有 → 原来那套色块 + 朝向三角，仍然不白屏。

### 12.8.7 顺带修的一个坑：`?sim=N` 之前完全没生效

`boot()` 里的 `while (guard++ < simParam) step(state.world)` 跑在**预览世界**上，而 `startBattle()` 是
`async`（先 `await initMagicProgram()`）才把 `state.world` 换成新世界 —— 新世界 tick 从 0 开始，把
`sim` 的结果整个盖掉。修法：`game/web/main.js:891`（`?auto=1`）与 `game/web/main.js:899`（`?sim=N`）两处改成 `await startBattle()`，注释说明
「必须 await，否则 ?sim 跑在预览世界上」。修完 `?sim=200` 实测 `tick=200`。普通玩法（不带 `?sim`）行为不变。
