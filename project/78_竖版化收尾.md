### 1.3 方案 A（推荐）

![方案 A](../work/vertical/v1_a.png)

- 算式：`s=min(750/1280, 695/960)=0.5859375`（宽受限），图 750×562.5，居中后上下各 66.25px；左右 0。
- 实现（只在 `campaign.html` 内，2 处）：
  1. `plotRect()` 去掉 `*0.965`；`y=(view.h-h)/2` 保持；`syncBg()` 已经用同一 rect，自动跟随。
  2. 装饰：最省事是 `#mapwrap` 铺一层绢帛纹理 + `#bgmap` 加金线 `box-shadow`（0 行 JS）；要做卷轴杆，则在 `syncBg()` 里把两根 `.maplb-rail` 定位到 `rect.y-18` 与 `rect.y+rect.h+6`（+2 行）。
- 为什么推荐：
  1. **60/60 始终可见**。B 默认把襄平（第 1 剧本开局城）和吳/會稽/下邳藏到屏外，对「先看全局再点城」的大地图是硬伤。
  2. **零命中风险**：`toScreen()` 一行不改，`bd < 40*40` 的点击容差不变，不存在「看得见点不中」。
  3. **1200×900 同样成立**：整个 #stage 等比缩放，装饰带按同一比例缩，不会在宽屏露出新的空白。
  4. 改动只有 1 个常量 + 可选 2 行装饰，另一个 agent 正在改 campaign.html，冲突面最小。
- 代价：地图本体仍只占 695 的 80.9%。如果 lead 的验收口径是「地图像素必须铺满 695」，那只能选 B——这是唯一真正满幅的方案。

`#mapwrap` 当前是 `flex:1 1 auto;min-height:0;position:relative`（`campaign.html:50`），装饰带必须画在 `#mapwrap` 内、`#bgmap` 下/上，不能加进 `#logbox`，否则会挤掉 196px 的战报区。

### 2.1 统一口径

四页现在共用同一串（`index.html:5`、`items.html:5`、`deploy.html:5`、`city.html:5`）：

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">
```

| 页面 | 改前 | 改后 |
|---|---|---|
| `index.html` | `device-width, initial-scale=1, viewport-fit=cover`（缺 max/user-scalable） | 统一串 |
| `items.html` | `device-width, initial-scale=1, maximum-scale=1, user-scalable=no`（缺 fit） | 统一串 |
| `deploy.html` | 同 items | 统一串 |
| `city.html` | **`width=750`** + initial + fit | 统一串 |
| `campaign.html`（未动） | `device-width, initial-scale=1, maximum-scale=1, user-scalable=no`（只差 `viewport-fit=cover` 一个 token） | 由它的 owner 补 token；`width` 口径已经一致 |

### 2.2 约定（复制到每个竖屏页）

1. **viewport 只有一种写法**：`width=device-width`，禁止 `width=750`。`width=750` 会在真机（390 CSS px）上把整页缩成 0.52 倍，文字变小；`device-width` + `fit()` 才是同一份设计稿在 750 模拟器、390 真机、1200 桌面都成立。
2. **设计坐标系固定 750×1334**：所有 px、字号、间距都写在这个坐标系里；不写 `vw/vh`（安全区用 `env(safe-area-inset-*)` 包在 padding 内）。
3. **`#stage` 必须先绝对定位再 scale**，`transform-origin:0 0`；禁止「flex 居中未缩放的 stage」——1200×900 时 flex 会先把 1334 高的 stage 居中，scale 后标题被顶出视口（`campaign.html` 的 fit 注释里已经踩过）。
4. **`body` 尺寸 = 缩放后的 750s×1334s**，`html,body{overflow:hidden}`；否则浏览器按未缩放的 stage 算滚动区，出现横向/纵向滚动条。
5. **页眉/页脚属于 1334 内部**，不允许「body 滚动兜底」；超了就是布局错，按 §3 的方式压间距/字号，不许删内容。
6. 媒体查询只允许在 `max-width:750px` 内做「页眉压缩」，不得改 stage 的 750×1334。

可直接复制的 fit 模板：

```html
<style>
  html,body{margin:0;width:100%;height:100%;overflow:hidden;background:#0b0d11}
  #stage{position:fixed;left:0;top:0;width:750px;height:1334px;transform-origin:0 0;overflow:hidden}
</style>
<script>
(() => {
  const DW = 750, DH = 1334, stage = document.getElementById('stage');
  function fit() {
    const s = Math.min(innerWidth / DW, innerHeight / DH);
    stage.style.transform = `scale(${s})`;
    stage.style.left = ((innerWidth  - DW * s) / 2) + 'px';
    stage.style.top  = ((innerHeight - DH * s) / 2) + 'px';
    document.body.style.width  = (DW * s) + 'px';
    document.body.style.height = (DH * s) + 'px';
  }
  addEventListener('resize', fit, { passive: true });
  addEventListener('orientationchange', fit);
  fit();
})();
</script>
```

`items.html` / `deploy.html` / `city.html` 已经是这个结构（fit 分别在 `items.html:226-237`、`deploy.html:199-209`、`city.html:386-398`），本轮只统一了 meta，没有动它们的 fit。

### 2.3 `index.html` 的 640 到底护的是什么

- 规则在 `#error .box` 里（`index.html:115-120`），是**错误覆盖层对话框**的阅读行宽，不是页面限宽，也不是画布限宽。750 截图里从来没有 640 的限宽效果。
- 但它确实会在 `<640` 的窄屏上把对话框压到 592px（100vw-48 之前没有），所以不能简单删。改成：

```css
#error .box {
  width: 100%;
  max-width: min(640px, calc(100vw - 48px));  /* 750 上仍取 640；窄屏取视口-48 */
}
```

- 同时把 `@media (max-width:720px)` 改成 `750px`（`index.html:141-150`）：旧断点把 `.brand` 和 `#stat` 各占整行，750 上反而变三行；新断点压成「品牌+4 选择器+种子+开战」一行 + 状态一行，页眉 99.6 → **72px**，canvas 从 676×1202 → **691×1230**。
- 注意：`index.html` 的画布尺寸由 `main.js:1193-1207` 决定（见 §7 残余），本轮的 750 断点只是把页眉让出来的空间还给画布，没有改 main.js。
