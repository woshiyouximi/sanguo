# 29 城池内政八命令

把 `campaign.html` 底部的 3 个键（徵兵／開發／推進一月）补成原作的 **8 条内政命令**。
做法是**新建一整屏** `game/web/city.html`（750×1334），从大地图点自己的城进入；
`campaign.html` 一个字符都没改（那边的入口由另一个改动接上）。

纯逻辑全在 `game/web/city_model.js`（无 DOM，可被 node 直接 import 做自检）；
存档仍走 `game/web/saves.js` 的 API，**只新增字段，不改既有结构**。

## 1. 文件与入口

| 文件 | 说明 |
|---|---|
| `game/web/city.html` | 整屏页面：顶部城情 HUD ＋ 2×4 宫格 ＋ 结果日志 ＋ 4 个底部抽屉 |
| `game/web/city_model.js` | 8 条命令、掉落表、存档补字段、伪随机、URL 拼装，全部纯函数 |
| `game/web/city_selftest.mjs` | 25 条断言，`node city_selftest.mjs` 输出 `25 过 / 0 敗` |

依赖：`./saves.js`（只调用）、`../data/{scenarios,generals,items,wises,sango_system}.json`、
`items.html`（物品页）、`deploy.html`（出征页）。

URL 参数：`?city=城名` 入口；`?gold=N`、`?do=develop,search,…`、`?dump=1` 是**除错口子**，
UI 上没有入口（`?dump=1` 把前后差异塞进隐藏的 `<pre id="dump">`，供 CDP / `--dump-dom` 取）。

`eff = 1 + min(INT/400, 0.25)`（太守智力；`eff` 的系数是 [新设计]，只有"太守是城的字段"这一条依据）。

## 3. 搜索掉落表

| 结果 | 权重 | 池子（`items.json` / `generals.json`） | 文案 |
|---|---|---|---|
| `talent` 人才 | 30 | 该剧本 `CITY===本城` 且 `Status==='野'` 的将（排除已入池/已在我方的） | `%s將軍加入我方。` |
| `talisman` 兵符/阵法书 | 20 | `SearchType===0` 且 `Force>0`（兵符 13 件）或 `Battle>0`（阵法书 9 件） | `找到物品%s。` |
| `treasure` 宝物 | 25 | `SearchType` 1/2 的兵器坐骑，＋`SearchType===0` 的 `JEWEL_THING` 兵书、`Loyal>0` 珠宝 | `找到物品%s。` |
| `none` 空手 | 25 | — | `搜索一無所獲。` |

- 池子实测：`talisman 22 / treasure 50`；`Rate` 是**权重**，`Rate===0` 的 5 件（直劍/短錐槍/銅殳/眉尖刀/黃鬃馬）搜不到。
- 某座城没有在野将 / 池子为空时，对应权重直接置 0，不会抽到空结果。
- 可复现伪随机：`seed = hashFn('search', 城, 月, count)`（FNV-1a 32）→ `mulberry32(seed)`；
  `count` ＝ 本城历史搜索次数（0 基，数 `searchLog` 里 `cmd==='搜索'` 的条数）。
- **搜索函数自己写结果日志**，页面不再补记：否则 `count` 不递增、种子固定，同一城会永远搜到同一件东西。
- 人才是真的进池：`roster[城]` 追加该将名，之后「情報／移動／任命／出征」都看得到（已用襄平→閻圃验证）。

## 4. 存档新增字段（同一份 `localStorage['sanguo_campaign_v1']`）

| 字段 | 形状 | 用途 |
|---|---|---|
| `roster` | `{ [城名]: [将名…], _moved: { [将名]: 城名 } }` | 搜到的人才、调动的武将 |
| `appointed` | `{ [城名]: { major, wise } }` | 任命结果（空串＝用剧本默认） |
| `searchLog` | `[{ t:"第1年1月", m:1, city, cmd, kind, text }]` | 结果日志（本页显示最近 6 条），保留 60 条 |
| `cities[城].def` | number | 城防运行态（开发会改它，剧本里的是初值） |

- 缺字段要能容错：老存档没有这三个字段时按空补；型别错（`roster:'x'`、`cities:'oops'`、`gold:NaN`）归零不抛错。
- `campaign.html` 的 `normalizeCampaign()` 不删未知键、`ensureCityState()` 只补 `troops/pop/money`
  ⇒ 上面 4 个字段在两边来回读写不会丢。
- 每次命令后同步写三处：当前槽 `Saves.writeSlot(store, 槽, save, {scenarioName, ts})`、
  `Saves.saveStore(store)`、旧单档 `Saves.writeLegacy(save)`（`main.js` 战斗写回只认旧键）。

## 7. 一月一令（R8，2026-11 补）

原作每月只能下**一道**内政/军令：`0x4A64BC` 月内状态位（`docs/04c §1`：写入点 `0x41B6D5=0`、`0x427923=1`、
换月流水线 `0x41B69D` 内清零）。改之前只要有金就能连点开发/搜索/征兵，现已补上：

- 存档新增 `lastActionMonth`（number）：上次下过令的月份，`0` = 本月没下过。
  `M.monthLocked(save, unlimited)` 判定 `lastActionMonth > 0 && lastActionMonth === save.month`。
- `city.html`：本月用过一次后八个命令按钮全部 `disabled`（灰 + 红字「本月已行動」），
  顶部「月令」chip 显示 `可下 / 已用 / 不限`；`onCmd()` 另外兜一层，绕过 DOM 的调用同样被拦。
- `campaign.html`：徵兵/開發/出征（含 `?march=0` 的旧直接开战入口）同样置灰且点不动；
  「推進一月」不受影响，换月时 `M.clearMonthLock(save)` 清零（批量 `?adv=N` 每过一个清零一次）。
- 判定与记位只有一份实现：`city_model.js` 的 `monthLocked / markMonthActed / clearMonthLock / LOCK_HINT`，
  两个页面共用，不各写一套。
- 已知取舍：按 brief「八命令执行一次后当月禁用」，**情報/物品也一起禁**（原作`情報`是查看类）。
  若要放宽，`renderGrid()` 里给这两条单独留常开即可，判定逻辑不用动。

### 7.1 调试开关 `?unlimited=1`（**不是玩法**）

`?unlimited=1` 关掉一月一令，只给截图、自测、批量造数据用：

- `campaign.html?unlimited=1`：顶栏多一条橘字「除錯：不限行動次數」；徵兵/開發/出征不再置灰、也不记月令。
- `city.html?unlimited=1`：八命令常开，「月令」chip 显示 `不限`；跳内政/出征页时参数往后带（`&unlimited=1`），
  避免下一屏又锁上。
- 正式流程不传参 ⇒ 默认就是「一月一令」。除截图/测试脚本外不应使用；**别把它当玩法开关**。
- 另有 `?do=develop,search,...`（既有调试口子）：它本来就没有 UI 入口，**绕过月令**（`onCmd(cmd, true)`），
  否则同一串命令第二条就被自己挡掉；跑完仍把本月标记为「已行动」（所以截图里按钮是灰的）。
