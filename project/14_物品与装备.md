## 1. 结论
- **77 件分 6 组**：兵器 34 / 坐骑 8 / 兵书 8 / 宝物 5（以上可装备）+ 兵符 13 / 阵法 9（使用品）。

- 四槽 `weapon / horse / book / amulet`；`amulet` 是本重制新增的第 4 槽（原作只有 Weapon / Horse / Thing 三槽）。
- 自检 `node game/web/items_selftest.mjs` → **57 过 / 0 败**（exit 0），失败时 exit 1。

## 2. 分组（列表 6 组，组内按原作 `Sort` 升序）
| 组 | 判定 | 件数 | 原作 Sort | 可装备 |
|---|---|---|---|---|
| 兵器 weapon | `TYPE = JEWEL_WEAPON` | 34 | 1–34 | ✅ |
| 坐骑 horse | `TYPE = JEWEL_HORSE` | 8 | 43–50 | ✅ |
| 兵书 book | `TYPE = JEWEL_THING` | 8 | 35–42 | ✅ |
| 宝物 amulet | `JEWEL_MISC` 且 `Loyal > 0` | 5 | 73–77 | ✅ |

## 3. 四槽判定（`slotOf(item)`）
| 槽 | 判定 | 件数 | 代表 |
|---|---|---|---|
| `weapon` | `JEWEL_WEAPON`（不区分 WeaponType） | 34 | 直劍、蛇矛、方天畫戟 |
| `horse` | `JEWEL_HORSE` | 8 | 黃鬃馬、赤兔馬 |
| `book` | `JEWEL_THING` | 8 | 史記、孫子兵法 |
| `amulet` | `JEWEL_MISC` 且 `Loyal > 0` | 5 | 布匹、玉器、美女、黃金、珠寶 |
| `null` | 兵符（`Force`）/ 阵法书（`Battle`）/ 其余 | 22 | 朴刀兵兵符、方形陣法之書 |

`amulet` 用 `Loyal > 0` 当判据而不是图标前缀，因为 `Sprite` 只是图片路径（`JEWEL\JEWEL05`），不编码语义。兵符与阵法书刻意不给槽位：它们是「使用后解锁兵种/阵形」的消耗品，放进装备槽会误导。

## 4. 加成公式
```js
stat = num(general[stat]) + Σ_{slot ∈ 四槽} num(item[stat])   // stat ∈ STAT_KEYS 十项
```
- `num("") = 0`：原作空字符串表示无加成，不参与运算。
- `applyEquip(general, equips)` 返回**新**对象（不改入参），额外挂 `_bonus`（各项合计）与 `_equips`（实际生效的槽位）。
- 生命/技力：`generals.json` 没有 `MaxHP` 字段，`runtimeGeneral()` 先把 `BaseHP/BaseMP` 映射成 `MaxHP/MaxMP` 再算。
- **兵符特殊处理**：`bonusOf(item)` 第一个 `early return` 直接返回十项全 0；同时 `slotOf()` 返回 `null`，即使硬塞进装备表也会被 `normalizeEquips()` 以「槽位不符」丢掉。两条路径都保证「兵符不加属性」。
- `Force` / `Battle` 是 `1<<k` 位掩码，`applyEquip` 只做 OR 累积（这两类没有槽位，实际恒为 0）。

| 组 | 属性 | 范围 | 说明 |
|---|---|---|---|
| 兵器 34 | STR | 1–30 | 30 有 3 件（方天畫戟 / 丈八蛇矛 / 青龍偃月刀） |
| 兵书 8 | INT | 7–20 | 5 件；另 3 件给上限：太平要術 MaxMP 20、青囊書 MaxHP 25、遁甲天書 MaxMP 30 |
| 坐骑 8 | Speed | 1–6 | 赤兔馬 6（`ONLYONE`） |
| 宝物 5 | Loyal | 4–12 | 布匹 4 / 玉器 6 / 美女 8 / 黃金 10 / 珠寶 12 |
| 兵符 13 | — | 0 | `Force = 1<<0 … 1<<12`（朴刀兵…女兵），只解锁兵种 |

## 5. 存档结构
```json
// localStorage['sanguo_items_v1']
{ "equip": { "關羽": { "weapon": 45, "horse": 63 }, "張飛": { "horse": 56 } },
  "bag":   [1, 4, 49, 52, 14, 20, 45, 56, 57, 73, 76, 77] }
```
- `equip` 外层键是武将名（与 `generals.json` 的 `NAME` 一致），内层是 `{槽位: Sequence}`。这个形状本身保证「同槽只能一件」——同槽第二次装备直接覆盖，不需要去重逻辑。
- `bag` 是**拥有清单**而不是容器；初始 12 件 = 兵符 2（seq 1,4）+ 书 2（49,52）+ 武器 3（14,20,45）+ 马 2（56,57）+ 宝物 3（73,76,77）。「全部解鎖（調試）」把 77 件全塞进去并落盘。
- 读档逐槽校验：槽位不符、Sequence 不存在的装备一律丢弃；正在装备的物品会自动补进 `bag`（背包视为「拥有」，卸下不会消失）。

## 8. 已知缺陷
1. **使用等级不校验**：`generals.json` 没有等级字段（401 人都没有），`Level` 只用来显示，Lv45 的方天畫戟可以被任意武将装上。
2. **`ONLYONE` 未做唯一性**：16 件唯一物品允许多名武将同时装备同一件（存档按武将分表，天然不互斥）。
3. **`amulet` 槽与原作不同**：原作里珠宝 73–77 是 `Attrib=USED` 的消耗品，这里改成可反复装卸的第 4 槽。
4. **`Skill`/`HP`/`MP`/`Spirit`/`Tire` 全表为空**：77 件都是 `""`，加成表这五行只能显示「—」；可能是导出时丢了，需要回原作核对。
5. **兵符/阵法书的「使用」没实现**：只展示说明文字，不真的解锁兵种/阵形（位掩码已解码，等战斗侧接入）。
6. **背包没有数量与堆叠**：`bag` 是 Sequence 集合，同件不能持有 2 个；商店/掉落/搜索（`SearchType`/`Rate`）都没接。
7. **武将池与原 `deploy.html` 有偏差**：`save.owned` 为空时 deploy 会把 CITY 空的未登场者（姜維/趙雲…）排进前 12；本页退化成「CITY 非空」的全员，前 12 是 關羽/張遼/孫堅/曹操/夏侯惇/程普/黃忠/李典/劉備/嚴顏/袁紹/公孫瓚。`owned` 非空时两者一致。
8. **属性无上下限**：武力可超 100（关羽 129），也没有最低 0 保护；将来 `Spirit`/`Tire` 出现负值会直接相加。
9. **只算基础 + 装备**：没有官职/兵种/阵形/士气修正，与核心战斗公式还没打通。
10. **存档无版本号/迁移**：`sanguo_items_v1` 只有结构约定，字段改名会静默丢档（非法 Sequence 被丢弃而不是报错）。
