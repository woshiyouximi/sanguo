# 43 像素化实验：纯后处理能把 AI 精灵拉回"32 色原作画风"吗

2026-11-25 · 工具 `tools/pixel_post.py`（单图/批处理）、`tools/apply_pixel_post.py`（批量+命名约定）
产物 `work/pixel_ab/**`；对比图 `work/pixel_ab_units.jpg`、`work/pixel_ab_hero.jpg`（都叠在真实地形上）

**结论先行**：色数达标（32 色板，每帧 ≤32）、体积 −44%（PNG8 −86%）、边缘观感明显改善；
但"像原作的手绘像素画"只做到**一半** —— 剩下的差距不在色数，在**明暗阶数**与 AI 渲染自带的光照。

## §1 处理链（每步可开关）

| 步骤 | 参数 | 实测行为 |
|---|---|---|
| ① 调色板量化 | `--colors 32` | median-cut；**每张图一条色板**（`--palette file`），同一图集所有帧共用 → 帧间不闪色 |
| ② alpha 二值化 | `--alpha-threshold 0.5` | units 帧 alpha 实测只有 0 与 ≥128 两档，这步只动百来个边缘像素，近乎空操作 |
| ③ 1 px 描边 | `--outline-mode outside --outline-color auto` | 沿 alpha 外侧补一圈；auto = 邻域最暗 35% 均值 ×0.35 再吸附色板 → 实测吸附到 `#16120C`，与统一 `#12151A` 肉眼等价。**inside 会吃薄剪影、腿脚丢线，弃用** |
| ④ 像素化 | `--pixel 1`（默认关） | 2× 盒式下采样 + NEAREST 放大，输出尺寸不变 → json 不用改 |
| 追加 | `--kill-glint` | 清掉 AI 精灵自带的接地亮斑（帧底部低饱和高亮像素），默认关，**本实验推荐开** |

输出尺寸恒定、不覆盖原件、GIF/JPG 可选；`--png8` 写 8bit 索引色 PNG（像素完全一致，仅透明像素的隐藏 RGB 归零）。

## §3 判断：肉眼像不像原作

**像的部分（在 64 px 游戏尺寸上尤其明显）**
1. **边缘**：描边 + 二值化把源素材那圈白色 rim light 削掉了，剪影不再发光 → "贴纸感"去掉大半，压进 32 色地形后不再跳出来。
2. **色数与体积**：32 色达标，PNG8 后整包首屏体积降到原来的 1/6。
3. **在地形上读得出单位类型**：弓兵背/正、布衣走的色块分界清楚了，不再是"一团柔光"。

**不像的部分（三点，各有证据）**
1. **脸与细节被压成 mush**：32 个色名额被大面积深绿甲片占满，肤色只剩 2 个 entry（`_probe/zoom1.png` 7×）。
2. **内部还是连续明暗渐变**：AI 精灵是"上亮下暗 + 单侧补光"的 3D 渲染光，原作是"每个材质 3–4 个平色阶"。
   量化只是把渐变切成 30 段渐变色 —— 信息量差 1–2 个数量级，所以放大看仍像"低分辨率照片"。
3. **`--pixel 2` 对兵种是负收益**：2× 之后源帧等效 40×52，比原作 64×117 还粗，脸全糊（`_probe/sweep.png` 第 3 行）。
   `--colors 16` 更糟：亮部被映射成近白块，剪影散架（`_probe/colors_test.png`）。

**一句话**：这轮把"照片贴纸"变成了"分辨率偏高的手绘素材"，但没变成"32 色像素画"；
色数是必要条件、不是充分条件，缺的那一环是**明暗阶数**。

## §4 已知缺陷（照用前必须知道）

1. **接地亮斑**：源素材脚下自带浅灰椭圆（AI 烘焙），二值化后变硬边白块 → 用 `--kill-glint` 清掉，会留下约 1 px 的碎屑，可接受。
2. **描边会被帧矩形裁掉**：部分帧内容顶到矩形上下边界（外侧描边被裁），json 里没有多余边距 → 不在本轮修，需重新打包。
3. **立绘无 alpha**：`hero/關羽.png` 是 RGB，二值化/描边两步对它无效；描边只能靠 UI 面板框（九宫格）承担。
4. **fx 不要走这条链**：`game/web/assets/fx/` 是原作拆包 MAGIC 素材，本身已 32 色板 + 硬 alpha + 抖动渐变，
   加描边会毁掉火球/刀光的形状 → `apply_pixel_post.py` 对 fx 只做量化，且默认不处理。

## §5 如果继续做，按这个顺序调

1. **`--pixel` 别再动兵种**（保持 1）；长线素材（立绘 480×701、显示 120 px）用 2，甚至应先缩到显示尺寸再量化。
2. **`--colors` 保持 32**（16/24 实测更差）；真要更"像素"，加的是**亮度分阶**（把连续明暗压成 3–4 阶）而不是减色。
3. **下一步该加的不是参数而是第 5 步**：`--posterize-luma N`（每帧亮度分 N 阶再量化），这是"平色阶"的唯一出路；
   或直接做源侧（生成时不烘接地光斑、不用单侧 rim light），成本比后处理低。
4. 只允许动现有参数时：`--outline-color` 固定 `#12151A`（等价、省一次 auto 计算）；`--dither bayer4` 有风格合法性
   （原作 MAGIC 特效本身就是抖色做渐变），但用在兵种上会发脏，建议只给 fx/特效。

## §6 怎么用 / 怎么切回

```bash
# 单图或单目录
python tools\pixel_post.py game\web\anim\units_00.png -o work\pixel_ab --kill-glint
# 批量（anim + fx，产物在规定新目录，命名 units_00.px.png）
python tools\apply_pixel_post.py --targets anim,fx --out work\pixel_ab\batch
```
- 可直接替换的成品：`work\pixel_ab\{units_00,atlas_00,actions_00}.px.png`（RGBA）
  与 `work\pixel_ab\png8\` 下同名文件（8bit 索引色，**像素逐点一致**，体积再降 3–4 倍）。
- **切回原版**：产物全在新目录，原件一个字节没动；只要 `main.js` 不指向 `.px.png` 就是原版。
  要正式启用，把加载 anim 的目录/文件名换成 `.px.png` 一处即可（本轮**不改** `main.js`）。
- 复原/预览用的三层：`_alt_default\`（不带 `--kill-glint` 的纯默认链）、`_var\`（参数扫描）、`_groups\`（3 组代表 before/after）。
