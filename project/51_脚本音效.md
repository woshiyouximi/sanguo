## 1. R52：让脚本的音效真的播

### 1.1 原作口径（先确认"该播什么"）

用两个一次性脚本扫字节码（不是猜）：

- `work/sfx_script/sites.py` → `work/sfx_script/sites.json` / `sites.md`
  统计 `SYSCALL 0x300/0x301` 前面的 `PUSHS`（音名）+ `PUSHI`（音量）：

| 文件 | 发声站 | 说明 |
|---|---|---|
| `MAGIC.SO` | 116 | 各武将技的特效子脚本（CreateSlash / ExplodeRound / SwordBomb …） |
| `SYSTEM.SO` | 17 | AllRush / LoadingBattleMap / MajorDeath / SearchTalk … |
| 合计 | **133** | 73 个不同音名 |

音量分布 `{255:70, 128:7, 180:7, 200:5, 210:3, 220:3, 224:2, 230:2, 160:2, 1:1, 15:1}`
⇒ **音量是 0..255**，不是 0..1。这是 `volume255()` 的依据（`src/core/audio_bus.ts:114`）。

handler 反汇编（`export/script/syscall_handlers.asm.txt`）逐条核对过：

- `0x301 @ 0x420B77`：`push [ebp+0xc]; push [ebp+8]; call 0x4699a0` ⇒ `PlaySound(name, vol)`，2 参、无返回。
- `0x300 @ 0x420B26`：`call 0x421a80(arg1)` 把句柄解成 unit；`push [ebp+0x10]; push [ebp+0xc]; push (unit+0x10)>>16; push (unit+0xc)>>16; push (unit+8)>>16; call 0x469900`
  ⇒ `PlaySound3D(x,y,z, name, vol)`，**坐标来自 unit 的 16.16 定点**（+8/+0xc/+0x10）。与既有 `syscalls.ts:389-391` 的参数序一致。
- `0x12F @ 0x42089B → call 0x4442d4`、`0x130 @ 0x4208AC → call 0x4442f4`、`0x131 @ 0x4208B6 → call 0x4442fe`、`0x110 → call 0x44430d`。

**语义修正（重要，标 `[推测]` 但证据链完整）**：`0x131` 原来被实现成"屏幕闪白"，但

- `MAGIC.SO` 里 `0x131` 与 `0x110` **各 45 次、逐函数成对**（`SYSTEM.SO` 里各 1 次）；
- `HalfMoon @0x4738` 的实际顺序是 `SYSCALL 0x131` → `PUSHI 12` → `PUSHI 5` → `CALL DownBrightness`，末尾 `SYSCALL 0x110`；
- `_syscall_table.md` 记的是 `0x131 = 置 0x4A6660 = 1` / `0x110 = 清 0x4A6660`，而 `0x12F = 置 0x48E520 = min(v,0x10)`。

⇒ 这是一对**"特效压暗开 / 关"**的括号（16 级亮度），不是白闪。已按此改写（日志文案、蒙版、测试名都改了）。
**不确定的部分**：`0x4A6660` 到底是"压暗中"还是"过场中"，函数体（0x4442xx）在当前机器上反汇编不了 —— 原版 `Sango2.exe` 已不在盘上，见第 8 节。

## 2. 为什么"事件"和"播放"是两个数

`?sfxdbg=1` 的 HUD 左边 `sfx:` 是 `audio.js` 的**实际播放次数**，右边 `bus:` 是**脚本发出的事件数**。
两者不等是设计，不是 bug：

- 节流：同一 tick 最多 2 声、同名 60ms（`main.js:106-140` 原规则没动）。一个 tick 里 5 个兵同时阵亡 → 5 个 `death` 事件，只播 1 声。
- `r80_battle.png` 里 `death` 事件 54 / 播 25 就是这条。

**中途踩的坑（已修，值得记）**：一开始 `battleAudioEvents` 也把事件推 sink，`main.js` 的 `installAudioSink().sfx` 又转给 `battleSfx()`，而 `tickBattleSfx()` 自己也转一遍 ⇒ `defense` 播了 151 次（事件只有 90）。
用 `work/sfx_dbg/probe_calls.mjs`（CDP 里包一层 `api.sfx` 打印调用栈）定位到两条栈：`main.js:160` 与 `main.js:152`。
修法：`audio_bus.ts` 拆出 `emitSfxInternal(input, forward)`，战场事件走 `forward=false`（只记账），技能事件照旧直连 sink。

## 8. 没做到的 / 风险

1. **`0x4A6660` 的真实含义没有 100% 确认**。`0x131`/`0x110` 实现成"压暗开/关"是[推测]（成对 45+45、紧跟 DownBrightness、setter/getter 连号），但原版 `Sango2.exe` 已不在盘上（`Downloads` 与 `F:\sanguo` 都没有副本），`0x4442d4/0x4442f4/0x4442fe/0x44430d` 四个函数体反汇编不了。
2. **R79 不是"跑 SYSTEM.SO 字节码"**，是宿主侧重写（原因：没有 `system_so.{bin,symbols.json}`，且 `game/data/` 不在授权内）。另外 34 个函数没实装，且它们依赖的 10 个 syscall（`0x200/0x205/0x206/0x209/0x210/0x211/0x212/0x124/0x139/0x114`）在 `syscalls.ts` 里还没实现 —— 想继续做，先补这批。
3. **`0x135`（"视觉表现未复现"占位）仍在跳**：`smartscript_audio` 跑技能时控制台会有一条 `[smartscript] 占位 syscall 0x135`，属既存占位，不在 R52 范围。
4. **`m016a` 是兜底**：`sc3602`/`Xsc3602` 用 `m016a`，音频包里没有这个资源，别名到 `m016snd01`（`audio_bus.ts:106` 的 `SFX_ALIASES`）。是有意为之，但不是原作原声。
5. **小兵"受击"（`hit02`）在实战路径上几乎不会响**（一击必死），这条只在测试的分支里覆盖。
6. `?sim=` 路径的 `tickBattleSfx(0)` 用的是"每 tick 2 声"上限且 gap=0，所以无头跑出来的播放数偏高（真实 rAF 下 gap=60ms 会更少）；截图里 `death` 54 事件 / 25 播就是这个差。
7. 没动 `battle.ts` / `battleView.ts` / `campaign.html` / `city_model.js` / `index.html` / `game/data/`。
