# 142 · 音频 CDN 上线

> 目标：包内不放音频（主包 2.36 MB + 分包 14.55 MB），109 档音频（16,851,271 B ≈ 16.07 MB）放 CDN，
> 运行时由 `game\cocos\assets\scripts\AudioHost.ts` 按 `audio-remote.json` 的 `base` 拉 `audio-manifest.json` 再逐档加载。
> 源文件 `game\cocos\assets\bundles\res\audio-remote.json` 的 `base` **永远留空**，地址只在出包时注入。

## 0. 一次看懂的四步

```powershell
# ① 出包（同时把 base 写进产物：raw json + Cocos 编译后的 import json）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_wechat.ps1 `
  -AppId wxf631d432ca7abcee -Mode upload -SkipWeb -Audio cdn `
  -AudioBase https://cdn.example.com/sanguo/audio

# ② 上传：把 dist\audio-cdn\{audio\, audio-manifest.json} 同步到 base 指向的目录
#    -Target 只能是「已经挂载成本地盘符/UNC 的目录」，脚本不内置 sftp/cos/oss 协议
powershell -NoProfile -ExecutionPolicy Bypass -File tools\publish_audio_cdn.ps1 -Target X:\sanguo\audio

# ③ 验证：逐档 HEAD，比对 200 与 Content-Length（并发 4）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\publish_audio_cdn.ps1 -Verify https://cdn.example.com/sanguo/audio

# ④ 发布前全量自检（清单 / 代码点名键 / 包内 base / 远端 HEAD）
node tools\check_audio_cdn.mjs --pkg dist\wechat-upload --base https://cdn.example.com/sanguo/audio
```

## 1. 怎么传

- 产物在 `dist\audio-cdn\`：`audio\bgm\*.mp3`（10 档）、`audio\sfx\*.mp3`（99 档）、`audio-manifest.json`（10,786 B）。
- CDN 上的目录结构必须和 `dist\audio-cdn` **一模一样**：`audio-manifest.json` 与 `audio\` 同级。
  因为 manifest 里每档的 `path` 是 `audio/sfx/hit01.mp3` 这种相对路径，运行时拼成 `<base>/audio/sfx/hit01.mp3`。
- 所以 `-Target` 要指到 **base 对应的那个目录**，不要把 `audio-cdn` 多套一层：
  - ✅ `-AudioBase https://cdn.example.com/sanguo/audio` + `-Target X:\sanguo\audio`（X: 挂的是 bucket 根）
  - ❌ `-Target X:\sanguo\audio\audio-cdn`（上传后变成 `/sanguo/audio/audio-cdn/audio/...`，全 404）
- 只接受本地目录：

  | 想要的 | 实际做法 |
  | --- | --- |
  | sftp | `sshfs` / `rclone mount` 挂成本地盘符 |
  | 腾讯 COS | `cosfs` 或 `rclone mount` |
  | 阿里 OSS | `ossfs` 或 `rclone mount` |
  | S3 | `rclone mount` / 网络驱动器 |

  直接传 `sftp://`、`cos://`、`oss://` 会**明确报错并退出 2**（不会静默跳过）。
- 脚本行为：逐档打印 `相对路径 / 字节 / sha256 前 12 位 / copy|same`；目标已存在且 size+sha 相同就不重写；
  末尾打印「本次写入 N 档 …；已一致跳过 M 档」。**幂等**：第二次跑应该是 `本次写入 0 档` + `PUBLISH OK（0 变化，幂等）`。
- 目标目录里多出来的旧文件默认只警告不删；确要清理加 `-Prune`。

## 2. 怎么填 base

- **不要手改** `game\cocos\assets\bundles\res\audio-remote.json`（源文件必须保持 `"base": ""`）。
- 出包时传 `-AudioBase <url>`；构建脚本在 2.7 段写两处（缺一不可）：
  1. `dist\wechat-upload\subpackages\res\audio-remote.json` —— 人可核对的 raw 副本；
  2. `subpackages\res\import\<uuid 前2>\b81ff5a3-….json` —— Cocos 编译后的 JsonAsset，`bundle.load('audio-remote')` 真正读的是这份。
  两处不一致 = 运行时静音。写不进去（找不到编译资源）会直接 `Fail`，不静默。
- 构建摘要会打印 `audio base = https://…`；前置检查也会打印 `audio base : …`。
- 约束：`-AudioBase` 只能配 `-Audio cdn`，且不支持 `-Mode remote`（remote 的 res 整体走 CDN，包里没有可注入的 bundle）。
- 地址会被规范化：去首尾空格、去结尾 `/`。不要带查询串。
- 不带 `-AudioBase` 出包 = 基线包：包里无音频、base 为空 → 运行时**静音**（不报错，不崩）。

## 3. 怎么验

| 命令 | 查什么 | 失败退出码 |
| --- | --- | --- |
| `publish_audio_cdn.ps1 -Target …` | 上传 + 逐档 sha256 校验 + 幂等 | 2 |
| `publish_audio_cdn.ps1 -Verify <base>` | 逐档 HEAD 200 + Content-Length 一致 | 1（缺失/大小不符）、2（用法/协议） |
| `node tools\check_audio_cdn.mjs` | ①本地 109 档 size+sha ②44 音效 + 3 BGM 都在清单 | 1 |
| `node tools\check_audio_cdn.mjs --pkg <pkg>` | 加 ③包根 manifest 逐字节一致 + 包内 base 注入正确 | 1 |
| `node tools\check_audio_cdn.mjs --pkg <pkg> --base <url>` | 加 ④远端 110 档 HEAD | 1（本地）2（仅远端）3（用法） |

- 构建期 gate：`-Audio cdn` 时 `build_wechat.ps1` 自动跑 `check_audio_cdn.mjs --pkg <out> [--base …] --allow-remote-fail`。
  本地项失败 → 构建失败；远端 HEAD 失败只 `[warn]`，因为**通常是先出包、后上传**。
  发布前必须自己复跑一次不带 `--allow-remote-fail` 的版本（脚本会打印完整命令）。
- `base` 为空时 check 打印 `[warn] audio base 未设置，包内静音`，只做本地三项。
- 期望输出（正常）：`109/109 档存在`、`音效 44/44`、`BGM 3/3`、`HEAD 110/110`、`RESULT: PASS`。

## 4. 常见错

### 403 / 401（HEAD 或 GET 被拒）
- bucket 是私有的：要么开公有读，要么给 CDN 回源加签名（微信小游戏端不能带自定义 header，别指望客户端签名）。
- 防盗链 Referer 白名单：小游戏请求没有浏览器 Referer，必须放行空 Referer。
- CDN/对象存储只放行了 GET：`publish -Verify` 和 check 都是 **HEAD**，要单独允许 HEAD。
- 签名 URL 过期：base 里不要带 `?sign=…`。

### 404 / 大小不符
- `-Target` 多套了一层 `audio-cdn`（见 §1），或 base 与实际目录差一级。
- 上传中断：`publish` 会打印 `copy` 但下次跑会按 size+sha 重新 copy；`-Verify` 里「期望 N 实际 M」就是这种。
- 大小写：CDN 区分大小写，清单键全是小写，别改。
- `Content-Length` 缺失（chunked / 动态压缩）：HEAD 返回 `-1` 或没有 CL → check 报「200 但没有 Content-Length」。对 `*.mp3` 关掉 gzip/br。
- 同一路径被 CDN 缓存了旧对象：刷新缓存，或上传时带版本化前缀（`/audio/v3/…`，base 跟着改）。

### 编码
- `audio-manifest.json` 必须是 **UTF-8 无 BOM**；`audio-remote.json`（注入产物）也必须无 BOM。
- 改 `tools\*.ps1` 必须保留 **UTF-8 BOM（EF BB BF）**：Windows PowerShell 5.1 按 cp936 读无 BOM 的中文会级联语法错，构建 0 秒静默失败。
- 手工编辑后自查（两条都要 0 errors）：

  ```powershell
  powershell -NoProfile -Command "[void][System.Management.Automation.Language.Parser]::ParseFile('F:\sanguo\tools\build_wechat.ps1',[ref]$null,[ref]$e); $e.Count"
  ```

### MIME / 播放
- `.mp3` → `audio/mpeg`，`.json` → `application/json`。MIME 错在部分安卓机上表现为「能下载但播不出」。
- 微信小游戏后台要把 CDN 域名加进 **downloadFile 合法域名**（https、已备案、不能是 IP）。

### 缓存策略（建议）
- `audio/**`：`Cache-Control: public, max-age=31536000, immutable`（文件名不带 hash，改音频就换目录）。
- `audio-manifest.json`：`max-age=60`，便于换 CDN/加档后快速生效。

## 7. R193：base 改成配置驱动，占位域名硬拒

之前的问题是：验收把 `https://example.com/sanguo/audio` 写进了包内 `audio-remote.json`，而构建脚本对此毫无意见——这种包一旦发出去，运行时就是「静音 + 每首都在 404」。

现在的口径（三处一起改）：

1. **权威来源是配置文件**：`tools/audio_cdn_config.json` 的 `base` 字段（空字符串 = 静音出包）。构建优先级 `-AudioBase 参数 > 配置文件 > 空`。
2. **占位/本机地址硬拒**：`tools/build_wechat.ps1` 与 `tools/check_audio_cdn.mjs` 都对 `example.com/org/net`、`your.com`、`localhost`、`127.0.0.1` 直接失败（构建 throw，自检 exit 3），不再允许它们进发布包。
3. **静音是显式选择，不是意外**：未配置 base 时构建打 `Write-Warning`（「音频将以静音出包…」）并继续，日志里能看见；这样「静音」永远是一个被写下来的状态，而不是忘了填。

发布前要做的三步（只有第一步需要人）：
1. 把 `dist/audio-cdn`（110 档 16.86 MB，`tools/publish_audio_cdn.ps1 -Target` 产出）上传到你的 CDN，拿到根地址；
2. 把根地址填进 `tools/audio_cdn_config.json` 的 `base`；
3. 重出包 `powershell -File tools\build_wechat.ps1 -AppId <appid> -Mode upload`，再跑 `node tools/check_audio_cdn.mjs --pkg dist/wechat-upload --base <根>`，必须 `RESULT: PASS`。

注意：`tools/build_wechat.ps1` 是 **UTF-8 with BOM** 的 PowerShell 脚本，用会丢 BOM 的编辑器改它会让 Windows PowerShell 5.1 按 ANSI 读、中文注释变乱码并直接 parse error（R193 实际踩过，`-File` 报 `Unexpected token '-AudioBase'`）。改完请确认 `[System.Management.Automation.Language.Parser]::ParseFile` 的 `parseErrors=0`。
