## 0 · 结论先说（含对任务书猜测的纠正）

1. **`0x44D450` 不是「突击/火计/伏兵/嘲骂」那类战术 AI，而是「军师技（WISE 表）在战斗中结算一次效果」的派发器。**
   66 条分支 = 22 类效果 × 3 档（弱/中/強）+ 若干单档；`data/wises.json` 的 `Execute` 列**就是分支号**（`Execute` 唯一、`WiseLevel` 是该行的档位），
   67 条军师技与 66 条分支**逐条吻合**，`work/str_big5.tsv` 里每条分支的日志字符串也一一对上。
   任务书点名的「伏兵」实为 `Execute 44 十面埋伏`（原文是「敵方無法退兵」），「嘲骂」实为 `Execute 1-3 降敵士氣` / `Execute 58-60 喝阻敵軍`。
2. 因此本轮实现的策略 = **原作这 67 条军师技的战斗内效果**，一条不多造。触发点是 `battle.ts` 的 tick 循环（`step()` → `tickStrategy()`），
   「世界状态 → 指令」是纯函数 `planStrategy()`，落地是 `runStrategy()`，证据落在 `world.strategyEvents` / `world.log`。
3. **援军**：原作只有「第二支军队」的两个指针位（`0x4A8A20/0x4A8A24`），主循环里那支分支调的是**空函数 `0x447516`**，
   **没有**「按行军距离 N tick 抵达」的任何证据 ⇒ 按任务书 fallback 实现（守方兵力低于阈值 → 邻城出兵 → 城距折 tick → 后排外侧入场），全部标 `[推测]`。
   兵数来自真实数据（`scenarios.json` 的 `POPULATION` → `garrisonOf()` 预备兵 × 25%），不是写死的 100。
