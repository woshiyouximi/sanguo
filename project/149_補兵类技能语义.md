# 149 補兵类武将技语义（`ATTRIB=補兵` 的 7 条）

> **结论**：seq **5 / 17 / 19 / 31 / 37 / 57 / 81** 全部是 **`heal-troop`（给己方部队补员、复活阵亡兵槽）**，不是伤害技、也不是 INI 标错。
> `battle.ts:1970-1978` 的 `skillKindOf()` 把她们算成 `strike` 是**分类器缺项**：只认 3 个硬编码 seq 与「補血」，`補兵` 落进 `ATTACK>=40 ? 'aoe' : 'strike'`，而这 7 条 `ATTACK=0`。
> 铁证：7 条的 `MagicN` 体全长 4 条指令，只调 `MoreSoldier`/`BackSoldier`；EXE 施展入口 `0x43BAE3` **完全不读 ATTRIB**。「打伤害还是补兵」由 **Script 字节码**决定，ATTRIB 只是给 AI/选目标的范围标签。

## 2. 脚本内部：补兵做了什么

- **`MoreSoldier` #52 @0x5380**（dis:3114，argc=2）＝「伏兵」补新兵：`PUSHS "magic\000\*"`(3117)/`"magic\002\*"`(3119)+`SYSCALL 0x7` 载目录 → `loc1=LDG 2`(施法单位)、`loc3=LDG 5`(己方阵营) → `0x128`(3131) → `0x105/0x106`(3133/3136) 取 X/Y → `0x100`(3142)、`0x121`(3145) → **`0x116`(3160) 取上限 clamp 40**、**`0x10C`(3173) 取当前值** → `loc7 = min(arg2, max(0, loc6*5 - 0x10C))`(3169-3188)（每兵 5 点、上限 40 兵 ⇒ 最多 200）→ `loc7 != 0` ⇒ `PUSHS "ProduceSoldier"`(3194)+`CALLS`(3199) 真出兵（`#51 @0x4EF4`, dis:2942：`0x113`(2965/2975) 找槽 → **`0x119`(2989) 创建伏兵对象** → `PUSHS "StepShow"`(2991)+`CALLS`(2996)），再 `0x120`(3201/3202)、音效 `0x301 "m002snd01"/"m002snd03"`(3215/3218)、MoveCamera(3226/3232/3247)、`RaiseBrightness`(3258)、`0x110`(3259)；**`loc7==0` ⇒ `CALL CastFail`(3252)** —— 补满/没兵可补是"施法失败"，不是打空。
- **`BackSoldier` #212 @0x20EB0**（dis:18790，argc=2）＝「後伏兵」补后方/阵亡兵槽：结构完全同构，只换目录 `"magic\024\*"`(18795) 与出品函数 `"ProduceBackSoldier"`(18870)+`CALLS`(18875)（`#211 @0x20A24`, dis:18618），`CastFail`(18934)。
- 参数只是**等级档**（17/32/25/35/45/25/42 都被 `arg2=0` 与 `loc6*5-当前` 夹住）⇒ 数值大小不是伤害，只影响"最多补几个"；同为 MoreSoldier 的 #5(17) 与 #17(32) 效果同构。
