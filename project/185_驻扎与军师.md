## 2. 部隊駐紮（B）

定義（照需求原文）：**部隊不入城，在道路上停滯，阻擋沿道路來的敵人。**

### 2.2 推進凍結（渲染邏輯沒動）

唯一的推進點是 `advanceArmies(list)`（`campaign.html:1168`），它現在只做一件事：把 `planArmyMoves` 算好的
`progress` 寫回去。

```js
function advanceArmies(list) {
  const arrived = [], still = [];
  for (const it of planArmyMoves(list, (a) => marchStep(a.pathIndex))) {
    const a = it.army;
    a.progress = it.progress;          // 駐紮 → 原值；被擋 → 夾在接觸點
    (it.arrived ? arrived : still).push(a);
  }
  return { arrived, still };
}
```

`planArmyMoves`（`campaign.html:1346`）對 `stationed === true` 的部隊直接回傳原 `progress`（`frozen: true`），
所以 `drawArmyMark` 讀到的就是凍結值 —— 地圖上「靜止」是渲染本來就有的行為，**沒有改任何繪製碼**。

### 2.3 阻擋判定（同段 / 接觸點怎麼算）

**同段**：`marchSameLeg(mover, blocker)`（`campaign.html:1307`）
- `from`/`to` 相同，或 `from`/`to` 互換（A→B 與 B→A 是同一條道）→ 同段；
- 否則 `pathIndex` 相同 → 同段（劇本 `paths` 同一條）。

**接觸點**：`stationProgressLimit(mover, blocker)`（`campaign.html:1326`）回傳推進方允許的最大 `progress`。

| 情況 | 上限 |
| --- | --- |
| 同陣營 / 對方沒駐紮 / 不同段 / 對方 `progress` 不在 (0,1) | `1`（不擋） |
| **相向**（`mover.from === blocker.to && mover.to === blocker.from`） | `1 - blocker.progress - STATION_EPS`，夾進 `[0,1]` |
| **同向**（`from`/`to` 完全相同）且駐紮方在前（`pm < pb`） | `blocker.progress - STATION_EPS` |
| 同向但駐紮方在後（已被超過） | `1`（不擋，免得把人往回拉） |

- `STATION_EPS = 0.005`（`campaign.html:1199`）＝一整段行程的 0.5% 當「接觸容差」；兩個駐紮/推進單位
  之間的「貼住」就是靠它留出一線。
- `STATION_SLACK = 1e-9`（`campaign.html:1202`）是**浮點補償**：`0.005` 在 IEEE754 裡存成
  `0.005000000000000000104…`，`0.5` 存成 `0.5`，於是 `|0.495 - 0.5| <= 0.005` 會算成
  `0.005000000000000004 > 0.005` 而**永遠不成立**（真機上一次都判不出對峙）。比較一律寫成
  `<= STATION_EPS + STATION_SLACK`。
- 夾的寫法（`campaign.html:1367`）：`const next = want > limit ? Math.max(p, limit) : want;`
  ——夠得著就停在接觸點；已經貼住就原地不動（**不後退、不超車**）。所以「一步跨得太大」也只會走到接觸點。

**對峙偵測**：`stationStandoff(list)`（`campaign.html:1388`）回傳 `{ blocker, mover }`：
遍歷駐紮方（`0 < ps < 1`），找敵方、同段、`0 < pm < 1`、且自己沒駐紮（兩支都停著＝沒人來攻，不算對峙）的那支：
- 相向：`|pm - (1 - ps)| <= EPS + SLACK`；
- 同向：`0 <= ps - pm <= EPS + SLACK`。

判「離接觸點一個容差內」而不是「`pa + pb >= 1`」，是因為後者會把已經交錯而過的兩軍也認成對峙
（`armiesIntercept` 的舊判據）。

### 2.4 對峙 → 遭遇戰（複用唯一開戰鏈，沒有第二套）

`handleMarchEvents(batch)`（`campaign.html:4404`）在「路上相遇」段之後、敵軍抵達段之前插入第 1.5 段
（`campaign.html:4423`）：

1. `stationStandoff(list)` 命中後記 `stationSince`（配對鍵→首觸月份）/ `stationNoticed`（配對鍵集合）；
2. 戰報寫一行：`駐 紮 阻 擋：<守將> 在 <from> → <to> 道上擋住 <攻將>（敵軍 N 兵 停在接觸點）`
   —— 只在**首次接觸**或**對峙又拖過一個月**時寫，同月重複呼叫不再刷同一行；
3. **敵軍來撞、且是本月第一次接觸**：`notice()` 提示一次（9 秒）＋ `autosave()` ＋ `render()` ＋ `return false`
   —— 玩家還有機會撤兵/進城；
4. **拖過一個月，或玩家自己的部隊撞上去**：走 `startEncounter(blocker, mover, note)`
   —— `blocker`＝駐紮方＝**守**、`mover`＝來襲方＝**攻**；
5. `batch`（自動推進/多個月）時改走 `resolveEncounter(blocker, mover)`，不彈確認框。

`startEncounter(a, b, note)`（`campaign.html:4370`）是把原本 inline 的遭遇戰流程抽出來的**全頁唯一開戰鏈**：
按 `side` 把兩支歸一成 A/B（避免 `encounterUrl` 的「第一個參數＝我方」假設被打破）→ `removeArmy` ×2 →
`pushLog`（帶 `note`）→ `autosave` → `render` → `confirmBox`（出戰 `location.href = encounterUrl(A, B)`；
取消 `refundArmy` ×2）。原本那段 inline 程式與新增的駐紮對峙都呼叫它，沒有第二套戰鬥啟動。

### 2.5 與舊「路上相遇」不打架

`armiesIntercept`（`campaign.html:1179`）要求相向且 `pa + pb >= 1`；被夾住的推進方最多
`1 - ps - 0.005`，兩者相加 `0.995 < 1`，所以駐紮對峙**不會**同時被舊的相遇判定抓到（不會開兩場）。

## 3. 任命軍師（C）

定義（照需求原文）：**從軍團內找一個武將任命為軍師。**
可點性的正確理由：**軍團裡只有主將一人時沒人可挑，才灰。**

### 3.1 隨軍武將（`officers`）怎麼來

`armyRosterFor(city, general)`（`campaign.html:2820`）：

```js
const roster = (garrisonIn(city)?.officers || []).map((o) => o && o.name);
let queueNames = [];
try { queueNames = (DQ.queueOf(save, []) || []).map((s) => s && s.general); } catch { queueNames = []; }

```

`armyRosterPick(queueNames, rosterNames, general, max)`（`campaign.html:1259`，`ARMY_MAX_OFFICERS = 5`）：

2. 出征頁／出陣順序（`save.deployQueue` 的 5 槽）裡**屬於這座城名冊**的人優先（隊列裡的外城武將不跟著走
   —— 不隔空調人）；
3. 不夠就按出發城名冊補齊（第 2 人起＝非太守的在冊武將）；

**只做名單，不把人從城裡移走**（沒有 splice、沒有改 garrison）；回城 `enterCity()` 只併兵力，不會重複加武將。

## 6. 沒做成 / 已知限制（誠實清單）

1. **deploy.html 那條路的軍師技可能被清零**（§3.5）—— 禁改檔的既有限制，遭遇戰不受影響。
2. **軍師技只有一招**：一名武將可能學會多招，這裡一律取「最高檔那一條」（`armyWiseSeq` 的規則），
   浮層不讓玩家逐招挑（要逐招挑得改 deploy.html 的 `data-wise` 那一套，超出範圍）。
3. **駐紮部隊沒有「兵站/補給」概念**：原作沒有，這裡也不消耗；駐紮不吃糧、不掉士氣。
4. **AI 不會主動駐紮、也不任命軍師**（`spawnAiArmy` 只帶 `officers`，`advisor: ''`）。AI 兵團的軍師技
   仍走 `main.js:709 applyWiseOnBattleStart` 自動補位（原本就有）。
5. **隨軍武將不參與戰鬥數值**：`officers` 目前只當「誰能當軍師」的名冊；武將數不影響兵力上限、
   不影響戰損、戰敗也不會陣亡（原作分兵/多將出征沒做）。
6. **「拖過一個月才開打」的節奏**：這是為了讓玩家來得及撤兵，不是原作規則（原作無駐紮）。若覺得干擾，
   把 `handleMarchEvents` 第 1.5 段的 `stale` 判斷改成 `true` 就當月開打。
7. `stationSince` / `stationNoticed` 是**頁面內存**（不是存檔）：重新整理頁面後，同一場對峙會再提示一次
   （戰報仍只有一行，因為 `stationSince` 空了以後算「首次接觸」）。
