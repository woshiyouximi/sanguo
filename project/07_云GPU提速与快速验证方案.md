# 07 · 云 GPU 提速与快速验证方案

> 一句话：**云不用等，现在就能开**。V0 验证包 27 条任务，本机单卡 21 分钟、云上 4 卡 6–8 分钟、花费约 ¥1。
> 但要说清楚：云加速的是"出图/出视频"这一段；**从"有图"到"能玩"仍是客户端 10 天的活**，两者并行才叫快。

---

## 0. 结论先行

| 问题 | 答案 |
|---|---|
| 现在开不开云 | **开**。本机 3090 是串行瓶颈（全量 22 GPU·h ≈ 3 个工作日），云上 4 卡并行把墙钟时间压到 6 h 内 |
| 开几台 | V0 阶段 **1 台**够（21 分钟出完）；全量阶段 **4 台 × 4090**（或 2 台 A100 40G） |
| 花多少 | V0 ≈ **¥1**；全量 5 批 ≈ **¥50–120**（4090 按量 ¥1.5–2.5/h）。**成本不是问题，等才是问题** |
| 云能帮到客户端吗 | 不能。客户端在本地写；云的产出是"素材进仓库"，与 M0/M1 代码并行 |
| 最快能多快看到东西 | **D2 有 V0 全套图**（27 条任务跑完 + 回传 + 拼版），**D10 有可玩竖屏战斗切片**（100 兵 + 双视角 + 竖屏镜头） |

## 1. 为什么云能加速（而不是"感觉快"）

| 维度 | 本机 1 × 3090 | 云 4 × 4090 |
|---|---|---|
| V0 验证包（27 条） | 21 min | **6–8 min** |
| 全量静态图（≈765 张） | 6.4 h | 1.6 h |
| 全量视频（172 条 × 33–65 帧） | 2.4 h | 0.7 h |
| 620 帧身体动画的底稿（172 条视频） | 同上 | 同上 |
| 返工一轮（改 prompt 全量重跑） | 又是 6 h | **又是 1.6 h** |
| 合计（含重跑 2 轮） | 22 GPU·h ≈ 3 个工作日 | **墙钟 6 h 内** |

**真正的加速不是单卡更快，是"重跑一轮不再心疼"**。本机跑一轮 6 小时，你会不敢改 prompt；云上一轮 1.6 小时，一天能试 3 版风格。

## 2. V0 验证包（27 条，`cloud/jobs_v0.csv`）

| 组 | 条数 | 内容 | 目的 |
|---|---|---|---|

| C 场景与 UI | 7 | 草原战场 / 攻城战场 / 大地图 / 战斗 HUD / 城池 / 武将详情 / 阵形选择 | 验证"AI 只出底材、文字由引擎排"这条边界 |
| D 技能特效 | 4 | 半月斩 / 火龍 / 落雷 / 八卦阵纹，768×768 | 验证深色底 + 抠像流程 |
| E 图生视频 | 4 | 朴刀走/攻、弓兵射/走，33 帧 | 验证 Wan 动作管线能出"可用的 12 fps 序列帧" |

**V0 的验收标准（三条，缺一不算过）**

1. **双视角一致性**：同一士兵的背/正两张，斗笠朝向、持械侧、腰带结位置对得上（本机已验证，见 `art_ref/_two_views.jpg`）。
2. **64 px 可读性**：把 13 兵种缩到屏上 64 px 做成两两配对辨认题，命中率 ≥ 80%（`03 §3.4` 的手绘基准是 93%，AI 版允许低 13 个点）。
3. **"能当底稿"**：精修员看一眼能说出"改哪里"，而不是"重画"。判定方式：让精修员标注 10 张的改动区域，若 >3 张要整张重画，说明 prompt 还不到位。

## 5. 两阶段跑批（先图，再视频）

```
阶段 1  t2i  ──> out/soldier_M1_back.png 等
                      │
                      ├─ 人工/脚本挑"起始帧"（背视站立的那一帧）
                      ▼
           云机 ComfyUI/input/   ← 把挑中的图拷进来
                      │
阶段 2  i2v  ──> out/seq_M1_walk.png ~ _32.png（33 帧序列）
```

- `jobs_v0.csv` 里 `kind=t2i` 的先跑；跑完把 `soldier_*_back.png` / `_front.png` 拷进 `ComfyUI/input/`，再跑 `kind=i2v`。
- i2v 输出**逐帧 PNG**（不是视频）——因为下一步就是抠像 + 归一 + 落 96/64 px，给视频还得再拆一次。
- 想一次跑全：`python run_batch.py --jobs jobs_v0.csv --workers 4 --out out`
  想只跑阶段 1：加 `--filter kind=t2i`。

## 6. 断点续跑（云上最重要的一件事）

- 每个成功的任务写一个 `out/<id>.done`；**重跑同一条命令只跑没完成的**。
- `out/_manifest.json` 逐条记录 `status / 秒数 / 文件数 / 错误信息`，实时落盘（不是最后才写）。
- 内置重试：HTTP 错误、OOM、超时各重试 2 次，退避 3 s / 6 s。
- 云机被抢占怎么办：重新开一台 → `upload.ps1`（模型跳过）→ `pull` 不回来也没关系，**CSV 不变就能续跑**；已经跑完的 `.done` 若丢了，最多重跑那一批。

### 9.5 云端实测（2026-11-24，现有 pod：RTX 5090 32 GB）

不是估算，是这一轮真跑出来的数：

| 项 | 实测 |
|---|---|
| 机器 | RTX 5090 32 GB / 64 GB RAM / 驱动 610.57.04 / ComfyUI **0.43.0** |
| 模型 | `qwen_image_2.1_Q8_0.gguf` 7,624,265,888 B（**与本机同一个文件**）+ `qwen3vl_8b_int8_convrot`、`qwen_image_2.1_vae_bf16`（ModelScope 软链） |
| t2i 832×1216 / 20 步 | **16.0 s/张**（本机 3090 为 48 s → **3.0×**） |
| t2i 512×768 / 24 步 | **10.0 s/张**（本机 27–30 s → 2.7–3×） |
| 显存占用 | 约 **17.4 GB**（含 1.0 GB 预留），单 worker 跑满 GPU |
| **V0 的 23 条 t2i** | **5.4 分钟**跑完（1 个 worker，无失败），产物 32.5 MB |
| 折合费用 | 按 5090 ¥2–3/h ≈ **¥0.2–0.3** |

**四条只有跑过才知道的坑**：

1. **ComfyUI 不自启**：实例重启后必须 `bash /workspace/tools/launch_comfy.sh`（内含 `--listen 127.0.0.1 --port 8188` 与 90 次探测），看到 `READY` 才算好。
2. **8188 不对外**：公网只开了 SSH（`...-s1.podtcp.compshare.cn:27684`）。所以 `run_batch.py` 要**在 pod 内**跑、直连 `127.0.0.1:8188`；本机只负责传脚本、下产物。
3. **`COMFY_OUTPUT` 必须显式给**：默认值 `ComfyUI/output` 是相对 cwd 的，在 `/workspace/sanguo` 下会解析成不存在的路径，症状是"图生成了但报 `无输出文件`"。
   ```bash
   COMFY_OUTPUT=/workspace/ComfyUI/output python3 -u run_batch.py \
       --jobs jobs_v0.csv --out ./out --filter kind=t2i
   ```
4. **`tar` + Windows 解压中文名会乱码**（`hero_寮犺窘.png`）→ 回传后用 Python 的 `tarfile` 解（它按 UTF-8 解码），或干脆把任务 id 全用 ASCII。

> 结论：**5090 上 1 张图 ≈ 16 秒，V0 半分钟级等待→ 5 分钟出全套**。这条链路已经通了，`06` 里"批 0/批 1 在本机跑"的排期可以直接改成"云上跑"。
>
> **迭代速度实证**：发现 8 将撞脸后，改 `make_jobs.py` 的 `HERO_LOOK` 锚点 → 重新上传 csv → 重跑 8 张 → 下载 → 出拼版，**全程 4 分钟**。这种"改一版看一版"的循环是本机做不到的，也是开云的真正理由。

## 10. 已知限制（别踩第二次）

1. **Wan 5B 的动作幅度偏小**。本轮"士兵背视走路"33 帧里，身体只有轻微起伏，脚步迈不出来。
   → 对策：prompt 里加"大步迈出、手臂大幅摆动、重心前移"；或拆成"起始帧 + 关键帧"，用 i2v 做**参考**、精修员补关键帧；必要时换 14B（显存要 40G，正好是 A100 的理由）。
2. **AI 不出可读文字**。UI 图上全是乱码字形（已两次验证）→ 所有文字引擎排版，图只出底材/框体。
3. **文本编码器不能换**。`qwen_2.5_vl_7b` 会直接 `RuntimeError: normalized_shape=[4096] ... size[1, 43, 3584]`；必须 8B。
4. **量化版模型不一定能公开拉到**。`int8_convrot` 是本机现有文件，公开仓库无同款 → 用 `upload.ps1` 传，不要在云上"找个差不多的"。
5. **首次跑会编译/预热**：ComfyUI 第一次执行要加载 17 GB 模型到显存，约 40–60 s 不进采样计时。
