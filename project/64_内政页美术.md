## 1. b1 為什麼放棄 PALAIS，本輪怎麼解

`project/49_內政與征兵.md` §6.2 放棄 PALAIS 的理由是「640×480 鋪 750×1334 要放大 2.78×、裁 58% 寬只剩地毯與半張臉」。這個算術是對的，但它只在「**整張當 `background-size: cover` 的主背景**」這個前提下成立。

本輪換掉前提：**PALAIS 不是「背景」，是「朝堂遠景」——一個 750×562 的畫面帶**。

| | b1 的做法 | 本輪 |
|---|---|---|
| 縮放 | 640 → 1,779 寬（**2.78×**） | 640 → 750 寬（**1.17×**），零裁切 |
| 裁切 | 只剩中間 **42%** 寬 | **0%**，左右衛兵、紅帳、橫匾全在 |
| 下面 772px | 同一張圖繼續放大 | 換成 hall_0N ＋ 底邊拉伸的柔焦地面 |
| 結果 | 糊成一片 | 朝堂看得清，台下是地面 |

並排對照見 `work/cityart/bg_compare.png`（左 A＝b1 的 cover 470×835，右 B＝本輪配方 470×835，同一張 `palais_03`、同一尺寸視窗、未經任何 AI 處理）：A 只剩橫匾「光…大」、寶座和一塊紅地毯，兩排衛兵全被裁掉；B 兩排衛兵、紅帳、地毯前沿都在，接縫以下變成柔焦地面。

**接法（五層，全部在 `#stage > .art` 這個 `z-index:-1` 的裝飾層裡）**

| 層 | CSS 位置 | 作用 |
|---|---|---|
| `.art-hall` | `city.html:160-168` | `background:var(--palais) center top / 100% 100%`，750×562。上緣用 `mask-image` 壓暗天花板 `[推測]` 讓標題區不刺眼 |
| `.art-floor` | `city.html:169-175` | `top:562px;height:318px`，`background:var(--palais) center bottom / 100% 2000%` ⇒ **只取原圖最底 24 列、縱向拉伸 12×**，再 `blur(9px)`；這就是「底邊延伸」，不是鏡像 |
| `.art-seam` | `city.html:176-178` | 470→770 的壓暗漸層，把接縫那 20px 的亮度差吃掉 |
| `.art-warm` | `city.html:179-183` | 600px 以下一層暖色 `linear-gradient`，把亮黃殿和暗石室的色溫拉近 |
| header/footer rail | `city.html:186-188`、`256-257` | `rail_gold.png`（WAR06）當 header 底線與 footer 頂線，12px |

為什麼用「拉伸底邊」而不是「垂直鏡像」：鏡像會讓地毯在接縫下方**再次收束**（因為鏡像把遠近關係倒過來），看起來像地毯的倒影；改成拉伸原圖最底幾列，接縫處每一列像素與上方**完全連續**（同一行像素複製），所以沒有硬接縫，往下漸變為柔焦地面。`[推測]` 原作若真有整張 750×1334 的內政圖，其透視也應該是這樣往下張開的。

## 3. alpha 檢查（先驗再選，不留「看著像」）

證據：`work/cityart/alpha_check.txt`（UTF-8，256 行）。做法：對 `SHAPE/MENU/` 全部 **166 張**逐張 dump 四邊 **4px 與 1px 的 min/mean**，之後把實際入庫的 10 張另記一段 `USED`（含 insets 與用途）。

結論：

1. **166 張裡只有 75 張四邊 4px 全 255**，可以拿來當四邊框；其餘四邊有洞（鏤空角飾、半透明、漸隱），當九宮格會缺邊。
2. **`WARINFO01` / `WARINFO02` 複現了 f-ui 的坑**：212×293 看上去是標準面板，但 `bottom 4px min=0 / mean=126.3`、`bottom 1px min=0` —— 底邊是半透明的，拿來當四邊框會缺底邊。**本輪沒用它。**
3. **`WARINFO03` 67×67 不能用**：它烘了「對」字（金印），不是通用徽章。原本想拿它做裝飾印，看到圖就放棄。
4. **`WAR05` vs `WAR06`**：都是 111×12、四邊全 255。WAR05 是空心雙線、WAR06 是粗亮線。本輪只用 WAR06；WAR05 拷進來後又刪掉（不留死檔）。
5. **SB_V* 重新評估結論：可用，但要挑著用。**
   - `SB_V1`（19×417，左右 min=0）——當 **track** 反而對：細金線本來就在中央，兩側鏤空。
   - `SB_V4`（18×14 實心金塊）——當 **thumb**，縱向拉伸。
   - `SB_V6`/`SB_V7`（19×25，金框＋紅箭頭）——當 **上下箭頭按鈕**，`::-webkit-scrollbar-button` 撐得起來（實拍見 `after_sheet.png` 右緣）。
   - `SB_V2` 當 thumb **失敗**：`border-image:… 12 0 12 0` 左右 slice=0，中段沒有東西可填，只畫得出上下兩片紅邊。這條寫進註解 `city.html:285-286` 免得後面的人再踩。
6. f-ui 當年放棄 SB_H*/SB_V*，理由是「`--hide-scrollbars` 看不到 ＋ webkit 滾動條佔 19px 會擠列表」。本輪補兩條：截圖**不加** `--hide-scrollbars`；`.sheet .bd` 本來就有 `padding:12px 20px`，19px 的滾動條吃的是右側 padding，列表寬度不變（`after_sheet.png` 實拍沒有擠壓）。

## 5. 字感與數字

原作是位圖字，網頁用系統字；在不引字型檔的前提下，能加的只有「描邊 ＋ 多層陰影 ＋ 漸層」：

| 對象 | 手法 | 位置 |
|---|---|---|
| 大標題 `代縣` | `background-clip:text` 漸層（`#FFF7E0→#F4E1B2→#D8B36A→#A87C36`）＋ `-webkit-text-stroke:1px rgba(30,18,6,.55)` ＋ 三層 `drop-shadow` | `:189-195` |
| 數字（人口/金/兵…） | `font-variant-numeric:tabular-nums` ＋ `text-shadow:0 1px 0 #000, 0 0 10px …`（金色/警告色各一套） | `:210-215` |
| 命令主字 `開發` | `0 2px 0 rgba(0,0,0,.72)` ＋ 14px 外擴 ＋ 1px 頂光三層 | `:235` |
| 命令副字、列時間/城池 | 各一層 `0 1px 0 rgba(0,0,0,.8)` | `:236`、`:249-251` |
| 抽屜標題 | 兩層 | `:277` |

全頁 `text-shadow` 共 16 處（測試要求 ≥10）。**沒有 `@font-face`、沒有任何 `.woff/.ttf/.otf`**（測試會守）。

## 6. 順手修掉的兩個 b1 遺留 bug

`#stage>*{position:relative;z-index:1}`（`city.html:30`）是 id 選擇器，**特異性壓過所有 class**，所以：

1. **`.mask`/`.sheet` 的 `position:absolute` 從來沒生效** —— 抽屜一直在文檔流裡。一按「徵兵」，抽屜把 `.body` 擠成 0 高、整頁壓成 390px、抽屜的「取消/確定」掉到畫面外（`?sheet=appoint` 可復現）。
   修法：`#stage > .mask{position:absolute;inset:0;z-index:5}`、`#stage > .sheet{position:absolute;left:0;right:0;bottom:0;z-index:6}`（`city.html:270-271`）。
2. **新的 `.art` 畫層同理**：第一版沒補這條，`.art` 變成 `position:relative` 的 0 高方塊，`overflow:hidden` 把整張 PALAIS 裁光（整頁看不到畫的真因）。
   修法：`#stage > .art{position:absolute;inset:0;z-index:-1;pointer-events:none;overflow:hidden}`（`city.html:157`）。測試有一條專門守這三行。

## 8. 沒做到的 / 已知限制

1. **接縫仍是「兩個空間」的過渡，不是同一個房間**。上半是 `palais_03`（亮黃殿、紅帳），下半是 `hall_03`（暗石室、長凳）。我用暖色漸層＋柔焦把色溫拉近，但它們畢竟不是同一個房間；要真的一體，只能整張重畫或找一張 750×1334 的原作圖（原作沒有）。
2. **字仍是系統字**，只是加了描邊與多層陰影。真正的位圖字感（原作 12px 點陣字、筆畫帶硬邊）做不到，除非引入字型檔 —— 任務明文禁止。
3. **命令按鈕是 9 塊，不是任務書寫的 8 塊**（頁面本來就是 3×3 九宮）。我沒有為了對數字去砍一顆。
4. **滾動條只在抽屜裡看得到**。內政主頁沒有可滾動區域（`.log` 是 `overflow:hidden`），所以 `SB_V*` 的實拍證據只有 `after_sheet.png`；主頁面看不到。
5. **`after_wide.png` 左右有黑邊**，這是 `fit()` 的既有行為（`s = min(1200/750, 900/1334) = 0.6746`，畫布 506×900 居中），不是本輪加的。粗看時 13px 的金框會縮到 ≈9px，比手機上細。
6. **只對 `palais_03` 做了並排對照**（代縣＝172,000 人，`applyHall()` 給的就是 03）。另外四張沒逐一拍對照圖，但配方是同一套 CSS 變數（`var(--palais)`），`?hall=1..6` 可直接驗。
7. **`.cmd[disabled]` 的木紋圖（`ui_btn_wood_disabled`）仍是 b1 的 AI 素材**，本輪沒換 —— 沒找到「禁用狀態」的原作圖元（BUTTON01..10 都烘了字）。
8. **`#dump`（`?dump=1` 的除錯面板）沒接原作滾動條**，只做了 `.sheet .bd`。它是除錯 UI，我判斷不值得佔位。

## 9. `[推測]` 清單

- `[推測]` PALAIS 底邊那 24 列拉伸出來的地面，原作真正的 750×1334 圖大概也是類似走向（一點透視往下張開），但**我沒有原作大圖可以對照**。
- `[推測]` 原作內政頁的「量條」就是 C4_A（紅→黃漸層 121×9）—— 它是全 MENU 裡唯一的漸層量條，f-ui 的 `project/54` 沒提到它的用途。我把它同時用在標題刻度與拉桿，如果原作其實只用在音量/戰力，這兩處就是我的延伸用法。
- `[推測]` `D25`（183×40，四角帶短豎線）在原作裡是「牌匾／輸入框」；我拿它當標題匾與資訊卡外框，尺寸靠九宮格拉伸，看起來合理但沒有原作截圖佐證。
- `[推測]` `.chip` 用不透明度 .90/.92 才壓得住背後的橫匾字，是為了「暗底白字」的可讀性做的讓步；原作是亮底深字，本來不會有這個問題（`project/17` 也記了這個口徑差異）。
