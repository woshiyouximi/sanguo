# 144 · 保真校验网（原作 ↔ 数据 ↔ 运行期）

不是对照表，是**可重复执行的断言**：每改一次代码，跑两条命令就能证明"和原作相比没变差"。
断言只有三个结论：**PASS**（有原作/反汇编证据，一致）、**WARN**（口径是 `[推断]/[推测]`，或数据/构建漂移，不算缺口）、**FAIL**（有证据却不一致）。竖屏必然带来的差异一律 **SKIP**，不计 FAIL。

## 怎么跑

```bash
# 1) 重新生成期望值（只在原作材料/extract 变了时才需要；产物已入库）
node work/fidelity/gen_expect.mjs              # → work/fidelity/fidelity_expect.json（941 KB）

# 2) 完整校验网（默认跑 game/dist/core；跑 src 加 --src）
node work/fidelity/check.mjs
node work/fidelity/check.mjs --only=magic.row  # 只跑一块，前缀同 id
node work/fidelity/check.mjs --verbose         # 逐条打印 PASS

# 3) 自证断言不是空转：往内存里注入一条假数据，校验网必须变红
node work/fidelity/check.mjs --only=magic.row --mutate=magics.0.MP=999
# → FAIL magic.row.001  got=["MP:999≠20"]  PASS 109 / FAIL 1（仓库文件不动）

# 4) CI 自带的那一层（核心子集，跟着 node --test）
cd game && node --test tests/fidelity_net.test.ts
```

退出码：`0` 全过 / `1` 有 FAIL / `2` 期望 JSON 缺失或参数错。末行固定为
`PASS n / FAIL m / SKIP k / WARN j`（当前 **PASS 458 / FAIL 0 / SKIP 3 / WARN 1**，462 条断言）。

## 竖屏差异，不算缺口（SKIP 3），断言即文档

- `vertical.map.letterbox`：地图 1280×960 装进 750 宽竖屏，`fitBox(contain)` 等比缩放后留黑边，坐标本身不动（`mapProj.ts`）。原作 640×480 无此问题——这是版面决策。

## `[推测]` 清单（8 条，都在 expect.speculations，来源拿不到 VA）

1. `spec.qiPercent` 技力消耗比例 = clamp(MP,20,80)% × 120000：POWER 全 100，没有 VA 说明，本作改用 MP 当百分比（`battle.ts` `qiPowerPercentOf`）。
2. `spec.castKind` heal/aoe/strike 由 ATTRIB/ATTACK 反推，与 magic.json category 非一一对应，只作回归口径。
3. `spec.activeMask` INI 的 ACTIVE 是中文串，数值掩码由导出工具按 4 值码推导（docs/03b:477-486，置信度中/弱）。
4. `spec.wiseTarget` 军师技目标码 1/2/4/8 的语义标签：存在反例（后选出阵=8、逼近敌军=1）。
5. `spec.typeShape` TYPE 1..15 → 造型符 `1..9,A..E,0`（project/48:19、docs/05b:84；400/400 覆盖，强视觉证据但仍非 VA）。
6. `spec.fxTtl` 特效驻留 = clamp(round(帧数×2.2),24,132)，无帧→30：原作只有"帧停留 tick 数"，无逐技总时长证据。

8. `spec.sfxCurated` 110 条里 35 条无 `work/dis_magicmap_skills.txt` 直证，取 `work/sfx84/map6.json` 策展值（证级 C/X）。
