## 3. 投影与 `pos_xy` 的吻合度

### 3.1 先纠正一件会影响验收方法的事：底图里**没有**烘任何城图标

任务写"这 6 个城建在图上能看出来，逐一核对"。实测：**`CHINAMAP.png` 是纯地形晕渲 + 橙色官道 + 蓝色河，没有任何城图标。**

- 目视：全图 ×1，加 4 个象限 ×2 放大（`work/map_orig/inspect/zoom_0_0.png`、`zoom_1_0.png` 等）翻了一遍，一个城图标都没有。城图元最小 22×18，×2 后是 44×36，不可能看漏。
- 量化：把 4 张城图元的**独有色**拿去全图精确匹配（1,228,800 像素）：

| 色值 | 出现在图元里 | 在 CHINAMAP 里的像素数 |
|---|---:|---:|
| (255,121,0) 金顶橙 | 27–33 次 | **0** |
| (255,130,0) | 28–56 次 | **0** |
| (33,16,8) 暗描边 | 12–27 次 | **0** |
| (255,162,0) | 20–28 次 | **0** |
| (189,138,107) | 8–17 次 | 3（巧合，非成片出现） |

→ 结论：原作大地图是"地形+路网"底图，城是运行时叠上去的图元。**这是好消息**：说明我们的渲染方式和原作一致。

**于是验收改为"和烘进图里的官道路网核对"**——官道是原作用同一套 `pos_xy` 画出来的，是最可靠的地面真值。

### 3.4 第二条独立证据：116 条行军路网的端点

`paths` 的 `points` 是原作的折线采点。把 116 条按 `Length>=30000` 的哨兵标记分开后：

| 类别 | 条数 | 首尾点到对应城 `pos_xy` 的最大偏差 |
|---|---:|---|
| 真实路 | 77 | **中位 1 px、≤2 px 的占 149/154 个端点（96.8%）、最大 5 px** |
| 哨兵路（`Length>=30000`，画了线但不可走） | 39 | 中位 48 px、最大 133 px |

真实路端点几乎精确落在城 `pos_xy` 上——**这和道路掩膜是两套完全独立的证据（一个是图像像素，一个是数据），都指向同一坐标系**。

顺带一个给接线用的坑：**画路线必须自己补端点**，`[起点.pos_xy, ...points, 终点.pos_xy]`。`campaign.html:1567` 现在是 `(p.points && p.points.length) ? p.points : [a.pos_xy, b.pos_xy]`，只在 points 缺失时才回退——于是路线和城之间会差那 1–5 px（哨兵路会差 48–133 px）。

### 3.5 结论：不需要偏移或缩放

`sx = sy = 1`、`dx = dy = 0`。

**没有做最小二乘拟合**，因为不需要——地面真值（烘进像素的官道 + 路网端点）本身就是同一坐标系，拟合会退化成单位阵。任务要求"若需要，拟合出 `sx,sy,dx,dy` 并给出残差中位数"：前置条件"若需要"不成立；残差中位 0.00 px 就是直接答案。

**C. 点击反查换成 `screenToMap` + `hitCity` 的语义**（替换 `campaign.html:1644-1655`）

现实约束：`campaign.html:267` 是 `<script type="module">`，但页面是**静态 HTML + 无 TS 构建**，直接 `import '../src/view/mapProj.ts'` 浏览器跑不了。所以给**语义完全一致的内联版**，将来 campaign 进 TS view 层时整块换成 import（数学逐字相同，行为不变）：

```js
const rc = ev.target.getBoundingClientRect();            // 画布的 CSS 尺寸
const px = (ev.clientX - rc.left) * (view.w / rc.width); // → design px
const py = (ev.clientY - rc.top) * (view.h / rc.height);
const P = plotRect();
const mx = (px - P.x) / P.s, my = (py - P.y) / P.s;      // ≡ screenToMap(P, px, py)
let best = null, bd = Infinity;
for (const c of ALL) {
  const d = (c.pos_xy[0] - mx) ** 2 + (c.pos_xy[1] - my) ** 2;   // 地图空间比距离
  if (d < bd) { bd = d; best = c; }
}
if (best && bd <= (14 / P.s) ** 2) { selected = best.NAME; render(); }  // 14 design px 手指半径
```
