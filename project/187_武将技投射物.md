# 187 武将技投射物（先飞后判 + 飞行实体）

> 承 183《法术域五红收口》§8 遗留第 3 条：「落月弓的弹丸在端口里仍然不会生成——R88 现在是靠兜底把伤害打到主将身上，与『弹丸飞过去撞主将』的观感不同。」
> 本轮把这条补上：**110 条武将技里 12 条真有飞行弹丸**，现在这 12 条会产出投射物事件、由视图画出飞行体，结算时机从「第 3 泵帧兜底」改成「弹丸到场 / 碰撞回调」。伤害公式、目标选择、MP/气力门槛全部未动。

### 2.5 两个「不能改坏」的地方

1. **目标选择**：兜底点仍是 `generalOf(targetHandle)`（R183 的 g3），弹丸落点也是它；`Hurt` 门闩（`dis:0012D8-0012E8`）要求的语义没动。
2. **伤害公式**：`applyHits()` 的 `generalDmg = 8 + floor(ATTACK/2)`、小兵 `rate` 判定全部原样；`applyProjectileArrival()` 用的是同一个公式。它存在的理由写在 `runtime.ts:1690-1702`：原作「弹丸撞人」与「脚本兜底」是两条独立通路（回调里 `CALL Hurt`，一技可以撞多次），端口的 `hitUnits`（整技对同一单位只算一次）只适用于 `applyHits`；拿它卡「弹丸到场那一击」会把这一击整发吞掉 —— 实测 46/62/85 的掉血从 43/49/61 掉到 23/29/35。

### 2.6 兜底拆成两半：主将延后、小兵留原处（`runtime.ts:1735` `applyCollateral()`）

R88 的落点兜底一次同时结算两件事：主将 `8 + floor(ATTACK/2)`、兜底半径内的小兵按 `ATTACK` 赔率各 −1。本轮只把**主将那一下**延到弹丸到场（那是原作 `CALL Hurt` 的时机，`dis:3456`），小兵那一下没有地址证据说要跟着延，而且延了会改小兵减员。

原实现（不拆）会掉进两个坑，都是实测踩出来的：

1. **`applyHits()` 的 `hitUnits` 去重会吞掉补刀**：連弩 5 支箭先撞上主将、主将进了 `hitUnits`，`finishFrames()` 里的补刀被 `unhitUnits()` 静默过滤 ⇒ 46/62/85 掉血 43/49/61 → 23/29/35。`applyProjectileArrival()` 因此绕开去重。
2. **小兵波及不能跟着延**：保真网 `battle.cast.strike`（`work\fidelity\check.mjs:811-820`，落月弓瞄小兵、240 tick 内必须有减员）就是靠这次波及过的；只延主将、小兵仍在 `framesSeen>=3` 结算后，该断言与全量保真都回到 `PASS 459 / FAIL 0`。

`applyCollateral()` 的点集与 `applyHits()` **完全一致**：先 `unhitUnits([fallbackPoint])`（把兜底圆 r=1.4 里的每个敌人各变成一个落在自己身上的 r=1.25 点），再对落在任一点 0.75 格内、非主将、未进 `hitUnits` 的小兵按同一 `rate` 掷骰 −1。主将不掷骰 ⇒ RNG 序列与改前逐次一致。

## 4. 没做到 / 残留

1. **脚本尾部的亮度收尾跑不到（既有缺陷，本轮未引入）**：`CALLS LockCamera` 是嵌套子脚本，端口里 `WAIT 1` 走 `tickClock()` 不挂起帧（`runtime.ts:1143-1148 / 1159-1164`），物件活着时它会把 1200 帧预算烧光 ⇒ `advanceClock()` 抛「技能虚拟帧超过 1200」、脚本截断（`runtime.ts:1171-1178`）。落月弓出生时 `clock` 已是 1201，所以 `dis:4137-4141` 的 `WAIT 60 → RaiseBrightness(16,5) → 0x110` 在端口里执行不到（只剩亮度没恢复）。本轮用 `SkillSession.holding` 让会话不推虚拟时钟继续等弹丸，**观感与结算都对了**，但「嵌套 CALLS 里的 WAIT 该不该阻塞虚拟时钟」这条没动 —— 真要修会改一堆技的帧数（§3.1 里 51/75/100 的 hits 已经在动），超出本轮范围。
2. **三聖華斬（88）/ 五嶽華斬（109）没有飞行体**：它们经 `HalfMoonNew @0x28914` → `PUSHS "HalfMoonNewMotion"; CALLS` 建 `40001`，而端口里该物件建在 (0,0)、且静态闭包只跟 `0x04 CALL` 不跟 `0x47 CALLS`，所以既登记不上飞行事件、也被「位置非 (0,0)」过滤掉。这两条仍是原来的「兜底打 g3」，伤害没变、只是没有刀光飞出去。
3. **劍輪舞（95）的 `2501` 碎片被登记成 `life 1..2` 的短飞行体**：视觉上是主将周围的小火花，不是真弹道；没有继续收紧过滤条件，怕误伤别的技。
4. **八面火（53）/ 八面火轉（67）**：`19002` 是「原地炸 + 碰撞回调」，被算进 12 条（因为它挂了回调），但没有明显位移，观感上仍是一次爆闪。
5. **`0x012` 修好后对落月弓的 frames/hits 无可观测变化**：因为 `LockCamera` 那个循环把时钟烧到 1201，物件的 `expiresAt`（86）永远小于它 ⇒ 物件立刻算「已死」。飞行表现靠 `ProjectileFlight.lifeTick`（取自 `o.frames`）而不是物件寿命，所以观感不受影响；但「物件在端口里活多久」这件事本身仍不准。
