# 38 战后与成长修复（R53 / R62 / R60 / R61 / R25）

本轮把「战后结算 + 升级成长」这条链上 5 条"便宜但玩家能感知"的缺口一次修完。
全部改动只落在 `game/src/core/{capture,battle}.ts`、`game/src/view/battleView.ts`、
`game/web/main.js`、`game/tests/**`；`docs/**`、`data/**`、`campaign/city/deploy.html` 未动。

## 一、五条逐条

### R53 招降三条硬门（`0x404344`，04b2 §2.2）
- 原作尾部三段**无条件**出口：`cmp [g+0x3C],0x5A/0x46/0x32` → `code 0x11/0x12/0x13` → `return 0`。
- 已修：`recruitChanceOf`（capture.ts:165-181）在 `t>=2` 之后依次判 `loyal>90/70/50 → 0`；
  `canRecruit`（capture.ts:232-242）同序早退并给出 `硬门 0x11/0x12/0x13` 的中文原因。
- 这三段在汇编里位于掷骰**之后**，所以只能表达成"概率恒 0"，不是"降概率"；
  三段合并等价于 `L > 50`，仍按三档各判一次，只为让文案对得上原作的 code。
- 既有概率式与 04b2 §2.2 的表一致（`1-L²` / `1-L` / `(1-L)/3`），未改动公式本体。
- 顺手修：`resolvePostBattle` 现在把 Web 层带来的武将级 `loyal/constancy` 传进 `profileOf`
  （capture.ts:322 附近），否则 `?bloyal=95` 这类存档值根本到不了判定。

### R62 战后士气 −20 / 忠诚扣减（`0x447520`）
- `settle()`（battle.ts:932 起）对**双方**主将各写一次：
  `morale = max(0, before - MORALE_BATTLE_LOSS)`（=20）、`loyal = max(0, before - (10-节操)*2)`。
  只对 `general.alive` 的将写；阵亡将 before/after 相同（不惩罚死者，但疲劳照加）。
- 士气字段依赖：本作士气同时挂在 `world.sides[side].morale`（`powerOf` 第 5 项读它）
  与 `general.morale`（HUD/战报镜像），`main.js` 的 `moraleApply()` 一直这么双写；
  `settle()` 沿用同一约定，两处都写（battle.ts:975-990 附近）。
- 忠诚扣减另有 `capture.ts:322` 的"被俘惩罚"——那是招降路径的**前置**扣减，与本条并存，不重复。

### R60 平手 / 大胜两种战报（`0x447037`，04b §6.1）
- `SettleResult.mode` 放宽为 `1|2|3|4`，新增 `report`；`MODE_NAME`（battle.ts:890）四档中文名。
- `settleMode()`（battle.ts:902）：`draw → 3`；敌将死或敌兵尽且我方可战兵 ≥ `GREAT_VICTORY_KEEP`
  → `4`；敌将死 → `1`；其余 → `2`。
- `settleReport()`（battle.ts:917）：平手 `雙方平手`；我方败 `我軍戰敗了` / `情況不妙全軍撤退` /
  `我軍在徹退中，全體被俘`（按败因分）；大胜 `我軍大獲全勝!!`。
- 分数按 04b §6.2 四档表重算（歼灭 ×51 + 败方分减半、击退 ×34、平手/大胜 ×17 且大胜双方 ×2）。

  标题只写 `勝利/敗走/平手`，四档细名留在下一行——避免 mode 2 击退也顶「大勝」的自相矛盾。

### R61 功勋写回疲劳（`0x41048D` ④，04b5 §2.3）

## 三、只能近似的地方（逐条）
1. **R62 的范围**：`0x447520` 反汇编里是先 `if (entry[i].status != 3) continue`，即**只罚被俘的将**；
   但 `docs/04b §9.4` 第 17 条写"战后惩罚：全员 士气 −20"，本轮任务也要求"双方存活武将"。
   本实现取 04b §9.4 口径（双方存活主将都 −20），差距记在此处，`docs/**` 未改。
   若日后以反汇编为准，改成"只罚被俘将"只需在 `settle()` 里加一个 `captured` 判断。
2. **R60 的阈值**：原作没有"大胜"的判定式（`0x447037` 只给 mode；mode 4 的分数倍率在 §6.2），
   `GREAT_VICTORY_KEEP = 0.7` 是本作取的常量 **[推测]**，改它只影响 mode 4/2 的分界。
   `歼灭/击退/大胜` 三条文案里只有 `雙方平手`、`我軍大獲全勝!!` 是原作字串，
   `敵軍潰退，我軍取勝`、`敵軍全軍覆沒，我軍大獲全勝!!` 是 **[本作拼装]**（原文只有胜负三态）。
   `unitL->+0x04 = 3/2/2/6`（败退状态）未落地——本作士兵没有败退/逃散状态位。
3. **R61 的秒数**：原作 `0x41048D` 用 `(11880 - countdown)/120` 取秒，本作没有 countdown，
   用 `tick/TICK_HZ` 取整秒再 `trunc(秒/10)`；两者在整秒级等价，余数处理可能差 1 秒。
   疲劳上限 100、双方都加、`15+秒/10` 三条与 04b5 §2.3 一致。
4. **R25 的持久化**：本作是单场预览壳，武将技能表只存在 `settle().learned` 与内存里的技能栏，
   没有大地图存档层的"武将已学技能"字段；军师技只进面板/消息，没有独立军师技栏。
   学习判定本身（等级门槛、同名去重、累计）与 §6.7/§9.3 一致。
5. **R53 的等价性**：三条硬门合并后实际等于 `L > 50 → 0`；`t >= 2` 的控制流在汇编里会漏出 1/3
   成功率（掷骰在"宁死不降"之前），本实现按文档表取 0，注释见 capture.ts:154-157。
