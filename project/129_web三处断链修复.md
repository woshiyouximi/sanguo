## 2. S1-1 敌军抵达不校验归属

**根因**：`handleMarchEvents()` 的抵达分支只按 `side === 'B' && progress >= 1` 取行军，
`campaign.html:3432`（r86 报告记的是 :3146，行号随文件长大漂移）——
完全没有「目标城还归不归我」这一步，取到就直接 `location.href = defendUrl(atk)`。
于是**已失守的城**（r86 实测 宛 / 汝南）敌军一抵达还是被拉成「守城战」；
玩家点撤退 = 战斗页没写回、城也没变，下一支敌军抵达又命中同一分支 → 「撤退后下一场又来」。

**修复**：新增标记块 `[[MARCH_ARRIVE_CORE]]`（`campaign.html:3323-3370`），里面是纯函数
`planEnemyArrivals(arrivals, ctx)`（`:3341`）：

- 目标城仍是我的（在 `save.owned`，或 `cities[to].owner === myForce` 的残状态）→ `battles`
- 否则 → `passes`：`kind = 'occupy'`（城无主 / 属别家势力，敌军占领）或 `'pass'`（出征势力自己的城，只是路过）
- 每条 pass 配一条战报：`敵 軍 佔 領：{from} → {to}（{to} 已非我軍，不進戰鬥）` / `敵 軍 路 過：…（{to} 非我軍城池，不進戰鬥）`

`handleMarchEvents()`（`:3432-3465`）改为：先算 `plan`，passes 逐个 `removeArmy()`；
`occupy` 时把 `cities[to].owner` 改成进攻方势力、守军按守城失败的同一系数缩到
`Math.max(30, round(敵兵 * 0.6))`（与 `resolveDefense()` 失守分支一致）；然后
`if (!plan.battles.length)` 才不跳转，有 `battles` 才走原来的 `resolveDefense`（批量）或
`defendUrl`（交互）——**`defendUrl(atk)` 现在只在 `plan.battles.length` 成立之后可达**（测试 ⑨ 是这条源码契约）。

## 3. S2-2 装备孤岛

**根因**：`items.html`（冻结）把装备写进独立 key `sanguo_items_v1`，而 `saves.js` 的
`equipOf()`（`:632`）**全仓零调用** —— 三张 `weapon/horse/thing` 表是死数据，所以
武力加成不进战斗、不进大地图，换将/读档后装备也不跟随。

**修复三块**：

1. **进快照**：v3 加了**可选**字段 `save.equip = { 將名: {weapon,horse,book,amulet} }`（物品**名字**），
   并镜像回原三表（`weapon→weapon`、`horse→horse`、`book→thing`），读写走
   `equipSlotsOf()`（`:707`）/`setEquipSlots()`（`:728`）；`metaFromSnapshot` 的 `equipCount`
   把只有饰品的武将也算进去（`:777-783`、`:809`）。
2. **桥**：`items_model.js:275-325` 提供 `normalizeBagEquip` / `equipNames` / `equipSeqs` /
   `bonusOfNames`，把序号表翻成名字表再交给 `saves.js`。
3. **消费者**（这是原来缺的那一步）：
   - 大地图显示：`monarchCardHtml()` `:1764-1765` → 「武 116 · 智 90 · 等級 6 · 裝備 武+30 智+20」；
     `generalRowsAll()` `:1890/:1897` + `renderGeneralSheet()` `:1919` 给全体武将。
   - 战斗建局参数：`statsOf`（`:1236`）→ `marchDirectQuery` `:3161`、`defendUrl` `:3200`、
     `encounterUrl` `:3388` 各写 `astr` / `aint`。
   - 调用链可 grep：`render()` → `equipBonusOf` → `equipNamesOf` → **`Saves.equipOf`（:1211）**。
   - 镜像入口三处：boot（`:1373`）、`snapshotForSave()`（`:1088`）、`render()` 首行（`:2157`）——
     「先清空再重建」，所以**在物品页卸下装备，大地图下一次 render 就掉加成**。

**为什么选「v3 结构里加可选字段」而不是加 `SNAPSHOT_REQUIRED` 或 v3→v4**：
`snapshotIsCurrent()`（`saves.js:229-231`）要求 `v === 3` 且每个 `SNAPSHOT_REQUIRED` 键都在。
往 REQUIRED 加 `equip` 会让**所有现存 v3 槽**一律判成 `changed` → 下次读档重写全部 10 槽，
并弹出毫无意义的 `v3 → v3` 升级提示；加一条 `v3→v4` 则要改 `SNAPSHOT_VERSION` 并让所有
`v===3` 的断言（`saves_r70.test.ts` / `yearsettle_r7.test.ts` 里多条）跟着漂。而
`ensureSnapshotShape()` / `deepClone()` 本来就不动未知键，可选字段零迁移就能穿过
`upgradeSnapshot` / `normalizeStore` / `metaFromSnapshot` / `prepareSnapshot`。
（`SNAPSHOT_REQUIRED` 与 `SNAPSHOT_STEPS` 本轮**一行未改**。）

## 4. S2-4 迁移提示死代码

**根因**：`loadStore()`（`saves.js:481`）内部就走 `normalizeStore()`，那里逐槽
`upgradeSnapshot()`（`:457`）已经把 v2 升到 v3 并写进内存里的 `store`；`campaign.html`
的 `normalizeCampaign()` 再调一次 `upgradeSnapshot()` 时看到的是 `from === 3`，
`campaign.html:1412` 的 `else if (snapshotUpgrade)` 于是**永不成立** —— 提示不弹，
升级后的快照也从未写回磁盘（每次开页都重升一遍）。

**修复**：

- `saves.js`：`normalizeStore()` 收集 `upgraded: [{slot, from, to}]`（`:465`），
  **只在 `up.from < up.to` 时记**（单纯 `changed` 还包括「缺摘要字段」的补算，那种不该提示）；
  `saveStore()` 落盘前 `delete disk.upgraded`（`:501`），保证这栏只在内存里活一次。
- `campaign.html`：boot 拿到 `const bootUpgrades = store.upgraded`（`:1307`），
  迁移块新增分支（`:1399-1409`）：**先 `Saves.saveStore(store, storage)` 写回**，再
  `autosave(false)`，再 `notice('舊存檔格式已自動升級：v… → v…（槽 n）', 12000)`；之后不再提示。
  原来那个 `else if (snapshotUpgrade)`（`:1412`）保留，但降级为**手动读槽**（`loadSlot()`）的兜底。

### 6.1 `game\web\main.js`（冻结）—— `?astr` / `?aint` 才生效

`campaign.html` 已经在三条出征/守城链接里带上 `astr` / `aint`，但 `main.js` 的

在 `generalFromQuery()` 里 `const params = new URLSearchParams(location.search);` 之后插：

```js
  // R86 S2-2：大地圖帶來的「裝備後」武力/智力（campaign.html 的 astr/aint）
  const override = (k) => {
    const n = Number.parseInt(params.get(k) ?? '', 10);
    return Number.isFinite(n) && n >= 0 ? n : null;
  };
  const aStr = override('astr'), aInt = override('aint');
  const withEquip = (g) => ({
    ...g,
    str: aStr === null ? g.str : aStr,
    int: aInt === null ? g.int : aInt,
  });
```

然后把该函数三处 `return` 包一层 `withEquip(...)`：`:455` 的空名分支、`:459` 的 `{name:q,str:97,int:75,level:6}`、
`:460` 的 `{name:hit.NAME,str:hit.STR,int:hit.INT,level:6}`。
`readConfig()` 的 `general: cfg.aGeneral`（`main.js:612`）与 `createWorld`（只認 `str/int/level`，见 `main.js:658` 注释）
无需再动。不带 `astr` 时行为与现在完全一致（`withEquip` 原样返回）。
