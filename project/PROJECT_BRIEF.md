## 1. 项目定义

- **形态**：微信小游戏，**竖屏**（9:16 为主，兼容 19.5:9 / 4:3 平板）。
- **玩法基线**：1999 年《三国群英传2》——大地图（城池/路径/移动）＋ 内政（月循环）＋ **100 人实时兵战**＋武将养成＋武将技/军师技。
- **v1 目标**：把原作**完整搬到竖屏**，UI 与美术**全部重做**，不沿用原作素材。
- **v1 之后**：以 v1 为基线做玩法增删（不在本轮讨论）。

## 3. 原作的可移植结论（来自逆向，直接当设计输入）

- 战斗只用**一条加算公式**：`战力 = 兵种相克 + 地形修正 + 阵形相克 + (全局+50)/100 + (士气−50)/5`；命中 `rand()%300 < 战力`（打武将时 `p = 150 + (攻武−守武)/2`）。
- 伤害：打武将 `rand[武/2, 武)/10`（下限 1）；**士兵没有 HP，命中即死**。
- 兵种 13 种、严格反对称相克（±68）；阵形 9 种、零和（±25）；**地形不参与数值**，只是场景选择器。
- 内政极简：一回合＝一个月、无粮草、城规模不变、AI 每月 1 个动作（权重 200/100/50）。
- 城池 60、路径 116（可通行 77）、武将 400（属性五剧本相同）。
- 100 兵 = 10 个"小队"×10 人，小队有阵形分区（前/中/两翼/本阵），布阵是 33 组硬编码坐标数组。
- 存档无校验和、定长头 0x1D0 + 七段。

## 4. 微信小游戏的硬约束（写文档必须遵守）

- **首包 ≤ 4 MB，整包 ≤ 20 MB**（超出走分包，单分包 ≤ 20 MB；代码包总大小受"总包 30 MB"上限约束）；**远程资源**用 CDN + `wx.downloadFile` 缓存。
- **不能热更代码逻辑**（审核要求），**能热更资源**；所有逻辑必须随包发。
- 只支持 **JS/WASM**，无 JIT 优化空间；低端安卓（骁龙 6xx / 4 GB 内存）是性能下限。
- 需要 **版号**（国内商业化），走"小游戏类目 + 版号备案"；测试期可用"小游戏体验版 + 无版号"但**不能开内购**。
- 包内不能含 `eval` 之外的可执行代码、不能动态加载 JS。
- 屏幕：`wx.getWindowInfo()` 拿安全区，**刘海/底部 home 条必须避让**。

## 5. 竖屏设计基调（所有 UI 文档统一）

- 设计分辨率 **750 × 1334**（等比适配，`FitHeight` 为主），安全区上下各留 ≥ 88 px。
- 竖屏的黄金三分：**上 12% 状态栏 / 中 62% 主视图 / 下 26% 操作区**。
- 单手握持：主要操作按钮落在**右下拇指热区**（x > 55% 宽, y < 35% 高）。
- 信息密度**必须低于原作**：原作横屏一屏能塞 6 个面板，竖屏一屏只放 1 个主面板 + 1 个次级面板。
- 列表优先"纵向滚动 + 卡片"，不要横排多列（原作大量横排表格要重排）。

## 6. 战斗竖屏方案（一句话）

**逻辑坐标一个字不改**（71 列前进轴 × 14 行横向 × 格 96×72 px，世界 6816×1008），**只把呈现转 90°**：横向的 14 行车道放到屏幕左右，前进的 71 列放到屏幕上下，**我方在下、敌方在上、向上推进**。

### 6.1 方案 A 的确定数字（所有文档以此为准）

| 项 | 值 | 推导 |
|---|---|---|
| 战场带 | 750 × 900（屏幕 y ∈ [100, 1000]） | `01 §4` / `02 §2.6` |
| 缩放 `s` | **0.7440** | 14 车道 × 72 px = 1008 → 750/1008 |
| 屏上格 | **53.6 × 71.4 px**（横 × 纵） | 72·s × 96·s |
| 一屏可见 | **14 车道全宽 × 12.6 行纵深** | 14 行恰满宽；900/(96·s)=12.6 |
| 推进轴可见比 | 12.6 / 71 = **17.8%** | 镜头纵向跟随，与原件"只看得见 6.7 列"同构 |
| 摄像机 | **一维（只跟世界 x）** | 横向 14 车道恒定全见，camY 恒 0 |
| 我方 | `screenY = 1000 − (worldX − camX)·s`（worldX≈0 在下） | 敌方 worldX≈70 在屏幕上方 |
| 横向 | `screenX = worldY·s + 750·(1−14·72·s/750)/2`，恒为 0 | 14 车道刚好铺满 |
| 缩放档 | 近景 1.34（要 camY 裁切）/ 标准 0.744 / 全景 0.67 | 近景宽 1350 > 750，需横向裁切 |
| 单位朝向 | **我方＝背视（朝屏幕上方走），敌方＝正视（朝下迎敌）** | 每套单位动画必须出**两套视角** |

### 6.2 由此带来的美术口径（写进 `03` / `06`）

- 原作单位只有**侧面一套 + 左右镜像**（实测 `MAJOR\BODY` 全部是 3/4 侧视朝右，8 个动作码 `A/D/F/H/L/R/S/W` 是动作不是朝向）→ 方案 A 必须为**每个身体/兵种多出"背视"一套**（敌方用正视，我方用背视，同一套资产两方向复用）。
- 武器、马、旗帜同样要两套视角；**技能特效**因地面投影被旋转，约一半需要重做（详见 `03` 的增量表）。
- 这是 v1 美术量的主要增量来源，`06` 的产量与算力预算按此重算。
