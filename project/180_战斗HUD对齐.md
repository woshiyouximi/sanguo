## 1. ① 顶部金牌倒计时是什么（有反汇编，不用推测）

录像里金牌是中文数字、一路减小（`98→92→86→79→73→67→60→53→46→39`，我另外读出的两帧是 `六十七`(08:42) 与 `五十八`(09:00)，18 秒降 9 点 = **0.5/秒**）。它**既不是回合数也不是我方行动倒计时，是战场剩余时间**：

- 变量 `[0x4AC35C]`，初值 `0x2E68 = 11880`（`0x4442AC` 战斗初始化、`0x444614`、`0x444459` mode 5 战场初始化，见 `docs/04b3_单挑流程.md:474`）。
- 每帧推进（`work/dis_battle_units2.txt:1029-1041`，xref 表 `work/units_per_side/refs_4A8_4B7.txt:389-398`）：
  `00444126 mov eax,[0x4ac35c]` / `sub eax,1` / `mov [0x4ac35c],eax` / `cmp [0x4ac35c],0` / `jg 0x444153` → `mov [0x4ac35c],0` / `push 0x1000; call 0x443CA8`。
  即**60fps 每帧 −1、下限夹 0，到 0 时用 `0x443CA8(0x1000)` 置「战斗结束」状态位**。
- 显示量纲：`0x443F2A() = (0x2E68 − [0x4AC35C]) / 0x78` 被当作「战斗时长」用于战功 bonus（`docs/04b_战斗系统.md:516`），`0x78 = 120` 帧 = 2 秒 ⇒ **显示值 = `ceil(cd / 120)`，起始 `11880/120 = 99`，每 2 秒降 1（0.5/秒）**，整场 11880 帧 = **198 秒 ≈ 3 分 18 秒**。
- 录像里出现 `98`、`95` 起始，只是因为录到的是开战后 2–8 秒；不是初值差异。
- 我们引擎 `TICK_HZ = 30`（`game/src/core/battle.ts:41`）⇒ 总时长 **5940 tick**，换算 `CLOCK_UNIT_TICKS = 60` tick / 单位，显示 `ceil((5940 − tick) / 60)`，起始 **99（九十九）**。实现：`game/src/view/battleView.ts:1689-1712`。

**到 0 之后发生什么**：原作 `0x443CA8(0x1000)` 置结束位后由 `0x447424(kind)` 走结算，攻方未破阵按「时间到」判负/和 —— 具体档位 **`[推测]`**（未逐档验证）。
**我们的现状**：`game/src/core/**` 禁改（另有 agent 在重写行动模型），core **没有战斗时间上限**，所以本次只在 HUD 上显示、`tick ≥ 5940` 后金牌停在 `零`，战斗不会自动结束。→ 已记 TODO 交 core 侧（§8）。

## 3. ③ 中文数字金牌

- `chineseNumber(n)`（`battleView.ts:1698`）：0–99 夹取、NaN→0、`十` 不写「一」（10→`十`、60→`六十`、67→`六十七`、99→`九十九`）。
- `clockUnitsLeft(tick)`（`:1708`）：`99 − floor(tick/60)`，夹 0–99。
- `drawClockPlaque()`（`:1714`）：`CLOCK_PLAQUE = {x:268,y:6,w:214,h:48}`（`layout.ts:88`），四层 —— 外框 `#241610` + 金边、`#b08a4e`、木纹芯 `#f2e4bf`、3 条 `#8a6f3e` 木纹线；文字 26px 加粗 `#2a1c0c` 居中。
