### 2.3 顺手修的数据形状 bug：`GeneralBook.ts` 的技能表

- 症状：卡片必殺技永远「—」。根因不在渲染——`game\cocos\assets\bundles\res\data\generals.json` 401 条的 `SKILL` 已经变成**多段字串数组**（`["1, 50", "6, 63", …]`，每将 7–8 段，关卡等级 1/6/11/…/40），而 `GeneralBook.ts:199 parseSkillPairs(raw)` 只吃 `typeof raw === 'string'`，数组一律回 `[]`。
- 改法（`GeneralBook.ts:677` 行文件）：
  1. 抽 `numPieces(raw: string): number[]`（按 `/[,，、\s]+/` 切，只留整数段）；
  2. `parseSkillPairs(raw: unknown)` 吃**四种落盘形状**：字符串数组 / 单串 / `[[lv,id]]` 二维 / `[lv,id]` 扁平——与 `BattleInput.ts:269 learnedSkillSeqs()` 同判据；
  3. `skillOf(raw, level, table)` 改成「**已学会的最高一段**」：`need <= 当前级` 里取 `need` 最大的，一段都没有才回落第一段；`unlocked` 跟着那一段算；
  4. 文件头「三個不是 bug 的資料事實」第 1 条重写（SKILL 是多段表），`skillLine` 上方旧注释从「已解鎖的招 + 還有 N 招未解鎖」改成「已學會的那一招」。
- 附带事实：`GeneralBook.ts:300 levelOf()` 现在走 R85 的 `scenarioLevelOf(name, 0)`，新档關羽是 **1 级**（旧注释写 20）；1 级时第一段（等级 1）一定学会 → 名册 401 人在各自等级下必殺技全解锁，軍師技 102 人解锁（`WISESKILL` 仍是单段）。
- 消费端只有 `GeneralBookPanel.ts:1130/1131`（`skillLine(row.skill,'必殺技')` / `skillLine(row.wise,'軍師技')`），没有别的代码读 `BookSkill.level`。

## 5. 坑

1. **必须轮询等图**：`openGeneralBook()` 之后 2.6 s 只够画行框与首字，`face/thumb` 是异步 `bundle.load`，首跑 dump 会全 `active:false`（真机同样：先看到首字，几十到几百 ms 后换脸）。断言/截图前要等「ready 数稳定」，别等固定秒数。
2. **手工包的 SpriteFrame 没有名字**：`ArtSprite` 里的 frame 是 `loadFrame` 手工 `new SpriteFrame()` 的，`sprite.spriteFrame.name === ''`。CDP 断言只能断 `!!spriteFrame` 与 `originalSize`，断不了文件名。
3. **mock 的 SpriteFrame 没有 `originalSize`**：headless 里 `contain` 缩不到 19.5×26，只能断「高 26、宽 19.4..26」；真机数值由 §3.3 的 CDP dump 兜底。
4. **`h.find(root, name)` 在 `steps_hud_dump.mjs` 里找的是组件类名不是节点名**（R207 踩过）：节点名要用自己写的 `walk` 版 `find`。
5. **pwsh 别内联含中文的 `node -e "…"`**：PowerShell 会拆坏引号（`ParserError`）；一律 `write` 成 `.mjs` 再 `node` 跑。
6. **改 `game/cocos/assets/scripts/**` 后必须 `tsc -p cocos/tsconfig.check.json`**（真 Cocos 声明），web 侧还要 `tsc -p tsconfig.build.json`；`work/cocos_book/_sim` 是三套 headless 的编译产物，改完要重跑 `node ..\..\game\node_modules\typescript\bin\tsc -p tsconfig.sim.json`。
