## 1 场地：71×14、96×72、与 640×480 的关系

### 1.1 原作事实

- `[确认]` 格是 96×72，**不是** 96×96：`0x48`=72。`04b1:37-38、46-51` 记的与此一致。
- `[确认]` 格坐标 (x,y) 对应像素格 `[x*96, x*96+96) × [y*72, y*72+72)`，其中心是 `(x*96+48, y*72+36)`；战场右边界 6816、下边界 1008。
- `[推测]` 640×480 的分辨率来自任务给定/该年代 SVGA 惯例，EXE 的 DirectDraw 初始化本单未查。按 640×480 算，战场横向 10.65 屏、纵向 2.1 屏，**两个方向都必须卷屏**；`04b1:38` 只写了「横向卷屏」，纵向是否卷未记 —— 若纵向不卷，y 0..13 的 1008 px 会超出 480 px 屏，逻辑上不成立，故判为双向卷（`[推测]`）。
- `[推测]` 镜头锚点跟随两军中点或主将，未见证据；本单不展开。

## 3 落位算法

### 3.1 原作事实（`04b1:141-211` 伪代码已逐条对过反汇编）

```
BuildSide(unit):                                // 0x442EFA(B) / 0x443498(A)
  [0x48E4C8] = GetAnchorX(formation)            // 0x442F14，= 上表 anchorX
  [0x48E4D0] = 6                                // 目标行；见 3.4
  N = N_步 + N_骑
  放主将（固定第 6 行、局部 x=0）
  for mode in {1,3,4,5,2}:                      // 0x443180..，顺序固定
     kc = GroupCountCav(formation, N_骑, mode)  // = w_m*N_骑/200
     ki = GroupCountInf(formation, N_步, mode)  // = w_m*N_步/200
     SpawnUnits(mode, slot 0..kc-1, 骑兵) ; SpawnUnits(mode, slot kc.., 步兵)

SpawnUnits(...):
  GetSlotPos(formation, slot, mode, &x, &y, anchorX)   // 0x404DAF：x=表内x+anchorX, y=表内y
  X = x + (200 - N)/25                                 // 0x442CB6，整除，向下取整
  Y = y
  variant 分支（unit+0x68）：1/2 → X+=12；3 → 不加偏移；4 → X = 0x22 - X
  if (A 侧) X = 0x47 - X                               // 0x442D1B，= 71 - X
  while (GetCellObject(X,Y) != 0)                      // 0x43AF7A
      X<=1 → X+=0x20 ; X>=0x70 → X-=0x20 ; 否则 X>=0x36 ? X+=1 : X-=1
  写槽、建对象、写占位表
```

- `[确认]` 人数分区：`k_m = w_m*N/200`，**mode1 吃掉全部余数**以保证 Σk = N（`04b1:119-131`、`:977`）。
  - `[补充]` 「mode1 吃余数」在 N 不能被 25 整除时可能让 k1 **超出 mode1 数组长度**（实测 `玄襄 N=189`：w=[40,42,40,40,38] 的 m2..m5 各向下取整少 1，k1 = 41 > 数组 40 项）。按累积取整写就没这个问题、且与原文在 10/50/100/200 四档完全一致：
    `k_m = floor(P_m*N/200) − floor(P_{m−1}*N/200)`，`P_m = w_1+…+w_m`（9 阵 × N=1..200 全扫，无溢出）。建议 #2 直接按累积式实现。
- `[确认]` 区内次序：**骑兵占低位 slot 0..kc−1，步兵接 kc..**（`04b1:172-173`，逐条核对 `0x443180`–`0x4432E8` 的 push 顺序）；`04b1:979` 概括为「骑兵靠中心，步兵在外」。
- `[确认]` 数组本身是**由内向外**填的：方形 m1 首 12 项 `(1,6)(1,7)(2,6)(2,7)(1,5)(2,5)(3,6)(3,7)(3,5)(1,8)(2,8)(3,8)` —— 从锚点列往 +x 长、行从 6 向上下扩。所以「低位 slot」= 靠近锚点/中线的格子。
- `[确认]` 变体 `unit+0x68` 的写入者仍未定位，`04b1:946` 判本版恒 0（走 default，不加 12）；`[推测]` 因此实战只有「X = slotX + (200−N)/25」这一条。
- `[确认]` 占位冲突挪格：主将先落子并写 `0x4B3CA0`，后续士兵撞到就沿本行 ±1 / ±0x20 跳。
- `[确认]` **主将那一格原作为什么不会被撞**：9 阵 × N=1..200 全扫，`(anchorX + (200−N)/25, 6)` 从不出现在任何士兵格上 —— 阵形表在锚点列的第 6 行是**刻意留白**（方形 m1 从表内 x=+1 起、m2 到 −1 止，x=0 整列不用；其余阵同样避开）。所以实战里 `0x43AF7A` 的挪格对「主将 vs 士兵」**一次都不触发**，主将格 = 名义公式值。

## 6 开局到接敌的帧数（40 帧/格，30 fps）

### 6.1 算式

- `[确认]` 行动闸门 `0x43B574` 复位 `[u+0x34] = 0x28` = 40 帧（`battle.ts:77` 注释、`project/155`）；30 fps（`battle.ts:41` `TICK_HZ=30`，`project/158:93`「0.75 格/秒 = 1/40×30fps」）。
- `[确认]` 交战条件 `ENGAGE_RANGE = 1.15`（`battle.ts:63`）⇒ 正交相邻（distance 1）可打，对角 1.414 不可。
- 从初始距离 `d` 到能打，需要把距离压到 1：**单侧推进** = `(d−1)` 步；**双侧对进** = `ceil((d−1)/2)` 步（两侧各走一半）。
- 帧数 = 步数 × 40；秒数 = 帧数 / 30。
