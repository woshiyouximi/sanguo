# 82 · 战斗页底部操作台：原作 MENU 图元化

> 目标：把战斗页操作台（HUD 下方：头像框 / 4 个技能格 / 突擊·撤退 / 日志框 / 条带分隔）
> 从 CSS 自绘换成《三國群英傳 2》原作 MENU 图元，让战斗页也「看起来是原作」。
> 交付物：`game/web/assets/battleui/`（7 张九宫切片，共 **3603 B**）+ `game/web/index.html` 的 CSS/叠层接线。

## 0. 先说一个和派单前提不一致的事实（已核实）

派单说「HUD 现在是 DOM：`<div class="hud">` 一类 + 4 个技能格 + 两个大按钮」。
实际 `game/web/index.html`（改动前 208 行 / 8042 B）里**没有任何技能格/按钮 DOM**，全页 DOM 只有
`header`（`#troopA/#formA/#troopB/#formB/#seed/#start/#stat`）、`<canvas id="stage" width=750 height=1334>`、
`#hudbot`（画布下方的装饰条）和 `#error`。唯一 `.hud` 在 `game/web/city.html:324`（内政页）。

战斗页操作台整块是**画在 canvas 上的**：

| 内容 | 位置 |
| --- | --- |
| 控制台底色 + 顶边金线 | `game/src/view/battleView.ts:1147-1267`（`drawConsole`） |
| 头像框 / 主将信息 / 三条 bar | 同上，`PORTRAIT={18,1012,86,108}`、`GENERAL_INFO={116,1012,250,100}` |
| 技能格底板 + 格内文字 | 同上，`skillSlotRect(i) = (116+98i, 1124, 88, 88)` |
| 突擊 / 撤退大按钮 | `battleView.ts:1269-1287`（`drawCommandButton`） |
| 提示框 | `MESSAGE_BOX={116,1224,392,84}` |

`main.js` 和 `game/src/**` 都在禁改清单里，所以**不可能**用 CSS 把 canvas 的渐变换成图元。
合规且效果等价的做法（也是 `project/54_原作UI素材.md` 里 f-ui 的手法）：**在画布上叠一层
`pointer-events:none` 的空心九宫格框**，框心透明，canvas 的文字照常从中间透出来；
命中矩形一个字节都不动。本次就是这么做的。

### 3.1 为什么必须补那 12 行 JS

canvas 的 CSS 尺寸是 `main.js:1193-1207 resize()` 按 `min(availW/750, availH/1334)` 算出来再写成
px 的，纯 CSS 拿不到这个比例；而 `#hudbot` 早就是靠一段内联 IIFE 读 `getBoundingClientRect()`
定位的。所以叠层沿用同一条路：读画布矩形 → `translate(rect.left+1, rect.top+1) scale(k)`，
`k = (rect.width - 2) / 750`（**减 2 是 canvas 的 1px 边框×2**，`* { box-sizing: border-box }`）。

同步有三个触发源：`resize`、`load`、`ResizeObserver(canvas)`，外加 200ms 的定时器兜底 ——
因为**页眉的统计行会随战况从 1 行变 2 行，画布会被顶下去而尺寸不变**，ResizeObserver 不触发。
这个坑是验收时抓到的：CDP 读到的 `transform` 比 `rect` 少了 5.8px（`translate(30.5px, 88.98px)`
对 `rect.top=94.8`），补上定时器后变成 `translate(30.5px, 95.7969px)`（= rect.top + 1）✅。
定时器里只在字符串变化时才写 `style.transform`，不制造无谓的重排。

### 3.2 几何：全部外扩 2px，包住 canvas 自己的描边

叠层原点 = 画布绘图原点（rect 左上 +1px 边框），单位是设计 px（750×1334）。

| 叠层元素 | 叠层矩形（design px） | 对照 canvas | 边框 / 切片 |
| --- | --- | --- | --- |
| `i.port` | 16, 1010, 90×112 | `PORTRAIT` 18,1012,86,108 | 14 / 14px |
| `i.slot.s1..s4` | 114+98i, 1122, 92×92 | `skillSlotRect(i)` 116+98i,1124,88,88 | 14 / 14px |
| `i.msg` | 114, 1222, 396×88 | `MESSAGE_BOX` 116,1224,392,84 | 10 / 10px |
| `i.cmd.aslt` | 526, 1122, 208×88 | `BTN_ASSAULT` 528,1124,204,84 | 14 / 14px |
| `i.cmd.retr` | 526, 1218, 208×88 | `BTN_RETREAT` 528,1220,204,84 | 16 / 16px |
| `i.sep.top` | 108, 1106, 624×12 | 信息行与技能行之间（避开头像右缘 104） | — 平铺 |
| `i.sep.bot` | 18, 1316, 714×12 | 控制台底缘 | — 平铺 |

### 3.3 保真与不遮挡

- 每个 `<i>` 都是 `position:absolute; pointer-events:none; border-image-repeat:stretch;
  border-image-outset:0; image-rendering:pixelated`，**不给元素本身加尺寸外的 border**
  （只在装饰元素上加 `border-width`，那 10 个 `<i>` 本来就是为这层新建的，不承载任何内容，
  所以「布局零位移」是字面意义上的：canvas 位置、尺寸、命中矩形全都没动）。
- 不给页面加任何遮罩；叠层只画边框，框心透明，HUD 数值（100/100、士氣 60、氣 59%）
  与提示行（「敵軍技 恢復技力；點技能格 → 點戰場施放。」）都在框内正常透出。
- MENU 空心框本身是**暗青铜 #725034**，直接贴在 `#1a1f27` 面板上几乎看不见，所以每个框都带
  `filter: brightness(1.25–1.7) saturate(1.1–1.15)` 提成金色；置灰的两处反而用
  `grayscale(.7-.8) + opacity(.5-.55)` 压下去。
- 结算态（`state.mode === 'settled'`）canvas 会盖一层压暗层，叠层通过 `data-mode="settled"`
  跟着退到 `opacity:.16; filter:saturate(.55)`，不会「亮着不暗」。

## 6. 没做到的 / 发现的坑

1. **不能真的「换掉」操作台**：`main.js` 与 `game/src/view/battleView.ts` 禁改，操作台是 canvas
   画的。本次是「叠空心框」，canvas 自己的面板底色、圆角、1px 白描边仍在框下面，所以技能格内
   会看到 canvas 那条细线（和原作「框内还有一道细线」的观感接近，但不是零残留）。
2. **技能格的禁用/选中态没有接运行时**：叠层是静态 DOM，`.is-off` 这个 class 钩子与
   `slot_off.png` 都已经备好（CSS 见 `index.html:116-121`），但要在 `main.js` 里按
   `state.skills[i]` 切 class 才能生效 —— 那属于改 JS，违禁，**故未接**。当前 4 格恒按「可用」画。
3. **大按钮同理**：突擊恒置灰、撤退恒高亮。真实运行时撤退在「已撤退 / 战斗结束」后应该变灰，
   现在只有结算态整层压暗兜底，战斗中撤退成功的瞬间不会变灰。
4. **`slot.qi` 是 NaN**（见 §4 末），导致任何技能都过不了 `castBlockReason`。这是既有问题，
   不在本次范围，但会让「技能点击后真的打出伤害」无法演示。
5. 叠层位置同步是「resize/RO + 200ms 轮询」，页眉换行导致的位移最多滞后 200ms（肉眼不可见，
   但不是零延迟）。纯 CSS 做不到，因为缩放比例来自 `main.js` 的 px 写入。
6. f-ui 的三个教训这次都复现了，记在这里免得下次再踩：
   - `WARINFO01/02` 底部 4 行 alpha 只有 **126.3**（min 0），套上去底边直接没有；
   - 九宫切片必须是 `inset + MID + inset`，第一版按 `2*inset` 切，`border-image` 的中间区为
     空，CSS 只画出四个角（`_make.py:39-45` 的 `MID=6` 就是为此）；
   - MENU 空心框主色是 **#725034** 暗青铜，不提亮就等于没画。
