# 215 · 双端口径：Cocos 是正式版，web 是调试台

> 立规日期：2026-11-26（用户指示：「过 web 和 cocos 差异的时候，cocos 是正式版，有一些 web 的调试内容不要当成正式内容也合并过来」）

## 1. 口径（一句话）

**Cocos = 正式版（发版物：原生包 / 小游戏包）。web = 调试台（CDP 取证、fidelity 对拍、逐帧截图、原作比对）。**
差异修复时，只有「游玩行为」需要双端一致；**web 的调试设施一律不往 Cocos 搬**。

## 2. 可以合并的（游玩行为 / 规则 / 数值）

- 内政九项、月推进流水线、经济（金→预备兵）、逐将年令、正月门
- 战斗规则（胜负、技力恢复、站位、拦阻、叫阵顺序）、随机流
- 面板数据源（存档运行时名单）、战后俘虏处置
- 存档字段语义（`save.roster` / `captured` / `acted` / `away` …）

## 3. 不合并的（web 专用调试设施）

| web 侧 | 性质 | Cocos 处理 |
|---|---|---|
| `?taunt=0` / `?from=campaign` / `?seed=` / `?rel=1` / `?loose=1` / `?adv=1` / `?unlimited=1` / `?probe=` | 调试/测试开关 | 不搬；Cocos 只保留**用户可见**的入口（如新建游戏） |
| `window.__sanguo`（`state/world/skipTaunt/...`） | 调试 API | 不搬；Cocos 用 `console.log('[Rxxx] …')` 做诊断 |
| 战斗页「三國群英傳2 · 預覽」开场卡 | 预览卡 | 不搬；Cocos 直接进大地图/内政 |
| `web/*.mjs` 自检、`city_selftest.mjs`、`tools/*probe*` | 取证脚本 | 不搬 |
| `work/**` 的探针与 fidelity 对拍 | 验证设施 | 不搬；Cocos 用 `work/*cocos*/` 自己的 CDP 探针 |
| `-Mode preview` 构建、dev server | 构建/运行方式 | 不搬（原生包走 `tools/build_native.ps1`） |

## 4. 门禁怎么落

1. `work/parity/features.json` 每条加 `"scope": "cocos" | "web-debug" | "both"`；
   `check_parity.mjs` **只对 `scope=cocos` 报 FAIL**，`web-debug` 只记录不判红。
2. 提交前必跑：`node work\check_parity.mjs` + 两道 tsc + 全量测试。
3. 新增功能先写 Cocos 侧（正式版），再考虑 web 是否要跟；**web 先做、Cocos 后补**是本项目反复分叉的根因（F-02/F-03/F-04/F-05/F-07 都是这么来的）。

## 5. 判定口诀

- 「玩家能感知到的」→ 必须双端一致，且**以 Cocos 为准**。
- 「只有调试/取证才用的」→ 留在 web，Cocos 不实现。

## 发布纪律（制作人 2026-11-26 明确指示）

- **微信小游戏包（`tools\build_wechat.ps1` 的任何模式，含 `-Mode upload` 与 `-Slim`）只在制作人明确要求时才做**；未要求时不要构建、不要瘦身、不要上传，也不要「顺手出一版」。
- 原生 APK（`tools\build_native.ps1`）不受此限，验证需要即可出。
- web 调试台与 `work/**` 探针不受此限。
