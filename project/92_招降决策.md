## 2. 候选集怎么来（三路，**不扩成"整城守将"**）

1. `save.captured`（`string[]`，main.js 战斗页写回）→ `from:'captured'`、`predicted:true`：引擎已经掷骰
   判定"招降成功"，玩家点招降就一定入城；
2. `save.executed` → `from:'executed'`、`predicted:false`：引擎判定"拒降后被斩"，招降键置灰，只剩斬首/放走；
3. `opts.atCity ∩ 剧本 kings[].NAME` → `from:'king'`：**君主行，只有"逃 走"，没有任何按钮**。

同名同时出现在两张单里 → **以斩首（`executed`）为准**（一张卡，不做两次处置）。

**为什么不用"被攻陷城的 `garrisonIn(city).officers` 全员"当俘虏列表？**
`main.js:600` 把 B 方建成 `general: {name,str,int,level:5}` 一个人，**没有 officers 字段**——这一战
根本没把整城守将送进战场引擎。面板若凭空把全城守将都当俘虏，等于**改战果、改平衡**（一次攻城抓 10 个将）。
要接"城破全俘"，得先让 `battle.ts/main.js` 把 officers 传进 `resolvePostBattle`（这两个文件本轮禁改，
且属另一处设计），所以本轮**不做**，记在 §10。

## 3. 与 `capture.ts` 的关系：**全部复用，零新增判定**

档位不是本档另起一套规则，而是直接吃 `capture.ts` 的既有实现：

| 用途 | 复用点 |
| --- | --- |
| 档位（可降 / 需再战 / 拒降） | `capture.ts:197 recruitChanceOf(g,state)` —— **纯函数、不掷骰**，返回 `p∈[0,1]`。`p===1 → must`、`0<p<1 → roll`、`p===0 → refuse` |
| 拒降理由原文 | `capture.ts:237 canRecruit()` 的 `reasons[]`（如「忠誠 84（70 < L ≤ 90）：硬門 0x12，必不降」）。**只在 p∈{0,1} 时调**——此刻 canRecruit 必在掷骰前早退，`rng` 传的是**抛错哨兵** `NO_ROLL`，一旦 capture.ts 改坏（提前掷骰）测试立刻炸 |
| 君主门 0x40975E | `capture.ts:150 isKingOf()` 仍在 `resolvePostBattle` 前置拦截：君主永不进 `captures/executed`。面板只是**另外**把君主的名字补一张"逃走"卡（数据来源：剧本 `kings[]`），**没有放宽任何门** |
| 招降落地的数值 | `loyal ≥ 50` 折 `floor(loyal*2/3)` 等由既有 `applyPostBattle → applyCapturesToRoster` 执行，本档不重算 |

**只复刻了两处 capture.ts 没导出的东西**（该文件禁改，且不导出）：
1. `isKingOf` 的判据 → `roster.ts:325 kingsInScenario()`（`data.scenarios[].kings[].NAME`），测试与
   `capture.ts` 交叉锁定；
2. `0x447520` 战败扣忠诚一行 → `statOf()` 里 `loyal = clamp(row.Loyal - (10-constancy)*2, 0, 99)`。
   **这行必须复刻**：引擎是在扣完忠诚之后才判档的，面板若显示表值，会和引擎判定打架
   （例：程昱 67 − 14 = 53 → 硬门 0x13 拒降；不扣则 67 还是拒降，但張遼 88−10=78 → 0x12，
   不扣则 88 → 0x11 —— 门都不一样）。反查 `project/89` 的四个样本（程昱 53 / 華佗 84 / 張遼 78 / 守將 40）
   全部吻合，测试里也钉了这组数。

**为什么不改 `capture.ts` / `battle.ts`**：本轮硬约束禁改；而且**不需要**改——档位计算是纯函数，
理由文案已经带中文原文，君主门也已经在引擎里拦住了。真正的改动只在"玩家怎么选"，
落在 roster.ts（纯逻辑，可测）+ campaign.html（UI）。

## 4. 三档文案与原作口径

`docs/04b2_招降斩首与战后结算.md` 里原作只有三类：**必降 / 掷骰 / 拒降**，没有"需再战"这个档。
本档按任务要求把它显示成「需 再 戰」，含义是"这一战已经掷过骰，判定成功，玩家招降即入城"——
**[推测]** 这是任务用词，不是原作字符串；映射关系：`must=必降（p=1）`、`roll=掷骰成功（0<p<1）`、
`refuse=拒降（p=0，含 0x10/0x11/0x12/0x13 四条硬门）`。

卡片上显示：**姓名 / 武 / 智 / 忠誠（扣过战败惩罚的值）/ 義理（CONSTANCY）/ 档位徽章 / 一行理由**。
`[新设计]` 中间档额外显示预估成功率百分比（`project/01 §4.7` 要数字、`project/02 §408` 要四档文字，
两者有张力）；本档取"数字 + 档位徽章"，因为逐将面板一张卡信息量小、玩家要做的是取舍而不是读长文。

## 5. 落库语义（`applySurrender`，roster.ts:509）

| 决策 | 结果 |
| --- | --- |
| 招 降（`recruitable`） | 走既有 `applyPostBattle → applyCapturesToRoster`：进 `save.roster[回城]`，并从别城同名副本摘掉（一人不可能在两城） |
| 斬 首 | 走既有 `removeFromPools`：从**所有城**名单删除 + `roster._moved[name]='陣亡'`（`city_model.rosterOf/wildPool` 之后都查不到 → 永不再被搜索/招降） |
| 逃 走 / 放 走 | 什么都不做（原作 status=2） |
| 君主（任何按钮） | 一律 `escaped`，**绝不出池、绝不动名单**（`0x40975E`） |
| 拒降档硬塞 recruit | `rejected` + 按放走处理（防绕硬门），不进池 |
| 未决策 | 保持待决：不落库、不清名单、下次重进还弹 |
| 我方被俘（`save.captured` 里混进自家将） | 面板前就剔掉 + 战报一行「（我方）X 被敵軍俘去，本城名單不變」——**自己人不该被自己斩首**（`project/89` 的夏侯惇案例） |

**幂等/不重复结算**：`finishSurrender` 把**所有已决策名字**从 `save.captured / save.executed` 摘掉；
`applyCapturesToRoster` 本身也是幂等 push（已在名单里就不再加）。所以"重进 → 再落一次库"是空操作，
测试里钉了「二次结算不重复」。

  标题「抓 到 敵 將」、副标「逐將詢問：招降的進 X 武將池，斬首的出池永不復活」；

- 底部批量：「剩餘全部招降」（能降的降、降不了的放走、君主逃走）/「剩餘全部斬首」（全斩、君主仍逃走），

  就能把待决面板顶掉、俘虜永远悬着。面板必须决策完才回大地图（`project/01 §4.7` 也是"遮罩点击无效"）。

## 7. 踩到的坑（给后来者）

**`?sur=` 探针不能放在启动流程中间（:1174）**：探针要调 `startNewGame()` → `render()` → `drawMap()`
→ `syncBg()`，而 `USE_BG` 是文件后半段的 `const`，模块还没求值到那里 → 实测
`ReferenceError: Cannot access 'USE_BG' before initialization`，整段结算是静默不执行的（面板不弹、无报错弹窗）。
所以探针和"补弹待决名单"都放在**文件最末尾**（`campaign.html:3937`），此时所有声明都已就绪。

## 8. 验收参数（本档既有 `?saves=1 / ?probe=1 / ?adv=N` 风格，不带即完全不影响正常玩法）

| 参数 | 作用 |
| --- | --- |
| `?sur=名1,名2` | 种 `save.captured`（模拟战斗页"预判招降成功"） |
| `?surdead=名` | 种 `save.executed`（模拟"拒降后被斩"） |
| `?surking=名` | 往"该城守将"里塞一个剧本君主名 → 出"逃走"卡 |
| `?surstart=君主名` `&surscen=N` | 全新 profile 也真开一局（走 `startNewGame`，和玩家点选一样） |
| `?surall=recruit\|kill` | 面板一开自动按批量键 |
| `?surafter=1` | 处理完自动停在"这城的武将池"（`rosterOf` 列表，降将高亮标「降 將」） |

最后一项是 `[新设计]`：`city.html` 的武将名单只藏在"移动/任命"下拉里（`:841/:863`），
`势力明细`走的是 `garrison.json` 守将表（`officersByCityAll()`，**不含**招降入池的将），
两者都拍不出"招降后这城有谁"。所以复用 `#forceSheet` 的壳，按 `city_model.rosterOf()`（`save.roster` + `_moved`
的唯一真源）列一遍该城武将，**只在 `?surafter=1` 下触发**，正常流程一行都不跑。

## 10. 没做到 / 遗留

1. **"城破全俘"**：本战只把 1 个敌将送进战场（`main.js:600` B 方无 `officers`），所以面板一次最多几行。
   要一次抓整城守将，得改 `battle.ts/main.js` 传 officers（本轮禁改），属另一处设计。
2. **"釋 放"按钮**：原作三选一（招降/斩首/释放，`0x491DF4`），本轮按任务要求只做两键，放走通过
   "批量全招降里降不了的将放走" + 君主逃走覆盖；单独的释放键留给下一轮（`project/31` 第 50 条仍标部分）。
3. **探针种的名单不落存档**：`?sur=` 在模块末尾才跑，启动流程的 autosave 已经过了，所以刷新后
   （不带参数）不会再弹。真实战斗流程不受影响——那时 `save.captured` 是 main.js 先写进 localStorage 的，
   boot 的 autosave 会把它带走，重进靠文件末尾那句"还有待决名单就补弹"接上。
4. **成功率只在中间档显示**（`[新设计]`），必降/拒降档只给档位与理由，不给 `0%/100%` 这种废话数字。
5. 面板宽度跟随 `.sheet`（`left/right:70px`），没有做成 `project/01 §4.7` 的 600×760 固定弹窗；
   竖屏 750 宽下按钮 98px 两列，实测点按够大，暂不改。
