# 151 战斗指令界面（R151 / g19）

> 本轮范围：**只做视图层的两层指令界面**（6 大按钮 + 随阵形变的 6 条部队指令子菜单），
> 内核与数据全部复用 g15 的 `game/src/core/army_cmd.ts`（33 组 × 6 条、`canUseArmyCmd`、
> `applyArmyCmd`、`applyArmyCmdKind`），视图层**不抄任何一条指令表**。
>
> 改动文件只有两个 + 一个新测试：
> - `game/src/view/battleView.ts`（1928 → 2176 行，+248：几何 / 语义 / 绘制 / 命中）
> - `game/web/index.html`（483 → 533 行，+50：CSS 两套变体 + 6 个 `.cmd6` 装饰框 + `data-slots`/`data-menu` 同步 + 截图钩子）
> - `game/tests/battle_cmd_ui.test.ts`（新建 466 行，**25 条全绿**）
>

> `game/cocos/**`、`game/src/view/layout.ts`（**一个常量都没动**）。

## 3. 子菜单交互

| 动作 | 结果 |
|------|------|
| 点第 2 颗「部隊指令」（或键 `S`） | `toggleArmyMenu()` → 面板展开／收起 |
| 面板展开时点某一行 | 命中 `{ type:'armyCmd', slot, label, kind, canUse, reason }`；`canUse=false` 的行**照样命中**（和突擊/撤退同一套：置灰 ≠ 不可点，由 `main.js` 自己拒） |
| 点面板内空白 | 命中 `{ type:'armyMenu' }`（**吞掉**，不落到战场） |
| 点面板外任意处 | 先 `setArmyMenuOpen(false)`，然后**这一次点击继续走正常命中**（点技能格就放技、点战场就是 field） |
| 展开时点第 2 颗钮 | 收起（按钮露在面板外，见 §2.3） |
| `Escape` | 本轮没接（`main.js` 现在的 Escape 只清 `selectedSkill`；建议 §6 接线时顺手加一行 `setArmyMenuOpen(false)`） |

置灰与文案：

- 可用性一律问 `canUseArmyCmd(world,'A',slot)`；不可用整行 `COLORS.textFaint` +
  右侧写 reason（`戰鬥已結束` / `已無士兵` / `當前狀態不可下令` / `我軍已在撤退` …）。
- 已下过令的槽（`armyOrderOf().slots[slot] != null`）画金框 + 右侧写 `已下令`（截图 04）。
- 每行左侧有 `1..6` 的槽号（**不是键位**，键位是 `Shift+1..6`，`main.js:1334` 已实装）。

## 4. 与 R82 叠层的取舍

R82 留了 4 个静态 `.slot` 窗格（`:1122`，92×92，`slot.png`）与一条 `sep.top`
（`:1106`，108..732）。8 格技能把第一行提到 **y=1100**，与 `sep.top(1106..1118)` 必然重叠；
右列又要放 6 大按钮。三处冲突用 `#battleui` 的**两套数据属性**解决：

```css
/* 8 格：旧窗格与上分隔带整体让位（4 格时这两条不匹配，像素级维持原样） */
#battleui[data-slots="8"] > i.slot,
#battleui[data-slots="8"] > i.sep.top { display: none; }

/* 6 钮列接管右列：分隔带缩短、突擊/撤退框搬到左列 */
#battleui[data-cmdbar="6"] > i.sep.top { width: 400px; }   /* 108..508 */
#battleui[data-cmdbar="6"] > i.sep.bot { width: 470px; }
#battleui[data-cmdbar="6"] > i.cmd.aslt { left: 16px; top: 1126px; width: 92px; height: 88px; }
#battleui[data-cmdbar="6"] > i.cmd.retr { left: 16px; top: 1216px; width: 92px; height: 88px; }

/* 子菜单展开时，面板盖住右列下两行 → 那 4 个角括号一起藏 */
#battleui[data-menu="1"] > i.cmd6.c2,
#battleui[data-menu="1"] > i.cmd6.c3,
#battleui[data-menu="1"] > i.cmd6.c4,
#battleui[data-menu="1"] > i.cmd6.c5 { display: none; }
```

新增的 6 个装饰框：`<i class="cmd6 c0..c5">`，`104×88`，`border-image: url(assets/battleui/cmd_off.png)
14/14px/0 stretch`，位置 = 按钮矩形 `-2 / +4`（`c0 522,1028 / c1 630,1028 / c2 522,1122 /
c3 630,1122 / c4 522,1216 / c5 630,1216`）—— 和 R82 的 `.cmd` 同样的"图元框比命中框大 2px"
手感，`opacity:.9` + `brightness(1.45)` 让 `cmd_off.png` 的暗金接近技能格的亮度。

`data-cmdbar="6"` 直接写死在 `<div id="battleui">` 上（本轮没有 4 钮版本）；
`data-slots` / `data-menu` 由页面里那个已有的 200ms 定时器同步：
`data-slots = (state.skills.length > 4 ? '8' : '4')`、`data-menu = armyMenuOpen() ? '1' : '0'`
（视图模块 `import('../dist/view/battleView.js')` 只 import 一次，之后每 tick 读一个布尔）。

**取舍的代价（明写在报告里，别当没发生）**：

1. 8 格时旧窗格全藏 → 8 格技能只有 canvas 画的框，没有 `slot.png` 的纹理。板式一致、亮度接近，
   但近看能分出差别；挂回 8 个 `slot.png` 需要把 `.s*.s*` 的位置按 88×56 重排（本轮不做）。
2. 面板展开会盖住右列下两行（武將技除外）→ 展开期间点不到「武將出擊 / 主將後退 / 全軍撤退」，
   必须先收起。这是「就地展开、不遮战场」的代价：控制台没有第二块 228×216 的空地。
   （原作是把第二层画在**整个屏幕**上的，本作竖屏 750×1334 做不到。）
3. `data-menu` 有 200ms 级的延迟（截图 03/04 都是 4.5s 后拍的，看不出）。真机上由 `main.js`
   在同一次点击里同步 set 才是零延迟（§6 的 diff 里可选）。

## 5. 命中契约（`hitTest` 的对外形状）

新增三支，**全部附带可用性与文案**，`main.js` 不用再问一次 core：

```ts
export type Hit =
  | { type: 'start' } | { type: 'restart' }
  | { type: 'skill'; index: number; seq: number; canCast: boolean; reason: string | null }
  | { type: 'assault' } | { type: 'retreat' }                 // 语义不变，矩形搬到 CHIP_*
  | { type: 'field'; gx: number; gy: number; worldX: number; worldY: number }
  // ↓ 本轮新增
  | { type: 'cmd6';    btn: number; kind: Cmd6Kind; label: string; canUse: boolean; reason: string | null }
  | { type: 'armyMenu' }                                       // 面板内空白：吞掉
  | { type: 'armyCmd'; slot: number; label: string; kind: ArmyCmdKind; canUse: boolean; reason: string | null };
```

`hitTest` 判定顺序（从上到下，先中先返回）：

1. `mode === 'ready'` → `start`；`settled` → `restart`（未动）
2. **面板展开态**：`armyCmdRects()` 6 行 → `armyCmd`；`contains(armyMenuRect())` → `armyMenu`；
   否则 `setArmyMenuOpen(false)` 并**继续往下**（`closedByThisClick`）
3. 技能格 `skillSlotRects()`（未动；幽灵格仍返回 `null`）
4. `cmd6Rects()` 6 钮 → `{ type:'cmd6' }`；**点第 2 颗且不是"刚被收起"→ `toggleArmyMenu()`**
5. `CHIP_ASSAULT` → `assault`；`CHIP_RETREAT` → `retreat`
6. `screenToCell` → `field`

兼容红线（`hud_slots.test.ts` 16 条 + 既有 `main.js`）：

- `skill` / `assault` / `retreat` / `field` / `start` / `restart` 名称与语义**不许动**；
- **`x410..498 / y1124..1212`（3 个技能时的幽灵第 4 格）必须仍是 `null`** ——
  新命中区全都避开了它（chips `x ≤ 106`、6 钮 `x ≥ 524`、面板 `x ≥ 512`）；
- `assault` 只由 `CHIP_ASSAULT` 返回、`retreat` 只由 `CHIP_RETREAT` 返回。

`ViewOptions` 新增一个可选键：`armyMenu?: boolean`（省略时读模块状态 `armyMenuOpen()`）。
`main.js` 的 `viewOptions()` 一行都不用改 —— 拿到 `undefined` 就是"用真实状态"。

`buildFrame` 内新增的绘制出口（都在 `drawConsole` 末尾）：

```
drawCmd6Bar(out, world, opts, menuOpen)   // 6 大按钮（填充/键位/正题/小字/置灰）
drawCommandButton(out, CHIP_ASSAULT, …)   // 原来的两颗，只换矩形
drawCommandButton(out, CHIP_RETREAT, …)
if (menuOpen) drawArmyMenu(out, world)    // 面板 + 6 行（整层最后画，压住右列下两行）
```

## 9. `[推测]` 与本轮未做

- `[推测]` **键位 `A/S/D/F/G/H`**：原作是光标 + 确认键，PC 版没有字母快捷键，这 6 个字母是本作自定
  （避开技能格 `1-8` 与 `Shift+1..6`）。要改只改 `cmd6Defs()` 的 `key` 字段。
- `[推测]` 第 4 颗「主將待機／主將後退」的翻转方向：按 `ARMY_BTN.lordOrder` 位判定
  （置位 = 已下後退令 → 按钮显示「主將待機」）。原作是 `[0x4a8ae0] & 0x10`，g15 的位定义一致，
  但"置位对应哪一颗"是 g19 按 `applyArmyCmdKind` 的清位/置位方向推的。
- `[推测]` 子菜单面板的落点（右列 512..740 / 1116..1332）：原作第二层是**整屏**翻页，竖屏没有
  第二块空地，只能就地覆盖 —— 代价见 §4 第 2 条。
- `[推测]` 6 钮的可用性判据（`cmd6Usable`）：`已下令護衛` / `已出擊` / `已無士兵` / `主將陣亡` /
  `無武將技` 都是本作自定，core 只提供 `canUseArmyCmd`（第二层）。若 g15 之后给第一层也加
  `canUseArmyCmdKind()`，把这些分支搬过去即可（视图层只有一个出口）。
- **没做**：`武將技`（第 3 颗）现在只是"把视线引到技能格"并写一句提示，没有真的切页/翻页动画；
  原作这一颗会切到技能列表页。技能格本身已经在同一块地方，切页收益为零，所以只做了提示。
- **没做**：`Escape` 收起子菜单（`main.js` 不归我改，§3 末行给了一行建议）。
- **没做**：面板的"下过令之后仍可重下"（`canUseArmyCmd` 对已下令槽不置灰，只有 `flags & mask`
  才灰）—— 这是 core 的语义，视图层照搬，没有额外加限制。
