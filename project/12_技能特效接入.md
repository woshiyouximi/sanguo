## 1. 结论
- 818 帧 / 40 个目录全量导出（源 `extract/pak/SHAPE/MAGIC`）。`000` 是公共件；根目录 `M013WINGA6.SHP` 是怪物翅膀，跳过（否则 819）。
- 110 个武将技里 **103 个**能用原作序列帧播，7 个伏兵系没有任何素材（§6）→ 退回虚线圈，不报错。
- 体积：逐帧 PNG 4,069,238 B（3.88 MiB）超过 3 MB 阈值 → 落成 **40 张横向图集 3,735,590 B（3.56 MiB）+ index.json 25,758 B（含 seqDirs/rot，共 41 个文件 3,761,348 B = 3.59 MiB）**，比逐帧**小 8.2%**，请求数从 819 降到 41。
- 朝向：原作是**横版**（`docs/04b1_阵形站位表.md:38`：战场 6816×1008 = 71×96 横向卷屏，推进 = 屏幕横向），竖版战场推进方向变成纵向，所以整帧要**绕帧内热点转 90°**：A 方 +90°、B 方 −90°。汉字/竖柱/立物/坐骑这 12 个目录转了会坏，保持 0°（§4.5）。
- 运镜：`core` 一放技就把 `Fx` 推进 `world.fx`，`main.js` 跟着它把镜头摇到特效那一格，跟 ≈1 s（`Fx.ttl=30` tick）再交还自动跟随（§4.5）。

## 2. 导出流程
```bash
python tools/export_magic_fx.py                # auto：先出 PNG 量体积，超阈值自动重出图集（本次走这条）
python tools/export_magic_fx.py --mode atlas   # 强制图集（复现本次产物用这个）；--dirs mapped 只导 map 用到的目录
```
- 解码直接用现成的 `tools/sango_shp.py`（RGB565 + 行 run，色键在头部 `+0x10`），脚本不重复实现解析。
- **保持原尺寸、原 RGB**：不放大、不调色；色键像素写 alpha=0，所以 alpha 只有 0/255 两档。缩放交给渲染时按 `fxScale` 做。
- 逐帧热点取 SHP 头 `+0x1C/+0x20`（`load()` 的 `offx/offy`），**可能为负**（012 的 offx=-30，014 的 ay 有 -5/-16），元数据按帧存，不按目录取平均。
- 播放序 = 文件名自然序（`f000.SHP`…），不用字典序，避免 `10` 排在 `2` 前面。

## 3. 图集结构（`game/web/assets/fx/index.json`）
```json
{ "version":1, "mode":"atlas", "tickLife":30, "dirCount":40, "bytes":3735590,
  "dirs": { "001": { "frames":10, "w":118, "h":122, "anchor":[58,60], "sheet":"atlas_001.png",
            "sheetW":1174, "sheetH":122, "list": [[0,0,61,65,30,32],[118,0,71,79,35,39]] } },
  "map": { "50":"001", "104":"004" } }
```
- `list` 每项 `[sx, sy, sw, sh, ax, ay]`：图集矩形 + 帧内热点（以帧左上角为原点，可负）。
- 打包用 **shelf packing**：按高度降序逐行铺，宽上限 2048，帧间留 2 px 透明缝（投影后的坐标带小数，双线性采样会吃到隔壁帧）。旧版按「目录内最大帧」划等大格子，填充率只有 19.7%（003 目录仅 6%）；改 shelf 后图集总面积 36.63 → **12.36 MPix**。
- `dirs[*].w/h/anchor` 取面积最大帧，只作目录概览；渲染**一律用 `list` 的逐帧值**。
- `map` 只收有现存目录的技：优先 `fx_dir_primary`，不存在再退到 `fx_dir` 里第一个存在的目录。

## 4. 渲染接入
改动集中在两处（core 未动）：

| 位置 | 改动 |
|---|---|
| `battleView.ts` · `SpriteCmd` | 加 `comp?: 'lighter'`、`rot?`、`ox?`、`oy?` |
| `battleView.ts` · `ViewOptions`/`Fx*` | `ViewOptions.fx?`（可空）、`FxFrame{ x,y,w,h,ax,ay }`、`FxDir{ img, frames, rot? }`、`FxAtlas{ map,dirs,seqDirs?,life?,scale? }` |
| `battleView.ts` · `buildFrame`/`drawFx()` | `actors` 之后才画 `fx`（原来在兵下面会被挡住）；多段/单目录都画序列帧（含 `rot`），没目录走原虚线圈分支 |
| `battleView.ts` · `execute()` | `globalCompositeOperation = c.comp ?? 'source-over'`；`rot` 时 `translate+rotate` 绕锚点画（都在 save/restore 内） |
| `main.js` · `loadFxIndex()`/`ensureFxDir()` | 拉 `assets/fx/index.json` 并按需加载单张图集（`mode !== 'atlas'` 不接；读 `?fxrot=` 覆盖） |
| `main.js` · `frame()` | 施法运镜：新 fx → `fxFocus/fxFocusT`，`camX` 平滑摇过去（`?follow=0` 关） |
| `main.js` · `boot()` | 调试参数 `?cast=<seq>,<x>,<y>[,<age>]`、`?debug=1`（状态条带 camX） |

渲染参数：

| 项 | 值 | 说明 |
|---|---|---|
| 帧号 | `t = (life−ttl)/life`；单目录 `idx = floor(t·n)`，分段 `idx = floor((t−from)/(to−from)·n段)`；`fxScale = 0.8` | `life = fx.life ?? atlas.tickLife`（逐技时长，§4.6）；`n`=该段目录帧数 → 每帧 ≈ `life/n` tick；原作 1 格 96 原画 px → 屏 71.4 px，0.8 和 66 px 的兵同量级 |
| 段选择 | `seqDirs[seq]` 里 `t ∈ [from,to)` 的段**全部**绘制；没有就退回 `map[seq]` 整段均分 | 段目录还没加载好先借任一已加载段，全部没加载才走虚线圈 —— 切段不闪白 |
| 混合/淡出 | `lighter`（加色）；`alpha = min(1, ttl/6)` | 原作特效是发光叠加；最后 6 tick 线性淡出，有 `comp` 时一定先 save/restore |
| 朝向 | `rot = dirs[dir].rot × (side==='B' ? -1 : 1)` | 默认 +90°（A）/ −90°（B）；12 个目录 0°（§4.5） |
| 锚点 | 旋转前先把热点当原点：`ox=-ax*s, oy=-ay*s`，再 `translate(p)+rotate(rot)` | 热点恒落在 `p = project(camX, fx.x, fx.y)`；不转时等价于旧的「底部中心」反推 |
| 技名 | 旋转后包围盒上方 10 px | 原作没有这行字，是为截图/排查可读性加的，跟兜底圈同名同色 |
| 缺素材 | 虚线圈（半径/虚线/颜色全同接入前） | `map` 没这条、图集没加载完、加载失败都走这里，**不抛错** |

### 4.5 朝向修正与施法运镜（v0.2 新增）

**为什么转**：原作战场 6816×1008，横向 71 列 × 96 px 是推进方向（横向卷屏），所以 MAGIC 帧都是"朝左推进"画的——`004 衝車` 撞头朝左、轮子在底，`001 半月斬` 第 7-10 帧是竖月牙拖着向右的尾迹。竖版重制把推进方向改成纵向（`sx = y·LANE_PX, sy = 550 + (x−camX)·ROW_PX`），帧不转就会"横着开、横着劈"。

**怎么转**：`SpriteCmd` 加 `rot/ox/oy`，`execute()` 在 `save/restore` 内 `translate(x,y); rotate(rot); drawImage(..., ox, oy, w, h)`；`rot/ox/oy` 由 `drawFx` 按 `d.dir.rot` 现算，热点仍是旋转中心，所以落格不偏。

12 个目录 rot=0：汉字 `013 傷`/`014 亂`、竖柱 `009/016/026/035`、立物 `025/034/039/040/041`、坐骑 `012`（转了就"人躺下"）；其余 28 个 +90°（A）/−90°（B）。表在 `tools/export_magic_fx.py` 的 `ROT_UPRIGHT`；整体强制 `?fxrot=90|0` 对照截图用。

**运镜**：`main.js` 每帧扫 `world.fx`（`WeakSet` 判新，core 复用对象只改 `ttl`），新 fx 且离画面 >1.2 格时 `fxFocus=fx.x, fxFocusT=1.0s`；跟随期间 `camX` 用 `dt*7` 的插值收敛到 `fx.x`，到点后交还 `camera(world)` 的常规跟随。`?follow=0` 关掉（对照用）；`?debug=1` 把 `camX=.. focus=.. t=..` 写进状态条，便于 headless 核对。另：`heal` 型的 `fx.x` 被 core 填成了 HP（`battle.ts:463`），视图侧只能特判回主将坐标；这是 core 的已知怪异点，本轮不改。

### 4.6 多目录分段 + 逐技时长（v0.3 新增）

**分段**：29 个技在原作里不止一个目录。`magic_so.dis.txt` 里效果函数开头总是 `PUSHS "magic\000\*"` + 本目录再 `WAIT 15/20`，PUSHS **不代表先后**；真正的先后只在 `Create*` 子函数里（`PUSHI <ThingID>` + `SYSCALL 0x011` + `WAIT n`），所以 `seqDirs` 按每一步 spawn 的对象序切（证据见 `docs/05c` §4.6/§4.7）：

| 类型 | 技 | 切法 |
|---|---|---|
| 接续 3 个 | `44 天地無用` 032→027→018、`110 鬼哭神號` 012→025→031、`104 神鬼亂舞` 004→014 | 按各目录帧数比例：`44`=`0/.174/.5/1`、`110`=`0/.4/.5/1`、`104`=`0/.154/1`（004 只演前 15%，其余留给收尾的 WAVE，即 `CreateLastAttack`） |
| 叠加 26 个 | `49 刀劍亂` 036 剑+026 水柱、`95 劍輪舞` 038(112 帧)+028 石头、`12/27/40` 031+041… | `to == from` 表示与载体同窗并发，每段各走自己的帧序；`from/to` 是 0..1 归一化时间片，`--index-only` 只重算它、不重出图（保留 `dirs[*].rot`） |

**时长**：`MAGIC` 没有时长字段，只有帧数。`Fx` 加 `life`，`cast(..., ttl)` 不传仍是 30（向后兼容），`fxTtlOf(data,seq) = clamp(round(fx_frames × 2.2), 24, 132)`：`004` 4 帧 → 57 tick 里每帧 2.2（不再一帧停 7.5），`038` 112 帧 → 132 tick（1.18/帧，112 帧全出得来），`46` 8 帧 → 24（下限），伏兵技 `fx_frames=0` → 30。AI 施放与 `?cast=` 都走 `fxTtlOf`。

## 7. 已知缺陷
1. **7 个伏兵技零素材**（§6）。原作这类"補兵"很可能本来就是 FORCE 直接出兵、没有独立 SHP，待用原版录像确认。
2. **多目录技的段边界是经验值**：`seqDirs` 已接（fx2 的 `SEQUENTIAL`/`OVERLAY` 表 + `drawFx` 按 `elapsed` 切段），但每段起止比例还没逐技对原作录像校准；早期只播 primary 的问题因此已解决。
3. **30 tick 硬上限（已修）**：`cast(ttl)` + `fxTtlOf` 解除，4 帧的 `004` 现在 57 tick、112 帧的 `038` 132 tick；剩下的是 `2.2 tick/帧` 这个**全局常数**还没逐目录实测（§9.3）。
4. **公共件 000（32 帧）没人用**：它很可能是所有技共用的收尾闪光，现在完全没接。
5. **没有真的分侧镜像**：现在只靠 ±90° 反转推进方向，图形本身没左右翻（原作 B 方多半是镜像），冲车/刀光的旗帜、刃口左右会不一样。
6. **转 90° 后地物会"翻个身"**：`004 衝車` 转完是轮子朝左、撞头朝上（竖版俯视），比原作的侧视观感生硬；这类"地面载具"如果在意，可单独把该目录的 `rot` 设 0，让它横着开。
7. **没有音效**（原作有语音/音效，不在本轮范围）；特效也不随镜头缩放进深（`fxScale` 固定 0.8），大帧目录（016 的 100×424 圣光）在高格位会接近画面边缘。

## 9. 还差什么才能让 110 个技全部有特效
1. **7 个伏兵技**：先查原作有没有特效。没有 → 在 `index.json` 加 `kind:"summon"`，用「地面光圈 + FORCE 出兵」表现，不走帧；有 → 去别的 PAK/SHAPE 分支找 `002`/`024`（当前解包集确实没有）。
2. **多目录串联（29 个技，已接、待校准）**：`seqDirs` 29 技 / 60 段已上线（接续 3：`44/104/110`；叠加 26），切点按各目录帧数比例；差的是逐技对原作录像校准边界——尤其 `104` 原文是 004/014 **交替** spawn，被压成两段是近似。
3. **每目录帧率表**：现在统一 `2.2 tick/帧`（`FX_TICK_PER_FRAME`）；要准得拿原版录像逐帧数，尤其 4 帧的 `004`、112 帧的 `038`、3 帧的 `025`。
4. **公共件 000 的用途**：确认是不是命中/收尾闪光，然后作为第二层叠加挂在每段末尾。
5. **演出层**：受击闪白、屏幕震动需要 core 暴露命中点/伤害列表，目前 `Fx` 只有一个中心点；分侧镜像建议在 `drawFx` 里加 `flipX`（`rot` 已在，翻一下坐标即可）。
