## 2. core_smoke.test.ts（72 条，2.74 s）

**目的**：把"验收靠嘴"变成"验收靠跑"——任何 core 改动把战斗跑崩，5 秒内失败。

矩阵：`terrain ∈ 0..11` × `scenarios[0,1,2]` × `seed ∈ {1,2}` = 72 世界，每世界 `createWorld()` + 最多 300 tick。
参数：双方各 24 兵（性能与覆盖面平衡：24 兵时单世界 31–38 ms；100 兵要 456 ms，72 世界会超 20 s），主将取剧本君主（`scenario.kings[0]/[1].NAME`，STR 80 / INT 60 / Lv1），`month = seed===1 ? 7 : 1`（让雨/雪两条天气分支都进矩阵）。

每世界断言：

1. `world.units.length > 0`、主将恰好 2 个；
2. `world.terrain === i`，`world.weather === weatherOf(month, terrain)` 且是 0..3 的整数；
3. 300 tick 内不抛异常；所有单位 `x/y/prevX/prevY` 有限，`y ∈ [−1, GRID_H]`、`x ∈ [−8, GRID_W+8]`（撤退/离场留余量）；
4. 若 `over`：`endReason ∈ {'troops','general','retreat'}`、`winner ∈ {'A','B','draw'}`；否则 `endReason/winner === null` 且场上仍有单位；
5. `stats.attacks > 0` 且 `stats.hits > 0`（真的接战了，不是空跑）；
6. 统计恒等式：`killsInf + killsCav === B.start − B.aliveCount`，B 侧同式。

72 个世界全部满足 5/6，恒等式无一例外——这条同时守住了"撤退单位被 cull 后不能算进击杀"的口径。

## 3. retreat.test.ts（16 条，146 ms）

对应任务书第 2 项，四个 `describe`：

**① requestRetreat 下令即全体转退却**
- 存活单位全部 `flee === true`（用 `assert.ok(!u.flee)` 而非 `=== false`，因为 `Unit.flee` 是可选的）；
- `world.status[side] === 2`、`world.fled[side] === true`、对面单位一个都不变；
- 重复下令返回 `false`（幂等）；两侧可以同时下令；
- `over` 之后再下令返回 `false`，且 `step` 是 no-op（tick / units 不变）。

**② 撤退离场：走出场地才算走，且不计阵亡**
- B 全军撤离 → 跑 ≤4000 tick 后 `over`、`endReason === 'retreat'`、`winner === 'A'`、`status.B === 2`；
- B 侧单位**全部**从 `units[]` 移除（含主将单位——主将也会走出去并被 `cullFled` 摘除）；
- 双方 `killsInf/killsCav` 全为 0：撤退不是阵亡，不记击杀、不进战功；
- A 侧镜像对称（winner B、`status.A === 2`）；
- `cullFled` 边界用"差一格"钉死：A 侧 `x = GRID_W + 4 − 0.135 − 1e-6` 留在场、`+1e-3` 摘除；B 侧 `x = −4 + 0.135 + 1e-3` 留在场、`−1e-3` 摘除（用 `units.includes(unit)` 判同一对象）。

**③ 撤退移动**
- 撤退者每 tick 位移恒为 `−MOVE_PER_TICK × RETREAT_SPEED = −0.135`（分离力不推撤退单位），且该 tick 不发起攻击（`attacksB === 0`）；
- `y` 仍夹在 `[0.2, GRID_H − 1.2]`，不会跑出竖屏。

**④ maybeRetreat：AI 兵力劣势自动撤退**

- `aiRetreat:false` 不触发（开关优先）；
- **`aiRetreat:true` 但该侧不在 `aiSides` 时不触发**——源码要求两个开关同时开，任务书漏写了 `aiSides`，测试里按源码钉死并在注释里说明；

## 4. weather.test.ts（17 条，1.56 s）

对应任务书第 3 项：

**① 生产函数（12 地形 × 12 月全表扫）**
- 雨：夏季 6–8 月 × 湿地形 `{船上 3, 草原 4, 平原 5, 山地 6, 森林 7}`；
- 雪：雪原 8 无视季节；冬天 12/1/2 除沙漠 9 外一律下雪（优先级高于雨/雾）；
- 雾：`{山地 6, 森林 7, 關卡 10, 長城 11}` 在非夏非冬（春秋）；
- 晴：城 0/1/2 与沙漠 9 的春秋、以及所有地形夏天无雨分支；
- 月份归一：13→1、0→12、NaN→1；`createWorld` 不传 `month` 时天气默认 0；
- `WEATHER_NAME` 对齐 `晴/雨/雪/雾`。

**② 数值契约**
- `normalizeWeather`：2.4→2、2.6→3、3.9→0、4/−1/NaN/Infinity/`'2'`→0（特意避开 `-0.4`：源码对它返回 `-0`，`assert.equal(-0, 0)` 在严格模式下会失败）；
- `weatherHitMod`：晴 0、雨 −10、雪 −15、雾 −20（1.4 取整后按雨算）；
- `createWorld` 对非法 `weather` 归一（9/−3/NaN→0、2.6→3）。

**③ 天气接进 hitChance 且只加常数**
四对位（兵→兵 220 / 将→兵 190 / 兵→将 134 / 将→将 150）在 0..3 四档天气下的差值**精确等于** `weatherHitMod`，且严格单调 `晴 > 雨 > 雪 > 雾`。

**④ 可复现 / 不碰随机流**
- 同 seed 不同天气：`world.rng()` 前 20 个值完全一致（天气只做加法，不消耗随机数）；
- 同 seed 不同天气：第一 tick（无接战）后世界状态除 `weather` 字段外逐字段相同（比较前把 `weather` 抹平）；
- 同 seed 同天气连跑 200 tick 逐字段一致；换 seed 会分叉（证明比较本身有效，不是恒真）；
- `month` 推导的天气 === 显式传入（两侧都传 `terrain:6`，否则地形加成不同会污染比较）；
- 聚合端到端：8 seed × 24v24 × 300 tick，命中总数 晴 192 > 雨 175 > 雪 169 > 雾 163（只断言 `>`，不锁具体数字）。

## 6. audio_bus.test.ts（15 条，241 ms）

对应任务书第 5 项。**只做 sink 契约，不重复 `smartscript_audio.test.ts` 的 MAGIC.SO 端到端序列。**

**① 一次 emit = 恰好一次回调**
- `setAudioSink(fake)` 后 `emitSfx('hit')` → sink 只收到 1 次，名字/音量/source/raw 都对；
- **151 次 `emitSfx` → sink 恰好 151 次（不是 302）**——这是 c-audio 修过的双发 bug 的直接回归；
- 连续 emit 不同名字顺序一一对应；换 sink 后旧 sink 不再收到；注销后不抛、事件仍记账；sink 抛异常被吞掉。

**② 名字归一化**
- `normalizeSfxName('m016a') === 'm016snd01'`（任务书锚点）；`' M016A '` → 同；`HIT01 → hit01`；空/纯空白/undefined → `''`；
- 转发的是归一化后的键，但事件里的 `raw` 保留脚本原样；
- 空名不转发、返回 `null`、`dropped` 计数 +1。

**③ 计数**
- `stats`：sfx 2 / magic 2 / flash 1 / brightness 1 / total 6、`byName {hit01:2}`、events 5；
- `emitMagic` dir 只留数字、补零 3 位、超长截末 3 位（`'016'/'007'/'123'/'567'/'000'`）；
- `emitFlash` 夹 0..1；`emitBrightness` 夹 0..16 且不进 `events`；
- `volume255`：255→1、0→0、128→128/255、255/1→1、0.5/−3→0、NaN→1；
- `resetAudioBus` 清空事件/sink/计数/序号（seq 从 1）。

**④ 战场路径不转发 sink（双播根因）**
- 40v40 seed 3 跑 300 tick：`battleAudioEvents` 产出大量事件，事件名 ⊆ `{hit01,hit02,defense,death,death3,horse02,yell01..04}`，但 fake sink **收到 0 次**（`battleAudioEvents` 内部走 `emitSfxInternal(..., false)`，播放交给 web 侧 `tickBattleSfx`）；随后显式 `emitSfx` 能收到 1 次，证明 sink 本身是接好的。

## 9. 疑似 bug（未修）

### 9.1 `garrison.levelFromExp` 在 98/99 级边界与 `battle.levelFromExp` 不一致（真 bug，当前不可达）

- 位置：`F:\sanguo\game\src\core\garrison.ts:122-128`（循环 `for (let i = 0; i < 99; i++)`）；对照 `F:\sanguo\game\src\core\battle.ts:1325-1329`。
- 最小复现：

```ts
import { levelFromExp as battleLevel } from '../src/core/battle.ts';
import { levelFromExp as garrisonLevel } from '../src/core/garrison.ts';
const exp = 650000;                 // ∈ [expToReach(98)=649512, expToReach(99)=662921)
battleLevel(exp);                   // 98
garrisonLevel(exp);                 // 99  ← 不一致
```

- 期望：两套实现同解（`expToReach(98) ≤ exp < expToReach(99)` ⇒ 98 级）。
- 实际：garrison 的循环上界是 `i < 99`，只查到 `f(98)`，于是 `exp ≥ f(98)` 一律 `return 99`，把 `[f(98), f(99))` 整段吞进 99 级。
- 影响：当前**不可达**——`generals.json` 的 `BaseEXP` 最大 9999（12 级），99 级要 662921 经验。但两套"同一张表"的实现已经分叉，将来若放开等级上限就会显形。
- 测试处理：`level_troop.test.ts` 里 `it('TODO(口径未定) 98/99 级边界两套实现不一致（已写进报告 §疑似 bug）')` 用源码实际值断言并标 `TODO(口径未定)`，不强行让两边相等。
- 建议（改 src 的 agent）：把循环上界改成 `i <= 99`，或直接复用 `battle.expToReach`。

### 9.2 两处"同接口不同口径"（不可达，仅记录）

1. `garrison.expForLevel(100) === 9999999`（查表哨兵） vs `battle.expToReach(100) === 676467`；
2. `levelFromExp(Infinity)`：garrison → 1 级（`numOf` 归 0），battle → 99 级。
   两者都只在等级上限 99 之外才有分歧，测试里以"口径差异（不可达）"命名并保留断言，避免以后有人误改。
