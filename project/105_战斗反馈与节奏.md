### 1.1 症状（97 报告）

### 1.3 三个根因（都实测复现过）

1. **判据错位**：`CastResult.killed` 的语义是「打死敵兵數」（`runtime.applyHpDelta` 兵分支 `killed++`）。打主将时它恒 0 ⇒ web 恒判「未命中」。
   实测：半月斬贴身，敵将 82→68（−14），而 `cast().killed = 0`。
2. **只回第 0 帧**：旧 `cast()` 里 `const first = session.frames[0]; const killed = session.done ? session.killed : first ? first.killed : 0;`（已删）。多帧技的后续帧击杀/伤害永远进不了返回值。
3. **会话不 `done` 就永不汇总**：旧 `accountSession()` 只在 `cast()`（done 时）或 `advanceSessions()` 的 `if (s.done)` 调用。半月斬在同步模型下跑满 348 帧仍未 `done`（`docs/04b3` 的动画帧数远小于虚拟帧上限），期间被法术打死的兵**从不计入 `spellKills`**。
   实测（修前）：半月斬打「敵将 + 20 兵」，场上确实少了 1 个兵（`session.killed=1`），但 `spellKillsA = 0`、`settle().spellKills = 0`。

### 1.4 原作语义裁决（要不要区分「法术击杀」）

- `docs/04b_战斗系统.md:35`：`0x44D450`(5040 B) 是**指令/策略派发器**（`[ebp+8]=side`、66 项 switch、索引 = `0x40A63A(x)-1`），处理「士气增减、按百分比扣兵」这类非普攻效果 —— 它**不是**伤害函数，也不产出「击杀计数」。
- `docs/04b4_普攻伤害与Process.md`：`0x43D400` 命中后只发 `OM_PAIN`，**扣血在受击对象的类处理器内**（多态，无单一公式）；打士兵是「`OM_PAIN` 自转 `OM_DEATH`，一击必死」。
- ⇒ **原作只有一个「单位死亡」计数，没有「法术击杀」这个分类**。所以：
  - `settle().kills = 起始兵数 − 现存兵数`（`battle.ts` settle，含法术打死的兵）**符合原作，不改**；
  - `spellKills` 是本作新增的统计（A 侧法术击杀），它只能是 `kills` 的**子集**；本次**只修漏计**，不改结算口径。
  - 一条恒等式已写进测试：`kills === killsInf + killsCav` 且 `spellKills <= kills`。

### 1.5 修法：内核记账 + 视图绘制（`game/web/**` 零改动）

**内核（`battle.ts`）**

- `SkillMark`（`battle.ts:457`）：`{ tick, side, x, y, kills, damage, healed, summoned, miss? }` —— 一次技能结算的**真实战果**，`miss:true` 才表示「真没打中」。
- `World.skillMarks: SkillMark[]`（`battle.ts:401`），`createWorld` 初始化；`stats.spellDamageA/B` 新增。
- `CastResult` 扩字段（`battle.ts:429-445`）：`damage?`（打掉敵将体力）、`hits?`（脚本命中单位数）、`hit?`（第 0 帧是否已生效）—— **`hit` 才是「命中判据」，不是 `killed`**。
- `effectSnapOf(world, side)`（`battle.ts:1870`）+ `recordEffect(...)`（`battle.ts:1899`）：用**前后对账**算真值
  `kills = 敌方死亡兵增量`、`damage = 敵将 HP 减少`、`healed = 我方主将 HP 增加`、`summoned = 我方兵数增加`。
  这比读 `session.killed` 稳：`applyHits` 对兵是「先掷 `rate` 才死」，对将只改 HP。
- **逐帧记账**：`advanceSessions()`（`battle.ts:2027`）每个 tick 对每个会话做 `snap → advance → recordEffect`，多帧技的击杀不再等到会话结束；`cast()`（`battle.ts:1951`）同样对第 0 帧记一次。
- `finishSession()`（`battle.ts:1929`）：会话结束（或截断）时若「一次效果都没产生过」且不是補血技 → 补一条 `miss:true` 标记。**MISS 从此只可能来自内核**。
- 死等保护：`world.tick − info.tick >= max(life + SKILL_MARK_TTL, EFFECT_WINDOW_MIN=240)` 时强制收尾（`battle.ts:1859`），避免「会话永不 done ⇒ 永远没有反馈」。`EFFECT_WINDOW_MIN=240` 保证 152 帧的劍輪舞动画仍能走完。

**视图（`battleView.ts`）**

- `markVisual()`（`:1097`）把标记变文本：`-N`（兵）/`-D`（将）/`+H`（治療）/`+S`（召喚）/`MISS`。
- `drawFloaters(...)`（`:1134`）新增 `marks / tick / skillPending` 参数：先画 web 的 Floater，但当**同刻有标记**或**还有技能在解算**时丢掉文本恰为 `MISS` 的 Floater（那是 web 抢跑），再画内核标记。`buildFrame` 的调用点见 `battleView.ts:533-540`。
- `battleMessage()`（`:1115`）改写提示栏那句「XX：擊殺 0 名敵兵。」→「XX：擊殺 N 名敵兵，敵將 −D 點體力。」（只认这一种句形；文案改版就自然失效、原样返回）。调用点 `battleView.ts:1386`。

### 2.2 归因（四项逐一排查，只有一项成立）

| 候选 | 判定 | 依据 |
|---|---|---|
| 命中率太低 | **否** | 将→将实测 47.3%、6v6 47.4%；`hitChance()` 与 `docs/04b3:24` `rand()%300 < 150+(STR差)/2`、`docs/04b4:189-191`、`04b4:171` 逐字一致 |
| 攻速太慢 | **是（仅主将段）** | `ATTACK_COOLDOWN=120`（4 s）无 VA 引用（`battle.ts:48` 旧注释只有「tick → 4 s」）；来历是 `project/09_战斗原型说明.md:104` 的手感调参表 18→36→60→90→120→150，`project/15_数值模拟报告.md:158` 自己标了 `[偏差·待核]` |

**真正原因**：主将互磨段的行动间隔 4 s。将对将命中 ≈47%、`basicDamage` 2.8~6.9/次（`(rand%(STR−STR/2)+STR/2)/10`）、`hpCapOf` 出 80~83 HP ⇒ 约 18 次命中 ≈ 38 次出手 ≈ 38 × 4 s ≈ 150 s，与 97 的 129 s、基准 duel p50 92 s 同量级。
另有一条独立印证：**全局改 40 时 6v6 的攻击数一个都没变**（378/179）—— 6v6 的节流是前排接触面（`ENGAGE_RANGE=1.15`），不是冷却；冷却只决定「互磨段」的长度。

## 3. 问题 3：神鬼亂舞恒不可放（`mp47 > mpMax 39/44`）

### 3.1 公式裁决：`mpCapOf()` 是对的，**不改**

| 出处 | 公式 |
|---|---|
| `docs/04b_战斗系统.md:231-234`（`0x40A098`） | `mp = BaseMP(+0x1A) + (level*2*t)/100; if (mp < BaseMP) mp = BaseMP; if (mp > 0x7FFF) mp = 0x7FFF;` |
| `docs/04b:644` | `技力上限 = BaseMP + level*2*t/100`，`t = (STR>INT) ? (STR+INT)/2 : INT` |
| `docs/04b5_战力基准与疲劳反汇编.md:108` | `general+0x14/+0x16` 由 INI `BASEMP` + 等级成长 + 装备 `MaxMP` 累积；**不存在 `60+INT/2` 或 INT→技力 换算** |
| `battle.ts:764` `mpCapOf()` | `s=round(str); i=round(int); t = s>i ? trunc((s+i)/2) : i; v=trunc(level*2*t/100); max(baseMp, min(0x7FFF, baseMp+v))` |

逐字一致 ⇒ **神鬼亂舞 Lv2 的 MP47 是原作门槛，不是算错**。实测：

```
張角 Lv1  createWorld mpMax=45  cast(seq104) → ok=false reason='mp'
張角 Lv2  createWorld mpMax=47  cast(seq104) → ok=true        ← 内核正确
張角 Lv3  createWorld mpMax=49  cast(seq104) → ok=true
```

### 3.2 真正不可放的两个原因（97 报告的 44 就是 BaseMP 原值）

1. **web 把 A 侧 `mpMax` 覆写成 `BaseMP`**（`game/web/main.js:652-659`）：
   ```js
   const aRow = (d.generals || []).find((g) => g.NAME === cfg.aGeneral?.name);
   if (aRow && Number.isFinite(aRow.BaseMP) && aRow.BaseMP > 0) {
     const ag = world.sides.A.general; ag.mpMax = aRow.BaseMP; ag.mp = aRow.BaseMP;
   }
   ```
   注释自称「原作 BaseMP（關羽 43 / 諸葛亮 45），沒有這個欄位才退回 createWorld 的 60 + int/2。必須在 applyWise 之前，增加技力才是『在 BaseMP 上加』」——但 `createWorld` **早已**用 `mpCapOf(BaseMP, STR, INT, level)`（`battle.ts:764`），所以这段是**基于旧假设的过期 workaround**：它把等级成长整个抹掉，后面的 `applyWise` 再从更低的基数往上加。張角 Lv2 内核 47 → 覆写 44，**缺口 3 點**，任何等级都放不出 47 的技（`docs/04b5:108`：原作 `+0x14/+0x16` = `BASEMP` + 等级成长 + 装备 `MaxMP` 累积，本来就是在等级成长上加）。97 报告的 `mpMax 39/44` 正是 張勳/張角 的 `BaseMP` 原值。
   复刻验证：Lv1/2/3 全部 `ok=false reason='mp'`（缺口 3）。
2. **技位写死 4 格且第 4 格是神鬼亂舞**：`battleView.ts:299` `export const DEFAULT_SKILL_SEQ = [1, 50, 2, 104]`；web `main.js:675` 调 `makeSkillBar(d)` 不传 seq。而 `104 神鬼亂舞` **張角的技能表里没有**（張角：`1,49; 7,56; 11,66; 18,71; 23,84; 30,95; 34,101; 41,106`）⇒ 第 4 格恒为死格。也就是说：即便修好 mpMax，張角也**不该**有神鬼亂舞——97 报告的第 4 格本身就是「把一个不属于他的技塞进技位」的显示 bug。
