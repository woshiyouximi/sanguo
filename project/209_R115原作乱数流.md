## 2. 反匯編還原：兩個非顯然的事實

1. **x86 的移位計數按 5 位取模**（`cl = 32` 等於不移），所以「`shr` 一段 + `shl(32-(x&31))` 一段相加」這種編譯器手寫 rotate，在**輪轉量 0 時會變成 `2x mod 2^32`**，而不是原樣返回。JS 的 `>>>` / `<<` 同樣按 31 取模，語義正好對上，代碼裡不需要特判——但文檔必須寫清楚，否則後人會「順手把它修成真正的 rotate」。
2. **因為上面的怪癖，`rand() & 1` 不是 50/50**。每組狀態每 32 步約踩到 1 步退化輪轉，實測三個種子各 10 萬次 `bit()==1` 佔比 **48.35% / 48.41% / 48.44%**（Python 參考 200k 次 48.24%）。測試因此斷言 47.8%..49.0%，而不是「均勻」。

三方交叉驗證（缺一不可，前面正是靠它抓到 OR/加法之別）：

- Python 獨立參考 `work/r115/sango_rng_ref.py`（`ror/rol` 用加法拼、`& M` 截 32 位）；
- 字符串位旋轉的第二實現（測試內，`k==0` 時 `(x+x)>>>0`）；
- TS 正式實現 `sango_rng.ts`。

## 6. 還沒同流的部分（誠實清單）

1. **Cocos 端**：`game/cocos/assets/scripts/core/**` 是 web 真源的**鏡像**（帶 Cocos 適配補丁，靠 `work/cocos_sync/sync_core3.mjs` 同步），本次只改了 `game/src/core/**`。所以 Cocos 戰場 `world.roll` 仍是 `null` ⇒ 走舊流，**行為不變、不崩**，但也沒接上新流。同步 ritual 由 lead 在當天收尾做（新檔 `sango_rng.ts` 還要配 `.meta`），本次沒動是為了不把「核心同步」和「功能改動」混在一次提交裡。
2. **戰後招降/斬首**（`capture.ts`，`world.rng` 從 `battle.ts:3266` 傳進）：原作這裡也是 `rand()%100`，接了才算全流。
3. **腳本 VM**（`core/smartscript/runtime.ts:1769/1946/1948/2256`）：MAGIC.SO 的隨機也走 `world.rng`。
4. **觀感抖動**（`commitStep` 像素偏移、`strategy.ts` 撤退漂移）：這些在原作裡也有 rand 消耗，但只影響像素，優先級最低；接它們會改變畫面的抖動序列對拍基準，等錄像對拍再做。

## 7. 坑

1. **不要把「兩段移位相加」當成真 rotate**。第一版寫成 `(x >>> n) | (x << (32-n))`，第 4 組向量與字符串實現對不上；改成加法（`k==0 → 2x`）後三方一致。OR 和加法在 `k>0` 時等價，只在 `k==0` 時分道揚鑣——這正是最容易「看起來對」的錯。
2. **`rand() & 1` 不是 50%**。第一版測試斷言「0/1 各 50% ±1.5%」，跑出來 48.41% 直接紅；查下去才發現是退化輪轉的副作用。測試改成釘偏置區間，並在模組頭註明——**這是原作行為，不是 bug**。
3. **`(0,0)` 不是好種子**：起步幾十個輸出只有高位在動（`7FFFFFFF, 3FFFFFFF, 1FFFFFFF…`），所以 `sangoSeedFrom()` 命中 `(0,0)` 時換 `0x6d2b79f5`。
4. **`node -e` 帶中文會被 PowerShell 拆壞**（`ParserError`）：測量/探針腳本一律先 `write` 成 `.mjs` 再跑（R208 已記過一次，本輪又踩）。
5. **`tsc -p tsconfig.build.json` 必須跑**：web 吃 `game/dist`，只跑 `--noEmit` 的話 `dist/core/sango_rng.js` 不存在，頁面會在 import 階段白屏。
6. **CDP 腳本裡的世界不是 `window.__sanguo.world`**，而是 `window.__sanguo.state.world`（第一次跑出來 `hasWorld:false`，誤以為接線失敗）。
