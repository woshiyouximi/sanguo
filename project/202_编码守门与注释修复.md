### 1.2 根因（机制，不是猜测）

PS 5.1 的 `Set-Content`/`Out-File` 默认 `-Encoding` 是 **ANSI = 代码页 936**：
UTF-8 的中文三字节被按 GBK 双字节贪心吃掉，落盘时**丢字节 → 变成 `?` 或被截断成非法 UTF-8**，
再以 UTF-8 读回来就是 `U+FFFD`。所以坏点长这样：

```
/** 战况条内的双方兵力条（A U+FFFD?B 右） */
                          ↑ 1 个 U+FFFD + 1 个 '?' 占位
```

丢的字符数 1~2 个不等，还**顺带丢了约 14 个注释内换行**——多行注释被并成一行，
所以「行数」本身不可靠（`layout.ts` 252 行 → 修好 291 行）。

同一根因更早还报废过 `work/fidelity/gen_expect.mjs`、`game/tests/yearsettle_r7.test.ts`；
本轮扫到 `work/fidelity/gen_expect.corrupt-r192.mjs` 是**另一种坏法**：UTF-8 字节被当 GBK 读，
落盘成 `淇濈湡…`（此处只引用前 3 个字，全文见 §4.2）这种**合法 UTF-8 乱码**——U+FFFD 查不出来，所以扫描器额外加了 mojibake 特征 WARN。

## 2 任务 1：编码守门

### 2.1 `work/enc/scan_utf8.mjs`（判定口径）

```
node work/enc/scan_utf8.mjs [dirs...] [--max=N] [--include-vendor] [--strict] [--quiet]
```

- 默认根：`game/src`、`game/web`、`game/tests`、`game/cocos/assets/scripts`、`tools`、`project`、`docs`、`work/fidelity`；
- 扩展名：`.ts .js .mjs .html .css .json .md .ps1`；跳过 `node_modules/.git/dist/build/out/coverage/.cache`；
- 判定：

| 情形 | 结果 | 说明 |
| --- | --- | --- |
| 含 ≥1 个 `U+FFFD` | **BAD** | 逐处给 `file:line:col`，默认每文件最多列 20 处 |
| 不是合法 UTF-8 | **BAD** | 手写严格校验（过长编码/代理区/`F0→90+`/`F4→8F-` 上界都算非法） |
| `.ps1` 带 BOM | 正常 | Windows PowerShell 5.1 读中文脚本**需要** BOM |
| 其它扩展名带 BOM | **WARN** | 不影响退出码（`.ts/.js/.mjs` 带 BOM 会让部分工具链出怪事） |
| 合法 UTF-8 但像 mojibake（≥3 种特征字） | **WARN** | 抓「UTF-8 被当 GBK 落盘」这种 U+FFFD 抓不到的坏法 |

- 输出：BAD/ERROR 先打、ALLOW 次之、WARN 最后；退出码 **0 干净 / 1 有 BAD / 2 用法或路径错误**。

### 2.2 三个「防假绿」设计（这轮加的，都是踩过坑补的）

1. **显式 scope 不存在 → 直接失败**：`node … gam/src`（手误）不会扫 0 个文件然后报 OK，
   而是 `error: scope not found … (0 files would be scanned -> refusing to pass)` + exit 2。
   门禁最怕的就是「查了个不存在的目录」这种静默通过。
2. **豁免必须写 reason**：`work/enc/allowlist.json` 里没有 `reason` 的条目会被拒绝加载并打
   `allowlist: entry "x" has no reason -> ignored`；`--strict` 可以无视整张名单再跑一遍。
3. **vendor 默认不扫**：`tools/cocos` 是引擎源码，里面本来就有非 UTF-8 的第三方文件
   （`LICENSES.chromium.html` 的 Latin-1 商标符号、Python27 测试样例）。扫它只会制造噪音。

### 2.3 `tools/check_encoding.ps1`（**带 UTF-8 BOM**）

- 3252 bytes、`BOM=YES`、零 CRLF、`sha256=74108951d8b8`、`[Parser]::ParseFile` 0 error。
- 参数：`-Scope <dir...>`（数组）、`-Max N`、`-IncludeVendor`、`-Strict`；node 或扫描器缺失 → exit 2。
- 透传 node 退出码；PASS 打 `ENCODING check: PASS (0 BAD)`，
  FAIL 打 `ENCODING check: FAIL (有文件被写坏)` + 一句**怎么修**：

```
怎么修：用 read/write/edit 工具、或用 python 显式 encoding="utf-8" 整文件重写；
绝不要再 `Get-Content -Raw | Set-Content`（PS 5.1 默认 CP936，会把中文写成 U+FFFD）。
```

- **为什么要 BOM**：PS 5.1 读无 BOM 的 `.ps1` 按 CP936 解码，本脚本里的中文提示会当场变乱码。
  用 `powershell.exe -NoProfile -File tools\check_encoding.ps1 -Scope game/src` 实测中文正常，
  这本身就是 BOM 生效的证据。
- 补 BOM 的小工具是 `work/enc/ps1.py`：`write <src> <dst>`（`src==dst` 即原地重写，实测 sha 不变）、
  `check <files>`（打印 bom/fffd/crlf/sha）。**所有 `.ps1` 都是它产出的**，不许用 `Set-Content` 保存。

### 2.4 G11 接进打包门禁

- 位置：`tools/gate_fidelity.ps1` 第 145 行起（`# ---- 汇总` 在第 166 行，脚本共 181 行），格式与其它关完全一致
  ——`Run-Step 'G11 编码守门' …`，PASS/FAIL 由汇总表统一打印。
- **不设 SKIP**：`check_encoding.ps1` 缺失、`powershell.exe` 缺失都记 **FAIL**，因为这道关守的是
  「源码本身还能不能被读」，缺工具等于这道关不存在。
- 传参方式（踩坑记录）：`Run-Step` 内部是 `& $Exe @ArgList`，**数组 splat 会把 `-Scope` 当位置值**，
  第一版直接报 `Cannot process argument transformation on parameter 'Max'. Cannot convert value "game/src"
  to type "System.Int32"`，G11 假 FAIL（`FAIL (exit=0)`）。改成：

```powershell
$psHost = Join-Path $env:SystemRoot 'System32\WindowsPowerShell\v1.0\powershell.exe'
Run-Step 'G11 编码守门' $root $psHost @('-NoProfile','-ExecutionPolicy','Bypass','-File',$encScript,'-Scope','game/src') 'ENCODING check: PASS'
```

  顺带实测了一条语义：被调脚本里的 `exit 3` **不会**杀掉调用方（回到调用方 `$LASTEXITCODE=3`）。
- 该文件原本**无 BOM 无 CRLF**，本轮 6878 → 7693 → **8339 bytes**，`BOM=YES`、`sha256=2dec15670f22`；
  改前备份 `work/enc/archive/gate_fidelity.pre_g11.ps1`。
- 整跑结果：

```
---- G11 编码守门
PASS   G11 编码守门   ENCODING check: scope=game/src | scan: 33 files, 0 BAD, 0 WARN, 33 clean -> OK | ENCODING check: PASS (0 BAD)
PASS 10 / FAIL 0 / SKIP 1  用时 52s
结论：门禁通过
```

### 2.5 自证

- **自动**：`node work/enc/selftest.mjs` → `selftest: 8 PASS / 0 FAIL`，8 个案例——干净 `.ts`；
  1 个 `U+FFFD`（exit 1）；非法字节（exit 1）；`.ts` 带 BOM（只 WARN）；`.ps1` 带 BOM（不报）；
  GBK mojibake（WARN）；无关扩展名（忽略）；**修好即转绿**（先 exit 1 再 exit 0）。样本建在
  `work/enc/_selftest/` 下，跑完删净。
- **手工**（任务书原文要求）：python 写 `work/enc/_selftest/bad.ts` 含 1 个坏字符 →


  删掉后再跑 → `ENCODING check: PASS (0 BAD)`，`exit=0`。

- **顺手的一次真抓**：这份报告第一版正文里直接抄了 9 个字面 `U+FFFD` 当例子，

  `BAD … 9 hits` + exit 1；改成文字 `U+FFFD` 后转绿。说明它抓的是**内容**，不是文件名白名单。

## 7 以后怎么用（速查）

```powershell
# 打包前整跑（G11 自动包含）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\gate_fidelity.ps1

# 只查编码（指定范围；省略则扫 8 个默认根）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\check_encoding.ps1 -Scope game/src

# 直接查文件（含未提交/临时文件）
node work\enc\scan_utf8.mjs game/src work/enc/_selftest

# 无视豁免看全貌
node work\enc\scan_utf8.mjs --strict

# 扫描器自身的回归
node work\enc\selftest.mjs

# 改完 .ps1 补 BOM（原地）
python work\enc\ps1.py write tools\check_encoding.ps1 tools\check_encoding.ps1
```

**唯一正确的改文件方式**：`read`/`edit`/`write` 工具，或 python 显式 `encoding='utf-8'`（`.ps1` 用 `utf-8-sig`）。
**永远不要** `(Get-Content -Raw $f) | Set-Content $f`——这就是这次 1962 + 150 个 `U+FFFD` 的来源。
