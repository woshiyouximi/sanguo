# 27 大地图行军

把「点城直接开战」补成原作流程：部队沿 116 条路走、到城下才开战、路上可被拦截。
纯逻辑在 `game/src/core/march.ts`（177 行，无 DOM）；页面逻辑在 `game/web/campaign.html` 内联同构一份
（浏览器不能直接 import `.ts`，本轮又不重建 `dist/`，故镜像；改一处必须同步另一处）。

## 数据与模块

- 路：`game/data/scenarios.json[0].paths`，`{Start, End, Length, points:[[x,y],...]}`。
  `Length >= 30000` 的 39 条是「画了线但不可走」的哨兵，全部跳过。
- 城：`cities[].pos_xy`。
- 导出（`march.ts`）：
  - `MARCH_PER_MONTH = 1/3`：一个月走路程的三分之一，近的 1 个月到、远的 3 个月到。
  - `pathBetween(scenario, a, b)`：两城之间的一条可走路下标；非相邻/只有哨兵返回 `null`。
  - `advance(armies, speed=1)`：`progress += MARCH_PER_MONTH * speed`，封顶 1；返回 `{arrived, still}`。
  - `intercept(a, b)`：同一条路、相向、`0 < progress < 1` 且两边进度之和 `>= 1` → 相遇。
  - `posOf(scenario, army)`：沿 `points` 折线按 `progress` 等距插值；从路的 `End` 出发时自动反向。

页面按原作 `Length` 分档：`months = clamp(ceil(Length/100), 1, 3)`，
`step = MARCH_PER_MONTH * (3 / months)`，因此短路过月即到、长路最多三个月。

## 状态机

```
             dispatch / AI 出兵
  [城中驻军] ─────────────────▶ [在途 progress 0..1]
       ▲                              │
       │ 退兵（守军 +troops）          ├─ progress >= 1 ─▶ [抵达目标城下]
       │                              │        │
       │                              │        ├─ A 到我方目标：不存在（A 只打敌/空城）
       │                              │        ├─ B 到我方城：守城战 defendUrl
       │                              │        └─ A 到敌城：deploy.html?from=march
       │                              │
       └──────── 取消遭遇 ────────────┴─ 与敌军进度交错 ─▶ [遭遇战 encounterUrl]
```

- 抵达后部队先留在 `armies` 里（`progress = 1`，地图标「抵達」），交互模式弹确认框：
  - 「抵達城下」确定＝移除部队并进编成；取消＝移除并把兵力退回出发城（上限 600）。
  - 「遭遇戰」确定＝进野战；取消＝两军各自退兵回城。
- 批量推进（`?adv=N`）不弹框：B 抵达直接 `resolveDefense()`；A 抵达只记一次战报；
  遭遇按兵力概率判定，胜方减半继续、败方消失。

## 月推进顺序（`advanceMonth`，行军模式）

1. `month += 1`，收税、己方民/金 +1%、敌城兵 +6（沿用旧逻辑）。
2. `advanceArmies(save.armies)`：所有在途部队走一个月。
3. `rollAI()` + `spawnAiArmy()`：本月新出的敌军从 `progress = 0` 起步，下月才开始走。
   - 同一座城已有在途 B 部队时不重复发；全场 B 在途上限 3 支。
4. `handleMarchEvents(batch)`：先遭遇，再 B 抵达（守城），再 A 抵达（城下）。
5. 结束 `autosave()` + `render()`；交互模式若触发跳转则提前 return。

`?seed=N` 仍可复现；`?marchdbg=1` 会把每月 `armies` 快照写进页面左上角 `#marchdbg`（`--dump-dom` 可读）。

## 拦截判定

```ts
a.pathIndex === b.pathIndex && a.side !== b.side &&
a.from === b.to && a.to === b.from &&
0 < a.progress < 1 && 0 < b.progress < 1 &&
a.progress + b.progress >= 1
```

同向、不同路、同一方、已经抵达（`progress = 1`）都不算拦截。

## 开关与回退

| 参数 | 行为 |
| --- | --- |
| 默认 | 行军模式：自己城多一个「出征」→ 选相邻目标 → 扣 100 兵 → 路上可见部队 |
| `?march=0` | 完全旧行为：自己城只有徵兵/開發；敌城「出征」直接跳 `deploy.html`；AI 直接 `resolveDefense` 判定；地图不画部队 |
| `?auto=1` | 旧快进路径：AI 直接结算、不跳转（测试/批量），路上部队冻结 |
| `?marchdemo=mid\|arrive\|three\|encounter` | 截图/验收用种子：两支在途 / 我軍已到城下 / 从 0 起步连推三个月 / 同路相向一个月后遭遇 |

存档兼容：`normalizeCampaign` 只补 `armies: []`、`armySeq: 0`，未知键原样保留；
`ensureCityState` 丢掉城名/路径对不上的部队，`progress` 夹在 `0..1`，不破坏已有字段。
旧档没有 `armies` 就是空数组。

## URL 衔接（沿用现路径，未改 deploy/main）

- 我方抵达敌城：`deploy.html?city=<目标>&from=march`（deploy 仍按自己的流程进 index）。
- 敌军抵达我方城：`index.html?defend=1&city=<我方城>&...`（沿用 `defendUrl`）。
- 路上遭遇：`index.html?city=<我方目标>&from=campaign&encounter=1&...`，提示「遭遇戰」。
- 结算回写仍靠 main.js 写旧键，campaign 下次启动同步到槽，未改战斗侧代码。

## 还没做（原作有、这里没有）

- 视野/侦察：原作只显示相邻或已探明区域，这里全图可见。
- 追击/撤退：没有「击溃后追击」「主动撤退」与伤兵/辎重。
- 多段路一次行军：`Army` 只有一条 `pathIndex`，只能打相邻城，不能绕过中间城。
- 疲劳/粮草/季节：原作行军消耗与士气未做。
- 部队合并/分兵、武将单挑、路上事件（山贼/援军）。
- AI 的兵力不从出发城扣除（旧 `resolveDefense` 也没有），只影响观感与到达判定。
