## 1 · R5 月内倒计时 / 年度进位 → ✅（特征对齐=不做）

**复核结论**：不是缺失，是我们**故意不还原**的界面层记账。

- `0x4C30E0` 全 EXE 只有 8 处引用（`work/rows85/xref85.py 0x4C30E0`）：
  - 写 `0x40E21A = 0xA`（调试快捷键，配合 `0x487310` 的 `xor 1` 开关 `0x40E1FB/0x40E203`）；
  - `0x41B6B9/0x41B6BE/0x41B6C1`：`dec [0x4C30E0]` 后 `cmp ≤ 0` ⇒ 归零则 `[0x4A64FC]=1`（年度进位）、`[0x4A64BC]=0`、弹 `0x48984C "%D200%內政時間到了....%k%%e%"`、`[0x4A6440]=1`，然后 `call 0x41B643` 月度主处理；
  - `0x41B84E`：`sub eax,[0x4C30E0] / idiv 0x12C(300) + 1` 夹 1..12 —— **只用来画「日期」格子**，不参与任何规则；
  - `0x41BC1F` 写 `0xE10 = 3600`（回到地图时重设计时器）。
- `0x4A64BC`（月内是否已下令）只有 4 处：`0x41B6D9` 清零、`0x4278B0/0x427907` 读、`0x427927` 置 1。
- ⇒ 原作**没有回合内多日/多步行动**：一个回合就是一个月，`0x4C30E0` 是「这个月还能在内政里待多久」的计时器（归零自动收月），玩家可感知的规则只有「一月一次行动」。这正是我们的 `advanceMonth` + `CM.monthLocked` 组合。

**改了什么**：无代码改动（已是等价形态）。新增两条断言锁住形态：
- `game/tests/rows85.test.ts` `R5：換月是一月一步…`（`advanceMonth` body 含 `save.month += 1`、`CM.clearMonthLock(save)`、`Saves.isYearStart(save.month)`；全文不得出现 `save.day|hour|turnStep`）；
- `R5：月令鎖就是「本月是否已下令」…`（`Saves.isYearStart(13) === true`、`12 === false`）。
- 既有事实依据：`Saves.isYearStart` 在 `game/web/saves.js:1220`（`monthOfYear(month) === 1`），`annualYearRollover` 在 `campaign.html:3173` 那一段。

**剩下没做的**：界面不显示月号绝对值（原作只显示年），我们显示「第 N 年 M 月」——这是**有意更友好**的偏差，登记不改。

## 2 · R6 城规模 RATE 1..5 无升级 → ✅（特征对齐=不做）

**复核结论**：RATE 在原作里就是一个**只读的美术/索引字段**，没有任何玩法效果，因此「不还原」即对齐。

- `--disp` 扫 `+0x6C` 全 EXE 24 处，其中字操作只有一处：`0x426D95 movsx ecx, word ptr [eax+0x6c]`（搜索权重表行索引）；其余全是别的结构体的 dword 偏移，不是 city。
- 搜索权重表 `0x48a260`（`imul RATE, 0x14`，20 字节/行）：行 1..5 全部 = `(50, 30, 20, 33, 66)` ⇒ **按 RATE 索引的结果与 RATE 无关**。
- 城池外观规模另有字段：`0x406056(city)` 按人口重算 `+0x44` 城郭等级（`pop > 30000 ? (pop−30000)/70000 + 6 : 5`，夹 5..15），`0x4060F8` 再折成 0..3 档 ⇒ 视觉规模随**人口**涨，与 RATE 无关。我们的 `hallIndexOf`（`city_model.js:286` 附近，`pop ≥ 300000 → 6` 档）就是这条的对应实现。
- `04c §2.5` 的结论一致：`+0x6C` 只在装载器 `0x42D8F0` 被读，无写入点 ⇒ 游戏中不变、无升级。

**改了什么**：无代码改动。新增断言 `R6：RATE 只驅動外觀/索引…`：`hallIndexOf` 1/3/5/9 → 5、`RATE 1 + pop 500000 → 6`、`isGate(RATE 0 / FLAGS 1)`、`Object.keys(M)` 无 `upgrade/promote/growCity`、`campaign.html` 不得出现 `.RATE =`。

**剩下没做的**：`city.html` 里 RATE 若仍显示为「规模」字样属于 UI 文案，不在本轮范围（且该档不归我改）。

## 7 · R20 搜索随机不可复现 → ✅（真随机 + 可注入）

**复核结论**：原作用 `0x450117(n)` = `rand_core() % n`，`rand_core` 是自维护 32 位移位寄存器（`[0x4922FC]++ / [0x492300]`），**不可复现**；我们原来用 `hash(city, month, count)` 当种子，等于「同城同月第 N 次搜索必得同一结果」，是取巧点。

**改了什么**（`game/web/city_model.js`）：
- 随机层：`setRng(fn)`（`:244`，模块级注入口）、`rngNext()`（注入 → `crypto.getRandomValues` → `Math.random`）、`randBelow(n)`（`rand()%n` 语义，`n<=0` 回 0）、`randomNonce()`（`:279`，32 位真随机）、`searchNonce(save)`（读 `save.searchNonce`，**缺省 0，刻意不在模型层自动生成**）、`setSearchNonce(save, n)`（`:296`）、`searchSeed(city, month, count, nonce=0) = hashSeed('search', nonce, city, month, count)`（`:308`）。
- `search()` 的种子改为 `searchSeed(city, save.month, count, searchNonce(save))`（`:928` 附近），返回值仍带 `seed`。
- `game/web/campaign.html:1224` 起：存档规范化后注入一次 —— `if (typeof CM.setSearchNonce === 'function' && !(Saves.num(save.searchNonce) > 0)) CM.setSearchNonce(save, CM.randomNonce());` ⇒ **每份存档一个随机 nonce 并随存档持久化**；`city.html` 读同一份存档也吃得到（`searchNonce` 是普通可枚举字段，进 JSON）。

**为什么 nonce 不在模型层自动生成**：`webfix_r83.test.ts:76-99` 断言「把 `searchSeq` 夹回 `min(i,60)` 时 `seeds.size === 61` 且 `maxRun >= 20`」。实测（`work/rows85/probe_hist.mjs`，200 个随机 nonce）「每份存档随机 nonce」下该断言 **29% 会红**（mean 27.9 / sd 2.8 / max 35）⇒ 会变成 flaky。所以选择：模型层缺省 0（纯函数可复现、测试与既有行为逐位一致），真随机由页层注入。取巧点已消除（玩家实际游玩时 nonce 是随机的、且不可从 `(城,月,次数)` 推出来），同时保住确定性入口。

**证据**：`R20：種子由 nonce 參與 —— 換 nonce 就換結果，同 nonce 完全可復現`、`R20：setRng 可注入、randomNonce 是真隨機且 32 位`。变异：`hashSeed('search', intOr(nonce, 0, 0)` → `intOr(0, 0, 0)` 使第一条红；已还原。

**剩下没做的**：原作 `rand_core` 的具体多项式未复刻（不影响可玩性；我们要的是「不可复现」这条特征）。
