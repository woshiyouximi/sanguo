## 4. 三个数据结构决策

### 4.1 武将：一份属性 + 五份站位

原作 401 个武将的属性在 5 个剧本里**完全相同**（`docs/03c` 已证），只有 `POS/CITY/Status` 随剧本变。
所以 `generals.json` 只存一份属性，另加三个数组：

```json
{
  "NAME": "關羽", "STR": 99, "INT": 85, "FACE": "FACE\\FACE385",
  "SKILL": ["1, 50", "6, 63", "11, 69", "17, 77", "22, 84", "29, 88", "35, 102", "40, 110"],
  "WISESKILL": ["1, 8", "6, 16", "12, 22", "19, 32", "26, 38", "32, 51", "39, 54"],
  "id": 87,
  "pos_by_times":  [4512, 4512, null, 4480, 4480],
  "city_by_times": [12, 12, null, 7, 7],
  "status_by_times": [1, 1, 0, 1, 2]
}
```

> **⚠️ 必须知道的两个坑（都已修，但重导时会再犯）**
>
> **坑 A：`SKILL=` / `WISESKILL=` 在 INI 里是重复键。** 一个武将有多少个技能，就有多少行同名键：
> `TIMES1.INI:14861-14867` 是關羽的 8 行 `SKILL=1, 46 / 6, 55 / …`，`14868-14870` 是 3 行 `WISESKILL=`。
> 早期 `read_ini` 用 `dict` 直接赋值，**后一行覆盖前一行**，导出的 401 将"人人只有 1 对技能"（UI 的必殺技 7 格只能画 2 实 + 5 空）。
> 现在 `read_ini` 见到同名键就**累积成 list**（`as_list()` 辅助），`coerce()` 对 list 逐项转换。
> 修完实测：**必杀技 1~8 对（共 2,061 对）、军师技 1~8 对（共 1,567 对）**，分布 2:16 / 3:51 / 4:81 / 5:100 / 6:64 / 7:44 / 8:45。
>
> **坑 B：`import_legacy.py` 会覆盖 `export_slots.py` / `export_fx.py` 合并进去的字段。** 那两个脚本往 `data\formations.json`（`slots`，316,013 B）和 `data\magics.json`（`fx_dir` 等，39,278 B）里**追加**内容，而 `import_legacy` 是从 INI 全量重写。所以**重导必须按顺序跑**：
>
> ```powershell
> python tools\import_legacy.py --strict   # 1) INI → JSON（会清掉 slots/fx）
> python tools\export_slots.py             # 2) 阵形 slot 合并（65 项自检）
> python tools\export_fx.py                # 3) 技能特效目录合并（110/110）
> python tools\gen_bundle.py               # 4) proto/data_bundle.js
> Copy-Item data\*.json game\data\ -Force  # 5) 客户端数据
> node proto\ui\_gen\gen_data_ui.js        # 6) UI 原型数据
> ```
>
> 顺序错的表现：`data_bundle.js` 从 129 KB 掉到 32 KB、`gen_bundle` 打印"0 组 slot"。


好处：改一个武将的武力只改一处；坏处：客户端要按 `scenarioId` 取下标（一行代码）。

### 4.2 城市与路径：按剧本整块存

`scenarios[i].cities` 是**该剧本的 60 城快照**（含 `KING/MAJOR/WISE/POPULATION/DEFENSE/MONEY/POS/FLAGPOS/RATE/FLAGS`），`paths` 是该剧本的 116 条路（`Start/End/Length/points`）。
没有做"城市主表 + 剧本覆盖表"——因为 5 个剧本的城市名与坐标完全相同，只有归属与数值不同，拆开反而增加一层 join。

### 4.3 矩阵：行=攻方，列=守方，反对称

```json
"troops": {
  "names": ["朴刀","长枪","大刀", ...],
  "matrix": [{"name":"朴刀","vs":[0,-42,-58, 44, ...]}, ...]
}
```

`matrix[i].vs[j]` = 第 i 个兵种打第 j 个兵种的修正值。
客户端用 `idx = troops.names.indexOf(name)` 建索引，战斗时 `power += troops.matrix[attIdx].vs[defIdx]`（`docs/04b` 的五段加算之一）。

## 5. 踩到的两个坑（都已在脚本里注释）

| 坑 | 症状 | 原因 | 修法 |
|---|---|---|---|
| 表头错位 | 兵种矩阵反对称 = **132**、阵形 = **46**、对角不为 0 | `xls_dump.py` 把表头放在 `header` 字段，`rows` 里**只有数据**；我按 `rows[0]` 当表头、又从 `rows[1:]` 取数据，整体偏移一行 | 用 `d["header"]`；数据从 `rows` 全取 |

## 7. 客户端怎么用（与 `04_技术方案_Cocos.md` §5 对齐）

```
data/*.json  ──build_data.py──>  assets/resources/data/*.json（压缩、去空格、可选 msgpack）
                                          │
                                    GameData 单例（启动时一次性读入，1.38 MB 可全内存）
                                          │
        ┌─────────────┬──────────────┬────┴─────────┬──────────────┐
     内政/大地图      战斗           武将面板        技能           物品
   scenarios/cities  troops/formations  generals    magics/wises   items
```

- **不热更数值表**：数值表打进包（`main` 分包），改数值发版；`wx` 的 `setStorageSync` 只存玩家进度。
- **1.38 MB 是可接受的**：JSON 压缩后 ≈ 240 KB，远小于 4 MB 首包预算。
- 若将来要"运营改数值"，把 8 张表挪到 CDN，加 `dataVersion` 校验即可——**结构不变，只改加载源**。

## 9. 回归闸门 `tools/validate_all.py`

§8 是"第一次迁移怎么验"，§9 是"以后每次改数据怎么验"。`import_legacy.py --check` 是迁移脚本自证自话，而闸门是**独立第三方**：它只读 `data/` 与 `assets/`，重算一遍已知事实，对不上就 `exit 2`。

**一条命令：**

```bat
python tools\validate_all.py
:: 期望末行 SUM pass=37 fail=0 warn=3  退出码 0
:: 报告落盘 F:\sanguo\work\validate_report.txt
```

每行格式 `<PASS|FAIL|WARN> <项> <期望/实际>`；`--quiet` 只写文件不刷屏（CI 用）。

### 9.1 它守住哪些不变量

| 分组 | 项 | 期望 | 依据 |
|---|---|---|---|

| 武将 | `template` | 含首段模板 `盜賊` | 它无 `SEQUENCE`、`BaseEXP=9999`，被误删会让编号整体错位 |
| 武将 | `關羽.skill` / `關羽.wise` | 8 对 / 7 对 | 全库最具辨识度的双料样本，改解析器时最先崩的就是它 |

| 武将 | `skill.level_monotonic` | 401 人等级列非降序 | 用"单调"反证 `SKILL` 是「习得等级,编号」而不是随机数 |

- `hero.*.coverage`：153/400 = 38.2%，立绘入库未完，不阻断。

> 2026-11-24 补记：`generals.field_type` 已按 §9.5 修掉（`import_legacy.py` 统一输出数组后重跑整条管线），该项由 WARN 转 PASS；现仅剩上面两条立绘覆盖率 WARN，闸门 `pass=38 fail=0 warn=2`。

### 9.3 自测：闸门真的会红吗

做过一次负向自测（内存里把 generals 砍成 400 条，不动磁盘数据）：立刻 `FAIL generals.count 401/400`、`skill.pairs 2061/2057`、`wise.pairs 1567/1562` 三条，退出码 2。所以"绿"是有信息量的绿。

### 9.4 什么时候必须跑

1. 改 `tools/import_legacy.py`（解析/合并规则）之后——**必跑**；
2. 改 `tools/export_slots.py`（阵形槽位填充）之后——看 `fill200/fill100`；
3. 改 `tools/export_fx.py`（技能特效目录映射）之后——看 `magics.fx_dir`；
4. 立绘批量入库之后——看 `hero.*.names` 有没有未知文件名；
5. 每次发版前，和 §8 的 `--check --strict` 一起跑，两条都绿才算 M0 Gate 过。

**铁律**：闸门红了先查脚本改动，**不许改 data/ 去迁就闸门**——数据是解包产物，闸门是它的契约。

### 9.5 字段形状约定：多值一律数组

从 `import_legacy.py` 起就钉死三条，导出后不再变形：

1. **可能多值的字段永远是数组**：`SKILL`/`WISESKILL`（重复键，1~8 行）、`POS`（5 个剧本槽位）、`BattleArray`/`Force`/`UseForce`（空格分隔的名字表）、城市的 `POS`/`FLAGPOS`（x, y）、路径的 `points`（坐标串）。
2. **1 条也给 `[x]`，0 条给 `[]`**——不给"单值退化标量"的优化。历史 bug：102 人的 `WISESKILL` 只有 1 条时被写成字符串 `"1, 5"`，消费方得先 `typeof` 再 `len`。
3. **消费方不再判类型**：`g.SKILL.length`、`g.POS[timeIdx]`、`g.UseForce[0]` 直接可用；`validate_all.py` 的 `generals.field_type` 项守着这条契约。

例外（有意保留标量）：`NAME`/`CITY`/`Status`/`Weapon`/`Horse` 等天然单值字段；`things.json` 的动画序列（`Wait`/`Walk`/`Attack`…）保留原始 token 串，因为它是有序流、要连 `#delay` 一起解析，拆数组反而丢语义。
