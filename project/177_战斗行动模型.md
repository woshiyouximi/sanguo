## 5. 必做项 5：落点抖动 + 逻辑格（0x43BE42 / 0x43BF26）

**原作事实**
- `0x43BF26`：逻辑格**瞬移**（`u+8=gx` / `u+0xc=gy`）。

- 没走成：`0x43C084` 用 40 帧滑回格心（不加抖动）。

**改法**
- `battle.ts:1862-1875` `unitCell()`：滑动中优先读 `slide.gx/gy`（逻辑格），否则 `round(x/y)`；**不再从抖动后的像素反推格**。
- `battle.ts:358-374` `UnitSlide` 增 `gx?/gy?`（逻辑格；`tx/ty` 仍是带抖动的视觉目标，view 用）。
- `battle.ts:2051-2070` `commitStep(u, cell, occ, rng)`：`jx = floor(rng()*0x30) - 0x18`、`jy = floor(rng()*0x24) - 0x12`；`dx = clampPx((cell.gx-u.x)*96 + jx, 120)`、`dy = clampPx((cell.gy-u.y)*72 + jy, 90)`；`slide.tx = u.x + dx/96`、`ty = u.y + dy/72`、`total=40`、`gx/gy=逻辑格`。
- `battle.ts:2072-2079` `clampPx()`；`battle.ts:2081-2095` `settleToCell()`（`0x43C084`）：不加抖动、40 帧滑回格心，已在格心则不动。
- `battle.ts:2375-2379`：`chooseStepCell` 返回 null → `settleToCell(u, unitCell(u))`，不再“原地不动 0 帧”。
- 随机源全部走 `world.rng`（同 seed 可复现）。

**验证**

### 8.2 硬时间上限（lead m00893 / project/180）

**原作事实**：`[0x4AC35C]` 初值 `0x2E68 = 11880`（60Hz 帧），`0x444126` 每帧减 1、不低于 0，到 0 调 `0x443CA8(0x1000)` 置“战斗结束”走结算；同一常数被 `0x443F2A` 当战功“战斗时长”分母 `(11880−cd)/0x78`；HUD 显示 `ceil(cd/120)`（起始 99、约 0.5/秒、整场 198 秒）。

**改法**
- `battle.ts:58`：`export const BATTLE_TICK_LIMIT = 5940;`（11880 @60Hz ÷ 2 = 5940 @ `TICK_HZ=30` = 198 s，注释含全部地址）；`battle.ts:60`：`export const BATTLE_SECONDS = BATTLE_TICK_LIMIT / TICK_HZ;`（=198，HUD/战功用同一个数）。
- `battle.ts:506`：`World.endReason` 增 `'time'`；`battle.ts:2574` `finish()` 的 reason 参数同步扩。
- `battle.ts:2614-2617`：`checkOver()` 在兵力判定之后 `if (!world.over && world.tick >= BATTLE_TICK_LIMIT) finish(world, aN>bN?'A':bN>aN?'B':'draw', 'time')`（胜负按当前存活兵力，复用 `sides.aliveCount`）。
- `battle.ts:3191`：postBattle 折档把 `'time'`（和 `'retreat'`）归到 `'troops'`（`capture.ts` 只有 troops|general 两档，不能新增枚举）。
- `battle.ts:3280`：`durationSec = round(min(world.tick, BATTLE_TICK_LIMIT) / TICK_HZ)` —— 与时限同一 tick 数推导，没另造常数。
