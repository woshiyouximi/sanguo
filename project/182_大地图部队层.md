## 2. 现有行军数据模型（第 1 步：先读，不猜）

**读的地方就是 `save.armies`**（不是 `plans`，全文没有 `save.plans`）。元素结构（`dispatchArmy()` 造它，`campaign.html:2565-2583`）：

```js
save.armies.push({
  id: nextArmyId(),      // 'm<月>-<序>'，:1162 nextArmyId() 自增 save.armySeq
  side: 'A' | 'B',       // A＝我軍、B＝敵軍（读档整理 :5023 只允许这两个值）
  from: '代縣',           // 出發城名
  to: '晉陽',             // 目的城名
  pathIndex: 3,          // scenario.paths 的下标，由 marchPath(from,to) 得到
  progress: 0,           // 0..1；advanceArmies() 每月 +marchStep(pathIndex)
  troops: 100,           // 兵力（出征时从出发城扣掉）
  general: '關羽',        // 主將名（可能缺；seed 的 lost 形态就没有）
  reported: false,       // 已抵达是否已记账
});
```

三条与「部队层」直接相关的既有事实：

1. **路的合法性只有一份**：`marchPath(a, b)`（`:951`）遍历 `scenario.paths`，`(Number(p.Length)||0) >= SENTINEL_LENGTH(30000)` 跳过哨兵路，返回 `pathIndex` 或 `null`。→ §6 的改道校验**直接调它**，没有第二套。
2. **每月走多少**：`marchMonths(pi) = clamp(ceil(Length/100), 1, 3)`（`:962`）；`marchStep(pi) = MARCH_PER_MONTH(1/3) * (3/marchMonths(pi)) = 1/月数`（`:968`）。所以 `progress` 每推进一月 +1/月数，1–3 个月到城下。
3. **存档里没有的字段**：`save.armies` **没有 advisor/军师**、**没有武将数组**（一支部队只带 1 名 `general`）、**没有驻扎/分兵**。这是 §7 两项灰字的根。

**改动前的地图并不是完全不画部队**：`drawMap()` 里原有一段 `:3105-3135` 的「行軍部隊」loop，用 `armyPos→toScreen` 画一个 21px 三角箭头 + `sy-34` 兵力标签。问题是：①三角箭头不像原作的小旗；②**没有点击**，点上去只会命中附近城的 `hitCity`。这次是把这段升级成「小旗 + 可点」，不是从零新建（现位置 `:3132`：`for (const it of armyScreenList()) drawArmyMark(g, it);`）。

## 3. 坐标公式（用现有投影，没另造一套）

### 3.1 三个坐标系

| 坐标 | 是什么 | 谁给 |
|---|---|---|
| **数据坐标** | 底图 `map_sheet.png` 的像素（1280×960），城的 `pos_xy`、路的 `points` 都在这一层 | `scenario` |
| **canvas 内部分辨率** | `view.w × view.h`，随 `#mapwrap` 尺寸变化（正常 750×761，选点态 750×1334） | `syncView()` `:2867` |
| **视口 CSS 像素** | 用户实际点到的位置（窗口 900×1500 时 stage 被 `fit()` 缩放到 1.1245…） | 浏览器 |

### 3.2 进度 → 地点 → 屏幕

```
progress --marchLerpPoint()--> 数据坐标 --toScreen()--> canvas 坐标
```

`armyPos(a)`（`:1126`，本次只留下一个真源）：
1. 取 `scenario.paths[a.pathIndex].points`，过滤掉非数组/长度<2/非有限数的点；
2. 点不足 2 个时用 `cityOf(p.Start/p.End).pos_xy` 兜底（老数据只有首尾）；
3. **方向**：`a.from === p.End && a.from !== p.Start` 时 `progress` 要镜像（否则部队「倒着走」）；
4. 返回 `marchLerpPoint(pts, a.progress, reverse)`。

`marchLerpPoint(points, progress, reverse)`（`:998`，纯函数）按**段长**插值（不是按点数）：

```js
const t = marchClamp01(progress);
const along = reverse ? 1 - t : t;
// 逐段累加 hypot，找到 want = along * total 落在那一段，段内线性插值
```

`toScreen(x, y)`（`:2891`，既有）：
```js
const r = plotRect();                     // {x, y, w, h, s}，按 CITY_BOX{88,84,1138,860}+CITY_PAD 26 定标
return [r.x + (x - MAP.x0) * r.s, r.y + (y - MAP.y0) * r.s];
```

所以整条链是：`progress →(marchLerpPoint) 数据坐标 →(toScreen) canvas 坐标`。**没有新的投影函数**，和城图标吃的是同一套 `plotRect/toScreen`，所以选点态把 HUD 藏掉、`#mapwrap` 变高之后，只要重算一次 `syncView()` 城和旗就一起跟过去（`syncPickLayout()` `:2755` 就是干这个的，注释写明了为什么必须重算）。

### 3.3 多支部队叠在一起

`marchStackPlace(base, MARCH_STACK_GAP=13)`（`:1032`，纯函数）：九宫格优先序 `原地 → 右 → 左 → 下 → 上 → 四角`，给每支找第一个「与已放置的都 ≥13px」的槽；全冲突才留在原地。同一批输入永远得到同一组位置。

**关键**：绘制与命中吃**同一份** `armyScreenList()`（`:2605`）：

```js
const list = MARCH_ON && save ? (save.armies || []).filter(a => a && a.id) : [];
const base = list.map(a => toScreen(...armyPos(a)));
const placed = marchStackPlace(base);
return list.map((a, i) => ({ a, x: placed[i][0], y: placed[i][1] }));
```

「旗画在这里、点击命中的却是那里」这种 bug 从结构上排掉了。

## 4. 画部队 + 命中

### 4.1 画（`drawArmyMark()` `:2625`，替换掉原来的三角箭头 loop）

```js
for (const it of armyScreenList()) drawArmyMark(g, it);
```

| 层 | 尺寸 | 颜色 | 为什么要有 |

### 4.2 命中（`hitArmy()` `:2613` + `marchHitArmy()` `:1054`）

- 判定方式：**圆**，不是方框（斜着点到也算，和画出来的旗视觉一致），取最近的一个；
- 半径：`MARCH_HIT_R = 16`（任务要求 ≥14；`tests/march_ui.test.ts` 有断言 `MARCH_HIT_R >= 14`）；
- 坐标：**必须先换算到 canvas 内部分辨率**，和城共用同一套：

```js
const r = ev.target.getBoundingClientRect();
const px = (ev.clientX - r.left) * (view.w / r.width);
const py = (ev.clientY - r.top) * (view.h / r.height);
```

- 优先级（`$('map')` click `:3193`）：**选点态 → 部队 → 城**。部队先判是因为小旗半径 16px 远小于 `hitCity` 的 40px（`HIT_R = 40`，`:2897`），后判会被附近的城抢走点击。

实测：真鼠标点在 `(451, 406)`（viewport CSS 坐标）→ 兵团指令弹出、`sel='m1-5'`，`hit:true`。

## 6. 变更目的 → 全屏选点态

### 6.1 进入

`enterPickMode(id)`（`:2763`）：非 A 侧直接 `toast('敵軍兵團不能變更目的。')`；否则 `pickArmyId=id` → `closeOverlays()`（菜单当场消失，**不弹确认框**，照 178 §2.2）→ `stage.classList.add('pick')` → `syncPickLayout()`。

样式（`:220-232`）：
```css
#stage.pick #pickBar, #stage.pick #pickCue{display:block}
#stage.pick header, #stage.pick .tabs, #stage.pick #list, #stage.pick #logbox,
#stage.pick footer{display:none!important}
#stage.pick #mapwrap{max-height:none!important}
```
顶部匾 = `#pickBar`「請選擇兵團目的城市」（`:279`，金边深底、居中 23px），下面一行小字 `#pickCue` 写操作法（原作没有这行，本作补，因为竖屏没有说明书）。`#notice` **故意不藏**：选点态里点错城要靠它说原因。

### 6.2 点城 → 校验 → 改道

```js
if (pickArmyId) { const dest = hitCity(px, py); if (dest) applyRetarget(dest.NAME); return; }
```

`applyRetarget()`（`:2785`）唯一一道校验是纯函数 `marchRetargetCheck(a, city, marchPath, mine)`（`:1078`）：

| 情形 | 结果 |
|---|---|
| 目的地就是当前目的 | 拒绝「兵團的目的地已經是 X。」 |
| 目的＝出发城 | 拒绝「目的城不能是出發城 X：部隊要回城請用『進入城內』。」 |
| `marchPath(from, dest) === null` | 拒绝「…沒有可行道路：兵團只能改為與出發城相鄰的城。」（**道路合法性完全走 `marchPath`，没有第二套**） |
| 目的是我方城 | 拒绝「X 是我方城池：本作兵團只能開往敵城或空城。」——因为 `handleMarchEvents` 的 A 侧抵达分支只处理「到敌城下」，往自家城走会没有落点 |
| 其它（相邻、非本方） | 通过，`{ok:true, pathIndex}`（**pathIndex 可以是 0**，测试钉住了） |

失败 → `notice(why, 5000)` 并**留在选点态**（换一座城再点）；成功 → `a.to / a.pathIndex / a.progress=0 / a.reported=false` → `pushLog('兵團改道：…')` → `persist()` → 退出选点态 → `render()` → `notice(...)`。

实测：代縣 出发的 A 侧部队，全 60 城过一遍 `marchRetargetCheck`，**只有 `易京 pathIndex:3` 通过**（代縣只与 易京 相邻且 易京 非我方）；点 易京 后 `{to:'易京', progress:0}`，战报出现「兵團改道：代縣 → 易京（1 個月）」。

### 6.3 取消

`exitPickMode()`（`:2775`）：右鍵（`stage` 的 `contextmenu`，`:3211`）或 `Esc`（`window` 的 `keydown`，`:3216`）→ 清 `pickArmyId`、去掉 `.pick`、`syncPickLayout()`、`render()`，并 notice「已取消變更目的：兵團照原路走。」。原作没有取消按钮，只能退，这里保持一致。实测两条都通（`picking:null, pickMode:false`）。

## 7. 做不到的项（明说 + 原因）

1. **部队驻扎** —— 按原作**置灰**。原作这一行本身就是灰字（帧上字面是「部队驻防」，任务书与 178 写作「部队驻扎」，UI 按任务用「部队驻扎」，灰字行为与位置一致）；本作 `save.armies` 也没有驻扎/分兵字段，`save.cities[x].troops` 是唯一的守军口径。要真做，得先定义「驻扎 = 部队进城的另一种？还是原地不动 + 消耗？」这套数值原作里没有，我不敢自创。
2. **任命军师** —— 置灰。`save.armies` 只有 `general`，没有 `advisor`；原作「军师」一栏和金旋本人同名，即**主将兼军师**。7 行军情里如实写「關羽（主將兼）」，不编一个军师出来。要做真，需要先给部队加 `advisor` 字段并接上军师技（`wises` 那套），超出本任务授权（`save.armies` 的结构在 `:5021-5030` 的读档整理与 `handleMarchEvents` 一带被既有逻辑钉着）。
3. **进入城内（部分场景）** —— 功能能用，但只在「部队停在我方城上」时。停在**敌方城**上不能进城（`X 不是我方城池`）——那不是「进城」而是「攻城」，属于 `handleMarchEvents` 的抵达结算，不该由兵团指令绕过。

## 11. 与原作的差异（都是竖屏/数据口径带来的，不是漏做）

1. **竖屏 letterbox**：原作是 640×480 横屏，选点态地图铺满；本作 750×1334 竖屏，地图按 `CITY_BOX` 比例居中，顶部匾上方会留一条裱带。没有为了「填满」去裁切或拉伸地图（会切掉 西凉/襄平）。
2. **部队**：原作是「骑马小人」，本作是「旗 + 骑座」的极简写法——11×8px 见方时，能读出的信息只有**阵营色**和**在路上**，画写实小人反而糊成一团。这是 §4.1 的刻意取舍。
3. **兵数**：原作兵团指令里写「兵数 30」；本作同样有，且**额外**在选中的旗上方挂一个兵力牌（平时不挂）。
4. **军师 / 武将数**：原作「军师 金旋 / 武将数 1」；本作「關羽（主將兼）/ 1」——同一事实的两种写法。
5. **金钱**：原作是**这支部队**的金钱；本作国库存的是单一钱袋，所以写「勢力共用」，不假装是部队私有。
6. **地形**：原作 `目前所在地形 城`；本作区分 `城（X）` / `平原（路上）`（`marchAtCity`），信息只多不少。
7. **立绘**：原作兵团指令右栏左上有一张立绘；本作没在 `#armySheet` 里放立绘（位图的兵团指令框是竖向 5 项 + 右侧面板，竖屏塞不下），立绘在「武将资料」里给（`window.SG.portraitUrl`）。

## 12. 已知问题 / 后续

1. **选中态与城选择互斥**：点空地**不会**清 `armySel`（只有点到城时才 `armySel = null`），所以关掉面板后那圈金环还留在地图上——这是**故意的**（那是「当前兵团」），但玩家可能以为是残留。想关掉的话在 `closeOverlays()` 里清 `armySel` 即可；我没做，因为 `#armyFoot` 那句「點地圖其他部隊可切換」要靠它。
2. **`#armySheet` 打开时点不到地图**：scrim 盖住了。要切换部队得先关面板（或点面板里的「×」）。原作也是一层一层退，暂不改。
3. **`progress:0` 的部队与城图标重叠**：旗正好画在城图标上，缩略图上看起来像「城上插了面旗」。这是 `armyPos` 的必然结果（progress 0 = 出发城中心），原作同样重叠。
4. **`park()` 探针只挂在 `?armyui=1`**：给验收/回归用，正常玩法不参与。
