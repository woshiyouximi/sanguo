## 1 空城占位将

**根因（两处叠加）**
- `game/src/core/garrison.ts:489-546` `battleSetup()`：城池没有守将时 `chief = pickCommander([])` 为 `undefined`，
  返回 `enemyGeneral:{ name: chief?.name ?? '守將', str: chief?.str ?? 0, int: chief?.int ?? 0 }`。
  即「守將 / 武0 / 智0」是**核心层给空城造的占位对象**（`enemyParams` 同时为 `null`）。
- 显示层把它当真人：`deploy.html` 情报行照抄 `守將 ${enemy.enemyGeneral.name}（武 ${str} / 智 ${int}）`；
  `main.js` 在没有 `?bgen=` 时又补一个 `'守將'`（原 `main.js:600` 一带的 `cfg.city ? '守將' : '張角'`），
  于是战斗页、战报、招降/斩首名单里都会出现一个叫「守將」的 0 属性武将。

**改法（不改 `src/core/**`，因为那是别的 agent 的地盘）**
- `deploy.html:277` `const enemyChief = enemy.enemyParams ? enemy.enemyGeneral : null;`
  —— 用 `enemyParams === null` 作「空城无守将」判据（`garrison.ts` 自己在注释里就这么定义）。
- `deploy.html:444-449` 情报行改成：
  `守將 公孫瓚（武 86 / 智 70）` 或 `守將 無（空城：只有城內民兵，沒有武將）`。
- `deploy.html:503-508` 空城**不再**往战斗页传 `bgen/bstr/bint/bmorale`（原来会传「守將」）。
- `main.js:607` B 方兜底名由 `'守將'` 改成 `''`（空名 = 没有武將）。
- `main.js:773-790` 结算名单加 `realName()` 过滤，`'守將'` / 空名不进「招降 / 招降失敗 / 斬首」。
- `main.js:849-874` 战后写回（疲劳/士气）跳过空名 B 方：以前会往存档写 `tire[""]`，提示条也会出现
  「疲勞 甲 0→15、 0→15」这种断句。

**证据**

## 3 君主「自己继位」

**根因（在 `monarch_model.js`，不在 campaign）**
- `campaign.html:2811-2850` `kingFell(formerOwner, deadName, …)` 的 `deadName` 是「失守城的太守」
  （`:2610` 传 `r.oldMajor`、`:2796` 传 `garrisonIn(atk.to)?.major`），**未必是现任君主**；
  而老的 `kingDeath()` 直接把 `opts.dead` 当君主死讯处理，只把它从继任候选里排掉。
- 继任排序 `successionScore = 同族×10000 + 忠诚×100 + str+int`，**现任君主本人也在候选池里**。
  于是「太守死了」→ 现任君主（常常就是势力 id，如「嚴白虎」）以最高分当选继任者 →
  `inheritForce` 把 `forces[f].king` 设成它自己 → campaign 打印
  `` `${formerOwner} 君 主 陣 亡：${res.heir} 繼 位` `` ⇒ 「嚴白虎 君主陣亡：嚴白虎 繼位」。

**改法（`game/web/monarch_model.js`）**
- `:267` `successionList()` 新增 `opts.king`：现任君主不进候选
  （`:273` `if (!o || o.name === dead || (sitting && o.name === sitting) || o.name === '盜賊' || seen.has(o.name)) continue;`）。
- `:395-403` `kingDeath()` 新增守卫：`const sitting = str(f?.king) || id;`
  **死者必须等于现任君主**，否则 `return { dead:false, reason:'not-monarch', deadName, monarch }`。
  `campaign.html:2838` 那句 `if (!res?.dead) return res;` 会让它**静默跳过**——战报不会再写、
  君主不会被换、`wasPlayer` 的 notice 也不会弹。
- `:410` `pickSuccessor(id, officers, { dead, king: sitting })`；`:413/:416` 返回值补 `deadName`，
  `res.deadName` / `res.monarch` 可让调用方（campaign 以后的战报文案）写出「谁死了」而不是「势力名死了」。

**为什么不用改 campaign**：`kingFell` 已经对 `!res.dead` 做了静默返回，守卫一加，
「太守死」这类误报自动消失；真正的君主死亡（`dead === king`）路径一个字节都没变。

**证据**（`work/ux83/p3_monarch.mjs`，用真存档的势力/君主重演，并内联重算改前算法做对照）
| 场景 | 改前 | 改后 |
|------|------|------|
| A 太守「鄒丹」死，君主嚴白虎活 | `heir:'嚴輿'`，`king` 被改成嚴輿（**君主被人顶掉**） | `dead:false, reason:'not-monarch'`，`king` 仍是嚴白虎 |
| A2 同上，但君主本人是最高分（89 原文） | `heir:'嚴白虎'` ⇒ 战报 `嚴白虎 君 主 陣 亡：嚴白虎 繼 位` | `dead:false`，战报不写 |
| B 君主本人真死（`dead===king`） | `heir:'嚴輿'` | `heir:'嚴輿'`（不变），战报 `嚴白虎 君 主 陣 亡：嚴輿 繼 位` |
| C 最后一座城也丢（`remaining:0`） | 灭亡 | 灭亡（不变），残将 `嚴輿/王晟 → wild` 进 `save.fate` |
| D 公孫瓚（king 已传公孫越）丢城、太守公孫續死 | 会换掉公孫越 | `dead:false, reason:'not-monarch'`，king 仍公孫越 |

### 6.2 通知默认 6s + 点击可关（问题 4 的最后一环）
`campaign.html:1261-1268`：

```js
function notice(msg, ms = 6000) {                 // 原 9000
  const el = $('notice'); if (!el) return;
  el.textContent = msg; el.hidden = false;
  el.style.cursor = 'pointer';
  clearTimeout(notice._t);
  notice._t = setTimeout(() => { el.hidden = true; }, ms);
}
// 加一次（模块顶层）：点一下立刻关
$('notice')?.addEventListener('click', () => { clearTimeout(notice._t); $('notice').hidden = true; });
```

现有调用点里把 `12000/14000` 保留即可（这就是「重要提示 12s」那一档）；
`campaign.html:1139` 那句「戰鬥結果已寫回，自動存到槽 N」建议改成 `notice(…, 6000)`，
