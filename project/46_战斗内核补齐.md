### R23 的一处任务书纠错（重要）

任务书写「最大技力 = `BaseMP + level*2*INT/100`」，但 `docs/04b:225-238` 与 `docs/04c:293` 写的是：

```
t = (STR > INT) ? (STR+INT)/2 : INT;      // 注意：只有武力>智力时才取平均
mp = BaseMP + (level*2*t)/100;  if (mp < BaseMP) mp = BaseMP;  if (mp > 0x7FFF) mp = 0x7FFF;
```

我按文档实现（`battle.ts:603`），并写了一条专门测这个分支的用例（`R23 mpCapOf 的 t 只在武力>智力时取平均`）。
副作用：智力 ≥ 武力的武将，技力上限基本不涨（例如 60/60 的 1 级主将 `mpMax = 61`，旧代码是 90）。

### R47 的结论（把 37a §四-1 的矛盾判掉）

- `0x442EFA` 建单位时 `[+0x4c] = 0xea60`（60000） → **这是初值**；
- `0x43E964` 每 tick `cmp [+0x4c],0x1d4c0 / jle` 再写回 `0x1d4c0`（120000） → **这是上限**；
- `0x43BAE3` 的消耗 = `MagicDef.POWER × 0x1d4c0 / 0x64` = `POWER × 1200`；`data/magics.json` 110 行 POWER **全为 100**
  （`docs/03a:53,131,484` 也印证「POWER 恒 100」）。

⇒ 一次武将技 = 120000 = **一整条**气力；开战只有半条（60000），所以**开局放不出技**，必须等回复。
`docs/04b:17/32/91/210/273/381/636` 把 60000 说成「满」是错的，`04b:273` 的「60000÷1200=50」也错（应为 120000÷1200=100）。

这条改变的手感很大（原本 `QI_COST_SCALE=120` 时一次技只花 12000，气力条根本用不完），但它是有地址的。

### R59 的关键推理（为什么「击杀×6/×12」就等于「带兵差×6/×12」）

`0x41048D` 里的 `unitL+0x14` / `unitL+0x18` 是**开战瞬间的步兵/骑兵快照**，`gL+0x44` / `gL+0x48` 是**战后**的同一对字段。
所以 `(unit+0x14 − g+0x44) = 步兵损失`、`(unit+0x18 − g+0x48) = 骑兵损失` ——
它和旧代码 `killsInf*6 + killsCav*12` 代数等价，只是旧代码走的是统计值、原作走的是两次快照差值。
为了「逐字对形」，现在 `SideRuntime` 多了 `startInf/startCav/aliveInf/aliveCav`（`battle.ts:242-246`，`battle.ts:473-475` 初始化、
`battle.ts:1008` 在 `recompute()` 里按 `kind` 数活口），`warMeritOf()` 直接吃这四个数并 `max(0, …)`。
