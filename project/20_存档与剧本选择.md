## 1. 舊版問題

| 舊行為 | 問題 |
|---|---|
| 只有 `localStorage['sanguo_campaign_v1']` 一份 | 開新局 = 蓋掉舊進度；不能多存檔；換劇本無入口 |
| `scenarios.json` 固定取 `[0]` | 5 個劇本（184 / 189 / 200 / 208 / 219）只能玩第一個 |
| 重啟後只能繼續當前盤 | 想回頭看某一月沒有辦法 |

## 2. 數據來源與劇本名

- `game/data/scenarios.json`：5 項，每項 `{ id, system:{YEAR,…}, cities[60], paths[116], kings[] }`。
- `game/data/sango_system.json`：`Times01 … Times05`，值形如 `"Times1.INI, 黃巾之亂"`，**取逗號後半**做劇本名（`Times01` 對應 `scenarios[0]`）。
  - 黃巾之亂 / 討伐董卓 / 群雄割劇 / 赤壁之戰 / 三國鼎立（`scenarios[2].system.TIME` 是「群雄割據」，以 `Times` 名為準）。
- 初始三城 = 該劇本 `cities` 前 3 個（襄平 / 北平 / 代縣），城池運行狀態由 `min(floor(POPULATION/2500)+110, 600)` 等公式生成，與舊版完全一致。
- 道路圖：`paths` 中 `Length >= 30000` 是「畫了線但不可走」的哨兵，不進 BFS 鄰接表（沿用舊邏輯）。

## 3. `localStorage` 佈局

```json
// sanguo_saves_v1
{
  "v": 1,
  "last": 1,
  "slots": [ entry | null, null, null, null, null, null, null, null, null, null ]
}
```

```json
// entry（slots[i]，i 從 0 開始；UI 的「槽 i+1」）
{
  "id": 1,
  "name": "槽 1",
  "time": "第1年3月",
  "ts": 1795519824024,
  "scenario": 4,
  "scenarioName": "赤壁之戰",
  "month": 3,
  "gold": 1828,
  "ownedCount": 3,
  "wins": 1,
  "losses": 0,
  "snapshot": { "seeded": true, "scenario": 4, "month": 3, "gold": 1828, "wins": 1, "losses": 0,
                "defWins": 0, "log": [], "owned": ["襄平","北平","代縣"],
                "cities": { "襄平": { "troops": 147, "pop": 95379, "money": 3050 }, "…": "共 60 城" },
                "ts": 1795519824024,
                "captured": { "襄平": { "day": 2, "note": "戰後" } },
                "drops": [ { "name": "孫子兵法", "from": "襄平" } ] }
}
```

要點：

| 規則 | 說明 |
|---|---|
| `snapshot` 是完整 campaign 物件 | `owned / cities / month / gold / wins / losses / defWins / log / seeded / ts`，加上所有不認識的鍵 |
| **不做字段白名單** | `main.js`（另一人）正在往存檔裡加 `captured` / `drops`，讀寫都是整份 deep clone，原樣保留；`normalizeStore` 連頂層未知鍵也不刪 |
| `last` | 最近使用的槽（1..10），自動存檔的目標 |
| 深拷貝 | `writeSlot` / `getSnapshot` 都 `structuredClone`（失敗退 JSON），改記憶體物件不影響已存內容 |
| 髒資料 | 壞 JSON、越界 index、非物件 entry 一律降級成空槽，不拋錯 |

`game/web/saves.js` 導出：`SAVE_KEY / LEGACY_KEY / SLOT_COUNT / STORE_VERSION`、`emptyStore / normalizeStore / loadStore / saveStore`、`hasAny / lastUsed / newestSlot / slotAt`、`metaFromSnapshot / writeSlot / getSnapshot / clearSlot`、`readLegacy / writeLegacy / clearLegacy / migrateLegacy`、`cityTroops / cityState / newCampaign`、`slotParts / slotSummary`。

## 4. 自動存檔與手動存讀刪

| 觸發 | 行為 |
|---|---|
| 推進一月（單月） | 跳守城戰**前** `autosave()`（否則戰鬥寫回會蓋掉本回合 AI 結果）；回來後由下一條接管 |
| 推進一月（`?adv=N` 批次） | 每輪 `rollAI` 就地結算，循環結束 `autosave()` |
| 戰鬥寫回 | `main.js` 只寫 `sanguo_campaign_v1` 並更新 `ts`；下次進 `campaign.html` 時若 `legacy.ts > slot.snapshot.ts` 且劇本相同 → 採用舊鍵內容、`autosave` 回槽，消息欄提示「戰鬥結果已寫回」 |
| 手動「存」 | 寫指定槽，`last` 改成該槽，徽章跟著變 |
| 手動「讀」 | 深拷貝該槽 snapshot → 重建劇本/地圖/城池狀態 → `last` 改成該槽 → 舊鍵鏡像 |
| 手動「刪」 | 該槽設 null，10 槽容器不縮；刪的是當前槽時提示「下次自動存檔會重新寫入」；**全部刪光時一併清 `sanguo_campaign_v1`**，避免下次啟動把它當舊檔又遷移回來 |
| 新遊戲 / 換劇本 | 立刻寫當前槽（= 舊進度被覆蓋，見 §5） |

`persist()` 只做「`save.ts = Date.now()` + 寫舊鍵」，不寫槽——普通內政（徵兵/開發）不製造槽寫入，等下次自動存檔或戰鬥寫回再落盤；同一份進度不會因為點幾下內政而出現多個不同時間的槽。

## 5. 劇本選擇

- 標題列下方 5 張橫卡（`.sc[data-sc]`，當前劇本高亮），當前年份一併顯示。
- 點其它劇本：
  - 有進行中的存檔（`gameStarted`）→ 先彈確認浮層，文案明確寫「會覆蓋目前進行中的存檔（槽 N · 第X年Y月），並從該劇本的第 1 年 1 月重新開局。其他槽位不受影響。」→ 確定才切。
  - 尚未開局（首訪）→ 直接開選劇本浮層。
- 切換動作 = `applyScenario(idx)`（換 `scenario / ALL / cities`，重算 `adj`，重繪地圖與 5 卡、清空選中城）+ `newCampaign(scenario)`（前三城、金 1200、第 1 年 1 月、戰績清零）+ 寫當前槽 + 舊鍵鏡像。
- 首訪沒有存檔時：背景先按劇本 1 鋪地圖，但 `gameStarted = false`，強制彈「選擇劇本」浮層（沒有 × / 取消，必須選一個開始）；浮層裡 5 張卡列出年份、勢力數、城數、道路數、開局三城。

## 6. 啟動流程（`campaign.html` 頂層）

```
loadStore()                                   # 壞 JSON → 空容器
  ├─ ?demo=1 且空 → seedDemoSlots()           # 只給截圖/演示，正常流程不會進
  ├─ readLegacy()，有效 = owned 是陣列 或 seeded===true
  ├─ 有槽：bootSlot = last（該槽空則用 newestSlot）
  │    └─ legacy.ts > snapshot.ts 且同劇本 → 用 legacy（戰鬥寫回），autosave 回槽 + 提示
  ├─ 無槽但有舊檔 → migrateLegacy() 遷到槽 1 + 提示一次（見 §7）
  └─ 都沒有 → 劇本 1 背景預覽，gameStarted=false，彈選劇本
normalizeCampaign() / ensureCityState()       # 只補默認值，不刪未知鍵
render() → fit() → render()                   # 先渲染 footer 再量地圖高度
```

## 7. 舊檔遷移（任務 ⑤）

- 條件：`sanguo_saves_v1` 沒有任何非空槽，且 `sanguo_campaign_v1` 能 parse 成物件、且 `owned` 是陣列或 `seeded === true`。
- 動作：`migrateLegacy()` 把它寫進槽 1（`last = 1`），消息欄顯示「偵測到舊版存檔（sanguo_campaign_v1），已自動遷移到槽 1」（12 秒）。
- **舊鍵不刪**：`main.js` 的戰鬥寫回仍然只認 `sanguo_campaign_v1`，campaign 每次存檔都同步鏡像；遷移後兩邊內容一致。
- 已有任何槽時不遷移（`reason: 'has-slots'`），避免每次啟動重複覆蓋槽 1。

## 8. UI 結構

```
header  ├─ 大地圖  [劇本名 · 第X年Y月]  [存檔 / 槽 N]
        ├─ 金/城/戰績
        └─ 5 張劇本卡
#notice                    絕對定位 banner（遷移/讀檔/戰鬥同步提示）
#scrim + 3 張 .sheet
  ├─ #saveSheet   10 行：l1「槽 N · 劇本（使用中）」 l2「第X年Y月 · 城N · X勝Y敗 · MM-DD HH:mm」
  │               右側 存/讀/刪（空槽只剩「存」可用，讀/刪 disabled）
  │               footer：#saveMsg（提示 / 上次操作結果 flash）+ 新遊戲 + 關閉
  ├─ #pickSheet   5 張劇本卡 + 開局三城 + 「會覆蓋」警告 + 開始新遊戲
  └─ #confirmSheet 換劇本二次確認
```

- 浮層打開時 `#notice` 會被 scrim 蓋住，所以存/刪結果同時寫進 `#saveMsg`（`flash()`，7 秒後復原提示文案）；讀檔會關浮層，`#notice` 直接可見。
- 空槽顯示「槽 N · 空 / 可存入目前進度」。
- 徽章：`槽 N` / `未開局`。

## 11. 已知限制 / 後續

- 槽不可重命名（原名固定「槽 N」），也未做縮略圖。
- `localStorage` 寫入失敗（配額滿 / 隱私模式）時 `saveStore` 返回 false，目前 UI 只依返回值跳過徽章更新，沒有明確報錯。
- 沒有雲端/跨設備同步；換瀏覽器 = 新檔。
- 舊存檔遷移只在「一個槽都沒有」時發生；若玩家已有槽又想併入舊鍵，得手動清空槽或自行處理。
