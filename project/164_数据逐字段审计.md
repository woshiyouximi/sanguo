## 2. 差异清单 · 已修（2 处，都是真差异）

### 2.1 `盜賊` 的 `Loyal` 键名不统一 〔确认〕

* 原作 `TIMES1..5.INI` 的 401 个 `[GENERAL]` 段里，**400 行用 `Loyal`，只有「盜賊」一行用大写 `LOYAL`**，值是空串。
* 本作 `game/data/generals.json:41` 原样照抄了这个异形键名 `"LOYAL": ""` → 于是所有按 `typeof g.Loyal === 'number'` 读忠诚度的代码（`src/core/battle.ts:2939`、`src/core/capture.ts:163` 的 `row?.Loyal ?? 50`）对盜賊会 fallback 成 50，而不是原作的空值。
* 修法（只改数据，不动结构）：`game/data/generals.json:41` `"LOYAL": ""` → `"Loyal": ""`。
* 影响面：盜賊是 id 0 的模板行，`campaign.html:1123/1332/2147/3150` 与 `deploy.html:324` 全部显式 `NAME !== '盜賊'` 跳过，`garrison.json` 里 0 次出现 → **无运行期副作用**。
* 审计侧：`cmp_generals.mjs` 对 `Loyal`/`LOYAL` 做大小写归一再比（视作同一字段），所以改名前也不产生假差异；改名后键集与其余 400 行一致。

### 2.2 `孫尚香` 的 `BLOOD` 每剧本不同，单值字段装不下 〔确认〕

* 原作 5 个剧本里只有她一个人 `BLOOD` 变化：`T1/T2/T3/T5 = 孫堅`，**`T4（群雄割據）= 孫權`**。
* 本作 `generals.json` 的 `BLOOD` 是单值，只能存 `孫堅` → T4 这一格与原作不符。
* 修法（按任务书 B.1，加可选字段、不动单值）：在 `game/data/generals.json:9858` 给她加
  `"BLOOD_by_times": ["孫堅","孫堅","孫堅","孫權","孫堅"]`，`BLOOD` 保持 `孫堅`（= T1 值）。
* 读取方现状：`BLOOD` 在 `game/src`、`game/web`、`game/tests` 里**没有任何读取方**（`campaign.html:11` 只有一个 CSS 变量 `--blood`），所以本次不需要、也不应该改代码；将来若要做「按剧本的血缘/家族」，约定读 `BLOOD_by_times[scenario] ?? BLOOD`。
* 审计侧：`cmp_generals.mjs` 的 `generals_era` 子表对每剧本取 `BLOOD_by_times[s] ?? BLOOD` 比对 → 修前 1 条差异，修后 0 条。

## 5. 审计实现（为什么可信）

* **独立解析器**：`work/data_audit/lib.mjs` 自己解 INI（`parseIni`），不复用 `extract/json` 的既有 parser —— 审计与被审计的解析链彼此独立，避免「同一个 bug 两边都错」。
  * 处理了原作脏格式：`KEY   = value ` 两侧空格、`#Flags` 注释行、`[DEFINE]` 里的自由文本行、`TIMES` 的 `Loyal`/`LOYAL`、`UseForce` 单值被本作包成单元素数组。
* **按单元格计数**：每格都记录 `(行标签, 行下标, 字段, 原作值, 本作值)`，差异逐条可定位；`null` 与 `''` 严格区分（这正是能抓 `盜賊.Loyal` 那种问题的关键）。
* **二级交叉校验**：宝典（简体 XLS）与反汇编表（`docs/04b`）各一套独立比对；只有「INI ↔ 宝典 ↔ 反汇编表」三方都一致才认定 0 差异。地形/阵法里 EXE 独有、INI 没有的列（`terrains.vs`、阵法第 10/11 列）只由反汇编表兜底。
* **负数自证**：`--mutate 表:行:字段=值` 把「本作侧」某格替换掉，测试里 5 条常驻断言要求每张核心表都必须能被注入抓红。

## 7. 踩过的坑（写下来省下一次）

1. **`xls_物品.json` 的行序被按 `Sort` 升序重排过。** 47..51 段 INI 是 `春秋左傳39/史記38/孟德新書37/兵書24篇36/孫子兵法35`，宝典是 `孙子兵法35…春秋左传39`（正好倒过来）；52/54 的 `太平要術42` 与 `遁甲天書40` 也互换。按行号对齐会造出 **20 条假差异**（`48:孙子兵法 Sort 原作35/本作39`、`INT 20/7` …）。改成**用 `Sort`（1..77 唯一）作稳定键**后 0 差异。→ 教训：跨源比表先找**稳定键**，别信行号。
2. **`Loyal` vs `LOYAL`**：只查大写会得到 1011 条假差异（每个守将一条）。→ 教训：比对前做键名归一，并把「原作本身不统一」记进报告。
3. **`UseForce` 在本作被包成单元素数组**（`["刀"]`）而原作是标量 `UsseForce=刀` → 401 条假差异。→ 比对时对标量字段拆单元素数组。
4. **`null` ≠ `''`**：`normScalar` 故意不把 `null` 当空串，才抓得住「字段缺失」与「空值」的区别。
