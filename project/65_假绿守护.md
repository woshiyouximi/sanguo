## 3. 打折扣 / 補不上的地方（如實記錄）

1. **R16 / R40 是「負證據」**：只能掃描字串是否存在，不能證明「沒有這個子系統」。已加正向控制（同批語料必須找得到 `搜索`/`ATTACK`/`hitChance`/`命中`）避免空掃描誤綠；但若有人用未列舉的別名（例如「決鬥」「一騎討」）實作，本測試抓不到。要真正守住，得靠「候選命令表只有 N 條 + 命令分派 switch 無單挑分支」這類結構斷言；本輪沒有做（沒有穩定介面可取）。
2. **R3 / R29 顯示層沒有 DOM**：`campaign.html` / `deploy.html` 是無 bundler 的瀏覽器腳本，本輪做的是「源碼契約」（正則斷言模板字串、檔位清單、滑杆屬性），不是真的渲染結果。這比 🟢 弱，但比原本什麼都沒有強；要更強得引入 jsdom（目前 repo 沒有這個依賴）。
3. **R29 與 37a 自述不符（37a 該行需修）**：37a 寫「兵力檔位 10/50/100/200」，實現是 `[50,80,100]`、上限 `SOLDIER_CAP = min(GEN_LEVEL*5, 100) = 100`，**200 檔不可能存在**。測試按實現斷言並在測試裡明文標註；37a 這一行的 ✅ 依據應改成「50/80/100，上限 100」。
4. **R17 的「SearchType 決定等級窗」並未實現**：04b2 §5.3 的偽碼有 `SearchType 1 → ±4 級窗口、ST2 → level>=lvl-4`，實際 `searchPools` 只做「Force/Battle>0 且 ST0 → 法寶；ST1/2 → 寶物；其餘不進池」，`Level` 從頭到尾沒被讀。這是**實現缺口**而非測試缺口，測試只能斷言真實行為（分區），並在此記錄；不能寫一條注定綠不了的測試。
5. **R14 的 `Rate = 80/(Length+1)` 也沒有實現**：37a 自己就標了「鄰接判定有、Rate 無」。本輪補的是「鄰接」與「AI 調將 rate = clamp(24+…,24,28)」，不是 04c §3.2 的 80/(Length+1)；後者是待補的實現缺口。
6. **R1 的 docstring 與程式碼不一致**：`:309-314` 註解寫「用 RATE===0 判」，程式是 `RATE===0 || POPULATION===0`。資料上 12 座關卡兩者皆 0，所以行為等價；但註解是錯的（57 報告也是照註解寫的「RATE===0」）。測試按程式行為斷言（`{RATE:1,POP:0}` 也算關卡），並在此 flag 註解待修。
7. **R17 的「128 槽」語義**：docs 04b2 §5.3 的「128 槽 × 0x56」是**物品表容量**（不是搜索輪盤有 128 個獨立槽位）；輪盤是 `for(i=0;i<0x80;i++)` 掃這張表。測試的賬本按「物品表 128 槽（77 有碼 + 51 空）」建模，這與文件一致；若日後有人把物品表擴到 >128 件，賬本會紅，需要同步改文件與測試。
