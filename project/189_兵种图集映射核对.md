# 189 · 兵种图集映射核对（「士兵用的是不是原游戏资源」）

> 结论先给：**资源是原作的、映射没错、阵营没反**。玩家说的「不同兵种看起来一样 / 不像对应兵种」，
> 真实成因是 **屏上尺寸太小 + 二次重采样发糊**，不是选错组。本轮去掉了二次重采样（见 §5），
> 「太小」这一半给了像素级数字（§4），属于镜头/取景决策（§6.1 建议），没在本轮动。

## 1. 为什么先怀疑「用错组」

`game\src\view\unitFrames.ts:98` 的 `GROUP_BY_TROOP` 用 **`troops.json` 的数组下标**当键，
而原作 `SHAPE\FORCE` 的兵种是**字母**（A–M），且字母顺序与中文兵种顺序**不是字典序**：

```
troops.json 下标 →  0朴刀 1长枪 2大刀 3弓箭 4链锤 5飞刀 6武斗 7蛮族 8铁锤 9藤甲 10黄巾 11弩兵 12女兵
原作字母       →   A     C     D     F     I     H     J     K     E     L     M      B      G
```

只要有人按「A,B,C…」的直觉写表，就会整列错位而**看起来全都对**（帧名合法、组存在、不报错）。
所以本轮不查代码，直接查像素。

## 5. 改了什么：屏宽 66 → 75，让兵种帧 1:1 上屏

### 5.1 问题

`game\src\view\battleView.ts:1240` 原本写死 `const w = 66`。这个 66 是**老图集时代的口径**
（老 `atlas.json` 的帧画布是 80×104），换到原作 FORCE 图集（画布 **75** 宽）之后：

- 图集生成时已经从原作 100 宽窗口 LANCZOS 缩到 75（`frame_scale_k=0.75`）；
- 绘制时又按 `66/75 = 0.88` 缩第二次，而且 `imageSmoothingEnabled` 默认 `true`（`main.js` 全文件没关过）。

等于**两次重采样叠加（0.75 × 0.88 = 0.66）**，士兵边缘发软，还比原作小 12%。

### 5.2 改动（3 个文件）

| 文件 | 位置 | 改法 |
|---|---|---|
| `game\src\view\unitFrames.ts` | `:66-73` 新增 `UnitFrameSet.w` | 注释说明「帧画布宽 = 屏上该画多宽」 |
| | `:151` `w: canvasWidthOf(atlas, frames[0])` | 选套时把帧画布宽带出来 |
| | `:207-216` 新增 `canvasWidthOf()` | 取第一帧矩形宽（那 13 组恒 75），取不到给 0 |
| `game\src\view\battleView.ts` | `:1140-1155` 调用处补 `set.w` | 兵种图集路径把宽度传下去 |
| | `:1203-1219` `pushSpriteFrames(..., allowSwing, designW = 66)` | 新增可选参数，老路径/降级路径默认 66 不变 |
| | `:1240` `const w = designW > 0 ? designW : 66;` | 替换写死的 `const w = 66` |
| `game\tests\soldiers.test.ts` | 见 §7.2 | 口径注释 + 公式 + 2 处新断言 |

### 5.3 改前 / 改后（同一帧、同一 tick 的真实绘制调用）

用 `drawImage` 钩子录 8 参数调用（`work\troopmap\expr_sizes.js`）：


`dest = 75` 与源等价 → **viewScale≈1 时零重采样**；兵体在屏上大 13.6%（面积 +29%），
地面线不变（`battleView.ts:2473` 是 `drawImage(img, sx, sy, sw, sh, c.x - c.w/2, c.y - c.h, c.w, c.h)`，
**x,y 是底边中点**，精灵往上长；`battleView.ts:1115` 的阴影 `E(out, fx, fy+13, 12, 4, …)` 也不动）。

### 5.5 Cocos 侧：把「统一压成 52」改成按帧画布高 1:1（lead 批准后）

同一处口径问题在 Cocos 版本里更严重：`BattleRoot.ts` 原来把**每个**士兵的帧画布高统一压成 **52**，
链锤（94）和弩兵（70）在屏上一样高 —— 兵种的高矮差被抹平，也是「看起来都一样」的一部分。

| 文件 | 位置 | 改法 |
|---|---|---|
| `game\cocos\assets\scripts\BattleRoot.ts` | `:1264-1273` `setOf()` 返回值 | 加 `force: boolean`（FORCE 组 `true`、老 atlas 降级路径 `false`），让尺寸段能区分两套图集 |
| | `:1319` | `const h = general ? 72 : (set.force ? Math.max(1, Math.round(frame.rect.height)) : 52);` |

- 宽度仍由 `frame.rect.width / frame.rect.height` 反算（`:1321-1322`），所以帧画布宽 75 自然得到 75；
- 锚点没动：`:1326` `slot.node.setPosition(p.x - HALF_W, HALF_H - (p.y + 8) + h / 2, 0)` —— 脚线固定在 `p.y + 8`，
  `h` 只决定中心抬高量，**改高不会让脚下悬空**（截图里脚仍踩在阴影椭圆上）；
- 只改了 `BattleRoot.ts` 这一段，没碰别的文件。

改前 / 改后实测（`work\troopmap\steps_cocos_size.mjs` 读 `unitPool` 的 `box.contentSize`，画布 876×1368、设计分辨率 750×1334）：

| 兵种 | 改前 contentSize | 改后 contentSize |
|---|---|---|
| 朴刀 troop 0 | 53×52 | 75×74 |
| 链锤 troop 4 | 41×52 | 75×87 |
| 弩兵 troop 11 | 56×52 | 75×70 |
| 大刀 troop 2（默认对局） | 42×52 | 75×93 |

改前三种高度**全是 52 → 1 : 1 : 1**（lead 预期成立）；改后 **74 : 87 : 70 = 1 : 1.18 : 0.95**。
链锤量到 87 而不是 94，是因为帧是**逐帧裁边**的：`units.json` 里 `lianchui_walk_*` 的 h 依次
`94,87,87,89,91,91,93,94,93,93,94,96`，采样那一 tick 正好落在 87 那帧；整轮 walk 的极值是
链锤 87–96 / 朴刀 70–74 / 弩兵 69–70，本体 bbox 高 94 / 74 / 70（见 §4 表）。
换句话说：**「把高矮差抹平」这件事被去掉了**，链锤就是比弩兵高一截。

## 9. 为什么不上 k=1（裁决记录，2026-11-25）

lead 裁决口径：**「太小」不是缺陷，是竖屏把 6.7 列拉成 14 道的必然结果**。换算如下：

| 版面量 | 原作 | 我们（竖屏） |
|---|---|---|
| 战场宽 | 640 px | 750 px（`game\src\view\layout.ts:24` DESIGN_W） |
| 横向格/道 | 一格 **96 px** → 一屏 **≈6.7 列** | **14 道**（`game\src\core\battle.ts:46` `GRID_H = 14`，`:64` `LANE_PX = 750/14 = 53.57`） |
| 兵帧窗口 | **100 px = 15.6%** 屏宽 = **≈1.04 列** | 图集帧 **75 px** = 10.0% 屏宽 = **1.4 道** |
| 按「格/道」等比折算 | 1.04 列 | 1.04 × 53.57 ≈ **56 px ≈ 1 道**（lead 口径记 54） |

**结论：我们现在画 75 px = 1.4 道，比按版面折算的 56 px（≈1 道）还大 34%。**
那个「7.6% 屏宽」的百分比不能跟原作的 15.6% 直接比 —— 原作一屏只有 6.7 列，我们一屏 14 道，
「一兵占一道」在竖屏上必然只占屏宽的 1/14 ≈ 7%。比值差 2 倍是**版式差异**，不是资源/映射缺陷。

所以：

- **不上 `--k 1`**：k=1 要把 572 帧原像素塞进图集（6.3 MPx，单页 2048×2048 装不下），
  还得改 `web\main.js:598-599` 支持多页，换来的只是把 1.4 道变 1.9 道 —— 反而偏离原作比例；
- 也不上 `w=100/117` 直接上采样（更糊）；
- 当前口径（图集 0.75 LANCZOS + 屏上 1:1，即 75 px / 1.4 道）就是竖屏版式下的正确尺寸。
- 真要「显示得更大」，该动的是版式本身（一屏露几道 / `LANE_PX` / 战场带高度 `FIELD_H`），
  按「竖屏只改版式」的原则另开一轮，**不是兵种图集的 bug**。
