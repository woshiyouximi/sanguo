## 7. 逐兵坐标示例（N = 10 / 50 / 100）

人数变化时**不是**重新缩放阵形，而是：**先按权重把人数切成 5 个区（k_m = w_m × N / 200），
每个区按自己的数组从第 0 项顺序取坐标**。所以：

- `N` 越大 → 每个区多占几个 slot → 阵形"从中心向外长出来"（数组本身就是由内向外排序的）；
- 各区之间的**相对位置永远不变**（因为表里的 x、y 是绝对值，不是相对中心偏移）；
- 唯一的缩放项是 `(200 − N) / 25`：N 越小，整块阵形越**远离己方底线**（朝敌方推）。

**读法**：

- `N=10`：只有 10 个兵，被切成 m1=7（140×10/200）、m2=3（60×10/200），
  坐标落在 `(17,6)(17,7)(18,6)(18,7)…`——即数组前 7 项 + 第二数组前 3 项。

- `N=100`：满编，占据 `x 10..20 / y 2..11` 的 20×10 = 200 格矩形中的前 100 格。
- **A 侧镜像**：`格X = 71 − 格X`，所以同样的兵在 A 侧落在 `x 51..62`（左右对称，见最后一块）。

### 7.3 如果只想抄"一个公式"，抄这个

```text
给定：阵形号 a(0..8)、总兵数 N（步兵 Nf + 骑兵 Nc = N）、所在侧 side(A/B)
1) 锚点 ax = table[0x485DA8 + a*0x0C + 0x0A]
2) 对 mode m = 1,3,4,5,2（按此顺序，m 的循环游标全局递增，不重置）:
       kc = w_m * Nc / 200            // w_m = table[0x485DA8 + a*0x0C + 2*(m-1)]
       kf = w_m * Nf / 200
       先骑兵: slot 0..kc-1  取 arr[a][m][0..kc-1]
       再步兵: slot kc..kc+kf-1 取 arr[a][m][kc..kc+kf-1]
       对每个格 (tx, ty):
           X = tx + ax + (200 - N) / 25
           Y = ty
           if (side == A) X = 71 - X
           while (格(X,Y) 已被占) X += (X >= 54 ? +1 : -1)     // 避开列 54
           落地(X, Y)
```

## 9. 新游戏可直接复用的规则清单

### 9.1 数据结构（照抄即可）

```text
Formation {
    int16   w[5];        // 5 个分区的兵数权重，和必须 == 200（用"千分比"更好：和 == 1000）
    int16   anchorX;     // 该阵形的整体横向偏移
    Vec2i*  slots[5];    // 每个分区一个坐标数组，长度 == w[m]
}
```
- 坐标数组元素 = `{int16 x, int16 y}`，**按"由内向外"顺序排列**（第一批兵在中心，后面的在外围）。
  这是整个系统能"随人数自然生长"的关键：不需要任何缩放公式，截断数组即可。
- 索引空间留出 33 行：11 个"正常阵形"（9 种 + 亂陣 + 特殊）+ 2 组变形（+11 / +22）。

### 9.2 生成流程（6 步）

1. 取权重 `w[m]` 与锚点 `anchorX`；
2. 名额 `k_m = w[m] × N / 200`（步兵/骑兵各算一遍；`mode1` 用减法吃掉舍入余数，保证 Σk = N）；
3. 依次处理 `m = 1,3,4,5,2`（顺序会影响槽位编号，但不影响坐标集合）；
4. 每区内**骑兵优先**占低位 slot（骑兵靠近中心，步兵在外——符合"骑兵突击、步兵结阵"的直觉）；
5. 坐标变换：`X = tx + anchorX + (200 − N)/25`，`Y = ty`；A 侧 `X = 71 − X`；
6. 占位冲突则沿 X 轴微调 1 格（远离列 54）直到空位。

### 9.3 设计上的三个"手感"要点（都是原版实际效果）

- **满编时阵形最靠前**：`(200 − N)/25` 让残兵自动后撤，10 人时后撤 7 格、100 人时后撤 4 格。
  效果是"兵越少越缩在后面"，省掉了额外的"胆怯"逻辑。
- **阵形是绝对坐标，不是相对主将**：主将死了阵形不散，兵仍站在原位。
  （`unit+0x68` 的 4 个变体是唯一让阵形"相对化"的钩子，本版未启用。）
- **分区的几何含义是明确的战术分工**：
  方形 = 大方块 + 小方块（主力 + 预备）；圆形 = 窄前 + 宽后（护卫）；
  锥形/雁形 = 斜向 V（`a3` 每列 x+1 时 y 上下各扩 1，`y 0..13`）；
  玄襄 = 5 条带（前/后/上/下/中，四边形包围）；鱼丽 = 前中后三段；
  钩形 = 双翼上下张开（`(13,3)` 与 `(13,10)` 交替，是"钩"的形状）；
  冲锋 = 细长前段 + 上下两翼；箭矢 = 最窄最深（x 到 28）。

### 9.4 如果重做，建议改的三处

| 原版做法 | 问题 | 建议 |
|---|---|---|
| 权重和硬编码 200，`mode1` 用减法吃余数 | 某个 mode 的 `w` 为 0 时该区直接消失，容易出现"某区 0 人但代码仍在跑"的边界 | 改成"比例分配 + 最大余数法"，并显式跳过 `w==0` 的区 |
| 坐标数组是绝对坐标、每阵形 5 份 | 数据量大（33 行 × 最多 5 个 200 项数组 ≈ 3 万项），且无法参数化 | 改成**生成函数**（方形/圆形用行列式，锥形/钩形用角度+半径），只存参数 |
| 占位冲突沿 X 微调 1 格 | 密集阵形下会推出很远的"尾巴" | 改成螺旋/BFS 找最近空位，或直接允许重叠（原版战斗网格本来就允许 71×14 里挤 200 人） |
