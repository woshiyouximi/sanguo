## 0. 結論速覽

| # | 問題 | 結論 | 證據強度 |
|---|---|---|---|
| 1 | 撤退中的單位會不會進入攻擊分支（能不能還手）？ | **基本不會**。原作不是「在攻擊函數裡擋一條 `test`」，而是**在「選目標」那一步把搜索降級**：`0x43BCA7` 對 `0x4000` 態只探**朝向那一側 1 格**（`n=1`），再由 `0x43BD64` 兜底擋「回頭打」。攻擊執行鏈（`0x43D686`→`0x43D400`）**本身一道門都沒有**——所以撤退者能打到的，只有它逃跑方向正前方那一格。 | 【已證】 |
| 2 | 「46 幀」的時長在哪裡定（常量還是 46+2Δ）？ | **兩者都有**：基底是常量 `0x2E`（46）寫進 `u+0x34`（`0x43B5FA`）；另有一個**條件追加項** `+2×(X敵−X己)`（`0x43B647`），條件是 `GetState(u)&1`（`0x43B6A8`）。 | 46 常量【已證】；`+2Δ` 的條件位語義【部分證據】 |
| 3 | 「只倒走」是位移方向被取反，還是只允許後退動作？ | **都不是**。是「撤退命令 `cmd 8` 只給 `±x` 一個方向（朝本方邊界），走位器照給定的候選方位走」，並且**每次移動都把朝向強制改成「走的那一邊」**（`0x43BF34`-`0x43BF5A`）。所以「倒走」= 朝向永遠背對敵人，不是位移取反、也不是「只准退後動作」。 | 【已證】 |
| 4 | `0x8000`（離場）與 `0x4000`（撤退態）的置位/清除順序？ | **`0x4000` 先、`0x8000` 後**，且 `0x4000` 全場只置不清。`0x4000` 有 4 個置位點；`0x8000` 只有 2 個置位點，兩處都以「已帶 `0x4000`」為前提或緊隨其後。清除只發生在 `0x1000`，與這兩位無關。 | 【已證】 |

## 1. 取證方法

1. `F:\sanguo\work\orig_numbers\text_dis.tsv` 是 6.3 MB 全量線性反彙編，4 列：`地址 \t 連續hex字節 \t 指令 \t 操作數`。用自寫腳本 `F:\sanguo\work\r91_retreat\dis.py`（`range` / `func` / `callers` / `grep` / `markers`）按函數切片、按地址反查調用者。
2. 跳表用 `struct.unpack` 直接從字節列解碼（`0x43D0C9` 命令分派表 10 項、`0x43E193` sprite 消息表 13 項）。
3. **關鍵方法論**：對 `0x4000` / `0x8000` 這種「某一位到底在哪被讀」的問題，不做「我看了幾個函數都沒看到」的消極論證，而是**窮舉全鏡像的立即數出現點**：
   - `and/test ...,0x4000` 全倉 33 條 `0x4000`，其中**戰鬥內核只有 6 條是「讀」**（§3 全列）；
   - `push 0x8000` 全倉 8 條，戰鬥內核只有 1 條；
   - `call 0x43b51e`（SetState）全倉 13 處，`call 0x43b538`（ClearState）全倉 2 處且都清 `0x1000`。
   這樣得出的「沒有門」是**枚舉完備**的否定，而不是抽樣。
4. 結構偏移先辨清（這是過去文檔最容易混的地方）：
   - **unit**：`+0x08` x、`+0x0C` y、`+0x1C` 序號、`+0x20` 槽位、`+0x24` cmd 緩存、**`+0x2C` 狀態位 flags**（`0x43B50D GetState` 讀的就是它）、`+0x34` 行動計時器、`+0x38` 攻擊鎖定、`+0x40` 軍團基址（`0x4A8A60`/`0x4B03A0`）、`+0x44` sprite、`+0x84`（sprite 裡指回 unit）。
   - **sprite/actor**：`+0x08`/`+0x0C` 像素座標、**`+0x2C` 朝向**（0=右 / `0x800000`=左）、`+0x34` Process id、`+0x4C` 消息函數、`+0x90` 淡出計時。
   兩者都用 `+0x2C`，但一個是 flags、一個是朝向；`0x43D5BF`/`0x43DA1A` 裡那些 `[reg+0x2c]` 的 reg 全是 sprite，不是 unit（這也是 `work\re4000\52_disp2c_accesses_in_kernel.txt` 那三條「假線索」的真相）。

## 3. 正證骨幹：全鏡像 `0x4000` 的讀取點窮舉（共 6 處）

`grep "0x4000\b"` 在 6.3 MB 反彙編裡共 33 條，去掉 `cmp [ebp-x],0x4000`（區域/參數比較）、`push 0x4000`（置位）、非戰鬥子系統（`0x40xxxx`/`0x41xxxx`/`0x42xxxx`/`0x44xxxx` 的 UI/軍團/音效）後，**戰鬥內核真正「讀這一位」的只有 6 條**：

| 位址 | 所在函數 | 讀來幹什麼 | 屬於 |
|---|---|---|---|
| `0x43B5F1` | `0x43B574` 行動間隔 | 撤退態 → 間隔寫 `0x2E`(46) | 節奏 |
| `0x43B694` | `0x43B67F` `isRetreating` | 謂詞本體（callers：`0x43C132`、`0x43D7C7`、`0x43E983`） | 查詢 |
| `0x43BCD8` | `0x43BCA7` **選目標** | 撤退態 → 搜索降級（1 格 + 單向） | **選目標** |
| `0x43BD74` | `0x43BD64` **回頭打門** | 撤退態 + 方向與朝向相反 → 跳過攻擊 | **選目標** |
| `0x43C684` | `0x43C6xx` 走位失敗 | 撤退態 + x 越界 → 置 `0x8000` 離場 | 走位 |
| `0x43D8E4` | `0x43D8D2` 撤退位移 | 非撤退直接返回 | 走位 |

**沒有一處在命中/傷害/攻擊執行的函數體內。** 這就是「不還手」的正證：原作把「能不能打」完全交給**選目標**，而選目標對撤退態是「1 格 + 只朝自己朝向那一側」。

反過來說，`0x43D76C`（武將單向攻擊）裡那條 `0x43B67F` 查的是**被打的目標**：`0x43D7C7` 在「隔一格有目標，且該目標 `GetState&1`」時，若目標**不在撤退**就 `return 0`（不打）。也就是「隔一格的敵將，只有在它逃跑時才追打」——這是**追殺逃兵**的規則，不是「逃兵不能打」。

## 4. 四問逐條

### Q1 撤退中的單位是否進入攻擊分支？—— 不進入（在選目標處被降級）

**答案**：原作撤退單位**能打的只有「它逃跑方向正前方一格」的敵人**；側面/背後的敵人**永遠不會被選為目標**，因此不會還手。擋點是兩道：

#### 擋點 A：`0x43BCA7`（選目標）的撤退分支 —— `0x43BCD8`

```asm
0043BCCF  push     ecx
0043BCD0  call     0x43b50d           ; GetState(u)
0043BCD5  add      esp, 4
0043BCD8  and      eax, 0x4000        ; ★★★ 撤退態
0043BCDD  test     eax, eax
0043BCDF  je       0x43bd06           ; 非撤退 → 走「普通搜索」
0043BCE1  mov      dword ptr [ebp - 0xc], 1    ; ★ 撤退：掃描格數 n = 1（只探 1 格！）
0043BCE8  mov      edx, dword ptr [ebp + 8]
0043BCEB  mov      eax, dword ptr [edx + 0x44]  ; sprite
0043BCEE  cmp      dword ptr [eax + 0x2c], 0     ; sprite 朝向（0=右）
0043BCF2  jne      0x43bcfd
0043BCF4  mov      dword ptr [ebp - 0x10], 1     ; 朝右 → dir = +1
0043BCFD  mov      dword ptr [ebp - 0x10], 0xffffffff  ; 朝左 → dir = -1
0043BD06  mov      dword ptr [ebp - 0xc], 2     ; 非撤退：n = 2
0043BD0D  call     0x450132           ; rand()
0043BD12  and      eax, 1
0043BD15  lea      ecx, [eax + eax - 1] ; dir0 = rand()&1 ? +1 : -1
0043BD34  jge      0x43bd5e           ; 迴圈 i = 0..n-1
0043BD3E  call     0x43bbe6           ; r = 沿 dir 掃描
```

逐句：

1. 先 `--[u+0x38]`，還 `>0` 就直接 `return 0`（攻擊鎖定期，本周期不探敵）。
2. `GetState(u)` 取狀態位，`and 0x4000`——**唯一一處「撤退態改變搜敵行為」的判斷**。
3. 撤退態：`n = 1`（只掃 1 格），`dir` 取 **sprite 當前朝向**（右→`+1`、左→`-1`），**不擲骰**。
4. 非撤退態：`n = 2`（射程 2），`dir0 = rand()&1 ? +1 : -1`（隨機決定先掃哪邊）。
5. 迴圈 `i < n`：`r = 0x43BBE6(u, dir)`；`r != 0` 就返回（找到目標）；否則 `dir = -dir` 再掃一次。

所以撤退者**只會看到「自己面朝方向、1 格內」的那個敵人**。它背後（逃跑方向的反面）那一格、以及弓箭手原本 16 格的射程，全部被這一行 `n=1` 抹掉。

#### 擋點 B：`0x43BD64`「不許回頭打」—— `0x43BD74`

```asm
0043BD64  push     ebp
0043BD68  mov      eax, dword ptr [ebp + 8]      ; u
0043BD6C  call     0x43b50d                     ; GetState(u)
0043BD74  and      eax, 0x4000                  ; ★ 撤退態？
0043BD79  test     eax, eax
0043BD7B  je       0x43bdb5                     ; 非撤退 → return 0（對普通單位完全無影響）
0043BD80  mov      edx, dword ptr [ecx + 0x44]  ; sprite
0043BD83  mov      dword ptr [ebp - 4], edx
0043BD89  cmp      dword ptr [eax + 0x2c], 0     ; 朝向 == 右？
0043BD8D  jne      0x43bd9c
0043BD8F  cmp      dword ptr [ebp + 0xc], -1     ; 而 dir == -1（往左打 = 回頭）
0043BD93  jne      0x43bd9c
0043BD95  mov      eax, 1                        ; ★ 朝右卻往左打 → 1
0043BD9C  cmp      dword ptr [ecx + 0x2c], 0x800000  ; 朝向 == 左？
0043BDA6  jne      0x43bdb5
0043BDA8  cmp      dword ptr [ebp + 0xc], 1      ; 而 dir == +1
0043BDAC  jne      0x43bdb5
0043BDAE  mov      eax, 1                        ; ★ 朝左卻往右打 → 1
```

逐句：`0x4000` 不在就直接 0（所以普通單位走這條路是純 no-op）；撤退態才比對「朝向」與「這次要打的方向」——**方向與朝向相反就是「回頭打」，回 1**。

呼叫點在**每一幀行動**裡（`0x43D2FE`，小隊；`0x43EB95`，主將）：

```asm
0043D2F6  mov      edx, dword ptr [ebp - 0x10]  ; r（上一步掃到的方向 ±1）
0043D2FA  mov      eax, dword ptr [ebp - 0x14]  ; u
0043D2FE  call     0x43bd64
0043D306  cmp      eax, 1
0043D309  jne      0x43d310
0043D30B  jmp      0x43d392                  ; ★ 跳過整段攻擊序列（不攻擊，直接去結算走位）
0043D310  push     ecx / call 0x43b6c9       ; 否則繼續：算攻擊時長
```

逐句：`r` 是「目標在左還是右」，`0x43BD64` 判斷「撤退態且這個方向與朝向相反」→ 返回 1 → `jmp 0x43D392` **整段攻擊序列被跳過**。普通態這個函數恆返回 0（因為第一條 `and 0x4000` 就不成立），所以對非撤退單位沒有任何影響。

#### 攻擊執行本身：零道門

`0x43D686`（攻擊執行）全文沒有任何 `GetState`：

```asm
0043D69D  call     0x43af7a        ; t = 該格單位(a->x+dir, a->y)
0043D6B2  call     0x43b961        ; 若沒人：射程 > 1 → 揮空
0043D6C3  call     0x43d5bf        ; 揮空記錄（§2.1），return 1
0043D6E3  call     0x43b663        ; 同陣營？→ return 0
0043D6F9  cmp      dword ptr [ebp - 4], 1   ; flag==1 → 必中
0043D70A  call     0x43d400        ; 否則擲命中
0043D730  ...  call dword ptr [eax + 0x4c]   ; 命中：向 t 的 sprite 發 0x10004
0043D754  ...  call dword ptr [eax + 0x4c]   ; 未中：發 0x1000A
```

**結論**：「不還手」不是一條 `test` 擋在攻擊裡，而是「撤退者根本選不到背後的目標」+「就算選到了、方向與朝向相反也跳過」。要照抄，就必須改**選目標**，不能改攻擊。

### Q2 「46 幀」在哪裡定 —— 常量 `0x2E` + 條件追加 `2Δ`

`0x43B574`（行動閘門，逐行實測）：

```asm
0043B5DB  mov      dword ptr [ecx + 0x34], 0x28   ; ★ 先無條件復位 40 (0x28)
0043B5E8  push     u
0043B5EA  call     0x43b50d                       ; GetState(u)
0043B5F1  and      eax, 0x4000                    ; 撤退態？
0043B5F6  je       0x43b656
0043B5FA  mov      eax, dword ptr [ebp + 8]
0043B5FD  mov      dword ptr [eax + 0x34], 0x2e   ; ★ 撤退態 → 46 (0x2E)，同一個欄位
0043B604  push     u
0043B606  call     0x43b6a8                       ; GetState(u) & 1 ？
0043B60B  test     eax, eax
0043B60D  je       0x43b656
0043B614  call     0x43b9fc                       ; 取「對手單位」
0043B61D  call     0x4429fd                       ; X_自己 = 目前格 x
0043B626  call     0x4429fd                       ; X_對手 = 對手格 x
0043B641  mov      edx, dword ptr [ebp - 0x10]    ; X_對手
0043B644  sub      edx, dword ptr [ebp - 0xc]     ; Δ = X_對手 − X_自己
0043B647  mov      ecx, dword ptr [eax + 0x34]    ; 46
0043B64A  lea      edx, [ecx + edx*2]             ; ★ 46 + 2Δ
0043B64D  mov      dword ptr [eax + 0x34], edx
0043B656  mov      eax, 1
0043B658  ret                                     ; 返回 1 = 本幀可行動
```

要點：

1. **46 是常量**（`0x2E`），寫在和 40 同一個欄位 `u+0x34` 上，**不是** `46+2Δ` 的一個特例。
2. `+2Δ` 是**條件追加**，條件是 `GetState(u)&1`（`0x43B6A8`）。`Δ = X_對手 − X_自己`（`0x4429FD` 實測為 `movsx word [ (u->[0x40])->[0x48] + 0x40 ]`，即該單位所在格 x）。
3. 兩者疊加後才寫回，所以撤退單位的間隔 ∈ {46, 46+2Δ}。
4. `GetState&1` 的語義**未定**（現有線索：`0x43B961` 對 `&1` 為真的單位直接給射程 1；`0x43D76C` 用它篩「隔一格的目標」；與「武將」高度吻合但**未證**）。→【部分證據】。

補丁建議：**46 這一段已經對，`46+2Δ` 先不要實現**（缺 `&1` 的語義 + 需要 `world` 才能取對手 X，會動 `actionIntervalOf` 的簽名）。理由與風險見 `PATCH.md` §3。

### Q3 「只倒走」是位移取反，還是只允許後退動作？—— 都不是

1. **方向由命令給死**。`0x43CC95`（小隊 `cmd 8`）/`0x43C7E3`（主將 `cmd 8`）只傳一個 `±x`：

```asm
0043CCAB  push     0x48e8e0        ; 走位權重 80/10/10
0043CCB0  push     0               ; sy = 0
0043CCB5  push     1 / push -1     ; sx = ±1（按 u->[0x40] 是不是 0x4A8A60）
0043CCBA  call     0x43c4c0        ; 走位（候選方位抽樣 → 逐格試）
0043CCD9  call     0x43b51e        ; ★ SetState(u, 0x4000)
```

主將版同形，權重 `0x48E658`（100/0，純直線），置位在 `0x43C827`。

2. **沒有「取反」運算**。走位器 `0x43C4C0` 只做「按權重抽一個候選偏移（dx,dy）→ 界內就走」。撤退的權重表 `0x48E8E0` = 80/10/10，所以 20% 機率會帶 `±45°` 的 y 抖動（不是嚴格一條直線）；主將 `0x48E658` = 100/0 才是純直線。
3. **朝向被強制改成「走的那一邊」**，這才是「倒走」的觀感來源。`0x43BF26`（所有走位唯一的落地點）：

```asm
0043BF34  cmp      ... ; 新 x > 舊 x ？
0043BF3A  mov      dword ptr [sprite + 0x2c], 0          ; 往右走 → 朝右
0043BF54  mov      dword ptr [sprite + 0x2c], 0x800000   ; 往左走 → 朝左
```

因為撤退者永遠往「本方邊界」走、而敵人在反方向，所以朝向恆定背對敵人 → 看起來就是「倒著走」。

4. 因此「只倒走」的正確建模是：**位移只允許 `±x`（朝本方邊界）+ 朝向 = 移動方向**。battle.ts 目前只做了前半（`retreatStepPlan`），**沒有 facing 欄位**，後半是缺的（影響的是 Q1 的「朝哪一側看」）。

### Q4 `0x8000` 與 `0x4000` 的置位/清除順序

**置位點全表**（`call 0x43b51e` 全倉 13 處，戰鬥相關 6 處）：

| 位址 | 置哪一位 | 情境 |
|---|---|---|
| `0x43C827` | `0x4000` | 主將 `cmd 8`（`0x43C7E3`） |
| `0x43CCD9` | `0x4000` | 小隊 `cmd 8`（`0x43CC95`） |
| `0x4447E2` | `0x4000` | 全軍撤退入口 `0x4447B7`（見下） |
| `0x444858` | `0x4000` | 同上，對每個下轄小隊（`&u[0xb4 + i*0x48]`，`i < u[0x58]`） |
| `0x44481D` | `0x8000` | 同上入口，`u->[0x84] & 0x40` 時**立刻離場** |
| `0x43C6B8` | `0x8000` | 撤退走位時 x 越界（`0x43C4C0` → `0x43C678`） |

`0x4447B7` 全文（既是「全軍撤退」入口，也解釋了「0x4000 先、0x8000 後」）：

```asm
004447BB  cmp      dword ptr [ebp + 8], 0
004447BF  jne      0x4447c6
004447C6  push     8 / push 0x100 / push u
004447D1  call     0x43aded                ; 命令槽 1..7 全部寫 0x100（撤退指令）
004447D9  push     0x4000
004447E2  call     0x43b51e               ; ★ SetState(u, 0x4000)
004447ED  mov      eax, dword ptr [edx + 0x84]
004447F3  and      eax, 0x40
004447F8  je       0x444825               ; 沒有 0x40 → 跳到「給每個小隊置 0x4000」
004447FC  push     0x1000b / push sprite  ; 有 0x40 → 先發離場動畫消息 0x1000B
00444814  push     0x8000
0044481D  call     0x43b51e               ; ★ SetState(u, 0x8000)：緊跟在 0x4000 之後
00444842  push     0x4000
0044484D  lea      edx, [ecx + eax + 0xb4] ; u + 0xb4 + i*0x48 = 第 i 個小隊
00444858  call     0x43b51e               ; ★ 每個小隊也置 0x4000
```

`0x43C6B8`（走位越界才離場）：

```asm
0043C684  and      eax, 0x4000            ; ★ 先確認「已經是撤退態」
0043C68D  ...      call 0x43af54(x, 0)    ; 只檢查 x 是否越界
0043C6B0  call     0x43bfe7               ; 走出場（移動 + 發 0x10001/0x1000B）
0043C6B8  push     0x8000
0043C6C1  call     0x43b51e               ; ★ SetState(u, 0x8000)
```

**清除**：`call 0x43b538`（ClearState）全倉只有 2 處——`0x43C63A`（清 `0x1000`）與 `0x444CC5`。**`0x4000` 與 `0x8000` 沒有任何清除點**。而且 `0x8000` 的消費（`0x43D1CE` 小隊 / `0x43EAA0` 主將）在行動閘門 `0x43B574` **之前**：一旦置了 `0x8000`，該單位本幀起只做淡出（`[actor+0x90] -= 1`，到 0 就 `0x421A43` 銷毀），**連「撤退態的 46 幀節奏」都不再走**。

**順序結論**：`0x4000` 先（下令/執行 cmd 8 時），`0x8000` 後（兩種情形：同一個撤退入口裡「帶 `0x40` 標誌 → 直接離場」；或撤退走位時 x 越界）。沒有任何路徑先置 `0x8000` 再置 `0x4000`。

## 7. 附錄：順手證實的兩件事

### 7.1 「撤退每幀氣力 −0x32」找到了（`project/160` §5 說「兩種搜法 0 命中」）

`0x43E964`（sprite 更新器，caller `0x43EFC5`）：

```asm
0043E96D  mov      ecx, dword ptr [eax + 0x84]   ; u = sprite->[0x84]
0043E976  mov      edx, dword ptr [ebp - 0x10]
0043E979  mov      eax, dword ptr [edx + 0x40]   ; army = u->[0x40]
0043E97F  push     ecx
0043E983  call     0x43b67f                     ; ★ isRetreating(u)
0043E98B  test     eax, eax
0043E98D  je       0x43e9a0                     ; 非撤退 → 正常更新
0043E992  mov      eax, dword ptr [edx + 0x4c]   ; army->[0x4c]（部隊氣力/行動值）
0043E995  sub      eax, 0x32                    ; ★ 每幀 −50
0043E99B  mov      dword ptr [ecx + 0x4c], eax
```

過去「兩種搜法 0 命中」的原因：這裡**不是** `sub dword ptr [mem], 0x32`，而是「先 `mov` 到 `eax` → `sub eax,0x32` → `mov` 回去」，而且判斷走的是**謂詞 `0x43B67F`**，不是直接的 `and 0x4000`——按 `0x32` 或按 `0x4000` 搜都會漏。
（本 R 不要求實現氣力消耗；若要做，落點是「每幀對撤退中的部隊扣 50 氣力」，對象是部隊而不是單位。）

### 7.2 `0x4447B7` = 「全軍撤退」入口（比 `battle.ts` 註釋更完整的真相）

`0x4447B7` 的順序是：命令槽 1..7 全寫 `0x100` → `SetState(u,0x4000)` → 若 `u->[0x84] & 0x40` 則發 `0x1000B` 並 `SetState(u,0x8000)`（該單位直接離場）→ 對 `u[0x58]` 個下轄小隊（`u + 0xb4 + i*0x48`）逐個 `SetState(小隊, 0x4000)`。
`battle.ts:200-218` 的註釋把 `0x4447E2` 記成「軍團」、`0x444858` 記成「每小隊 stride 0x48」——小隊那半是對的，但「`0x4447E2` 是軍團」不準確：它作用在**傳進來的這一個 unit** 上，且同一函數裡緊跟一個可選的 `0x8000`（`0x44481D`）。建議順手改註釋。
