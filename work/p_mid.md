## 3. 战斗流程状态机

### 3.1 状态、迁移与对应关系

```ts
enum S { INIT, COUNTDOWN, DEPLOY, MARCH, CONTACT, MELEE, DUEL_NEAR, ROUT, RESOLVE, SETTLE }
// INIT 建单位算战力(原作 0x43A1C4→0x442EFA/0x443498→0x44D450)  COUNTDOWN 读秒3s  DEPLOY 布阵≤20s
// CONTACT 首次接敌顿帧  DUEL_NEAR 主将相遇(MELEE 子状态,不阻塞)  ROUT 全军撤退(原作 0x4447B7)
// RESOLVE 胜负(原作 0x447037 返回 1败/2胜/3平手)  SETTLE 结算(原作 0x41048D)
step(){ t++; switch(state){
  COUNTDOWN: t>=90 → DEPLOY
  DEPLOY:    t>=600 || skip → MARCH
  MARCH:     anyEngaged() → CONTACT ; t>=480s → ROUT
  CONTACT:   t>=18 → MELEE
  MELEE:     ai.update(); combat.update();
             generalDist()<=2 && 双活 → DUEL_NEAR ; hero.hp<=0 || survival<0.25 → ROUT
  DUEL_NEAR: generalDist()>3 → MELEE
  ROUT:      t>=120 → RESOLVE ;  RESOLVE: t>=45 → SETTLE }}
```

原作没有显式状态枚举，靠 `[0x4A8144]`、`army+0x2c`、`army+0x80`、`[0x4A665C]` 四个标志位拼流程（依据：docs/04b §1）；上表 10 个状态的进出条件逐条锚定到这四个标志位，M1 可对照验收。`enter()` 只做三件事：重置计时、切强制机位、发 UI 事件；**所有迁移都在单帧内完成**，便于逐帧回放（§1.3 定点数就是为它服务）。

### 3.2 读秒、布阵、进军、接敌

- **读秒 3 s 是新增的**（原作进场直接开打），目的：让玩家 3 秒内看清"我方阵形 / 敌人在哪一行"。代价：单局 +3 s。
- **布阵可换阵**：`DEPLOY` 内换阵 = 重跑 §2.6 的分配（100 次 `toVertical` + 占位写入 < 0.3 ms），旧单位 0.5 s 内走到新位（不瞬移）；`MARCH` 之后不许换阵，只能撤退。面板对每张阵形显示"对我方阵 +X / 对敌方阵 +X"（数据来自 11×11 表 `0x48D2A0`，依据 docs/04b §2）——把原作藏在数值里的 ±25 变成玩家可决策的信息（新设计）。
- **进军是小队锚点推进**，不是整军平移：前锋线每 0.5 s 前进 0.4 行，每小队有自己的目标 row（§5.3）。理由：原作 `0x43C4C0` 逐格逼近，整军同速会让 100 兵像一堵墙，非常死板（新设计）。
- **接敌判定**：每逻辑帧对 `MARCH/ADVANCE` 单位查 1.5 格内敌人 → 转 `ENGAGE`；本帧首次出现 `ENGAGE` 则进 `CONTACT`。

### 3.4 主将相遇：沿用"没有单挑"的结论

**原作结论不变**（依据：docs/04b3 §1）：全 EXE 无单挑子系统、无"單挑/一騎"字符串、Process 表无单挑类、兵战从不暂停；玩家感知的"单挑"就是双方主将（Process 4）按普通攻击链互砍。竖屏**不新增暂停**，只把"相遇"做成观感事件（新设计），因为一屏 19 行、主将精灵仅 26 px 高，玩家会完全错过：

1. **触发**：双主将格距 ≤2（`dist2 ≤ 2.5²`）且都存活 → `DUEL_NEAR` + `CAM_DUEL` + zoom 1.5（可见 9×13 格，主将放大到 39 px，能读表情帧）。
2. **将战条**：视口顶部 44 px 横条，左我方名将脸 100×120 缩到 44×53 + 姓名 + 体力条，右敌方镜像，中间交叉刀图标随攻击节奏闪；**不遮战场**（战场视口从 y=160 起仍留 840 px）。
3. **命中演出**：3 帧顿帧 + 8% 白闪 + 伤害数字放大到 32 px + 木鱼声。竖屏没有别的办法让玩家"感到打中了"。
4. **自动脱战**：距离 >3 格或一方死亡 → 0.4 s 缓动回 follow。**不询问玩家要不要接受单挑**——原作不能选。
5. **两种干预**（都来自原作菜单）：`突击`（cmd 3 武將出擊）冲上去；`待機·后退`（cmd 4）缩回本阵；`DUEL_NEAR` 时两按钮高亮。
6. **技能可插入**（原作菜单 cmd 2）：技力够就放，这是"将战"里唯一的策略深度。

> 被否掉的方案："主将相遇 → 全屏黑边 + 慢动作 + 兵战减速到 0.2×"。否决理由：① 原作不暂停，违背基线；② 单局仅 3..5 分钟，每次将战停 3 s 会打断人海流动；③ 100 兵在慢动作里各自为战会暴露 AI 破绽。替代方案：只对主将两个单位的时间轴做 0.1 s 的 0.35× 局部减速（新设计）。

| 结果 | 条件 | 结算 | 依据 |

| 2 大胜 / 2 胜 | 敌方主将体力 ≤0（我方存活率 ≥60% 记大胜） | 玩家处置敌方被俘将（招降/斩首/释放） | docs/04b2 §1 |

## 4. 数值：完整公式与改动清单

### 4.1 战力五段（`unit+0x70`）

原作是**五段直接相加、不乘任何系数**（依据：docs/04b §2）。

```ts
function computePower(att, def, terrain, globalAtk): i32 {   // base=150 见下
  return 150
    + TROOP_COUNTER[att.troopId][def.troopId]      // c1 -68..+68，对角 0
    + TERRAIN_MOD[terrain][att.troopId]            // c2 12×13，约 -25..+25
    + FORMATION_COUNTER[att.formId][def.formId]    // c3 -25..+25，零和
    + idiv(globalAtk + 50, 100)                    // c4 通常 -1..+1（原式 idiv 100）
    + idiv(att.morale - 50, 5);                    // c5 -10..+10（士气 0..100）
}
```

**`base = 150` 是推断值（重要）**：`unit+0x70` 的初始化代码未定位（docs/04b §2 只记了五段加算位置），但命中判定是 `rand()%300 < power`（docs/04b4 §3），而武将命中基准恰为 `p = 150`（同文档）。两个 150 出现在同一套判定里，推断士兵战力基准也是 150；否则中性条件命中率 0%，不可玩。M1 若手感不对，第一个旋钮就是它，不是五段系数（§9 第 2 条专测）。

| 段 | 范围 | 典型值 | 命中率影响 | 玩家能否感知 |
|---|---|---|---|---|
| c1 兵种相克 | −68..+68 | 0 或 ±66 | 44 个百分点 | **极强** |
| c2 地形 | −25..+25 | 0 或 ±25 | 17 个百分点 | 强 |
| c3 阵形相克 | −25..+25 | 0 或 ±23 | 15 个百分点 | 强 |
| c4 全局 | −1..+1 | 0 | 0.7 个百分点 | **不能** |
| c5 士气 | −10..+10 | +6（士气 80） | 6.7 个百分点 | 弱 |
| 合计 power | 21..279 | 150±40 | 命中 7%..93% | — |

### 4.2 士兵命中（`0x43D400`）

```ts
function soldierHit(att, def): bool {
  let p = att.power;
  if (def.isGeneral) p = 150 - def.wuli * 20 / 100;    // 打武将：武力越高越难命中
  if (!def.arrived) p = p * 2 / 3;                     // 目标在移动
  if (rand() % 300 < p) return true;
  if (att.isCavalry && rand() % 300 < p * 2 / 3) return true;   // 骑兵二段判定
  return false;
}
```

依据：docs/04b4 §3 的 `0x43D400` 全文。**口径警告**：士兵打武将是 `150 − 武力×20/100`（武力 85 → 133），武将打武将是 `150 + (攻武−守武)/2`，**两套公式不可混用**。

### 4.3 武将命中（`0x43D4CB`）

```ts
function generalHit(att, def): bool {
  let p = 150;
  if (def.isGeneral)      p = 150 + (att.wuli - def.wuli) / 2;
  else if (def.isCavalry) p = 150 + att.wuli / 3;
  else                    p = 150 + att.wuli / 2;
  if (att.buffFlags & 0x200) p += att.buffValue;        // 军团级命中加成（+0x40->+0x74）
  if (!def.arrived) p = p * 2 / 3;
  return rand() % 300 < p;
}
```

武将打兵 `p = 150 + 武力/2`：武力 85 → 192 → 64%，这就是"主将冲进兵堆像切菜"的来源。**不必削弱**——被围时的约束来自士兵打他的 44% 命中与 §4.9 算例 C。

### 4.4 伤害（`0x43EC54`）

```ts
function computeDamage(att, def): i32 {
  let d;
  if (att.isGeneral) {                       // 武将打武将
    const h = att.wuli, half = idiv(h, 2);
    d = idiv(half + rand() % (h - half), 10); // rand[武/2, 武) / 10
  } else {                                    // 兵/箭打武将
    let p = att.power;
    if (att.isCavalry) p = idiv(p * 120, 100); // ×1.2（原作 p*0x78/0x64）
    d = idiv(p * 4, 192);                      // = p/48（原作 p*4/0xC0）
  }
  return d < 1 ? 1 : d;                        // 下限 1
}
```

依据：docs/04b4 §4。**没有防御/减伤项**——这正是"相克只能靠命中率体现"的根因。士兵互砍**不进本公式**：命中即死（`0x43E077` 播 `HIT01` + 自转 `OM_DEATH`，无 HP 池，依据 docs/04b4 §4）。士兵打武将 `p=150±40` → `d=3..4`（骑兵 4）；武将 HP = `BaseHP + 等级×2×武力/100`（docs/04b §4），30 级武力 85、BaseHP 100 → 151。

### 4.5 士气：三处独立，别混

| # | 位置 | 公式 | 作用 | 依据 |
|---|---|---|---|---|
| 1 | 战力第 5 段 | `(morale − 50) / 5` | 直接影响命中，±10 | docs/04b §2 |
| 2 | `0x43A14D` | `m > 50 ? −1 : clamp(m,4,50) × 6` | 返回值恒负，**调用点未定位** | docs/04b §2 |
| 3 | 战后 | 被俘者 `士气 −20`、`忠诚 −= (10−节操)×2` | **只对 status==3**，不是全体 | docs/04b2 §6 |

第 2 条 M1 不实现（贸然实装会让 480 s 长局士气崩塌）；第 3 条以 docs/04b2 §6 为准，docs/04b 记的"战后全体 −20"是偏移误读。

```ts
// 0x401910：势力刷新时（每 120 计数）对势力内所有将领执行
```

### 4.9 三组算例（实装校验用）

**A 相克强度**（大刀 vs 弓箭，士气 80、平地、同阵形、全局 0）

| 方向 | c1 | c5 | power | 命中率 |
|---|---|---|---|---|
| 大刀 → 弓箭 | +66 | +6 | 222 | **74%** |
| 弓箭 → 大刀 | −66 | +6 | 90 | **30%** |

相克值取 docs/04b §2 实测（大刀→弓箭 +66、大刀→藤甲 +68、長槍→藤甲 +66、飛刀→藤甲 −67）。→ **§9 第 3 条的量化标准：同一对兵种正反打命中率差 ≥ 40 个百分点。**

**B 士气**（其余段为 0）：士气 80 → 156 → 52%；士气 20 → 144 → 48%。**只差 4 个百分点，玩家感知不到**（原著固有缺陷，处置见 §4.10 第 6 条）。

**C 8 兵围主将**（武力 85、HP 151）

| 项 | 值 |
|---|---|
| 单兵命中 | `150 − 85×20/100 = 133` → 44%；骑兵二段判定后实际 ≈62% |
| 单兵伤害 | `power/48 ≈ 3`（骑兵 4） |
| 8 兵 × 每 1.2 s | 4.4 次命中/s × 3 ≈ **13 点/s** |
| 击杀耗时 | 151 ÷ 13 ≈ **11.6 s** |

## 5. 士兵 AI 与小队

### 5.1 组织：100 = 10 小队 × 10 人

原作 100 兵分 10 小队（依据：PROJECT_BRIEF §3），但小队指令槽只有 8 个（`army+0x94+idx*4`，idx 0..7，槽 0 是主将，依据：docs/04b3 §4），原作靠"槽 0x101 = 除主将外全军"批量下命令。竖屏沿用这个分层：

```ts
interface Squad { id: 0..9; units: Unit[10]; mode: 1|2|3|4|5;   // mode 来自阵形分区 §2.3
  anchor: {col, row};        // 小队锚点（逻辑坐标）
  state: SquadState; targetSquad: Squad | null; moraleLocal: number; }
```

**分队规则**：slot `i` 属小队 `floor(i/10)`。因骑兵占各分区**低位 slot**（依据：docs/04b1 §3.1），slot 0..13 全骑兵 → **squad 0 是纯骑兵队、squad 7..9 是纯步兵**。免费的好处：骑兵队天然是先锋队，与原作"骑兵靠中心"的布阵意图吻合。

### 5.2 小队状态机

```ts
enum SquadState { IDLE, ADVANCE, ENGAGE, FLANK, WITHDRAW, ROUT, DEAD }
IDLE→ADVANCE(进 MARCH)  ADVANCE→ENGAGE(队内有兵 1.5 格接触)
ENGAGE→FLANK(相克≥+20 且目标已 ENGAGE 且 |Δcol|≤2 且存活≥6)  FLANK→ENGAGE(到位)
任意→WITHDRAW(点撤退)  任意→ROUT(本队存活<3 或 全军存活率<25%)  任意→DEAD(存活=0)
```

### 5.3 小队决策（5 Hz，100 兵只有 10 次决策）

```ts
function decide(s, enemies) {
  for (const e of enemies) {                                   // 选目标
    if (e.state === DEAD) continue;
    const d = dist(s.anchor, e.anchor);
    const score = 60 / (d + 2)                                 // 距离：越近越优先
                + TROOP_COUNTER[s.main][e.main] * 0.35         // 相克：±24
                - e.engagedBy.size * 8;                        // 别都挤同一队
  }
  // 绕后：有相克优势 + 不在目标正面（|Δcol|≤2）+ 兵力足
  if (counter >= 20 && Math.abs(s.anchor.col - target.anchor.col) <= 2 && alive >= 6)
    s.state = FLANK, s.flankTargetCol = target.anchor.col + (Δcol >= 0 ? 3 : -3);
}
```

**为什么按小队而非每兵决策**：① 100 次评分/0.5 s 在低端机是 0.6 ms 固定开销，10 次只要 0.06 ms；② 原作小队共享 `flag`（必杀标记 `[0x4A6668]`，依据 docs/04b3 §6），说明原作也按队算；③ 玩家看到的是"一群兵一起冲"，小队级更符合观感。

### 5.4 单兵行为

```ts
update(u) {
  if (u.state === ENGAGE) {
    const t = nearestEnemy(u, 1.5);
    if (t) { u.face = atan2(t.y - u.y, t.x - u.x);
             if (u.atkCd <= 0) { u.atkCd = 30; resolveAttack(u, t); } }   // 1.0 s
    else if (dist2(u, u.squad.anchor) > 6.25) moveToward(u, u.squad.anchor);
  } else if (u.state in (FLANK, WITHDRAW, ROUT)) followFlowField(u);
  else moveToward(u, u.anchorOfSlot);        // 默认只朝"小队锚点+队内槽位"走
}
```

单兵**不做独立寻路**：默认只朝锚点走，遇敌就打；只有 `FLANK/WITHDRAW/ROUT` 三种要绕障碍的状态才查流场。

### 5.5 寻路：流场（主）vs A*（辅）

| 方案 | 100 兵成本 | 优点 | 缺点 |
|---|---|---|---|
| 单兵 A* | 100×40..80 节点 @2 Hz → 1.2..2.4 ms/s，**峰值单帧 0.4 ms 抖动** | 路径最优 | 各算各的抢热门格；峰值抖动 |
| 共享流场 | 840 格 BFS @5 Hz → **0.06 ms/帧分摊**，无峰值 | 全队共享"往敌人去"的图，天然不打架 | 目标是"所有敌人"，绕后需额外目标点 |

```ts
function rebuildFlow() {                       // 每 6 逻辑帧
  const dist = new Int16Array(840).fill(0x7fff), q = new Int32Array(840);
  let head = 0, tail = 0;
  for (const e of enemyUnits) { const i = idx(e.col, e.row); dist[i] = 0; q[tail++] = i; }
  while (head < tail) { const i = q[head++], d = dist[i] + 1;
    for (const n of N8[i]) if (!blocked(n) && dist[n] > d) { dist[n] = d; q[tail++] = n; } }
  for (let i = 0; i < 840; i++) flowDir[i] = argminNeighbor(dist, i);   // 3 bit 打包
}
```

内存：`dist` 1680 B + `flowDir` 315 B（840 格 × 3 bit）+ 队列 3360 B ≈ **5.4 KB**。8 方向单位向量用定点表，避免格心对齐的锯齿。流场只在上述三种状态且**本帧要移动**时查询。

### 5.6 远程：弓与弩

| 项 | 弓（兵种 3） | 弩（兵种 11） | 依据 |
|---|---|---|---|
| 射程 / 攻击间隔 / 箭速 | 8 格 / 2.4 s / 12 格·s⁻¹ | 6 格 / 3.6 s / 14 格·s⁻¹ | （新设计） |
| 命中判定 | 复用 `soldierHit`，**无远程修正**；弩同格可命中 2 目标 | 同左 | docs/04b4 §6 |
| 落空 | 角度偏转 ±0xB0、`rand(0x60)` 步长、`rand(3)+2` 步、停留 `0x18` 帧 | 同左 | docs/04b4 §6 |

```ts
step(dt) { t += dt;                                  // 发射时记"目标格"，不记 unit
  visY = lerp(fromY, cellY) - sin(PI * t / dur) * 0.35 * 256;   // 视觉抛物线抬 0.35 格
  if (t >= dur) { const tgt = randomEnemyInCell(toCell);        // 到达才结算
    if (tgt && soldierHit(shooter, tgt)) resolveAttack(shooter, tgt);
    else spawnMissEffect(toCell); recycle(); } }
```

**这让"移动目标 ×2/3"变成物理事实**：敌人在箭飞行的 0.7 s 里走 1 格，箭落旧格。此时再乘 2/3 = 惩罚两次（§4.10 第 10 条），所以竖屏只保留物理落格——而且**玩家能看见箭落在哪**，这是竖屏视野宽于横屏的唯一红利。箭矢对象池 64，超池回收最旧（不新建对象，避免 GC），同图集可合批。

## 6. 技能与军师技

### 6.1 数量与数据结构

| 类 | 数量 | 生效时机 | 字段 | 依据 |
|---|---|---|---|---|
| 武将技 | 110 | 战斗中（原作菜单 cmd 2） | 序号/名称/消耗技力/能量(气)/`ATTACK`/`Script`/属性/官衔/注释,级别/目标 | docs/08 §4 |
| 军师技 | 67 | **战前**（布阵阶段） | 序号/执行代码/军师技等级/名称/属性/等级/目标 | docs/08 §4 |

两个关键事实（docs/08 §4）：`MAGIC.INI` 的 `POWER` **恒为 100**、不是威力；气力消耗 `= POWER × 1200`，满条固定烧 2%；真正威力是 `ATTACK`（0..60，均值 10.5）。`Script` 501..610 映射 `SCRIPT\MAGIC.SO` 的 `Magic{num−500}`（docs/05c §2），**与技能序号不同序**（`Script=503` 是 `Magic3`），故 `skills.json` 必须同时存 `id` 与 `script`。

### 6.2 竖屏释放：三种指向交互

竖屏的核心矛盾是"手指在下 1/3、目标在屏幕上段"，手指会盖住落点。三类技能三套交互：

| 类型 | 例子 | 交互 | 遮挡处理 |
|---|---|---|---|
| 自身/全军 | 集氣、聖光治療 | 点技能格立即放 | 无需选点 |
| 区域（落点） | 半月斬、落石、火龍 | 点格 → `AIM` 态 → 拖动调落点 → 松手 | 瞄准态把**视口整体上移 2 行（92 px）**，落点圈恒在手指上方 ≥150 px |
| 单体（点名将） | 突擊系 | 点格 → 顶部弹敌将头像条（48×48×≤5）→ 点头像 | 头像在顶部，完全无遮挡；点不到就"最近敌将" |

`AIM` 态规则（新设计）：zoom 临时 1.5×、镜头跟手指落点行；战场压暗 30%、范围圈 2 px 亮边 + 15% 填充、圈内敌人 1 px 蓝描边；手指 y 映射 row 需 **+2 行偏移**（因视口上移）；松手做合法性检查（射程内、未被边界裁切）；手指拖回技能格 96×96 内松手取消、不扣技力。**`AIM` 不暂停兵战**（沿用原作"从不暂停"，docs/04b3 §1），但主将血量掉到 30% 以下自动取消并提示，输入宽限 0.4 s。

### 6.3 军师技：纯战前，但给一次即时令

67 条军师技原作**战前生效**（docs/08 §4）。竖屏放在 `DEPLOY` 面板第二页：`[阵形]` 9 卡横滑 + `[军师]` 3 卡（按军师等级解锁可选数），确认后按 1→2 顺序结算成 buff 再进 `MARCH`。

- **不做**：战斗中随时放军师技（原作不能，会破坏"战前准备"策略层）。
- **做 1 条（建议改）**：每局给 **1 次"军师令·即时"**，只限非伤害类（补给/鼓舞/伏兵），按钮在顶部战况条右端。理由：竖屏玩家对"战前 3 选 1"感知弱（面板小、时间短），一次即时使用才强化"我有个军师"。影响面：仅 20 个非伤害军师技，不改平衡。

### 6.4 特效屏占比与镜头（14 列 = 728 px 的硬约束）

### 7.6 降级阶梯（4 级，自动 + 手动）

触发：连续 **30 帧**均值 >22 ms（60 档）或 >38 ms（30 档）→ 降一级；连续 **300 帧**均值 <14 ms（60 档）→ 升一级。降级只弹一次"已切换省电模式"，不打断战斗。

| 级 | 帧率 | 士兵动画 | 特效 | 视差 | 粒子 | 收益 |
|---|---|---|---|---|---|---|
| L0 全效 | 60 | 4 方向×6 帧 | 2 并发+全屏 | 4 层 | 300 | 基准 |
| L1 锁 30 | 30 | 4 方向×6 帧 | 2 并发 | 2 层 | 240 | 渲染 −45% |
| L2 简化 | 30 | 距镜头 >12 行改 **2 帧**（站/击）+位移插值 | 1 并发，粒子 ≤120 | 1 层 | 120 | 动画 −60%，DC −8 |
| L3 极简 | 30 | 非主将全改**静态图+位移**，伤亡只播 1 帧爆点 | 只剩命中闪白+死亡烟 | **关** | 0 | DC ≤25，逻辑不变 |

**手动兜底**：设置页"省电/均衡/画质"直接映射 L3/L1/L0；`wx.getSystemInfoSync().benchmarkLevel < 20` 首战直接锁 L1。
**不可降级的红线**（新设计）：① 士兵数量 100 不降（缩编 = 违背玩法基线）；② 逻辑帧率不降（30 Hz 是手感底线）；③ 相克判定不降。

```json
  "process": 3, "cavalry": false, "moveSpeed": 1.45, "atkInterval": 1.0, "atkRange": 1.5,
  "animSet": "inf_dadao", "shadowSize": 0.55, "sfxHit": "hit_blade",
  "counter": { "3": 66, "9": 68, "5": -67 } }] }
```

`counter` 用稀疏对象（169 项里约 90 项非零，省 45% 体积）；`process` 直取 `THINGS.INI` 的 `Process`（3 士兵 / 4 主将 / 9·12 箭）；`cavalry` 对应 `unit+0x2c & 4`，影响 5 处（二段判定、被攻命中、伤害 ×1.2、尸体位移、死亡特例，依据 docs/04b4 §7）——**必须存数据，不能用 `id>6` 之类的约定**。

### 8.3 `formations.json` + `formations.bin`

```json
{ "version": 1, "formations": [{
  "id": 0, "key": "square", "name": "方形之陣", "anchorX": 9,
  "weights": [140, 60, 0, 0, 0],
  "areas": { "1": { "x0": 1,  "x1": 14, "y0": 2, "y1": 11, "count": 140 },
             "2": { "x0": -6, "x1": -1, "y0": 2, "y1": 11, "count": 60 } },
  "bakedSlots": "formations.bin#0",
  "counter": { "1": 7, "2": -18, "3": 19, "4": 13, "5": -6, "6": 23, "7": -23, "8": -15 } }] }
```

`areas` 是**可读意图**（策划改阵形改这里）；`bakedSlots` 是**精确迁移**：33 组共 3 万个 `{int16 x, int16 y}` 烘成 `int8` 对，每项 2 B → 60 KB（比 JSON 小 20 倍、比运行时生成零误差）。生成函数无法复现原作"由内向外"的 slot 顺序（§2.6 的表就是硬编码结果），所以必须烘焙。迁移脚本 `tools/bake_formations.py`，M1 断言：烘焙后解出的前 100 slot 与 §2.6/§2.7 表逐项相等。

### 8.4 `terrain.json`

```json
{ "version": 1, "terrains": [{
  "id": 3, "key": "forest", "name": "森林",
  "layers": { "floor": "floor_forest", "bg": ["bg_forest_a","bg_forest_b"],
              "mg": ["mg_forest_a","mg_forest_b"], "fg": ["fg_forest_a","fg_forest_b"] },
  "troopMod": { "3": 25, "7": -24 }, "slowFactor": 1.0 }] }
```

`layers` 对应原作 4 层视差（FLOOR 512×512 平铺 + BG/MG/FG 各 A/B 两层，docs/08 §4）；`troopMod` 对应 12×13 表 `0x48D030`。**注意矛盾**：PROJECT_BRIEF §3 说"地形不参与数值、只是场景选择器"，但 EXE 确有该表（docs/04b §2）。M1 只实装已确认的森林弓箭 +25、蠻族 −24，其余置 0，见 §10-5。`slowFactor` 保留但恒 1.0（无地形减速的实测证据）。

### 8.8 原作 INI/EXE 数据迁移映射

| 原作来源 | 位置/格式 | 目标字段 | 迁移处理 |
|---|---|---|---|
| `MAGIC.INI` `ATTACK` | 0..60 | `skills[].attack` | 直取 |
| `MAGIC.INI` `POWER` | 恒 100 | `skills[].power` / `qiCost` | `qiCost = power × 1200` |
| `MAGIC.INI` `Script` | 501..610 | `skills[].script` | 直取，运行时映射 `Magic{num−500}` |
| `MAGIC.INI` 消耗技力 | 整数 | `skills[].costMp` | 直取 |
| `SANGO.INI` `[TERRAIN]` | 12 行 | `terrain.json` 全表 | 直取，`key` 改英文 |
| 兵种相克 13×13 | EXE `0x48CD88` | `troops[].counter` | 稀疏化 169 → ~90 项 |
| 地形×兵种 12×13 | EXE `0x48D030` | `terrain[].troopMod` | 稀疏化 |
| 阵法 11×11 | EXE `0x48D2A0` | `formations[].counter` | 稀疏化；9=特殊陣型、10=亂陣 |
| 阵形权重 + anchorX | EXE `0x485DA8`（33×6 int16） | `formations[].weights` / `anchorX` | 直取 33 行，本版只用 0..10 |
| 阵形 slot 坐标 | EXE `0x485B10` 指向的 33 组数组 | `formations.bin` | 烘焙 `int8` 对，60 KB |
| `THINGS.INI` `Process` | 整数 | `troops[].process` | 直取（3/4/9/12） |
| 动作表 WAIT/WALK/ATTACK/PAIN/DEATH/SHOT1..3 | `SHAPE` 序列 `#N` | `troops[].animSet` 帧段 | 动作名 → 帧段索引；`#N` = 该帧停留 tick |
| 必杀标记 `[0x4A6668]` | EXE | 无 | 竖屏 M1 不做"1/8 必杀"（§10-5 外的另一处简化） |
