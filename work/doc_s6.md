## 6. 亂陣 / 特殊陣型 / 变形族（9..32 号）

`a` 的完整取值空间是 0..32，其中只有 0..10 是"由玩家/军师技直接选中"的阵形：

```asm
; 0x43A1C4 尾部（0x43A3FF..0x43A467）—— 根据 unit+0x10 调整阵形号
0043A402  cmp   dword ptr [eax + 0x10], 1      ; eax = [ebp+8] = A 侧 unit
0043A406  jne   0x43A419
0043A408  mov   ecx, [0x4A6674]                ; A 侧阵形号
0043A40E  add   ecx, 0xB                       ; +11  → 变形族 A
0043A411  mov   [0x4A6674], ecx
...
0043A41C  mov   eax, [edx + 0x10]
0043A41F  and   eax, 2
0043A426  mov   ecx, [0x4A6674]
0043A42C  add   ecx, 0x16                      ; +22  → 变形族 B
```

- `unit+0x10 == 1` → 阵形号 **+11**（11..19）
- `unit+0x10 & 2` → 阵形号 **+22**（22..32）

> **`unit+0x10` 的写入者未定位**：已扫过 `.text` 中 `mov dword [reg+0x10], imm` 与
> `or dword [reg+0x10], imm` 两种形式（含 eax/ecx/edx/ebx/esi/edi/ebp），
> 以及 `[0x4A8A70]` / `[0x4B03B0]`（= unit+0x10 的绝对地址）的 imm32 引用，
> 均无有效命中（`0x43A402`、`0x44859D` 是 `cmp`，不是写）。
> 因此 **本版运行时 `unit+0x10` 很可能恒为 0，11..19 / 22..32 两族数据不被启用**（推断）。
> 对应地 `0x43A0C0(a, flags, side)`（判断"阵形是否完好"）在 `flags==1` 时返回 0，
> 结果存 `0x4A8AC4`——这是同一套"阵形被破"机制的残留。

三个族的读法：

- **11..19（变形族 A）**：把该阵形合成为**单个 200 格数组**（不再分 5 区），坐标整体左移。
  `a=11` 的形状与 `a=0`（方形）同型：20 列 × 10 行 = 200 格，只是 x 从 `-6..14` 挪到 `-20..-1`。
- **22..32（变形族 B）**：权重与 0..10 完全一致，唯一区别是**第二个分区数组被换成"镜像版"**
  （`0x481550` x57..62 取代 `0x481460` x-6..-1），即该区被摆到网格**另一侧**。
  从数据形态看是"两翼同时展开/夹击"的布阵（推断）；锚点也相应减小（9→7、8→6…）。
- **20/21** 与 **9/10** 数组指针完全相同（乱阵/特殊阵型的副本），锚点也相同 → 无差别。
