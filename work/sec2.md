## 2. 竖屏投影：方案 A（战场转 90°）

> 一句话：逻辑网格一个字不改（71 列 × 14 行、格 96×72 px、世界 6816×1008），只把**呈现**转 90°——横向的 14 条车道放到屏幕左右，前进的 71 列放到屏幕上下，**我方在下、敌方在上、向上推进**（依据：PROJECT_BRIEF §6）。

### 2.1 为什么是 A（用户 m01722 拍板）

两案都算得出来。把数字摆在一起后，A 唯一输的是美术，赢的是**可见纵深**和**手势**：

| 维度 | A：转 90°（**选定**） | B：保持横向 + 横向镜头 | 差 |
|---|---|---|---|
| 可见推进纵深 | 12.6 / 71 行 = **17.8%** | 8.75 / 71 列 = 12.3% | A ×1.44 |
| 可见横向 | 14 / 14 车道 = **100%** | 14 / 14 行 = 100% | 平 |
| 一屏格数 | **176 格** | 122.5 格 | A ×1.44 |
| 拇指手势 | 战场纵向铺满，单指上下推（一维） | 战场铺在 750 宽里，横拖 5976 px 镜头 | A 省手势 |
| 单位朝向 | 背视 / 正视 / 侧视 三套（§6.2） | 只要原作侧视一套 | B 省美术 |
| 地面特效 | 约 55% 需重做（§7.4） | 全复用 | B 省美术 |
| 玩家决策 | 两翼全见、纵深 17.8% | 两翼出屏、纵深 12.3% | 平 |
| 用户决策 | m01722：「A，我说只换皮，包含视角转换带来的换皮」 | 已否决 | — |

结论：**选 A**。信息量比 B 大 44%、手势天然适合竖屏；代价 100% 集中在美术（三套视角 + 一半特效重做），而用户已把"视角转换带来的美术重做"明确算进"换皮"预算（依据：PROJECT_BRIEF §2 视角行、§6.2）。

### 2.2 投影公式与全部常量

| 常量 | 值 | 推导 |
|---|---|---|
| 世界坐标 | `worldX = gx*96 + 48`（0..6816，前进轴）、`worldY = gy*72 + 36`（0..1008，车道轴） | docs/04b1 §1 |
| 战场带 | 750 × 900 px，`screenY ∈ [100, 1000]` | PROJECT_BRIEF §6.1 |
| 缩放 `s` | **0.7440** | `750 / 1008`（14 车道 × 72 px） |
| 屏上格 | **53.6 × 71.4 px**（横 × 纵） | `72s × 96s` |
| 可见 | **14 车道全宽 × 12.6 行** | `900 / (96s) = 12.6` |
| 推进轴可见比 | **17.8%** | `12.6 / 71` |
| `camX` 范围 | **[0, 5606]** | `6816 − 900/s = 6816 − 1210` |
| `camY` | **恒 0** | `14 × 72 × s = 750.0`，恰好铺满 |
| 单位朝向 | 我方背视 / 敌方正视 | PROJECT_BRIEF §6.1 |

```ts
// 唯一的投影函数：逻辑层不知道屏幕存在，只有渲染层调它
const S = 0.744;                                  // = 750 / 1008
function project(u, camX) {
  return {
    x: u.worldY * S,                              // 车道横轴 → 屏幕 x
    y: 1000 - (u.worldX - camX) * S,              // 推进轴 → 屏幕 y（我方在下）
  };
}
// 定点实现（整数，1 px 精度）：
//   screenY = 1000 - idiv((worldX - camX) * 744, 1000)
```

- **Y 翻转是唯一的实质差别**：`screenY = 1000 − …`，`worldX = 0` 落屏幕下沿，`worldX = 70 格` 落屏幕上方。
- 以格为单位更直观：`screenCol = 格Y`、`screenRow(自下) = 格X`，即 `screenY = 70 − 格X`（再乘 `s` 加带偏移）。这就是"原 X → 新 Y、原 Y → 新 X"。
- **不裁剪**：投影无分支；带外单位由渲染层 cull（`screenY ∈ [−64, 1064]` 留余量），逻辑照跑。

### 2.3 三档缩放与一屏可见

| 档 | `s` | 屏上格（横×纵） | 可见车道 | 可见行 | `camY` | 用途 |
|---|---|---|---|---|---|---|
| 近景 `Z_NEAR` | 1.34 | 96.5 × 128.6 px | 7.8（需裁切） | **7.0** | 需，`∈[0,448]` | 主将相遇、技能瞄准、战后特写 |
| 标准 `Z_STD` | **0.744** | **53.6 × 71.4 px** | **14（全见）** | **12.6** | 恒 0 | 进军、混战（默认） |
| 全景 `Z_WIDE` | 0.67 | 48.2 × 64.3 px | 14（675 px，两侧黑边 37.5） | 14.0 | 恒 0 | 开战看全阵、长按战况条看全局 |

- `Z_NEAR` 是唯一需要第二自由度的档：`750 / (72×1.34) = 7.8` 车道 < 14，必须横向裁；`camY ∈ [0, 1008 − 750/1.34] = [0, 448]`。
- `Z_WIDE` 两侧各 37.5 px 黑边**不放任何可点元素**，只压暗，避免误触。
- 士兵屏高：`58 × 0.744 = 43 px`（标准）/ `58 × 1.34 = 78 px`（近景）/ `58 × 0.67 = 39 px`（全景）。**43 px 是 v1 的可读性基线**（§6.3）。

### 2.4 摄像机：一维纵向跟随便够

横向 14 车道恒定铺满，所以 `camY` 恒 0，镜头只有 `camX` 一个自由度：

```ts
const heroX  = ourGeneral.worldX;                    // 我方主将
const frontX = maxWorldX(ourLivingSoldiers);         // 我方最前兵
const focusX = 0.55 * heroX + 0.45 * frontX;         // 关注点
let   target = focusX - 544;                         // 544 = (1000-595)/0.744
target = clamp(target, 0, 5606);                     // 5606 = 6816 - 900/0.744
if (abs(target - camX) > 144) camX = approach(camX, target, 8);   // 死区 ±144，每帧 ≤8
```

- **544 的来历**：把关注点放在屏高 595（战场带下 45%），`(1000 − 595) / 0.744 = 544`。
- **为什么 0.55 / 0.45**：主将会冲（原作 `cmd 3 武將出擊`，依据：docs/04b3 §4），只跟主将看不见兵墙；只跟前锋主将会跑出屏。加权后主将最多偏出屏心 2.2 行，仍在 12.6 行视野内。
- **死区 ±144 世界 px**（= ±1.5 格 = ±107 屏 px），避免主将微动导致镜头呼吸。
- **每帧 ≤8 世界 px** = 240 px/s，快于步兵 1.45 格/s（139 px/s）——镜头永远追得上，不会出现"单位跑到镜头外"。

| 机位 | 触发 | `camX` 目标 | `s` | `camY` |
|---|---|---|---|---|
| `CAM_FOLLOW` | 默认 | 上式 | 0.744 | 0 |
| `CAM_DUEL` | 两主将同格/相邻（距离 ≤1），或隔格追击（原作 `0x43D76C` 的特例） | `(heroX_our + heroX_foe)/2 − 302` | 1.34 | `clamp(midY − 280, 0, 448)` |
| `CAM_SKILL` | 技能包围盒 > ½ 屏（§7.4） | 技能中心 `− 544` | 0.744 或 1.34 | 0 或上式 |
| `CAM_ROUT` | `0x4000` 全军撤退 / 主将亡 | 我方主将 | 0.744 | 0 |
| `CAM_SETTLE` | `[0x4A8144] == 8` | 战场中段 | 0.67 | 0 |

- `302 = (1000−595)/1.34`、`280 = 375/1.34`：都是"把某点放到屏心偏下 45%"的同一套算术，只是换了 `s`。
- **机位切换不改逻辑**：`camX/s/camY` 全是渲染状态，逻辑帧仍按 §5 跑；0.25 s ease，卡顿时直接跳变（宁跳不抖）。

### 2.5 UI 三分带、安全区与拇指热区

| 带 | 屏幕 y | 高 | 内容 |
|---|---|---|---|
| 上 12% | 0 .. 100 | 100 | 战况条：双方兵力条、士气、气力、计时、阵形名 |
| 中 62% | **100 .. 1000** | **900** | 战场（唯一接收战场点击的区域） |
| 下 26% | 1000 .. 1334 | 334 | 指挥区：4 个技能格 + 突击/撤退 + 主将头像 |

- 安全区：`wx.getWindowInfo().safeArea`，上下各留 ≥ 88 px（依据：PROJECT_BRIEF §5）；刘海机把战况条整体下移到 `safeTop`。
- 主按钮落 `x > 412`、`y > 867`（下 1/3 × 右 55%，依据：PROJECT_BRIEF §5）。
- 战场装饰（黑边、暗角）只画在带外，**不接收输入**；战场内也不放浮动按钮（会挡住 100 兵里最关键的那一簇）。

### 2.6 点选：把触点反投影回格子

```ts
function touchToCell(sx: number, sy: number) {        // 屏幕 → 格
  if (sy < 100 || sy > 1000) return null;             // 战场带外不响应
  const worldY = sx / 0.744;                          // 横轴 = 车道
  const worldX = camX + (1000 - sy) / 0.744;          // 纵轴 = 推进
  return { gx: Math.floor((worldX - 48) / 96), gy: Math.floor((worldY - 36) / 72) };
}
```

| 轴 | 屏上 1 格 | 44 px 指腹覆盖 | 对策 |
|---|---|---|---|
| 推进轴（纵） | 71.4 px | 0.62 格 | 精度足够，直接按格取 |
| 车道轴（横） | 53.6 px | 0.82 格 | 目标先**吸附到最近车道中心**（±26.8 px 容差），再取该车道内最靠前者 |
| 近景档 | 128.6 / 96.5 px | 0.34 / 0.46 格 | 更准；`CAM_DUEL` 时不改交互 |

- 三型技能指向照旧（§7.2）：点将走顶部头像条（不受战场带限制）、点地面走上面的车道吸附、自身走长按。
- 点选优先级：武将 > 小队旗 > 士兵；同层取"离手指最近的世界格"，不取"最靠前"（避免误选屏外）。

### 2.7 深度排序与像素对齐

- **排序键**：`worldX` 降序（远者先画），同 `worldX` 按 `worldY` 升序，同格按槽索引（`unit+0xB4` 的 idx）稳定排序。A 下"越靠上越远"——这是转置带来的唯一一处渲染差异。
- **像素对齐**：`camX` 取整；`screenX/screenY` 四舍五入到整数；精灵锚点 `(0.5, 0.12)` 脚底贴格心，避免浮空。
- **不按 1:1 世界像素出图**：世界 1 px 只占屏上 0.744 px，按 1:1 出图会白涨 1.8 倍带宽与内存。精灵按标准档屏上尺寸出图（士兵 43×64、主将 64×82），近景档只给**主将**另出 1.34× 一套（86×110）；士兵近景直接放大 1.8×（模糊可接受，`CAM_DUEL` 只持续数秒）。

### 2.8 视野变化的规则性影响与补偿

| 轴 | 竖屏 A | 原作 640×480 | 变化 |
|---|---|---|---|
| 车道（横） | 14 / 14 = **100%** | 640/96 = 6.67 / 14 = **47.6%** | 两翼第一次全见 |
| 推进（纵） | 12.6 / 71 = **17.8%** | 480/72 = 6.67 / 71 = **9.4%** | ×1.9 |
| 一屏格数 | **176** | 44 | ×4.0 |

两个结论：

1. **"敌方后阵永远在屏外"不是新问题，与原作同构**。原作只看得见 9.4% 的推进轴，玩家一辈子看不到敌方本阵；竖屏 17.8%，同样看不到。"要靠猜敌人还剩多少"的手感被完整保留，这也是 §2.1 里 A 胜过 B 的地方（B 只有 12.3%）。
2. **两翼全见是新变量**。原作看不全左右，包抄只能靠想象；A 把 14 车道全铺上，玩家第一次能看见"绕后"。这是**纯表现层变化**，不改任何 AI 权重；但看得见就会改变玩家操作，属于"规则性影响"——只描述、不补偿（遮住两翼只会更糟）。

| 屏外/易漏的东西 | 补偿 | 位置 |
|---|---|---|
| 敌方后阵、我军后续 | **竖条小地图**：71 行压成 300 px（4.2 px/行），12.6 行窗口框高 53 px | 右缘 x 706..730，y 350..650 |
| 屏外有敌（上方） | 上边缘箭头 + 距离（"3 队 · 12 格"） | y 100..112 |
| 我军掉队/溃兵（下方） | 下边缘箭头 | y 988..1000 |
| 开战时的全阵轮廓 | **战前阵型缩略图**（71×14 → 340×90，1/6 缩） | 布阵页（第 2 屏） |
| 关键事件 | 自动聚焦：主将接敌 → `CAM_DUEL`；技能 > ½ 屏 → `CAM_SKILL`；溃逃 → `CAM_ROUT` | §2.4 |

- 小地图画全部存活单位，按阵营着色，只分 3 类：将（3 px）、小队旗（2 px）、兵（1 px）。信息量必须低于战场。
- 小地图**不可点**（v1 不做"点小地图跳镜头"，那会引入新的操作负担）。
