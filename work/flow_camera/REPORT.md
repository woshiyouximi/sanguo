## 0. 一句话结论

**世界层（战场本体）两将从来不可能同屏**：开局两人相距 **45 行**，一屏只有 **13.33 行**，超限 **3.38 倍**；CDP 实测两将投影 `sy=1334px` / `sy=−845px`，一个出下沿 334px、一个出上沿 945px，**无论 camX 取何值都拍不到同一帧**。

玩家「能看到彼此武将」，来自三条**与世界距离无关**的信息通道（第 4 节），其中最硬的一条是 Cocos 端 `GeneralArt.clampShift()` **把主将贴边画进画面**——那才是「相距 45 行却同屏」的真正来源。

真正的差距不在「距离 30 格」（原作也是 31 格），而在两处：
1. **镜头锚点错了**：原作全程钉我方主将（`project/176` 实证），我们钉我方前锋 −2.6 行 ⇒ **我方主将自己的主将整场都在画面外**（r=+9.6 > ROWS_NEAR 5.894，实测 `sy=1334` 永远 > 1000）。
2. **缺开局两段运镜**：原作 `StartBattle` 是「MoveCamera→敌将喊话→MoveCamera→我将接话」，字节码铁证（`project/95:134-162`，实装 `game/src/core/syso_host.ts:1305-1337`）；web 开战路径**一次都没调用**。

> **落地更新（2026-11-26 07:3x）**：上面两条都已处理。①`camera()` 已改成钉我方主将（`battle.ts`，`CAM_GEN_BACK=2.0`），实测 camX 48.40→**56.00**、屏内我方 40→**101** 单位、我将 `sy` 1334.4→**692.4**；②叫阵运镜已由另一路在 `game/web/main.js` 落地（`beginTaunt`/`tickTaunt`，`?taunt=0` 可关），喊话时镜头停在喊话方主将（r=0、sy=550）——**用户的「看到彼此武将」正是这条，且它是原作行为**。详见 §附 5.2–5.5。

## 1. 一屏到底能看多少

### 1.1 纵向（纵深/行数）

生产投影（`game/src/core/field.ts:158-173`）：

```
rowScale(r)    = SCALE_CENTER · e^{ROW_K·r}                 r = gx − camX
rowScreenY(r)  = 550 + ROW_PX·SCALE_CENTER·(e^{ROW_K·r} − 1)/ROW_K
```

一屏行数由 `rowsForScales()`（`field.ts:97-101`）给出，实测常数（node 直跑 `field.ts` 复核）：

| 量 | 值 | 说明 |
|---|---|---|
| `ROWS_FAR` | **7.434** | 镜头行往敌方向还能看 7.434 行（画面上沿）|
| `ROWS_NEAR` | **5.894** | 镜头行往我方向还能看 5.894 行（画面下沿）|
| `ROWS_VISIBLE` | **13.327** | 一屏纵深 = 13.327 行（战场 0..70 的 **18.8%**）|
| `CAM_HALF_ROWS` | **6.300** | = 900/2/71.429，**只是换镜判据**，不是夹取 |
| 中心行格距 | 68.8 设计px = **63.7 设备px** | 一屏 ≈ 834 设备px / 13.33 行 |

**关键洞察（反直觉，必须写进决策记录）**：一屏行数**与 `ROW_PX` / `SCALE` 无关**。
因为 `sNear/sFar = 84.5/53` 是常数、`sNear−sFar = 31.5/ROW_PX`，代入 `rowsForScales` 后 `ROW_PX` 被约掉：

```
rows = FIELD_H·ln(84.5/53)/31.5 = 900·0.4664/31.5 = 13.32
```

⇒ 改 `ROW_PX`（0.744 那档缩放）**不会**改变一屏行数。想改行数只有两条路：改 `FIELD_H`（900），或把整条纵向投影乘一个统一倍数 z（= 镜头拉近）。

### 1.2 横向（车道）

`LANE_SQUEEZE = 750/(14·53.571·SCALE_NEAR) = 0.8453` 是**自适应**的：它保证最近一排的 14 条车道正好铺满 750px（`field.ts:147-151`）。

- 近排车道距 53.57 设计px（49.6 设备px）⇒ **14/14 车道 100% 满屏**
- 中心排车道距 43.6 设计px ⇒ 14 车道占 610px
- 远排车道距 33.6 设计px ⇒ 14 车道占 470px（梯形收窄，不裁边）

⇒ **横向永远看得到全部 14 条车道**（原作一屏只有 6.67 车道，见 5.2）。

### 1.3 判据公式

```
【世界层同屏判据】
  两将同屏 ⇔ 存在 camX 使 gx_A、gx_B 都落在 [camX−ROWS_FAR, camX+ROWS_NEAR]
          ⇔ |gx_A − gx_B| ≤ ROWS_FAR + ROWS_NEAR = 13.327 行
          且 |gy_A − gy_B| ≤ 13 车道（0..13；因为 14 车道全在屏内，该条件恒真）

【单侧入画条件（camX 给定）】
  我将在屏内 ⇔ camX ≥ gx_gen − ROWS_NEAR = 58 − 5.894 = 52.106
  敌将在屏内 ⇔ camX ≤ gx_genB + ROWS_FAR  = 13 + 7.434  = 20.434
【两者同时成立】⇒ 需 20.434 ≥ 52.106，永不成立（这正是 Δgx=45 的另一种写法）
```

**开局代入**：`|58−13| = 45 行`，允许 13.327 ⇒ **超限 3.38 倍，差 31.67 行**。判据判定：**不同屏，且无解**。

## 4. 「那为什么能看到彼此武将」——四条通道

> **补记（2026-11-26 07:3x）**：本节写于叫阵系统落地之前。之后 `game/web/main.js` 出现了开局叫阵运镜（`beginTaunt`/`tickTaunt`），喊话时把镜头直接停在喊话方主将身上（r=0、sy=550）——**这才是用户「能看到彼此武将」最直接的一条通道，且是原作行为**。详见 §附 5.5；下面四条仍然成立，但都属于「不靠镜头」的常驻通道。

世界层已排除（第 2、3 节）。以下每条都与距离无关：

### 通道 1：底部双主将卡（常驻，**与距离无关**）
`battleView.ts:2097 drawGeneralCard()`，两处调用 `:2238`（我將 Lv.6 / 兵·體·智）、`:2247`（**敵將 張角 / 兵·體·智，带「敵將」标签**）。
截图可见：右下角就是敌方主将卡。**这条是原作的忠实还原**（`battleView.ts:2008` 注释：「原作它是底部左右两块主将卡里的四个裸数字之一」），不是 bug。

### 通道 2：右侧 71 行小地图（**双方主将的点永远在屏上**）
`battleView.ts:1895-1903`：遍历**全部存活单位**，`y` 轴就是 0..70 的纵深，主将画 4×4、士兵 2×2。
⇒ 玩家随时能在地图条上看到「我方主将在下、敌方主将在上」，相距 45 格一目了然。**这是「能看到彼此武将」最字面的一条。**
（原作是否有同款小地图：**缺证据**，见 5.5。）

### 通道 3：Cocos 端 `clampShift()` 贴边——**唯一「真·同屏」的一条**
`game/cocos/assets/scripts/GeneralArt.ts:249-275`：把主将 sprite 的三层并集 bbox **硬夹进 `FIELD_TOP+4 .. FIELD_BOTTOM−4`**。源码注释自述（`:232-235`）：

```
顯示層貼邊：主將站在己方陣列最後 2 格，而鏡頭一屏只覆蓋 12.6 格縱深，
開局兩軍隔 30+ 格時主將被投到畫布外（實測 A py=1542 / B py=-1816，畫布高 1334）
```

⇒ 贴边后：**我将被摁到下沿 y≈996、敌将被摁到上沿 y≈104**，两人同时出现在画面里的上下边缘，且看起来「只隔一屏」。**这与用户描述「距离很远却能看到彼此武将」逐字吻合。**
web 端 (`battleView.ts:1143-1144`) 是 `if (sy < 100 || sy > 1000) continue;` ——**只裁剪、不贴边**，所以 web 端没有这条。
→ 若用户跑的是 Cocos/APK 构建，**这就是元凶，且是显示层作弊**（世界层 45 格，显示层强行压到 1 屏）。

### 通道 4：施法运镜会把镜头拽走（次要，但证明「镜头不是钉死的」）
`main.js:1667-1685`：任一新 `fx` 距当前 camX ≥ 1.2 行，就把 camX 摇到 `fx.x`，保持 `FX_FOCUS_SEC = 1.0 s`（`main.js:123`），插值系数 dt·7。
敌将入画需要 `camX ≤ 20.43`（=13+7.434）；实测特效落点最远在敌军前锋（~24–28），**差 4–8 行，仍不足以单独把敌将拍进来**，但它会让画面在两侧阵营间来回甩。

## 7. 三组候选参数（供拍板）

前置结论：**镜头锚点必须改成我方主将**（否则主将自己看不到），这一条三组共有。差别只在「一屏压多紧」和「要不要动几何」。

### 7.1 方案 A · 保守（只改镜头 + 补开局运镜，几何一动不动）

| 项 | 现值 | 建议值 |
|---|---|---|
| `camera()` 锚点 | `aMin − 2.6` | **`genA.gx − 2`**（`battle.ts:3204-3212`）|
| 换镜分支 | 距离 >12.6 切中点 | **删掉**；或只在「双方前锋都已接战」时允许中点偏移 ≤2 行 |
| 一屏行数 | 13.327 | **13.327 不变** |
| 开局 | 直接 fighting | `syso_host.startBattle()` 两段运镜 + `open_taunt` 两句台词，演完把 camX 锁回 `genA−2` |
| Cocos 贴边 | `clampShift` 生效 | **关掉**（改 `dy=0`，或只在「真实位置已在带内」时不贴）|

## 附 2. 镜头锚点（`game/src/core/battle.ts:3201-3220 camera()`）

### 2.1 目标公式（可直接替换整段）

```ts
// 我方主将锚点：主将放屏幕 ~70% 高（r=+2）；三条守卫决定阵形过深时牺牲谁
const CAM_GEN_BACK = 2.0;   // 锚点前置量（行）
const GEN_MAX_R = 5.0;      // 主将最差也得留 r=+5（离下沿还有 0.894 行）
const GEN_MIN_R = -7.0;     // 主将最差不得出上沿超过 r=-7

export function camera(world: World): number {
  let aMin = Infinity, aMax = -Infinity, bMin = Infinity, bMax = -Infinity;
  let aN = 0, bN = 0;
  let genAX = NaN;   // 我方主将 gx：world.sides.A.general 只有 hp/str/int、没有坐标，只能从 units 找
  for (const u of world.units) {
    if (!u.alive) continue;
    if (u.side === 'A') {
      aN++; aMin = Math.min(aMin, u.x); aMax = Math.max(aMax, u.x);
      if (u.isGeneral) genAX = u.x;
    } else { bN++; bMin = Math.min(bMin, u.x); bMax = Math.max(bMax, u.x); }
  }
  let cam: number;
  if (aN && bN) {
    if (Number.isFinite(genAX)) {
      cam = genAX - CAM_GEN_BACK;               // 默认：钉我方主将
      cam = Math.min(cam, aMin + ROWS_FAR);     // 守 1：我方前锋别顶出上沿
      cam = Math.max(cam, genAX - GEN_MAX_R);   // 守 2：主将别掉出下沿
      cam = Math.min(cam, genAX - GEN_MIN_R);   // 守 3：主将别出上沿
    } else {
      cam = aMin - 2.6;                         // 主将已阵亡：退回现状「跟前锋」
    }
  }
  else if (aN) cam = (aMin + aMax) / 2;
  else if (bN) cam = (bMin + bMax) / 2;
  else cam = GRID_W / 2;
  return clampCameraX(cam);
}
```

- 改动要点：**删掉 `mid` 分支与 `half` 判据**（`const half = CAM_HALF_ROWS;` 与 `(aMin - bMax > 2 * half)` 一起走；`tsconfig.json` 没开 `noUnusedLocals`，`:50` 的 `CAM_HALF_ROWS` import 留着也不会报错，建议顺手清），并把函数上方 docstring 里讲 `half` 的两句（`:3196-3199`）换成「钉我方主将 + 三条守卫」的说明。
- 新增 import：`game/src/core/battle.ts:50` 现为 `import { CAM_HALF_ROWS, clampCameraX } from './field.ts';` → 加 `ROWS_FAR`。**真源写 `.ts` 后缀**，镜像由同步器去后缀 ⇒ 别手改镜像。
- 为什么不要 `mid`：它的本意是「两军接近后一起看」，但满员接战时 camX 被拉到 `50.50`，我将 `r=+7.5` 仍出画 ⇒ **既没让主将入画，又把敌人拉近**，是纯副作用。原作 `project/176:362-376` 记录镜头全程钉我方主将、52 帧扫描敌将从未入镜 ⇒ 锚主将才对得上。
