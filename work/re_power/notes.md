## 2. Q1 战力基准 150 的取证链

### 2.1 先证伪"150 是算出来的"
`0x442EFA`（B 侧，1438 B）对 `+0x70` 的 5 次访问全是 read-modify-write：
```
00442FC0  8b4a70        mov  ecx,[edx+0x70]
00442FC3  03c8          add  ecx,eax
00442FC8  894a70        mov  [edx+0x70],ecx
```
（`0x442FE8`/`0x44300B`/`0x443029`/`0x443049` 同构；A 侧 `0x443498` 在
`0x443566/0x443586/0x4435A9/0x4435C7/0x4435E7`。）
**没有任何 `mov dword [..+0x70],0x96`** ⇒ 150 不是这个函数产生的。

### 2.2 再定位初值：全 .text 对该两槽的绝对寻址只有 4 条
```
0043A3AD  c705 d08a4a00 96000000  mov dword ptr [0x4a8ad0],0x96      ; 写 A 侧
0043A3B7  c705 10044b00 96000000  mov dword ptr [0x4b0410],0x96      ; 写 B 侧
00446091  6b05058a4a00...          imul eax,dword ptr [0x4a8ad0]      ; 读（WARINFO05）
004462C6  ...                      imul edx,dword ptr [0x4b0410]      ; 读（WARINFO05）
```
前两条在 `0x43A1C4`（战斗初始化，796 B），后两条在 `0x445DBF`（`MENU\WARINFO05`）。

### 2.3 证明 `0x4A8AD0 = 0x4A8A60 + 0x70`
- 算术：`0x4A8A60+0x70 = 0x4A8AD0`，`0x4B03A0+0x70 = 0x4B0410`。
- `0x43A1C4` 通篇以 `[ebp+8]`（=A unit `0x4A8A60`）/`[ebp+0xC]`（=B unit `0x4B03A0`）为基址
  做 `+0x14/+0x18/+0x1C/+0x20/+0x24/+0x28/+0x2C` 的写入（见 §1.2 表）。
- 写完 0x96 后紧接：
  ```
  0043A3C1  68608a4a00  push 0x4a8a60
  0043A3C6  e849fdffff  call 0x43a114
  0043A3CE  68a0034b00  push 0x4b03a0
  0043A3D3  e83cfdffff  call 0x43a114
  ```
  → 两条写指令与两个 unit 基址一一对应。
- 调用者 `0x443A3E` 也印证：`push 0x4A8A60; call 0x43A14D` → `[0x4A8A50]`；
  `push 0x4B03A0; call 0x43A14D` → `[0x4B5BE8]`。

结论：**`unit+0x70` 初值 = 立即数 `0x96`(150)，不是公式算出来的。[确认]**

### 2.4a 阵法表的行列方向（踩过一次坑，记下来）
初版以为 `0x4307E5` 收到的是 `(敌阵, 己阵)`，因为 B 侧 push 的是 `[0x4A8A30]`，
而 `0x4A8A30` 挨着 `0x4A8A60`（A 方 unit），看着像 A 方的变量。挖 `0x43A0F6` 才定死：
```
0043A0F9  cmp [ebp+8],0          ; side
0043A0FD  jne 0x43a109
0043A102  mov [0x4a6674],eax      ; side==0 → A 方阵形
0043A10C  mov [0x4a6678],ecx      ; side==1 → B 方阵形
```
调用点：`0x43A1D8 push 0 / call 0x43a0f6`（A）、`0x43A1E9 push 1 / call 0x43a0f6`（B）。
再 `0x43A1F9 [0x4B4C2C]=[0x4A6674]`（**A** 阵）、`0x43A205 [0x4A8A30]=[0x4A6678]`（**B** 阵）。
于是 B 侧传 `arg1=[0x4A8A30]`=己方、A 侧传 `arg1=[0x4B4C2C]`=己方
⇒ **行=己方，列=敌方**，与相克表同向。
（行索引：`0x430796 imul edx,edx,0x34` 用 arg1；取表：`0x43079F mov eax,[edx+eax*4+0x48cd88]` 用 arg2 做列。）
- `idiv` 全是**有符号**除法，负数向 0 截断；JS 里对应 `Math.trunc(a/b)`，不是 `Math.floor`。
- 除法前的 `+0x32`(50) 是让均值居中（士气 50 → 0；unit+0x30=-50 → 0）。
- 顺序固定：相克 → 地形 → 阵法 → 全局 → 士气，**全部是加法**，没有乘法。
- 之后才是兵力段（`min(带兵,上限)`、`min(骑兵,上限)`、`[unit+0x58]=带兵+骑兵`、
  `0x442CB6` 建士兵），与 `+0x70` 无关。

### 2.5 战力的生命周期
- `0x442EFA`/`0x443498` 的唯一调用者：`0x443A3E`（107 B，"开战前算双方战力"）。
- `0x443A3E` 的唯一调用者：`0x443BE6`（在 `0x443B84`，211 B）→ 再上层 `0x44461E`（`0x444459`）。
- 结论：**战力开战前算一次，之后所有判定只读 `unit+0x70` 缓存**（没有中途重算）。

## 3. Q2 疲劳（general+0x3A）

### 3.1 字段身份的硬证据（三条独立互证）
1. TIMES1.INI `[GENERAL]` 解析器 `0x42D1A3` 的键名表里**没有** 士气/疲劳/忠诚，

### 3.3 涨①：战后结算 `0x41048D`（1276 B）

### 3.5 疲劳没有消费点？——只有间接
- 战力：不读（§3.2）。
- 命中：不读。
- 间接：疲劳 ≥ 60 → 每月 士气 -1 → 战力第 5 段 `(士气-50)/5` 每点 -0.2（整数截断后常为 0）。
- `[未解]`：是否影响行军/单挑/技能。建议下一步：查 `EVENT`/`MAGIC.SO` 脚本表与
  `0x44xxxx` 之外的读 `+0x3A`；已知 `.text` 里没有别的消费点了。

## 4. Q3 守将属性 → 战斗参数

### 4.1 结论：原作没有这层换算
`0x442EFA`/`0x443498` 只从 general 读 **`+0x38` 士气**（第 5 段），
武力/智力一个字都没读。整段 0x430000–0x455000 里读 `word [reg+0x34/0x36]`
的 160 处命中，真正是 general 武力/智力的只有 7 个函数：

| 函数 | 读什么 | 用途 |
|---|---|---|
| `0x43D400` | def 武将的 +0x34 | 兵→将命中 `150-武力*20/100` |
| `0x43D4CB` | 双方 +0x34 | 将→将 `150+(STRa-STRb)/2`、将→兵 `150+STR/2`、`0x43B6C9` 目标 `150+STR/3` |
| `0x43E72E` | `max(+0x36,+0x34)` | 武将技效果值 ×倍率（130/150/200/76/66/50%） |
| `0x44D3E0` | +0x36 | AI 选目标（智力高优先） |
| `0x441212` / `0x449900` / `0x44EEA6` | 全部 | UI 面板/菜单绘制 |

### 4.2 "兵种强度"从哪来：兵种相克表
`0x430766` → `相克[自][敌]`（13×13 dword @0x48CD88，值域 -68..+68，反对称，对角 0）。
兵种表 `0x4862C8`（13×0x38）里只有 id/sprite/flag（`[+0]=100..112`），**没有强度数值**。
所以"兵种强度"就是相克表的加成点数，与武将属性无关。

### 4.3 技力从哪来
`general+0x14/+0x16`（当前/上限），INI 里是 `BASEMP`(+0x1A) + 等级成长 + 装备 `MaxMP`(+0x3E)。
战前 `0x43A337 [unit+0x20]=(short)g+0x14`、`0x43A355 [unit+0x28]=(short)g+0x16`；
战后 `0x4107EE [g+0x14]=[unit+0x20]` 回写。**没有 INT→技力 的换算**（`60+INT/2` 是自创）。

### 4.4 给 bstr/bint 的建议
- 若 `bstr/bint` 语义是"兵种强度/兵种智力"（表里的兵种数值）→ **绝不能**塞进守将 STR/INT，
  因为它会污染命中率与武将技；应改走相克表 + 一个固定的兵种基数。
- 若 `bstr/bint` 其实就是守将的武力/智力（守军 JSON 里换了名字）→ 直接当 STR/INT **是对的**，
  原作本来就这么用；缺的不是"换算层"，而是"守将等级/成长 + 装备"。

## 5. 表数值（可直接抄进实现）
见 `dump.txt` §[7]。摘录：
- 相克 13×13 @0x48CD88（行=己方，列=敌方）
- 地形 12×13 @0x48D030（行=地形，列=兵种，索引 = 地形*0x34 + bit*4）
- 阵法 11×11 @0x48D2A0（调用传 `(己阵, 敌阵)`，行=己方；F[i][10]=F[10][j]=25）
- 兵种 bitmask → 索引：`0x4491AC`（bit0..12，无置位返回 -1，相克返回 0）
